## v0.212.0

**タイトル:** 評価制御と台帳互換性を改善

**バージョン:** v0.212.0

**日付:** 2026-10-08

このリリースでは、キャンセル可能な Plutus 評価、Musashi genesis の解析、Dijkstra の validity 検証を改善し、スタンドアロンのサンプルを削除し、任意で実行できる cardano-node 統合テストハーネスを追加します。

### 新機能

* 追加: Plutus V1 から V4 までのコンテキスト対応 Plutus 評価により、処理開始前または評価中に処理をキャンセルして `context.Canceled` を受け取れるようにしました。既存の評価メソッドとの互換性も維持します。
* 導入: cardano-node のソケットに接続し、ChainSync を実行してブロックをデコードし、tip を確認し、停止と再起動を検証する任意実行の統合テストハーネスを追加しました。

### 改善
* 改善: Musashi Shelley genesis の `leiosKey` フィールドを `blsKey` に変更し、`blsPubKey` と `blsPossessionProof` を含む形式を受け付けるようにしました。両方の値を有効な 16 進数として解析し、正確なバイト長を検証して、デコードした鍵を初期プール登録用に保持します。不正な 16 進数や正しくない長さの場合は genesis の解析に失敗します。
* 修正: Dijkstra の validity のデコードとトランザクションオフセットの抽出で、CBOR のブール値だけを受け付けるようにしました。null、undefined、整数などの非ブール値は false として扱わず、エラーになります。

### 重大な変更
* 削除: スタンドアロンのプロトコルサンプル、そのビルドとリリースの自動化、およびサンプル用の `make build` と `make clean` のターゲットを削除しました。これらに依存するアプリケーションでは、ライブラリパッケージと独自のテストまたはビルド手順を使用してください。
* 変更: Musashi Shelley genesis の設定では、`leiosKey` の代わりに、`blsPubKey` と `blsPossessionProof` を含む `blsKey` を使用してください。両方の値には有効な 16 進数と正確なバイト長が必要で、旧フィールドでは BLS キーが設定されません。
* 必須化: Dijkstra の `is_valid` には CBOR のブール値を指定してください。null、undefined、整数などの非ブール値は、トランザクションのデコードまたはオフセット抽出でエラーになります。
