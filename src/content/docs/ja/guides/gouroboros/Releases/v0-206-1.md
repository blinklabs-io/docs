## v0.206.1

**タイトル:** ピア応答を制限し、検証を改善

**バージョン:** v0.206.1

このリリースは、ピア共有応答を制限し、本番動作を変更せずに台帳検証のテスト範囲を拡大し、デコード時に不正なプールリレーデータを拒否します。

### 破壊的変更
* 制限 **SharePeers 応答の処理:** サーバーは各応答を要求されたピアアドレス数まで切り詰めます。ただし、上限は `MaxSharedPeers=230` です。プロトコルフレームワークは `MaxPendingMessageBytes=5,760` を超えるメッセージを拒否します。クライアントは、受信したピアアドレス数が記録された要求数を超えた場合にのみ `ErrTooManyPeersShared` を返します。
* 強化 **プールリレーのデコード:** `PoolRelay.UnmarshalCBOR` は、`4` バイト以外の IPv4 幅、`16` バイト以外の IPv6 幅、およびホスト名リレー種別における null の `dns_name` 値を拒否します。これらの不正な値に対して `ErrPoolRelayAddressWidth` または `ErrPoolRelayMissingHostname` を返します。

### 追加の変更
* 拡充 **台帳検証のカバレッジ:** テストは実際の mainnet Conway fixture と本番の `NewBlockFromCbor`、`VerifyBlock`、`VerifyKes`、`VerifyKesComponents` パスを使用して、ブロック本文ハッシュ、VRF データ、KES データを検証します。このリリースではテスト範囲を拡大しますが、本番動作は変更されません。
