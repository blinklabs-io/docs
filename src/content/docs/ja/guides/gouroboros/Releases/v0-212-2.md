## v0.212.2

**タイトル:** トランザクションプロジェクションとプロトコルの安全性を拡張

**バージョン:** v0.212.2

このリリースでは、UTxO-RPC で利用できるトランザクションデータを拡張し、現行の Dijkstra プロトコルパラメータを追加するとともに、プロトコルとペイロードの検証をより予測可能かつ安全にします。

### 改善
* 追加: Shelley から Dijkstra までの完全なトランザクションプロジェクションを追加しました。minting、withdrawals、collateral、explicit total collateral、validity intervals、explicit zero time to live、governance and proposal data、parameter updates、witnesses、auxiliary data、redeemers、transaction success を含みます。プロジェクションは canonical ordering and indexing を適用し、不正な governance、script、redeemer、execution cost data を拒否するとともに、負の大きな整数と幅広い rational values を正しくエンコードします。

### 破壊的変更

* 構成: Leios の fetch、notification、voting プロトコルは、アプリケーションが対応するバージョン互換の `WithLeios...Config` 値を提供した場合にのみ起動するようにしました。未構成のアクセサは `nil` になり得て、構成なしの peer protocol ID はディスパッチせずに失敗します。Leios を使用するアプリケーションは、一致する構成値を提供する必要があります。

* 変更: デコード時と body proof validation 中に SSC proof hash と delegation または update payload signature を検証することで、Byron ブロックペイロード認証をデフォルトで有効にしました。このリリースでは、`EnableByronSscProofHashValidation` と `EnableByronPayloadValidation` のオプション、および旧 `VerifyConfig` パラメーターを削除しました。アプリケーションでは、明示的な parse-only バイパスとして `SkipBodyHashValidation` を引き続き使用できます。デコーダーは不正な `ssc_proof` データや末尾データを拒否します。

### 検証と互換性

* 強化: コンストラクターの検証を強化し、末尾データのない正確な CBOR デコードを必須にしました。また、Shelley 入力ハッシュの幅と出力インデックスの範囲をパニックなしで確認し、配列とバイト文字列の形状を厳密に適用するとともに、Dijkstra ヘッダーと Leios 拡張をより厳密に検証します。

* 導入: 現行の Dijkstra プロトコルパラメータと、現行の Peras および reference-input コストパラメータ 8 個を導入しました。実装は現行の 54-field CBOR レイアウトをサポートしながら、以前のパラメータレイアウトも保持します。値は genesis、governance、Plutus 変換を通じて公開され、Peras 設定を検証するか、デフォルト値を提供します。
