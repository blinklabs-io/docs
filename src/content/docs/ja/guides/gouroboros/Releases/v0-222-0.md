## v0.222.0

**タイトル:** ledger の動作と protocol interoperability を整合

**リリース日:** 2026-11-28

**バージョン:** v0.222.0

このリリースでは、reference implementation に合わせて ledger の計算と protocol の動作を整合し、malformed input の処理を強化し、protocol interoperability を改善します。また、reference model の coverage を拡張します。

### 新機能

* 拡張: Conway と Dijkstra の `cardano-ledger` reference model の coverage を拡張します。

* 追加: Dijkstra の sub-transaction rule-cell test を網羅的に追加します。

* 有効化: 複数の mux segment にまたがる handshake を有効にします。

* 改善: `PerasVotes` の await と server-idle 処理に reference timeout を追加します。

* 再起動: client の done message 後に 6 つの protocol server を再起動します。

* 拡大: Shelley ベースのすべての era で Dijkstra まで account state にアクセスできるようにし、Byron は引き続き拒否します。

* 解読: Conway と Dijkstra の Local State Query で `GetFuturePParams` query type `33` を decode します。

### 破壊的変更

* 整合: fee、size、minimum coin の計算を `cardano-ledger` に合わせ、Mary の `MinCoinTxOut` が `TransactionOutput` を受け取る API に変更しました。呼び出し側はこの API に渡す引数を更新する必要があります。

* 必須化: TPraos overlay schedule を使用する verification で `VerifyConfig.TPraosOverlay` を必須にしました。

* 再構成: `LeiosVote` message を CIP-0164 の 3 要素形式に変更しました。以前の full-vote offer を処理するアプリケーションでは `LeiosLegacyVote` を使用する必要があります。

* 改定: pipeline の drain と result delivery を `LosslessResults` と `ResultsDropped` を使用する形に変更しました。lossless mode を有効にしない場合、result delivery で結果が失われる可能性があります。

* 修正: `CalculateRollingNonce` が rolling nonce に組み合わせる前に導出済みの 32 byte contribution を受け取るようにしました。

* 切り替え: constructor encoding に Plutus-compatible CBOR を採用し、serialized byte と hash を変更しました。

* 拡張: `cbor.Value` decoding の `MaxArrayElements` と `MaxMapPairs` を tagged content を含む nested value tree 全体に適用し、過大な retained allocation を防ぎます。

* 安全化: Stop と restart の protocol lifecycle operation を安全にし、Start 前の `SendMessage` call を queue し、server の protocol access に restart-safe な `ProtocolInstance` を使用し、`PerasVotes` の context、re-entrancy、panic handling を改善します。embedded または promoted された `*protocol.Protocol` method に依存する application は新しい API に移行する必要があります。

* 拒否: Local State Query の empty または null な era history を拒否し、Byron の slot から epoch への変換を Byron boundary で停止します。

* 送信: negotiated handshake data を送信し、recognized version key の順序を検証し、server agreement data を reference の動作に合わせます。

* 更新: node-to-node ChainSync の `MustReply` timeout を `[601, 911)` seconds に変更し、65,535-byte message limit と 462,000-byte receive budget を分離します。

* 設定: KeepAlive の `Period` と `Timeout` が non-positive の場合に default を使用します。`Period` は `ClientTimeout` より小さく設定してください。

* 変更: Local State Query の filter set encoding を era ごとに行い、Conway 以降では CBOR tag `258` を使用し、nil filter を empty set として encode します。

* 受入: 32-bit の protocol minor value を受け入れ、parameter update と Conway hard-fork following で minor-version wraparound をサポートします。

* 要求: `ValidateHeaderInput` に `Envelope` と、該当する場合は `TPraos Overlay` を必須とし、consensus header validation order、envelope limit、TPraos overlay check を reference に合わせます。

* 検証: `BadInputsUTxO` で collateral input と reference input を検査し、最初に報告する missing-input error を変更します。以前の error type に一致させる caller は対応が必要です。

* 指定: ledger rational には CBOR tag `30` をちょうど 1 つ要求し、Local State Query result では plain rational decoding を維持します。

* 測定: Shelley family transaction size を outer CBOR framing ではなく transaction parts から算出し、fee と maximum-size の動作を安定させます。

* 制限: ChainSync pipelining を server tip 付近で制限し、sync 中の `GetCurrentTip` が carried tip を返すようにし、callback と context の shutdown 処理を改善します。

* 拒否: reply が owed の状態で `Stop` が `MsgDone` を送信できない場合、ChainSync の接続上で `Start` を恒久的に拒否し、`ErrStoppedWithoutDone` を返して muxer を閉じます。

* 適用: Dijkstra governance で `eMax=0` と pledge leverage が `1` 未満の場合を拒否し、cap の削除は引き続き許可します。

* 同期: concurrent な `Close` と handshake setup を調整し、`Dial` が teardown の完了を待つようにします。

* 防止: concurrent な ChainSync operation で response が不一致にならないよう、`GetCurrentTip` が自身の intersect response を待つようにします。

* 返却: `RunLoop` を開始できない場合、`LeiosVotes` と `LeiosNotify` の `Sync` が `ErrProtocolShuttingDown` を返し、stale な running state を残さないようにします。

* 明確化: callback または wire send の前に txsubmission の blocking / non-blocking request-style を検証し、無効な style は protocol violation を返します。

* 区別: peer-sharing timeout で client の `WithTimeout` は `Busy` を待ち、server は `BusyTimeout` を維持し、`Idle` には timeout を設定しません。

* 段階化: Shelley から Conway までの protocol-parameter update map と proposal を段階的に decode し、大きな allocation の前に無効な entry を拒否します。

* 整合: Local State Query の acquire、release、restart の動作を整え、idle 中の `Release` は `ErrNotAcquired` を返し、`AcquireImmutableTip` は node-to-client v16 以降に限定し、call 後に implicit state を release し、server は `MsgDone` 後に restart します。

* 検証: Local Tx Monitor の lifecycle error を整え、idle 中の `Release` は送信せず `ErrNotAcquired` を返し、shutdown 中の `GetMeasures` は送信せず `ErrProtocolShuttingDown` を返します。

* 要求: `ConstructorDecoder` と `cbor.Value` の constructor field が CBOR list であることを要求します。

* 受入: Alonzo parameter update で正しいサイズの PlutusV2 cost model を受け入れます。

* 追加: `DijkstraLeiosKeyAgeContext`、`KeyAge`、`KeyRegisteredIn`、state interface method を追加し、aged-out voting key で署名された Dijkstra Leios certificate を拒否します。direct caller と state implementation は新しい API 要件への対応が必要です。

* 強制: pipeline の `ApplyFunc` より前に `MaxKesEvolutions` を適用し、normal mode で `SkipKesEvolutionsValidation` による bypass を拒否します。pipeline start の動作がより厳格になります。

* 禁止: `GetEraHistory` reply の leading CBOR tag と pre-Conway の set-shaped field 上の CBOR tag を拒否し、Conway 以降の pool-owner set は untagged または tag `258` がちょうど 1 つの場合だけ受け入れます。

### バグ修正

* 削減: local transaction monitor の cache memory 使用量を削減し、transaction ID の collision を安全に処理します。

* 削除: local transaction submission の default `Busy` timeout を削除し、submission にこの timeout を自動適用しないようにします。

* 検証: Conway mainnet header の protocol version を検証します。

* 強化: raw CBOR map decoding を強化し、過大な malformed declaration を処理する際の問題を防ぎます。

* 防止: large allocation の前に malformed input を拒否することで、general constructor decoding を強化します。

* 整合: DMQ message expiry の範囲を `dmq-node` の動作に合わせます。

* 調整: message-submission request timeout を `dmq-node` の動作に合わせます。

* 修正: handshake negotiation、simultaneous open、agreed-version data の処理を修正します。

* 是正: earlier level に由来する Dijkstra committee proposal を修正します。

* 制限: protocol version 16 以降の node-to-node transaction ID request を制限します。

* 算出: stored CBOR がない場合に transaction-body encoding を hash して transaction ID を導出します。

* 改善: PPUP と MIR の edge case validation を改善します。

* 保留: DMQ opcert counter と rate の記録を commit まで遅らせ、拒否された message が古い counter state を残さないようにします。

* 返却: `NoPeerSharing` が local または remote で negotiation された場合に empty peer list を返し、その場合は `ShareRequestFunc` を呼び出しません。

* 固定: `BuildHeader` output を ouroboros-consensus header golden file に固定します。

* 計上: genesis-delegate witness の検査で bootstrap witness root を数え、witness-rule model の coverage を拡張します。

* 解読: tag-258 set を `cbor.Value` で decode し、composite map key をサポートし、これらの value に whole-tree decoding budget を適用します。

* 再試行: transaction-scoped memo build を panic 後に再試行し、waiter が nil/nil の成功結果を受け取らないようにします。

* 検証: 両方の PBFT header validator で Byron PBFT delegation-certificate signature を検証します。

* 整合: ledger/common decoding を `cardano-ledger` に合わせ、bignum multiasset quantity と Mary coin bignum を拒否します。

* 待機: muxer の Stop 時に receiver cleanup の完了を待ち、re-registration の際に置き換えられた live sender と receiver を停止します。

* 安定化: `MsgDone` 後に KeepAlive server を再起動し、Stop と restart の race を処理します。

* 是正: epoch-aware な `PoolRegistered` logic、slot-aware な block state、Dijkstra の cross-level view を統一し、reaped pool を registered として扱わず、同一 block 内の再登録を正しく分類します。

* 保護: governance model evaluation で nil の Conway voter を安全に扱い、proposed ではない hard-fork predecessor に purpose-root state を要求します。

* 共有: combined block decoder と streaming block decoder で transaction-offset extraction を共有し、transaction 数と offset 数の不一致を拒否します。

* 待機: BlockFetch の `Start` が prior-instance goroutine と terminal range callback の完了を待ってから return するようにします。

### その他の変更

* 限定: protocol timer を receiver-only operation に限定し、Local State Query と Local Tx Monitor の default timeout を削除します。

* 追加: CIP-0177 Tachys schedule の conformance test を追加します。

* 削除: duplicate DMQ message-size-check declaration を削除し、package が正常に build できるようにします。

* 補完: admission generation drift の regression coverage を補完します。

* 更新: 必須の `Envelope` input と reference validation order に対応する Tachys model test を更新します。

* 安定化: protocol read-loop test を安定させます。
