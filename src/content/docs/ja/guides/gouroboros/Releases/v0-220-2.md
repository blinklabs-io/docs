## v0.220.2

**タイトル:** プロトコル互換性と入力検証を改善

**リリース日:** 2026-11-15

**バージョン:** v0.220.2

このリリースでは、プロトコル互換性を高め、サイズ超過または不正なデータからデコーダーを保護し、時代ごとの台帳互換性を拡張し、ローカル状態クエリ API を更新して、依存関係を更新します。

### バグ修正

* 改善: トランザクション送信の安全性を高め、`Config.MaxTxSize` と `WithMaxTxSize` を追加しました。台帳デコード前に `ReplyTxs` 本文をサイズ制限し、固定の `MaxTxSizeBytes`（65,540 バイト）を超える `ReplyTxIds` の広告を拒否します。設定した上限は `ReplyTxs` 本文にのみ適用されます。
* 強化: 有理数の検証でデコード前に生の構成要素を確認し、有理数配列を10項目に制限して、ユークリッド計算の削減を最大96ステップに制限します。
* 修正: v11/v12 および v13 以降の CBOR レイアウトで IPv6 アドレスのワードをビッグエンディアンでエンコードおよびデコードします。IPv4 のエンコードは変更されません。
* 一致: ローカル状態クエリでノードの `GetGovState` ワイヤーエンコーディングに合わせます。
* 保持: pre-Conway の重複する withdrawal 報酬アカウントでは最後の金額を保持し、Conway と Dijkstra では重複を引き続き厳格に拒否します。
* 拒否: 必須ブロックコレクションの null または undefined を拒否し、補助データセットにはマップ、無効トランザクションコレクションには配列を要求します。空の definite および indefinite コレクションは引き続き有効で、単独のトランザクション補助データには null を使用できます。

### 破壊的変更

* 変更: 非 myopic 報酬のローカル状態クエリ API は、型付き `NonMyopicMemberRewardsKey` 入力を使用し、正規のノード互換 CBOR 順序で coin キーと credential キーを返すようになりました。

### その他の変更

* 更新: Plutigo 依存関係を v0.12.1 に更新しました。
* 改訂: `x/crypto` 依存関係を v0.59.0 に更新しました。
* 有効化: Babbage では重複する補助データインデックスに last-value-wins を適用し、Conway では重複を引き続き厳格に拒否します。
