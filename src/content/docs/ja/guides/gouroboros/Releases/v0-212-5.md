## v0.212.5

**タイトル:** プロトコルのデコードと検証を改善

**バージョン:** v0.212.5

このリリースでは、Era 履歴とレジャーのデコード互換性を改善し、エンコードされたデータの検証を強化するとともに、レート制限中のアーティファクトワークフローの再試行をより信頼できるものにします。

### 破壊的変更
* 改善しました。ローカル状態クエリの Era 履歴が標準および不定長のセーフゾーンを受け入れ、Era の終了が上限なしであることを示す CBOR `null` と上限付きの終了を区別し、オプションの Peras フィールドを保持し、無効なカウンター、配列長、末尾の CBOR バイトを拒否します。プロトコルに準拠した `EraHistoryResult` の新しいネスト型とフィールド名に合わせて、以前の API および型定義への参照を更新する必要があります。

* 強化しました。レジャーのデコードで固定アリティのタプルが不定長 CBOR 配列と末尾バイトを拒否し、Dijkstra の各バリアントが配列長を検証するようになりました。`cbor.Decode` は提供されたバイト列から直接読み取り、消費したバイト数を予測可能な形で返します。このデコード修正の一環として Plutigo を `v0.9.1` に更新しました。

### 追加変更

* 最適化しました。ベンチマークアーティファクトのダウンロードに `actions/download-artifact` `v8.0.2` を使用し、GitHub が HTTP `429` のレート制限応答を返した場合の再試行動作を改善しました。

* 更新しました。ベンチマークとファズのアーティファクトのアップロードに `actions/upload-artifact` `v7.0.2` を使用し、GitHub が HTTP `429` のレート制限応答を返した場合の再試行動作を改善しました。
