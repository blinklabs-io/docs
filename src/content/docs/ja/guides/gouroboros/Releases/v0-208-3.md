## v0.208.3

**タイトル:** ChainSync のピアパイプライン処理と非同期応答を修正

**バージョン:** v0.208.3

このリリースでは、ChainSync のエージェンシー遷移中におけるピアのパイプラインメッセージ処理を修正し、非同期サーバー応答の動作を明確にします。サーバーはパイプライン化されたリクエストで `AwaitReply` を使用しながら、リクエスト順序とプロトコル状態の遷移を維持できます。

### バグ修正
* 修正 ピアのパイプラインメッセージをピアのエージェンシーが有効になるまで遅延させ、プロトコルが状態上処理できる場合にのみ処理するようにしました。
* 削除 ピアのパイプラインメッセージ用の個別の早期処理経路と遷移マーカーを削除し、状態遷移が通常のプロトコルフローに従うようにしました。
* 明確化 パイプラインメッセージの状態セマンティクスを明確化し、その時点でプロトコルがパイプラインメッセージを処理できるかどうかを状態チェックに反映するようにしました。
* 改善 ChainSync の `MustReply` の受け入れ条件を改善し、NtN と NtC の両方でパイプライン化された `MsgRequestNext` メッセージを受け入れるようにしました。`CanAwait` ビューが許可された状態にまだ追いついていない場合も含まれます。

### その他の変更
* 拡張 `RequestNextFunc` コールバックが、コールバックの戻り前、戻り後、または別のゴルーチンから応答を送信できるようにし、`AwaitReply` とパイプライン化されたリクエストを使用する非同期 ChainSync サーバー応答に対応しました。
* 保証 サーバーが、前のリクエストへの応答を受信し、サーバーが `Idle` に戻った後にのみ、パイプライン化された `RequestNext` の処理を開始するようにし、非同期応答のリクエスト順序を維持しました。
