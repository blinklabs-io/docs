## v0.220.4

**タイトル:** コンセンサス性能とプロトコル検証を改善

**リリース日:** 2026-11-18

**バージョン:** v0.220.4

このリリースでは、コンセンサス性能を改善し、アクティブなリーダー割り当てと Conway トランザクションデータをより正確に検証し、チェーン選択とピア共有の動作を強化して、台帳パラメータの互換性を明確にします。

### パフォーマンス

* 改善: Byron PBFT 状態の更新で共有 append-only ログを使用し、issuer window のコピーや再カウントを行わずに最新状態を定数時間で進めます。ブランチとロールバックの動作は変わりません。`k=2160` では、ベンチマークが約 12,500 ns、65,536 B、1 allocation から約 105 ns、153 B、0 allocations に改善しました。

### 破壊的変更

* 修正: 非 Byron ブロックの issuer 検証で、`VerifyConfig.LeaderPoolVrfKeyHash` を通じてアクティブな leader distribution snapshot を使用します。issuer を検証する呼び出し元はこの callback を提供する必要があります。slot snapshot に含まれる限り、引退済みまたはまだアクティブでない VRF ローテーション済み pool も検証できます。

* 更新: Praos チェーン選択で slot と cold issuer が一致する場合に operational certificate issue number を比較し、VRF output の比較前に大きい番号を選択します。`ChainTip` の実装では `IssuerVkey()` と `OpCertSequenceNumber()` の提供が必要です。

* 強化: Conway 以降の candidate switching に `PreferCandidate` と `PreferredCandidate` を通じた five-slot equal-height VRF distance limit を適用します。`PraosChainSelector` に `ProtocolMajor` を追加し、従来の preferred switching メソッドを非推奨にしました。カスタム `ChainSelector` 実装では新しいメソッドの追加が必要です。

* 名前変更: Dijkstra parameter 55 の正式名を `RefInputsCostPerMultiAssetByte` と `refInputsCostPerMultiAssetByte` に変更し、`RefInputsCostPerMultiAssetPolicy` を非推奨 alias として残します。競合する alias 値は拒否され、CBOR key 55 は変わりません。設定では正式名を使用し、競合する alias を指定しないでください。

### バグ修正

* 拒否: Conway の optional transaction body field が存在する場合、typed decoding 前に CBOR major type が期待された型か確認します。省略された field と有効な zero、array、map のエンコードは引き続き受け入れ、malformed な null、undefined、その他の型違いは拒否します。

* 復元: phase 2 invalid value conservation で使用する Conway DRep deregistration refund を、記録された deposit ではなく certificate amount から計算します。certificate deposit の規則では phase-gated agreement validation が引き続き適用されます。

* 防止: ローカルの peer sharing が無効な場合、`Client.GetPeers` が mini protocol 10 の `ShareRequest` を送信する前に `ErrPeerSharingDisabledLocally` を返します。サーバーは受信したリクエストに空の `SharePeers` で応答し続けるため、`UnknownMiniProtocol` のリセットを防ぎます。
