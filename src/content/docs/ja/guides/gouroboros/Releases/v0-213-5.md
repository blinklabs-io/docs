## v0.213.5

**タイトル:** ブロック取得の制限と台帳評価の拡張

**バージョン:** v0.213.5

Block Fetch のリソース使用を制限し、取得結果の明示的な解放を必須にします。Plutigo v0.9.6 に検証を更新し、大きな台帳データを UPLC の構造ノード上限から分離します。

### 互換性に影響する変更

`MaxBlocksPerRange` と `MaxRangeBytes` で各範囲の累積ブロック数とエンコード済みバイト数を制限し、延長されない `RangeTimeout` を追加しました。上限を超える範囲は `ErrRangeBlockLimit`、`ErrRangeByteLimit`、`ErrRangeTimeout` を返します。`Results()` または `DrainResults()` で受け取ると生 CBOR の予約は自動解放されますが、利用側は各結果の処理後に `BlockItem.Release()` を呼び、自分が所有するデータを消去する必要があります。合計保持予算は `PipelineConfig.MaxRawCborBytes` または `WithMaxRawCborBytes` で設定します。プロトコルの読み取りバッファー計上にも `bytes.Buffer` の保持容量を含めます。

### 修正

- 第 2 段階と Dijkstra の検証フィクスチャに、有効な redeemer データと UTxO 出力アドレスを使用し、対応する Plutigo 評価の互換性のある定数サイズ走査を保持します。
- プールされた評価マシンのパニックと未知の呼び出し元構築項を安全に処理し、定数走査を `syn.Value.Entries()` に変更して、Plutigo を v0.9.6 に更新しました。
- Plutus V1～V4 の datum、redeemer、スクリプトコンテキストを信頼する Plutigo データとして渡します。1,000,000 ノードを超えるインライン datum を含む大きな台帳由来コンテキストは、UPLC 構造ノード数に計上されません。
