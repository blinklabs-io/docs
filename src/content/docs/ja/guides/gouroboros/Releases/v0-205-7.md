## v0.205.7

**タイトル:** 検証、互換性、リソース安全性を改善

**バージョン:** v0.205.7

このリリースは、台帳の検証、時代互換性、暗号処理、公開 API のエラー報告、保留中のネットワークデータの上限を改善します。

### バグ修正
* 強化 **Leios と Dijkstra の検証:** signer bitfield は最大 `8,192` バイトを受け入れ、Dijkstra body は CIP-0164 に従い、トランザクションが同時に存在する場合に Leios 証明書を拒否します。

* 安定化 **ChainSync Stop テストのアサーション:** テストは競合状態のあるタイミングの前提に依存しなくなり、本番の動作は変わりません。

* 改善 **不正な台帳入力の予測可能な失敗:** 不正な Byron 入力、nil の Byron ヘッダー、範囲外のガバナンス ID、不正な検証用 hex は、エラーまたは決定的なセンチネル出力を返します。公開関数 `ledger.NewByronTransactionInput` は `(value, error)` を返すようになりました。

* 保護 **KES secret の処理:** ゼロ化によるクリーンアップが強化され、evolve-chain テストの失敗時に、より明確な診断情報を提供します。

* 修正 **Alonzo 出力と担保の検証:** min-UTxO のサイズ計算が各出力を考慮し、デコーダーは削除された CBOR キー `15` を拒否し、担保上限の計算は正しく丸められ、オーバーフローガードが不正な計算を阻止します。`alonzo.MinCoinTxOut` 関数は `TransactionOutput` を受け入れるようになりました。

* 拒否 **Conway と Dijkstra の不正なマルチアセットエンコーディング:** ゼロ数量と空のマルチアセット値は各時代のルールに従って失敗し、Conway より前の動作は変わりません。

* 適用 **DRep とガバナンスアクションの上限:** DRep 値は必須の CBOR 形式に従い、資格情報には `28` バイトが必要で、ガバナンスアクションのインデックスは `65,535` を超えられません。

* ブロック **Conway と Dijkstra の不正なポインターアドレス:** 範囲外のポインターアドレス構成要素は検証に失敗し、古い時代では従来の緩やかな動作が維持されます。

* 制限 **保留中のネットワークデータ:** TxSubmission は保留中のバイト数、未処理のリクエスト数、コールバックの戻り値を制限します。接続全体の多重化再構成バッファにはデフォルトで `16 MiB` の上限を設け、`MaxPendingMessageBytes` を `721,424` として導出します。
