## v0.202.7（2026年9月3日）

**タイトル:** 検証とリクエストの信頼性を強化

**日付:** 2026年9月3日

**バージョン:** v0.202.7

このリリースでは、証明書とトランザクションの検証を強化し、leiosfetch のリクエスト処理を改善し、サポート対象の各 era で Shelley ステークプール証明書の検証を追加します。

### 💪 改善

* 強化 **証明書とガバナンスの検証:** 証明書とガバナンス投票者の認証には、適切な witness が必要になりました。同じ credential ルールを key credential と script credential の検証に適用し、Plutus redeemer pointer と native script のチェックを厳格化し、withdrawal が混在する場合の redeemer の順序を修正して、トランザクション検証を改善します。エクスポートされた MIR genesis delegate quorum API により、アプリケーションは quorum を直接検証できます。

* 強化 **トランザクションと redeemer のインデックス検証:** Alonzo と Dijkstra は、値がプラットフォームの整数型でオーバーフローするインデックス、または該当するコレクションの範囲外にあるインデックスを、32 ビットビルドを含めて拒否します。

* 改善 **leiosfetch のリクエスト処理:** 設定されていないリクエストがハングせず、状況に応じて明示的な「ブロックなし」の応答または接続エラーを返します。リクエスト型は共有 coordinator を使用し、ストリーミングによる範囲配信を維持しながら、放棄されたリクエストを安全に完了します。`VotesRequest` と `BlockRangeRequest` は context パラメーターを受け取るため、呼び出し元がリクエストの有効期間を制御できます。

* 追加 **Shelley ステークプール証明書の検証:** Shelley から Dijkstra まで、`POOL` 証明書を検証します。検証には、`minPoolCost`、報酬アカウントのネットワーク、VRF キーの再利用、登録、廃止に関するチェックが含まれます。型付きエラーとプロトコルパラメーターおよび epoch capability のサポートにより、アプリケーションは検証の失敗と era 固有の要件を確認できます。
