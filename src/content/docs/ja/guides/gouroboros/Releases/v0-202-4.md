## v0.202.4（2026年9月1日）

**タイトル:** シャットダウン、検証、パイプラインの信頼性を向上

**日付:** 2026年9月1日

**バージョン:** v0.202.4

このリリースでは、サービスのシャットダウンを決定的にし、無効な台帳データと Plutus データを早期に拒否し、パイプラインのキャンセルと排出を一貫して処理します。

### 💪 改善

* 改善 **ローカルメッセージ通知のシャットダウン:** `Server.Stop` がエクスポートされ、`Start` の前後でも繰り返し呼び出しても安全になりました。シャットダウン時にサーバーとプロトコルの完了チャンネルを閉じるため、ブロックしている `RequestMessages` と `WaitForMessage` が完了でき、期限切れクリーナーとタイマーも停止します。停止前に呼び出した場合、`Protocol.Start` は何もせず、完了チャンネルは正確に一度だけ閉じます。

* 修正 **ステークプールマージンの処理:** JSON と CBOR の境界、報酬計算、Shelley genesis の `extraPool` 解析、UTxO RPC 変換でマージンを検証するようになりました。有効なマージンは包含的な `[0, 1]` の範囲内で、分母が正であり、変換の範囲条件を満たす必要があります。無効または欠落したマージンは、受け入れたりゼロとして扱ったりせず、エラーを返します。

* 強化 **Plutus スクリプトの検証:** Plutigo v0.5.0 により、フェーズ 2 の実行前にプロトコルに応じて Plutus データを検証します。担保返却と Dijkstra サブトランザクション出力の参照スクリプトも検証し、typed nil スクリプトには不正なスクリプトエラーを返します。不正な witness と参照スクリプトは、フェーズ 2 の実行中やパニックではなく、より早く決定的に失敗します。

* 改善 **パイプラインの停止と排出:** 停止開始の状態を追跡し、その後の `Submit` と `Fence` による作業を拒否し、呼び出し元のキャンセルを優先するようになりました。`WaitForDrain` は `PendingCount` のポーリングではなく、受け入れた作業の正確な境界を待ちます。明示的な停止では成功し、親のキャンセルでは `ErrPipelineStopped` を返します。`PendingCount` は観測用の値としてのみ扱います。
