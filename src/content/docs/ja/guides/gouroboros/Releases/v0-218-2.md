## v0.218.2

**タイトル:** トランザクション検証と台帳互換性を改善

**バージョン:** v0.218.2

このリリースでは、トランザクションエンベロープ処理、検証設定、デコーダーの厳密性、ジェネシス JSON の互換性、従来の Plutus 変換、Dijkstra の性能を改善しました。

### バグ修正

* 改善し、Alonzo 系トランザクションエンベロープで、`IsValid` を省略した正規の 3 要素形式を受け入れ、トランザクションサイズを正規の方法で計算し、トランザクション時代をより正確に分類し、不正な位置に移動した `IsValid` 形式を拒否するようにしました。
* 修正し、Byron ブートストラップ出力属性のサイズ計測が、CBOR のフレーミング、キー、ネットワークマジックを除外し、デコード済み HD 導出パスのペイロードと未知の属性値だけを数えるようにしました。64 バイトの上限は維持されます。
* 強化し、Babbage 出力と Conway redeemer で 64 ビットの CBOR マップヘッドを拒否し、Byron 属性キーの昇順を必須にし、指定された Dijkstra パラメータフィールドにバージョン 12 の bounded rational 検証を適用するようにしました。
* 追加し、フェーズ 2 が無効な Alonzo および Babbage トランザクションについて、ステーク登録のデポジットと登録解除の返金を計上するようにしました。
* 修正し、ブートストラップのネイティブスクリプト証人ハッシュで Byron アドレスルートを使用し、不正なルートをスキップするようにしました。
* 改訂し、Shelley、Alonzo、Conway のジェネシス JSON の検証と正規化をリファレンス実装に合わせました。ジェネシス JSON では必須フィールドと数値範囲を満たし、対応する別名を使用し、重複キーを正しく扱い、正規の数値形式を使用する必要があります。
* 拒否し、アドレスキー `0` または値キー `1` がない Babbage のマップ形式出力を受け入れないようにしました。Conway でも同じ検証動作を回帰テストで確認しています。
* 整合させ、従来の Plutus V1 と V2 の withdrawal の順序および Byron のフィルタリングを台帳に合わせ、`GenesisKeyDelegation` と MIR 証明書の変換を追加しました。

### 破壊的変更

* 追加し、`VerifyConfig.MaxKesEvolutions` と `SkipKesEvolutionsValidation` を提供します。検証をスキップしない限り、検証には明示的な 0 以外の KES 設定が必要になり、`VerifyBlock` では Shelley の `maxKESEvolutions` 上限を適用します。`VerifyBlockLocal` の動作は変わりません。

### パフォーマンス

* 削減し、キャッシュ済み Dijkstra トランザクションハッシュの計算時の割り当てを減らしました。ハッシュの動作は変わりません。
