## v0.220.0

**タイトル:** セキュリティと台帳互換性を改善

**バージョン:** v0.220.0

このリリースでは、Go と暗号ライブラリの脆弱性を解消し、Dijkstra の最小手数料計算を改善し、IPv6 リレーの表現を修正し、Leios 証明書と台帳の検証を厳格化しました。

### セキュリティ

* 更新し、ルートモジュールと tools モジュールの Go バージョン要件を `1.26.10` から `1.26.11` に変更して、`govulncheck` が報告した標準ライブラリの脆弱性を解消しました。
* 解決し、両モジュールとそのチェックサムで `golang.org/x/crypto` を `v0.58.0` から `v0.58.1-0.20261009181718-2f1f834330b2` に更新して、モジュールレベルの `govulncheck` の検出結果に対応しました。ビルドとテストの動作は変わりません。

### バグ修正

* 修正し、Dijkstra の最小手数料計算に、トップレベルのトランザクションとサブトランザクションが消費するリファレンススクリプトを含めることで、最小手数料の過少計算やゼロ計算を防ぐようにしました。

### 破壊的変更

* 標準化し、`PoolRelay.Ipv6` の保存形式を標準ネットワークバイト順にしました。一方、CBOR、genesis、UTxO RPC のシリアライズでは台帳のワイヤー順序を維持します。無効な IPv6 変換は UTxO RPC エラーを返すようになり、以前のワイヤー順序の値を永続化している利用側では移行が必要になる場合があります。
* 設定し、Leios 証明書検証で通知ブロックの raw 32 バイトハッシュをデフォルトで使用するようにしました。台帳 capability の設定で CBOR フレーム化されたプロトタイプエンコーディングを選択でき、未対応の値は設定エラーを返すようになりました。
* 強制し、Shelley の `DELEG` とリレーの `dns_name` がない場合のチェックを、ステーク登録と登録解除、MIR のタイミングとポット検証、genesis delegation、プロトコルバージョン別のリレー検証に適用しました。台帳状態では関連する capability が必要になり、利用できない場合はエラーを返すようになりました。
