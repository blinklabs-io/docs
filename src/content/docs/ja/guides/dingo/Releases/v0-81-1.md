## v0.81.1

**タイトル:** 台帳処理、同期、ストレージ、APIの信頼性を改善

**バージョン:** v0.81.1

**リリース:** [v0.81.1](https://github.com/blinklabs-io/dingo/releases/tag/v0.81.1)

Dingo v0.81.1では、Dingoノードとライブラリの台帳処理、同期、ストレージ、APIの保護を改善しました。リリース配信、ガバナンスの動作、運用の可視性も強化しました。

### 推奨ネットワーク互換性 ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### ノード運用とリリース配信
* 追加: `ledgerApplyRowBatchingEnabled`を既定で無効な設定として構成、CLI、環境変数に追加し、コアストレージで対象となる未検証の台帳書き込みを任意にバッチ処理できるようにしました。
* 確保: メインイメージのマニフェストがイメージのビルド成功後にだけ公開されるようにし、リリース成果物のビルド成功を確認できるようにしました。
* 復元: Conway Mithrilスナップショットのアンカーepochへの寄付を復元しました。

### ストレージと台帳処理
* 最適化: SQLiteのバッチUTxO支出計画でポイントルックアップを使用し、SQLite固有のステートメントを他のデータベース方言のキャッシュから除外しました。
* 検証: 保留中のアカウントと状態のオーバーレイ、およびmempoolの保持バイト数を検証し、安定した利用不能状態を明示的に処理しました。
* 改善: 移植可能なページネーションと移行リプレイ、SQLiteのメンテナンス、アセット専用UTxOクエリ、運用アラートを改善しました。
* キャッシュ: 頻繁に使用するSQLステートメントをキャッシュし、接続間のSQLiteステートメントエラーを防止しました。

### 同期とネットワーク運用
* 延期: 予測範囲を超えるChainSyncヘッダーを遅延させ、チェーン選択やBlockFetchで使用せず、ピアにペナルティを科さないようにしました。
* 再起動: ヘッダーキューが満杯になったときにBlockFetchを再起動し、復旧に失敗した場合は明示的な失敗理由で再同期するようにしました。
* 防止: leios-fetchピアが見つからない場合に台帳停止カウンターが増加しないようにしました。

### API、設定、ガバナンス
* 制限: unary UTxO RPCの同時実行数、レスポンスバイト数、mempool読み取りを制限し、既定値を`MaxConcurrentBulkRequests=32`、`MaxResponseBytes=16 MiB`、`MaxMempoolItems=1000`、`BulkResponseWriteTimeout=30s`に設定して、リクエストログも強化しました。
* 強化: DevNet鍵のインストールを強化し、公開APIで末尾のCBORバイトを拒否し、タイムアウトした`WaitForTx`検索をキャンセルし、Mithril lottery indexに上限を設けました。
* 導入: `LedgerPrefetchAheadEnabled`を既定で無効なCLI、環境変数、設定オプションとして追加しました。
* 修正: Conway DRepのライフサイクル、委任のクリーンアップ、PV10遷移の処理、台帳状態の解析を修正しました。
