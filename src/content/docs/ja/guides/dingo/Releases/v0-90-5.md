## v0.90.5

**タイトル:** ノードの同等性、プロトコル互換性、性能、運用を向上

**バージョン:** v0.90.5

**リリース:** [v0.90.5](https://github.com/blinklabs-io/dingo/releases/tag/v0.90.5)

**比較:** [v0.90.4...v0.90.5](https://github.com/blinklabs-io/dingo/compare/v0.90.4...v0.90.5)

Dingo v0.90.5では、ノード同等性ワークフロー、プロトコル互換性、トランザクション処理、ピア操作、開発ネットワークの検証を改善しました。

### 推奨ネットワーク互換性 ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

#### ノード同等性と同期
* 追加: `node-parity from-genesis`で`--boundary-capture-dir`をサポートし、chainsyncセッションを維持し、境界処理前にUTxOを取得し、一時的なKoios `/tx_info` 失敗を再試行するようにしました。これらのワークフローで境界データを取得し、一時的なトランザクション情報の失敗が発生しても処理を継続できます。
* 除去: ノード同等性の再構築中にAllegraで償還されたByron UTxOを除外し、限定的な不一致サンプルを含めることで、差異を無制限に出力せず確認しやすくしました。

#### ネットワークとコンセンサス
* 付与: Genesisデータを照合できるピアに受信スロットを割り当て、照合中もそのピアが参加できるようにしました。
* 出力: Leiosを使用しないDijkstraチェーンで10フィールドのPraosヘッダーを生成し、適用対象のチェーンに対してのみLeiosブロック生成を有効にしました。
* 適用: Leios投票にCIP-164のウォールクロック時間を適用し、関連するVoteManagerとヘッダーイベントのインターフェースを更新して、変更後の時間動作を渡すようにしました。

#### トランザクション処理とPlutus評価
* 変換: Alonzo、Babbage、Conway全体で`TxInfo`から`PlutusData`への変換をキャッシュし、3つすべての時代にわたるベンチマークを追加しました。繰り返しの変換でキャッシュ結果を利用できます。
* 構造化: 型付き台帳エラーとPlutus再構築コンテキストを含む、Conwayの構造化された`LocalTxSubmission`拒否理由をエンコードしました。クライアントは具体的な理由データを受け取れるようになりました。
* 再利用: 利用可能な場合はキャッシュ済みのトランザクション署名検証結果を再利用し、結果が既知のトランザクションで検証を繰り返さないようにしました。
* 保持: 成功したConwayおよびDijkstraのPlutusフェーズ2評価を再利用できるよう保持し、同じ成功結果を繰り返し評価しないようにしました。
* 保存: `LedgerView`ごとにMIR保留報酬を保存し、同じビュー内での繰り返しの読み取りでキャッシュ済みの報酬状態を利用できるようにしました。

#### 開発ネットワークと設定
* 拡張: PV10およびPV11のPlutus境界付き引数に関するdevnet conformanceの対象範囲を広げ、PV11仕様の処理を高速化し、`DEVNET_SPEC_OVERRIDE`の値を使用前に検証するようにしました。
* 変更: Genesisの既定の制御グループを削除し、既定の`genesisBootstrap.corroborationPeers`を`1`から`0`に変更しました。既定の設定で照合ピアが割り当てられなくなります。
