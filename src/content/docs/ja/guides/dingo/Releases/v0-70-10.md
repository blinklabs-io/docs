## v0.70.10

**タイトル:** ストレージの安全性、同期の信頼性、ネットワーク対応を改善

**日付:** Not provided

**バージョン:** v0.70.10

**リリース:** [v0.70.10](https://github.com/blinklabs-io/dingo/releases/tag/v0.70.10)

このリリースでは、データベース保持、tracing設定、Leiosの処理、SQLite queryのパフォーマンス、stateの検証、rollbackからの復旧、schedulerの更新、MusashiおよびCardano prototypeの準備状況を改善します。

### 推奨ネットワーク互換性 ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### ハイライト

* `auth_committee_hot` の増加を、書き込み時とメンテナンス中のpruningによって上限内に収め、設定可能な `CommitteeAuthRetentionSlots` に対応しました。rollback時も必要なエントリを保持し、そのポリシーを `DATABASE.md` で説明します。

* tracingが無効な場合、長期間使用するSQL poolに対する `otelsql` のラップを無効化し、tracingが有効な場合の動作は維持しました。`OpenDB` は `tracingEnabled` を受け取るようになりました。

* MusashiおよびCardano prototypeの設定を `docker-cardano-configs` の `20260910-1` とprototype `2026w36` に更新しました。genesisおよびprotocol値、LeiosとPlutus V4のパラメータ、topologyとpeer snapshot、`leiosKey` に代わる `blsKey`、pool metadata hashの処理、関連する依存関係と設定も更新しました。

* roll-forward headerからのLeios local vote emissionを有効化し、decline metricsを追加し、declined voteに対するwarningをthrottledに変更しました。

* `queryUtxoStakeRefs` を `tx_id` のbatch処理を中心に再構成し、SQLite indexを維持して大規模なscanを回避しました。

* Badger lifecycle test configurationを制限し、migration済みmetadata templateを再利用して、範囲を限定した再現可能なlifecycle coverageを実現しました。

* Windows snapshot interruption setupのtimeoutを30秒から2分に延長し、setupが早期に失敗する問題を減らしました。

* UTxORPC `FollowTip` で `SlotToTime` のエラーを返すようにし、あいまいな `Timestamp=0` を返さないようにしました。ただし、origin rollbackではこの値を維持します。

* 負のSQLite `maxConnections` 値を拒否し、tracing-gatingの経路をテスト対象にしました。

* `LedgerView` のstorage faultを返すようにし、rule verdictを返さないようにしました。これにより、storage failureとledger resultを区別できます。

* 古くなったテストを現在の動作に合わせて更新しましたが、製品の機能は変更していません。

* 設定の読み込みで不正なgenesis security parameterを検出し、startup前に失敗するようにしました。

* 読み取り不能または不正な形式のMithril trust-boundary slot stateを検出した場合はstartupを失敗させ、hash reconstruction failureではstartupを停止しないようにしました。

* accelerated DevNetの `txpump` quarantineを100 slotに短縮し、canonical runでは600 slotを維持しました。quarantineはconfirmationでもrollback recoveryでもないことも明確にしました。

* `LedgerView` ごとに成功したUTxO readをmemoizeし、benchmark結果を改善して重複したreadを減らしました。

* rollback後のreload failureが発生した場合に即座に失敗し、そのfailureを `FatalErrorFunc` に伝えるようにしました。

* `gouroboros` を `v0.204.3` にアップグレードし、test fixture hashを修正しました。

* scheduler interval updateを1 slotのcoalescing bufferによって確実に配信するようにしました。
