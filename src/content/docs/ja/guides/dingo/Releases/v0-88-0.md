## v0.88.0

**タイトル:** スナップショットのセキュリティ、プロトコル互換性、サービス信頼性を改善

**バージョン:** v0.88.0

**リリース:** [v0.88.0](https://github.com/blinklabs-io/dingo/releases/tag/v0.88.0)

**比較:** [v0.87.1...v0.88.0](https://github.com/blinklabs-io/dingo/compare/v0.87.1...v0.88.0)

Dingo v0.88.0では、スナップショットの完全性、トランスポート認証、ローカル状態の互換性、リソース保護、チェーン検証、サービスの信頼性を強化しました。

### 推奨ネットワーク互換性 ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### セキュリティとデータ整合性
* 追加: 宣言されたペイロードサイズとSHA-256ダイジェストを検証する認証済みクラウドスナップショットミラーリングを追加し、署名のないスナップショット、シンボリックリンク、置換されたエントリを拒否し、マニフェストより先にペイロードをアップロードし、ディレクトリのアップロードのみをサポートする宛先には検証済みファイルをステージングするようにしました。
* 限定: インバウンドトポロジーの権限を、アドレスとポートを含む正確なトランスポート識別情報に限定し、ホストのみのNATまたはプロキシの一致が信頼やバレンシーを継承しないようにしました。
* 保護: キーなしのローカル復元でプライベートな信頼済みスナップショットパスを必須にし、ペイロード、メタデータ、マニフェストの書き込みをディレクトリ置換から保護しました。置換が発生すると、スナップショット作成は`ErrSnapshotDirectoryReplaced`を返すようになりました。
* 検証: 保持された候補祖先と運用証明書状態に対してピアフォークヘッダーを検証し、検証まで遅延ヘッダーを保持し、ロールバック中に候補キャッシュを消去するようにしました。
* 抑制: ノードからクライアントへのすべてのLocalStateQueryリクエストの受信を、信頼済みリスナーを含めて`1 MiB`に制限し、再構成前にサイズ超過リクエストを拒否するようにしました。

### 互換性とプロトコル動作
* 防止: Dijkstraトランザクションが、保留中の登録に含まれるキーを含め、アクティブなプールまたは将来のプールのBLS投票キーを再利用しないようにしました。
* 復元: 従来のShelley `GetPoolDistr`ローカル状態クエリを、ポイントを認識するステークスナップショットと正しいベアマップ`GetCBOR`エンコーディングで復元しました。
* 維持: 履歴バックフィル中に報酬のライブステーク累計を維持し、ライブUTxOステーキングキーの累計が欠落している場合は不変条件エラーとして扱うようにしました。
* 強化: Mithrilパブリックカタログのリクエストをキャッシュして統合し、クライアントごとのダウンロード受付制限を追加し、最低レートを`64 KiB/s`とする30秒の猶予期間を適用しました。不正な登録は`400`を返し、刈り込み済みスナップショットは`409`を返すようにしました。
* 高速化: インデックス化したアドレスからトランザクションへのマップによりBlockfrostメンプールアドレスクエリを高速化し、グローバルに4つ、クライアントごとに1つの受付スロットを設けました。サービスが容量を使い果たすと`Retry-After: 1`を伴う`429`を返し、結果には連鎖したトランザクションを含めるようにしました。
* 精密化: バイト完全一致のCBORコンフォーマンス規則で、再シリアライズしたバイト列と期待されるバイト列を正規化せずに比較するようにしました。バイト完全一致でない規則は正規化を維持し、完全一致の不一致には固有の理由を報告します。
* 固定: Mesh v1.4.15とKupo v2.12のOpenAPI契約を固定しました。Meshのエラーは再試行情報を本文に含むHTTP `500`を返し、Meshの`/account/coins`はページネーションメタデータなしで完全なUTxOセットを返します。Kupoはスロット0セレクター、uint64出力インデックス、厳密なミューテーションデコードを統一し、欠落したdatum、スクリプト、チェックポイント、スクリプト言語をJSON `null`として返します。
* 整合: Blockfrost OpenAPI v0.1.93に合わせてルート、クエリ、レスポンスのコンフォーマンス検査を追加し、空の`/pools`レスポンスを`null`ではなく`[]`としてエンコードするようにしました。
* 修正: 台帳、UTxO RPC、設定、Mithril、Ouroboros、ノード互換性にわたる32ビット整数幅の扱いを修正し、`GOARCH=386`のvetカバレッジと境界テストを追加しました。

### リソース制御とサービス運用
* 分離: Barkのクラウドカタログスキャンをカタログゲートから分離し、スキャン世代が現在の世代と一致した場合にのみ結果を公開し、宛先ごとの指数バックオフを30秒から5分まで適用するようにしました。
* 必須化: `StreamOperationProgress`に検証済みクライアント証明書を必須とし、ストリーム数をグローバルで32、証明書ごとに4に制限し、15分後に`DeadlineExceeded`でストリームを閉じるようにしました。
* 終了: 信頼済みローカルのノードからクライアントへのアイドルセッションをデフォルトで2分後に終了するようにしました。ただし、アクティブなプロトコル処理とChainSync `AwaitReply`はアイドル期限を一時停止します。
* 簡素化: インバウンドのノード間受付を簡素化し、予約を接続へ不可分に変換して、容量を正確に1回だけ解放するようにしました。
* 保存: オフチェーンメタデータポインターの検出に永続カーソルと64行のキーセットページを追加し、インプレース更新を最終的に再スキャンし、`NULL`アンカーを安全にスキップするようにしました。
* 作成: シンボリックリンクを追従せずに`DINGO_LOG_FILE`用の新しい`0644`通常ファイルを作成し、標準出力と標準エラーを取得し、既存のターゲット、シンボリックリンク、FIFOを拒否するようにしました。
* 制御: Meshの`/construction/submit`、UTxO RPCの`SubmitTx`と`EvalTx`、内部送信経路でトランザクション送信の受付を制限し、送信スロットをメタデータ読み取り容量と連携するようにしました。外部リクエストはデコード前に容量を予約し、容量が埋まっている場合は再試行可能またはリソース不足のエラーを返します。内部の`AddTransaction`呼び出しは待機またはコンテキストのキャンセルに従い、ピア切断時にはピア検証をキャンセルします。組み込みUTxO RPCプロバイダーは`Host`が空の場合に`127.0.0.1`へバインドし、リモートアクセスには明示的なホスト設定が必要です。
* 統一: 外向きHTTPの`User-Agent`を`dingo/<version> (<GOOS>/<GOARCH>)`に統一しました。有効な`DINGO_HTTP_USER_AGENT`で上書きでき、Dingoは無効な上書きを無視します。既存のリクエストヘッダーを優先し、コンポーネント固有の`userAgent`設定も引き続き優先します。
* 拒否: 適用可能な時代固有の`MaxTxSize`をバリデーターが提供する場合、デコード前およびメンプール変更ゲート前にサイズ超過トランザクションを拒否するようにしました。不明または未適用の制限は、引き続き台帳の検証に委ねます。

### コンセンサスと配布の更新
* 更新: 同梱のnviewおよびtxtopコンテナイメージを`0.16.0`から`0.17.0`にアップグレードし、固定されたダイジェストを更新しました。
* 拡張: `GetStakePoolState`、Praos2 `GetChainDepState`、ノードからクライアントへのv21からv23向けに修正したShelleyジェネシスレイアウト、永続化されたBLS登録エポック、gouroboros v0.213.10により、MusashiとLeiosのローカル状態互換性を拡張しました。
* 制限: BlockFetchポイント検証を同時32件のルックアップに制限し、検証が容量に達した場合はデータベース処理の前に`NoBlocks`を返し、欠落ポイントのローテーション中も接続ごとの失敗ルックアップ予算を維持するようにしました。
* 通知: セキュリティ深度の確定後に`SlotBattleEvent`を発行し、正規チェーンの所属から`Won`を計算し、ルックアップに失敗した場合は再試行するようにしました。
* 改善: ライブ処理ループの取り込みハーネスが直ちにチェーン先端へ到達するようにし、同期テストの信頼性を高めました。
* 精緻化: ledger-rulesコンフォーマンスレポートがコーパスや合計値をシリアライズしないようにし、NDC台帳リビジョンを更新し、述語マッピングを精緻化しました。
* 予測: 適用済みチップのヘッダー検証中にConwayからDijkstraへの境界をまたぐ後継時代のパラメーターを予測し、Leios DevNetがエポック1で遷移を検証するようにしました。
* 固定: DevNetのテストネット生成ツールをv0.2.0に固定し、cardano-node 11.1のトレーシング設定に対応させ、関連するDevNetガイダンスを更新しました。
* 転送: 決定論的なピアのインバウンドエンベロープ失敗と集約`MaxBlockExUnits`失敗をreject-and-rewind回復へ移行しました。ローカルでフォージしたブロックと信頼済みリプレイに対する既存の例外は維持します。
* 導入: ネットワークマジック`6`を持つ名前付き`DijkstraNet`ネットワーク選択、埋め込み済みの標準設定、リレー探索時の複数アドレスDNS展開を追加し、ホスト名拒否リストの動作を維持しました。cardano-configs、gouroboros、Goランタイムのピンも更新しました。
* 解消: Musashiのリーダー資格とDijkstraトランザクション検証に対する暗黙のバイパスをなくしました。Leios証明書検証は不可分に管理された投票マネージャーを使用し、マネージャーが利用できない場合は再試行します。
* 追加: LeiosのGrafanaダッシュボードとナビゲーションリンクを追加し、休止中のLeiosメトリクスとフォージングメトリクスの動作を文書化しました。
* 防止: `LeiosNotify`が送信完了の通知前に送信中の投票エントリを再提示しないようにしました。待機中のリクエストはコミットまたは解放後に起床し、次のエントリを受け取ります。
