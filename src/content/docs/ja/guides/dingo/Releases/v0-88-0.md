## v0.88.0

**タイトル:** スナップショットのセキュリティ、プロトコル互換性、サービス信頼性を改善

**バージョン:** v0.88.0

**リリース:** [v0.88.0](https://github.com/blinklabs-io/dingo/releases/tag/v0.88.0)

**比較:** [v0.87.1...v0.88.0](https://github.com/blinklabs-io/dingo/compare/v0.87.1...v0.88.0)

Dingo v0.88.0では、スナップショットの完全性、トランスポート認証、ローカル状態の互換性、リソース保護、チェーン検証、サービスの信頼性を強化しました。

### 推奨ネットワーク互換性 ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### セキュリティとデータ整合性
* 追加: 宣言されたペイロードサイズとSHA-256ダイジェストを検証する認証済みクラウドスナップショットミラーリングを追加し、署名のないスナップショット、シンボリックリンク、置換されたエントリを拒否し、マニフェストより先にペイロードをアップロードし、ディレクトリのアップロードのみをサポートする宛先には検証済みファイルをステージングするようにしました。
* 限定: インバウンドトポロジーの権限を、アドレスとポートを含む正確なトランスポートIDに限定し、ホストのみのNATまたはプロキシの一致が信頼やバレンシーを継承しないようにしました。
* 保護: キーなしのローカル復元でプライベートな信頼済みスナップショットパスを必須にし、ペイロード、メタデータ、マニフェストの書き込みをディレクトリ置換から保護しました。置換が発生すると、スナップショット作成は`ErrSnapshotDirectoryReplaced`を返すようになりました。
* 検証: 保持された候補祖先と運用証明書状態に対してピアフォークヘッダーを検証し、検証まで遅延ヘッダーを保持し、ロールバック中に候補キャッシュを消去するようにしました。
* 抑制: すべてのノード間クライアントLocalStateQueryリクエストの受信を、信頼済みリスナーを含めて`1 MiB`に制限し、再構成前にサイズ超過リクエストを拒否するようにしました。

### 互換性とプロトコル動作
* 防止: Dijkstraトランザクションが、保留中の登録に含まれるキーを含め、アクティブなプールまたは将来のプールのBLS投票キーを再利用しないようにしました。
* 復元: 従来のShelley `GetPoolDistr`ローカル状態クエリを、ポイントを認識するステークスナップショットと正しいベアマップ`GetCBOR`エンコーディングで復元しました。
* 維持: 履歴バックフィル中に報酬のライブステーク累計を維持し、ライブUTxOステーキングキーの累計が欠落している場合は不変条件エラーとして扱うようにしました。
* 強化: Mithrilパブリックカタログのリクエストをキャッシュして統合し、クライアントごとのダウンロード受付制限を追加し、最低レートを`64 KiB/s`とする30秒の猶予期間を適用しました。不正な登録は`400`を返し、刈り込み済みスナップショットは`409`を返すようにしました。
* 高速化: インデックス化したアドレスからトランザクションへのマップによりBlockfrostメンプールアドレスクエリを高速化し、グローバルに4つ、クライアントごとに1つの受付スロットを設けました。サービスが容量を使い果たすと`Retry-After: 1`を伴う`429`を返し、結果には連鎖したトランザクションを含めるようにしました。

### リソース制御とサービス運用
* 分離: Barkのクラウドカタログスキャンをカタログゲートから分離し、スキャン世代が現在の世代と一致した場合にのみ結果を公開し、宛先ごとの指数バックオフを30秒から5分まで適用するようにしました。
* 必須化: `StreamOperationProgress`に検証済みクライアント証明書を必須とし、ストリーム数をグローバルで32、証明書ごとに4に制限し、15分後に`DeadlineExceeded`でストリームを閉じるようにしました。
* 終了: 信頼済みローカルのノード間クライアントアイドルセッションをデフォルトで2分後に終了するようにしました。ただし、アクティブなプロトコル処理とChainSync `AwaitReply`はアイドル期限を一時停止します。
* 簡素化: インバウンドのノード間受付を簡素化し、予約を接続へアトミックに変換して、容量を正確に1回だけ解放するようにしました。
* 保存: オフチェーンメタデータポインターの検出に永続カーソルと64行のキーページを追加し、インプレース更新を最終的に再スキャンし、`NULL`アンカーを安全にスキップするようにしました。
* 作成: シンボリックリンクを追従せずに`DINGO_LOG_FILE`用の新しい`0644`通常ファイルを作成し、標準出力と標準エラーを取得し、既存のターゲット、シンボリックリンク、FIFOを拒否するようにしました。
