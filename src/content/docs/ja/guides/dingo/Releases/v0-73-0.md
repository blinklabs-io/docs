## v0.73.0

**タイトル:** 台帳検証、復旧、ノードの耐障害性を改善

**日付:** 2026-09-25

**バージョン:** v0.73.0

**リリース:** [v0.73.0](https://github.com/blinklabs-io/dingo/releases/tag/v0.73.0)

Dingoは直接利用できるCardanoブロックチェーンノードおよびAPIプロバイダーであり、Goライブラリのドキュメントは [`go doc`](https://pkg.go.dev/cmd/go#hdr-Show_documentation_for_package_or_symbol) と [pkg.go.dev](https://pkg.go.dev/github.com/blinklabs-io/dingo) で参照できます。このリリースでは、台帳とガバナンスの検証を改善し、同期と復旧の処理を保護し、ノード運用を制御する手段を明確にします。

### 推奨ネットワーク互換性 ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### 検証とガバナンスの改善

* 改善し、無効または空の入力を安全に処理して、存在しない値を参照しないようにしました。([変更内容](https://github.com/blinklabs-io/dingo/pull/4707))

* 強化し、Conway委員会証明書を順番に検証することで、トランザクションが同じ辞任を繰り返したり、同じメンバーを辞任させた後に承認したりすることを防ぎます。([変更内容](https://github.com/blinklabs-io/dingo/pull/4711))

* 安定化し、listenerを制御したノード間の整合性確認における再接続テストを安定させ、再接続動作への信頼性を高めました。([変更内容](https://github.com/blinklabs-io/dingo/pull/4693))

* 整合させ、Byronトランザクションとbootstrap blockの終了時の検証をcardano-ledgerの動作に合わせました。シリアライズ後のサイズ、未知の属性の上限、位置に基づくwitness、重複入力集合の意味、feeとLovelaceの上限、正規アドレスルート、bootstrap block終了時の順序、決定的なreplay recoveryを含みます。([変更内容](https://github.com/blinklabs-io/dingo/pull/4710))

* 防止し、ConwayおよびDijkstraのパラメータ変更でprotocol version key `14`を受け入れず、enactment時にそのkeyを削除します。([変更内容](https://github.com/blinklabs-io/dingo/pull/4699))

* 堅牢化し、Mithril backfill recoveryで不正なblockとoffset failureをfail closedとして扱い、最後にcommitしたcheckpointを保持し、過去のwithdrawal accountが不足している場合にerrorを報告します。([変更内容](https://github.com/blinklabs-io/dingo/pull/4473))

* 追加し、完全なreward snapshotによって登録済みpoolがzero stakeになったことを確認できる場合に、情報提供用の`pool_zero_stake` Koios parity categoryを追加しました。snapshotが不完全な場合はfail closed classificationを維持します。([Change details](https://github.com/blinklabs-io/dingo/pull/4692))

* 認識し、明示的に空のConway genesis committeeをcommittee validationでauthoritativeな値として扱うようにしました。([Change details](https://github.com/blinklabs-io/dingo/pull/4517))

* 更新し、test database connectionで新しいSQLite data source nameを使用して、SQLiteベースのtest runをサポート対象の設定に合わせました。([Change details](https://github.com/blinklabs-io/dingo/pull/4713))

* 是正し、Conway governanceとcommitteeの意味を正しく扱うようにしました。validなzero quorumとSQL `NULL`を区別し、committeeのないRATIFYを処理し、expired actionと重複したremovalを拒否し、canonical Plutus V3 orderingを保持し、Byron witness dependencyに対応します。([Change details](https://github.com/blinklabs-io/dingo/pull/4704))

### 信頼性、recovery、同期の改善

* 保証し、UnixのBadger close operationがdirectory lockの解放をbounded best-effort waitで待機するようにしました。Windowsのclose operationは引き続きこのwaitなしで完了します。([Change details](https://github.com/blinklabs-io/dingo/pull/4671))

* 安全化し、`LedgerView.GetAdaPots`をpanicなしで呼び出せるようにしました。errorを返すmethodは引き続き`ErrNotImplemented`を返します。([Change details](https://github.com/blinklabs-io/dingo/pull/4511))

* 調整し、peer tip staleness checkでselector clockを使うようにして、freshness decisionをpeer選択用のclockに結び付けました。([Change details](https://github.com/blinklabs-io/dingo/pull/4677))

* 保存し、chain truncation前にbounded rollback undo outboxを永続化してreplayすることで、rollback workのat-least-once deliveryを実現しました。([Change details](https://github.com/blinklabs-io/dingo/pull/3910))

* 反映し、epoch rollover、header verification、startup recoveryのepoch nonce calculationに、開始するepochの`extraEntropy`を含めました。([Change details](https://github.com/blinklabs-io/dingo/pull/4518))

### ノード運用と依存関係

* 導入し、ChainSyncにGenesis Limit on Patienceを追加しました。default capacityは`1000`、leak rateは毎秒`5` tokensです。Dingoは対応するeventとmetricを発行し、limitを超えたpeerをrecycleし、CLI、configuration、environment settingで`genesisBootstrap.limitOnPatienceEnabled`、`genesisBootstrap.limitOnPatienceCapacity`、`genesisBootstrap.limitOnPatienceRate`を公開します。([Change details](https://github.com/blinklabs-io/dingo/pull/4686))

* 更新し、gouroboros dependencyを`v0.207.4`に変更しました。([Change details](https://github.com/blinklabs-io/dingo/pull/4714))

* 削除し、supported release workflowからWindows automated check、build、release artifactを取り除きました。([Change details](https://github.com/blinklabs-io/dingo/pull/4701))
