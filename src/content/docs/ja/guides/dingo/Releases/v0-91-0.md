## v0.91.0

**タイトル:** トレーシング、可観測性、性能、運用を向上

**バージョン:** v0.91.0

**リリース:** [v0.91.0](https://github.com/blinklabs-io/dingo/releases/tag/v0.91.0)

**比較:** [v0.90.5...v0.91.0](https://github.com/blinklabs-io/dingo/compare/v0.90.5...v0.91.0)

Dingo v0.91.0では、ノード間トレーシング、運用上の可視性、ノード同等性の設定、データベース性能、コンテナビルド、プロトコル検証、ドキュメント品質を改善しました。

### 推奨ネットワーク互換性 ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

#### トレーシングと可観測性
* 追加: 各ブロックハッシュから共通のトレース識別子を導出するブロックトレーシングを追加し、ステージ、トランザクション受付、キャッチアップ、Mithril、データベースのライフサイクルスパンをノード間で結び付けました。ログのトレース相関、任意のOTLPログおよびメトリクス出力、サービスリソース設定、サンプリングされたトレースだけのSQLスパン、トレーシングダッシュボード、常時サンプリングするプールの許可リストにも対応しました。
* 除外: オブザーバーに降格されたピアをLimit on Eagernessの候補から除外し、可観測性専用のピアがチェーン選択を制約しないようにしました。

#### APIとデータアクセス
* 高速化: 追加の処理が到着しない場合は250ミリ秒のアイドル期間後に収集済みブロックを適用し、処理中のストリームには1秒の上限を維持しました。
* 公開: 許可されたオリジンのブラウザクライアントが、Blockfrostの受付でHTTP 429が返された場合に`Retry-After`を読み取れるようにしました。許可されていないオリジンは引き続きブロックされます。
* 再利用: Blockfrostのトランザクション数を繰り返し取得する際に検証済みトランザクションデータを再利用し、マニフェストと本文の整合性を再確認しながらフォールバックエラーを維持しました。
* 集約: APIモードで検証済みブロックごとにアドレス、履歴、証人、メタデータのインデックス書き込みをまとめ、最後のフラッシュに失敗した場合はアトミックにロールバックしました。

#### 台帳、ガバナンス、メタデータ
* 保持: 深くネストされたメタデータや非JSONメタデータのラベルを保持し、未使用のJSONフィールドを`null`として表現しながら元のCBORをインデックスしました。
* 維持: コンテナ値のメタデータマップキーをインデックス済みCBORに保持し、JSON出力から除外しました。
* 固定: 保留中のガバナンス批准を確定済みの境界提案とDRep状態に結び付け、期限切れと孤立項目の削除を決定的にしました。
* 反映: インポートした残高でカバーされる報酬クレジットを正確に1回だけ折り込み、チェックポイント前に残りの対象出力を排出して重複や古いクレジット状態を防ぎました。

#### Era互換性と性能
* 最適化: 委員会規模のBLSキー処理で並列デコード、効率的な集約、検証済みキーの上限付きキャッシュを使用し、証明書の検証結果を変えずに処理を改善しました。
* 対応: Dijkstraから開始するネットワークでConwayトランザクションを検証するため、関連する検証経路全体で必要な埋め込みConwayパラメータを一貫して導出しました。
* 尊重: GenesisでスケジュールされたDijkstraハードフォークのエポックを反映し、早すぎるブロック生成を防ぎ、Era履歴、Leiosの実行時ゲート、Genesisのステークウォームアップを整合させました。
* 再利用: 対応するSQLバックエンドが書き込みトランザクション中に準備済みの同期状態読み取りを再利用できるようにし、最新の読み取りを維持しながら別の読み取りプール競合を避けました。
* 制限: 現在のチップでアカウント残高の読み取りを一括受付とキャンセルで制限しました。飽和した要求は`ErrUnavailable`を返し、キャンセルされた要求はデータベース処理とエラーレスポンスを停止します。`MeshLedgerState.UtxosByAddress`は`context.Context`を受け取るようになりました。
* 記憶: 安定した選出VRFキーのハッシュ参照をロールバック世代のフェンス付きでメモ化し、古いハッシュを使わずに同期とヘッダー検証の繰り返し処理を減らしました。

#### コンテナビルド
* 復元: `gnupg`を先にインストールしてPostgreSQLリポジトリキーを検証することで、Dockerのamd64およびarm64イメージビルドを復元しました。
