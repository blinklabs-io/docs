## v0.72.0

**タイトル:** 検証、同期、運用効率を強化

**日付:** 2026-09-24

**バージョン:** v0.72.0

**リリース:** [v0.72.0](https://github.com/blinklabs-io/dingo/releases/tag/v0.72.0)

このリリースでは、ledger、governance、network、credentialの検証を強化し、同期、報酬処理、データベースのdurability、運用状況の可視性を改善しました。

### 推奨ネットワーク互換性 ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### 検証と互換性の改善

* 強化し、gouroboros `v0.206.2`によってpeer sharingとpool relayの処理を改善しました。サイズ超過の`SharePeers` replyはstrictに失敗し、governance、ledger、threshold cacheのcorrectnessも改善されます。

* 拒否し、active networkと異なるnetwork magicを持つByron outputがvalidationに入らないようにしました。

* 確認し、catch up capを超えて進むchain frontierを異なるconnectionでcorroborateしてから受け入れるようにしました。未検証のfrontierを追跡するリスクを抑えます。

* 最適化し、SQLiteのrewardおよびparity cacheのdurabilityをwrite batchingで改善しました。test cacheではdurabilityを緩和してtest実行を高速化します。

* 防止し、ByronおよびShelleyのgenesis UTxO referenceが重複している場合、partial stateを書き込む前に処理を停止するようにしました。

* 保持し、rollback後も置き換えられたgovernance voteをvote history migrationで復元できるようにしました。

* 復元し、`NewConfig`のhistorical validationとstrict UTxO validationにfail closedのdefaultを設定しました。明示的に変更しない限り、これらのcheckは有効です。

* 明確化し、`reference_lag`だけが原因のepochではstrict Koios parity checkをshutdownしないようにしました。実際のdata failureは引き続きfatalとして扱います。

* 整合させ、Byron canonical JSONのduplicate key、escape sequence、unsigned fieldの処理をreference behaviorに合わせました。

* 評価し、SPO governed actionを同じboundaryのstake snapshotに対して判定するようにしました。ratificationされていないactionがratification済みとして扱われることも防ぎます。

* 保護し、Mithril credentialとsigned URL dataをredactionし、userinfoを含むURLを拒否するようにしました。

* 検証し、`Acquire`中にLocalStateQuery pointがquery可能か確認するようにしました。pinned era checkとretention handlingも改善しています。

### 同期、ガバナンス、可視性の改善

* 再配置し、gosec `G703` lint suppression commentの位置を修正しました。security checkを維持しながらruntime behaviorは変更しません。

* 削除し、retired Go Report Card badgeをproject presentationから取り除きました。

* 切り替え、Antithesis Moog downloadで`GITHUB_TOKEN` authenticationを使用するようにしました。

* 拡張し、`epoch_rollover` timing、stage maximum gauge、広いlatency bucket、dashboard panelを運用metricに追加しました。

* 導入し、Koiosを利用したgenesisからのnode parity validationと、completeおよびincomplete resultのreportingを追加しました。
