## v0.70.16

**タイトル:** rollback stateを保護し、network reliabilityを改善

**日付:** 2026-09-20

**バージョン:** v0.70.16

**リリース:** [v0.70.16](https://github.com/blinklabs-io/dingo/releases/tag/v0.70.16)

このリリースでは、Dingoをv0.70.15からv0.70.16に更新しました。rollbackとtransactionの安全性、connection lifecycleの処理、block synchronization、transaction submission、Mithril処理、database migration、retrieval security、release validation、test coverageを強化しました。

### 推奨ネットワーク互換性 ⚠️

|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### ランタイムおよび運用面の改善

* 改善し、`consumed_utxo_prune_floor` retention floorを永続化して、Dingoが永久に削除したデータより下へのledgerまたはlifecycle rollbackおよびtruncationを拒否するようにしました。Peerおよびreplay recoveryは安全にresynchronizeするかrecoveryを制限し、clamp metricを公開します。Operatorsはfloor以上でtruncateするか、新しいnodeをbootstrapする必要があります。

* 追加し、pending transaction barrierとtransaction completion callbackによって、rollbackがuncommitted writeを待機し、deferred eventがtransaction完了後にのみpublishされ、rollback restorationが安全に維持されるようにしました。

* 保護し、ChainSync、Leios serving waiters、LocalStateQuery pins、LeiosNotifyを通じて、synchronization、serving、query、notificationのcleanupを所有するconnectionに関連付けました。古いclose callbackがconnection identifierを再利用するreplacement connectionに影響しなくなりました。

* 修正し、BlockFetch batchをrollback generationに関連付け、superseded bodyを破棄し、適用済みblockの進捗を正確に追跡し、endpointを検証することで、rollback後のblock retrievalを改善しました。通常の完了時にはtransportを閉じずに`BatchDone`を返します。

* 維持し、ConwayおよびDijkstraがLocalTxSubmissionを通じて報告する具体的なrejection causeを保持するようにしました。infrastructure failureはgenericに分類し、empty-input errorをeraごとにencodeし、表現可能なrejectではsessionを開いたままにします。

* 更新し、Dingo Blockfrost Explorer exampleのViteを`8.2.2`から`8.3.0`に変更し、lockfile tooling dependencyを更新しました。

* 防止し、main refで後からpushされた変更がpublish runをcancelしないようにしました。他のrefでは一度に1つの実行を維持します。

* 保持し、importされたMithril DRepのexpiry epochを保存するようにしました。これによりsnapshot dataがexpiry時期を決定し、DRepが無期限にactiveのまま残らなくなりました。database semanticsもこの動作を反映します。

* 安定化し、startup reward precomputationのtestからraceを取り除き、queued epochおよびnonce assertionを強化しました。

* 強化し、CI validationでlint、vulnerability check、quick SQLite test、platform test、build、Docker jobを段階的に実行するようにしました。testをbuildおよびreleaseの条件に設定し、release uploadが明確に失敗するようにし、standalone workflowを削除しました。

### Dependency、database、securityの改善

* 更新し、protocolおよびstorage dependencyを`v0.205.5`、`v0.17.1`、`v1.58.0`に変更し、VRF mismatch testの信頼性を維持しました。

* 完了し、Mithril live stakeをrunning totalから確定して性能を改善しました。

* 拡張し、70 transactionに対するHaskell reference coverageとmanifest validationによって、Leios BlockTxs interoperability validationを強化しました。

* 削除し、supported databaseのmigration v19でwrite-onlyの`asset.name_hex`と`idx_asset_name_hex`を取り除き、`name`からhexadecimal valueを再計算し、`DROP` migrationのreplayを安全に繰り返せるようにしました。Operatorsはupgrade時にこのschema変更を考慮する必要があります。

* 制限し、Mithril retrievalをinitial URL、DNS-resolved destination、redirect、proxy、custom transportに限定し、privateまたはspecial-use destinationへのaccessを防止しました。private-network retrievalには、local developmentまたはtesting向けに`AllowInsecureHTTP`が必要です。
