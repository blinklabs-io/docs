## v0.70.16

**タイトル:** rollback stateを保護し、network reliabilityを改善

**日付:** 2026-09-20

**バージョン:** v0.70.16

**リリース:** [v0.70.16](https://github.com/blinklabs-io/dingo/releases/tag/v0.70.16)

このリリースでは、Dingoをv0.70.15からv0.70.16に更新しました。rollbackとtransactionの安全性、connection lifecycleの処理、block synchronization、transaction submission、Mithril処理、database migration、retrieval security、release validation、test coverageを強化しました。

| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### ランタイムおよび運用面の改善

* 改善し、`consumed_utxo_prune_floor` retention floorを永続化して、Dingoが永久に削除したデータより下へのledgerまたはlifecycle rollbackおよびtruncationを拒否するようにしました。Peerおよびreplay recoveryは安全にresynchronizeするかrecoveryを制限し、clamp metricを公開します。Operatorsはfloor以上でtruncateするか、新しいnodeをbootstrapする必要があります。

* 追加し、pending transaction barrierとtransaction completion callbackによって、rollbackがuncommitted writeを待機し、deferred eventがtransaction完了後にのみpublishされ、rollback restorationが安全に維持されるようにしました。

* 保護し、ChainSync、Leios serving waiters、LocalStateQuery pins、LeiosNotifyを通じて、synchronization、serving、query、notificationのcleanupを所有するconnectionに関連付けました。古いclose callbackがconnection identifierを再利用するreplacement connectionに影響しなくなりました。

* 修正し、BlockFetch batchをrollback generationに関連付け、superseded bodyを破棄し、適用済みblockの進捗を正確に追跡し、endpointを検証することで、rollback後のblock retrievalを改善しました。通常の完了時にはtransportを閉じずに`BatchDone`を返します。

* 維持し、ConwayおよびDijkstraがLocalTxSubmissionを通じて報告する具体的なrejection causeを保持するようにしました。infrastructure failureはgenericに分類し、empty-input errorをeraごとにencodeし、表現可能なrejectではsessionを開いたままにします。
