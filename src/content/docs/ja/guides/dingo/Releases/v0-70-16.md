## v0.70.16

**タイトル:** ロールバック状態を保護し、ネットワークの信頼性を改善

**日付:** 2026-09-20

**バージョン:** v0.70.16

**リリース:** [v0.70.16](https://github.com/blinklabs-io/dingo/releases/tag/v0.70.16)

このリリースでは、Dingoをv0.70.15からv0.70.16に更新しました。ロールバックとトランザクションの安全性、接続ライフサイクルの処理、ブロック同期、トランザクション送信、Mithril処理、データベース移行、取得時のセキュリティ、リリース検証、テスト範囲を強化しました。

### 推奨ネットワーク互換性 ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### ランタイムおよび運用面の改善

* 強化し、`consumed_utxo_prune_floor`の保持下限を永続化して、Dingoが永久に削除したデータより下へのledgerまたはlifecycle rollbackおよびtruncationを拒否するようにしました。Peerおよびreplay recoveryは安全にresynchronizeするかrecoveryを制限し、clamp metricを公開します。Operatorsはこの下限以上でtruncateするか、新しいnodeをbootstrapする必要があります。

* 追加し、保留中のトランザクションバリアとトランザクション完了コールバックによって、rollbackが未コミットの書き込みを待機し、deferred eventがtransaction完了後にのみpublishされ、rollback restorationが安全に維持されるようにしました。

* 保護し、ChainSync、Leios serving waiters、LocalStateQuery pins、LeiosNotifyを通じて、同期、serving、query、notificationのcleanupを所有するconnectionに関連付けました。古いclose callbackがconnection identifierを再利用するreplacement connectionに影響しなくなりました。

* 修正し、BlockFetch batchをrollback generationに関連付け、superseded bodyを破棄し、適用済みblockの進捗を正確に追跡し、endpointを検証することで、rollback後のblock retrievalを改善しました。通常の完了時にはtransportを閉じずに`BatchDone`を返します。

* 維持し、ConwayおよびDijkstraがLocalTxSubmissionを通じて報告する具体的な拒否理由を保持するようにしました。インフラストラクチャ障害は一般的なエラーに分類し、eraごとにempty-input errorをencodeし、表現可能なrejectではsessionを開いたままにします。

* 更新し、Dingo Blockfrost Explorerの例でViteを`8.2.2`から`8.3.0`に変更し、lockfileのtooling dependencyも更新しました。

* 防止し、main refへの後続のpushがpublish runをcancelしないようにしました。他のrefでは一度に1つの実行を維持します。

* 保持し、importしたMithril DRepのexpiry epochを保存するようにしました。これによりsnapshot dataがexpiry時期を決定し、DRepが無期限にactiveのまま残らなくなりました。database semanticsもこの動作を反映します。

* 安定化し、startup reward precomputationのtestからraceを取り除き、queued epochおよびnonceのassertionを強化しました。

* 強化し、CI validationでlint、vulnerability check、quick SQLite test、platform test、build、Docker jobを段階的に実行するようにしました。testをbuildおよびreleaseの条件に設定し、release uploadが明確に失敗するようにし、standalone workflowを削除しました。

### 依存関係、データベース、セキュリティの改善

* 更新し、プロトコルおよびストレージ依存関係を`v0.205.5`、`v0.17.1`、`v1.58.0`に変更し、VRF mismatch testの信頼性を維持しました。

* 改善し、Mithril live stakeをrunning totalから確定して性能を高めました。

* 拡張し、70 transactionに対するHaskell reference coverageとmanifest validationによって、Leios BlockTxs interoperability validationを強化しました。

* 削除し、対応するdatabaseのmigration v19でwrite-onlyの`asset.name_hex`と`idx_asset_name_hex`を取り除き、`name`からhexadecimal valueを再計算し、`DROP` migrationのreplayを安全に繰り返せるようにしました。Operatorsはupgrade時にこのschema変更を考慮する必要があります。

* 制限し、Mithril retrievalをinitial URL、DNSで解決したdestination、redirect、proxy、custom transportに限定し、privateまたはspecial-use destinationへのaccessを防止しました。private-network retrievalには、local developmentまたはtesting向けに`AllowInsecureHTTP`が必要です。

### テストおよび検証の改善

* 適用し、Conway-at-genesisのepoch 1 rewardに空のgenesis previous block countを設定し、potおよびstake snapshotのconformance checkを拡張しました。

* 簡素化し、SQLite WAL checkpoint timing testを順番に実行し、共通の10秒boundを使用してrunner負荷によるflakinessを減らしました。
