## v0.92.0

**タイトル:** 同期、コンセンサスの信頼性、台帳性能を向上

**バージョン:** v0.92.0

**リリース:** [v0.92.0](https://github.com/blinklabs-io/dingo/releases/tag/v0.92.0)

**比較:** [v0.91.0...v0.92.0](https://github.com/blinklabs-io/dingo/compare/v0.91.0...v0.92.0)

Dingo v0.92.0では、同期、コンセンサス検証、台帳処理、Mithrilインポート、運用の可視性を改善しました。

### 推奨ネットワーク互換性 ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

#### 破壊的変更
* 変更: メタデータAPIでコンテキストが必須になりました。報酬状態をプルーニングする呼び出し元はコンテキストを指定する必要があり、制限付きの適応バッチはバッチ間でキャンセルを確認するようになりました。

#### 同期とストレージ
* 拡張: Leiosの既定パイプラインウィンドウを、1秒の基準期間に設定済みShelley genesisのスロット期間を掛けて切り上げる方式に変更し、意図した実時間のウィンドウを維持しました。明示的な時間オーバーライドは、サブ秒スロットのネットワークを含めて変更されません。
* 増加: 1回の検証で読み取る不変エントリの上限を16 MiBから128 MiBに引き上げ、Mithrilインポート時の二重読み取りを減らしながら、上限付きのフォールバック検証を維持しました。
* 改善: コンセンサスコンテキストの変更後に保持しているフォークの祖先を再検証し、トランザクション単位の台帳状態を共有し、検証済みの外向き接続が確立した後にのみピアアドレスを通知することで、ピアの継続性を高めました。
* 調整: CoreモードとAPIモードのMithril同期でBadgerの1 KiB値しきい値を使用するようにしました。APIモードの大きなブロック本体は値ログを使用し、明示的なしきい値は引き続き既定値を上書きします。
