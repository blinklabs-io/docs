## v0.85.0

**タイトル:** 同期、API、ストレージ、運用の信頼性を改善

**バージョン:** v0.85.0

**リリース:** [v0.85.0](https://github.com/blinklabs-io/dingo/releases/tag/v0.85.0)

Dingo v0.85.0では、チェーン復旧、Blockfrostの対応範囲、台帳の永続化、リソース受付、コンフォーマンスツール、運用の信頼性を改善しました。

### 推奨ネットワーク互換性 ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### 同期と台帳状態
* 改善: 遅延中のプロデューサー認証ヘッダーをチェーン選択と正規ロールバックから除外し、台帳が進んだ後に該当ピアを再試行することで、ピア選択を改善しました。
* 拡張: SQLマイグレーションv49と順序を保持するエンコーディングにより、運用証明書カウンターを`uint64`の全範囲で保存できるようにしました。
* 強化: Midnightの登録検証で`authTokenPolicyId`と`authTokenAssetName`をセットで必須にし、ポリシーとアセット名の完全一致を確認して、ポリシー変更後に登録状態を再構築するようにしました。
* 拡大: Blockfrostにエポック、アカウント、プール、ガバナンスの履歴クエリを追加し、保持されていないデータには決定的な`404`を返し、ガバナンス投票履歴を完全に取得できるようにしました。

### ストレージとリソース管理
* 計測: 保持されたLeiosキャッシュの割り当てを追跡し、シャットダウンとクリーンアップのエラー報告を改善しました。
* 効率化: 遅延SQLite UTxOインポートをバッチ処理し、呼び出し元から渡された入力を変更しないようにしました。
* 削減: 後続のAPIバックフィルまで使用しないCore MithrilのUTxOオフセット書き込みを省略し、ストレージ処理を削減しました。
* 分離: トランザクション評価の受付をグローバル制限とホスト単位の制限で分離し、Mithril署名の受付も分離しました。
* 拡充: UPLC Turboレポートの対象範囲を広げ、各シャードに固定した変数を使うようにコーパス入力を変更し、デフォルト値とタイムアウトを増やして、コンフォーマンスツールを更新しました。
* 解消: データベーステストのクリーンアップ競合を解消し、テスト実行をより安定させました。
* 安定化: BadgerとDMQのテストの信頼性を高め、選択したクリーンアップエラーを報告するようにしました。
* 分割: Linuxのraceテストをシャード化し、race実行中は一部の高コストなテストをスキップするようにしました。

### APIと統合
* 追加: APIマイグレーションv45とv46により、BlockfrostのウォレットおよびdAppクエリ操作を追加しました。
* 更新: `plutigo`統合をv0.9.7に更新しました。

### セキュリティと運用
* 保護: `DINGO_DEBUG`を有効にした場合を含め、コンテナ起動ログからシークレットをマスクするようにしました。
* 整合: コンフォーマンスレポートと固定コーパスを一致させ、結果を一貫させました。
* 設定: Core同期で1 KiBのBadgerしきい値を使用し、明示的な`valueThreshold: 0`を尊重するとともに、その動作を文書化しました。
