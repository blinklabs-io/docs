## v0.70.12

**タイトル:** 履歴クエリの精度、ガバナンスインポートの安全性、ノードの信頼性を改善

**日付:** Not provided

**バージョン:** v0.70.12

**リリース:** [v0.70.12](https://github.com/blinklabs-io/dingo/releases/tag/v0.70.12)

このリリースでは、履歴付きLocalStateQueryの結果、Mithrilのガバナンスおよびbootstrapの検証、peerの復旧、stake distributionの精度、topologyの安全策、データベースのライフサイクル処理を改善しました。また、診断用audit、永続化の安全性、observability、依存関係の保守も強化しました。

### 推奨ネットワーク互換性 ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### ハイライト

* continuation auditの診断処理を改善し、rollbackのrearmingとrecovery rewindをまたいでproducerとendorserの追跡を維持し、audit windowの所有権を直列化し、primary chainの証拠を引き継ぎ、producerとendorserのqueueを同時アクセスから保護しました。auditは診断専用のまま、誤ったエラーやconcurrent map failureを報告しなくなりました。

* LocalStateQuery `GetUTxOWhole`にpinned queryの動作を追加し、as-of UTxO iterationと、spent-UTxO retention floorより古いpinに対する明確な`ErrHistoricalStateUnavailable`応答を実装しました。chain tipが実行中に変化しても、クエリ結果がずれなくなりました。

* Mithril import中に、importしたConway committee stateをenacted governance stateと照合するようにし、説明できない不一致やparse failureでは安全側に停止しつつ、正当な`NoConfidence`および`UpdateCommittee` transitionを許可しました。

* trusted query対応の設定変更に合わせてlocal state query connectionの設定を修正しました。

* live stake sumで使用するprepared statementをStoreごとにcacheし、ライフサイクル変更時に無効化し、cache miss時のfallbackも維持しました。

* 1つのconnectionで30秒以内にblockを延長しない拒否が20回発生した場合にpeerをrecycleし、延長に成功した後はカウントをクリアし、この状態を示すPrometheus counterを追加しました。

* `GetStakeDistribution`をmark snapshotではなく要求されたslotのlive stakeから計算し、zero-stake poolを保持し、pinned queryにはhistorical VRF registrationを使用し、解決できないpoolの省略数をカウントするようにしました。

* consumed-UTxO deduplicationでinputごとの`Sprintf` allocationを削除してoverheadを減らし、double-hex encodedのlogとhashのformatを修正し、`google.golang.org/api`を`0.294.0`から`0.297.0`へ更新しました。

* Mithril bootstrap後のgenesis UTxO、staking、governanceのreinsertionを省略し、synthetic genesis CBORは保持するようにしました。

* topology configurationでaccess pointのaddressとportを検証し、該当する場合は`warmValency <= valency`および`valency <=` access point数を強制し、未対応のSRV relay validationを拒否するようにしました。

* Dingoのdependencyを`gouroboros` `0.204.7`、`plutigo` `0.7.0`、および関連するGo versionへ更新し、duplicate-key metadata mapを`ErrJSONUnavailable`として分類するようにしました。

* LocalStateQuery `AcquireSpecificPoint`でpointを即時に検証し、invalidまたは古すぎるpointをwire levelのgracefulなacquire failureへ変換し、invalid pointを記録しないようにしました。

* `RewardStakeCalculationVersion`のstartupおよびrebootstrap gateを必要な範囲に絞り、安全なsnapshot rowを再stampするmigration v15を追加し、影響を受けるepochを報告するようにしました。

* importしたoperational certificate counterを永続化前に範囲内へ制限し、範囲外のstateをwriteせずにfailureとするようにしました。
