## v0.92.3

**タイトル:** インデックス作成、プロトコルの信頼性、運用制御を改善

**バージョン:** v0.92.3

**リリース:** [v0.92.3](https://github.com/blinklabs-io/dingo/releases/tag/v0.92.3)

**比較:** [v0.92.2...v0.92.3](https://github.com/blinklabs-io/dingo/compare/v0.92.2...v0.92.3)

Dingo v0.92.3では、トランザクションのインデックス作成、プロトコル検証、Leiosの配信、データベース効率、運用制御、リリース関連ツールを改善しました。

### 推奨ネットワーク互換性 ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

#### API、インデックス作成、データサービス
* 改善: Blockfrostメタデータラベルのトランザクションページネーションで、インデックスに適したクエリとスキーマv58のインデックスを使用します。共有アドミッション制限でリクエストを管理し、各ページに15秒の期限を設定し、過負荷時は`Retry-After`とともに`429`または`503`を返します。
* 追加: Midnightトランザクションのインデックス作成元として`LedgerState.BlockTransactions`を使用します。これにより、Leiosエンドーサーブロックのトランザクションを追跡、バックフィル、再構築、ロールバックの各処理でインデックス化します。
* 拡張: サンプリングしたKoiosパリティチェックで、入力、コラテラル、参照入力、出力、妥当性を比較します。リトライ回数を制限し、キャッシュもサポートします。
* 削減: Genesisのステージングで発生するメモリコピーと割り当ての増加を抑え、frontier間で観測点の履歴を共有します。
* 最適化: SQLiteの書き込み接続でステートメントジャーナルをメモリ内に保持し、`temp_store=MEMORY`を使用します。

#### プロトコルとピアの信頼性
* 維持: 再読み込みしたプロトコルパラメータの値が同等の場合、ロールバック後もヘッダー判定のコンテキストを保持します。
* 検証: Leiosオファーを記録する前に検証して上限を設定し、ホストごとの予算と接続ごとのキャッシュおよびソース制限を適用します。
* 訂正: Byron証人の検証をzipセマンティクスに合わせ、対応しない末尾の入力または証人を検証から除外します。空の証人セットはプロトコルマジックを検索せずに検証します。
* 制限: 永続化したロールバックアンカーとハイウォーターマークを使用して、ピアの累積ロールバックを制限します。
* 導入: プールごとにDMQメッセージの通知間隔を設定できるようにします。既定の間隔は60秒で、保留中のメッセージ数を制限し、CLI、YAML、環境変数で設定できます。

#### ストレージ、配信、テストの信頼性
* 再構成: マイグレーションv57で`reward_account_output`のインデックスを変更して書き込み増幅を抑え、読み取り処理も更新します。
* 遅延: 未読Leiosアナウンスの先読みを遅らせ、台帳処理がポイントごとにアナウンスを取得する代わりにオファーを通知します。
* 改良: マイグレーションv56でブロックnonceのインデックスにスロット先行インデックスを使用し、最新nonceのアクセス経路を更新します。
* 制限: Leios devnetのフォーク待機時間をシナリオの期限内に制限します。
* 同期: ChainSyncテストの待機を適用済みチップの公開と同期し、タイミング競合を解消します。

#### 検証と運用
* 改善: 期限切れの未取得アナウンスを待たずにLeiosクロージャを処理し、完全なクロージャの検証は維持します。
* 明確化: 書き込み可能なancestorのsticky bit診断を明確にし、fsGroupに必要なsticky bit要件を文書化します。
* 設定: 信頼済みローカルNtCのアイドルタイムアウトを設定します。0は無効化し、正の値は有効化し、負の値は拒否します。既定値は2分から無制限に変更されました。
* 訂正: PBFTの委任と認証で、ネットワークに対応したByron証明書スロットを使用します。
* 保持: tipのみの公開でもヘッダー判定を保持し、期限切れのアドミッション検証を最大3回再試行します。
* 同期: `cardano-configs`のコンテナピンと組み込みMusashi設定を`20261107-1`で同期しました。Musashiは`EgressBudgetMbps 250`を使用し、`LeiosAdaptiveEndorsements`を有効化し、`MinNodeVersion 11.2.0.164-rc-2026w44`を要求し、`TxSubmissionLogicVersion V2`を使用し、リモートbearerログを抑制します。最小ノードバージョンとトランザクション送信動作がこれらの設定に変更されました。
* 適用: ループバックNtC TCP listenerの既定の`privatePort`を`0`に設定し、TCP listenerを無効化しながらUnixソケットを維持します。TCPが必要な場合は、0以外の`privatePort`を設定する必要があります。`serve-mode`の検証では`0`を許可し、devnet設定では`CARDANO_PRIVATE_PORT=3002`を明示的に設定します。

#### 依存関係とツール
* 更新: `ouroboros-mock`を`v0.21.2`に更新します。
* 改訂: `docker/login-action`を`v4.8.0`に更新します。
* 反映: 関連モジュールとともに`google.golang.org/api`を`v0.311.0`へ更新します。
* 最新化: AWS SDK S3クライアントを`v1.114.8`に更新し、関連モジュールも更新します。
* 強化: `github.com/jackc/pgx/v5`を`v5.11.0`から`v5.12.0`へ更新し、`require_auth`と`channel_binding`に関する上流のセキュリティ修正を取り込みました。カスタム`pgx.BatchResults`実装は新しい`Tx`メソッドを実装する必要があり、この要件はこれらの実装で互換性を損なう変更です。
