## v0.83.0

**タイトル:** 同期、ストレージ、運用制御を改善

**バージョン:** v0.83.0

**リリース:** [v0.83.0](https://github.com/blinklabs-io/dingo/releases/tag/v0.83.0)

Dingo v0.83.0では、v0.82.1と比較して、同期、台帳状態の処理、サービスの信頼性、ストレージ効率、運用制御を改善しました。

### 推奨ネットワーク互換性 ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### 同期と復旧
* 改善: オーバーレイ再構築時に想定される検証スナップショットの変更を`ERROR`ではなく`DEBUG`で記録し、誤解を招く同期エラーを減らしました。再試行のクールダウン動作は変わりません。
* 修正: Mithrilインポート時のエポック境界におけるプール処理を修正しました。ステージング中の再登録を保持し、現在のレコードとステージング中のレコードを登録インデックスとともに保存し、有効なまたは延期されたVRF所有権を適用して返金とヘッダー検証を処理します。デプロイメントではデータベースマイグレーションv43を適用する必要があります。
* 追加: Genesisモードに`Limit on Eagerness`を追加しました。候補の交差点で選択とヘッダー配信を停止し、保持中のピアを一時停止し、密度の競合を解決し、eagernessゲージと`eagerness_held`を報告します。シャットダウン時には待機もキャンセルします。

### ピアとサービスの信頼性

* 拡張: Blockfrostクエリのスケーラビリティを高めました。拡張プール、引退したプール、DRep、アセット保有者のページネーションを保存し、リクエストのキャンセルを伝播し、整合性のあるページネーションのために`utxo_address`メタデータを永続化してバックフィルします。
* 分離: ヘッダーの不一致追跡を接続ごとに分離しました。不一致が発生した接続だけが、永続的なフォーク再同期のしきい値に到達します。

* 保持: バイト予算内で件数制限を超えたためにまだ適用できないピアヘッダーを、接続ごとに24 MiB、合計64 MiBの履歴として保持し、フォーク復旧時に保持した履歴を走査します。
* 保護: バッチ復元に失敗した後のチェーン復旧を、ブロックとヘッダーの状態変更を追跡して保護し、ノード構築時とヘルパーパスで明示的なCLIフラグが確実に機能するようにしました。
* 制限: ローカルチップより遅れているピアのリサイクル要求を、接続全体で30秒に1回に制限しました。アクティブな要求やスケジュールできない要求ではタイマーをスキップまたは解放します。
* 更新: Kupoの`/matches`ストリームへの書き込みごとに30秒の書き込み期限を更新し、サーバーの`WriteTimeout`を0のままにして、停止したクライアントが読み取りスナップショットを解放できるようにしました。
* 許可: デフォルトで無効な`barkBlockDownloadAllowPrivateAddresses`設定により、プライベートなアーカイブ先を許可しました。設定、YAML、環境変数、またはフラグから構成でき、オリジンの許可リスト、HTTPS、リダイレクト検証、暗黙のプロキシ無効化は維持します。

### ストレージと運用
* 導入: `leiosPersistenceRetentionSlots`と`DINGO_LEIOS_PERSISTENCE_RETENTION_SLOTS`を導入しました。正の値では、永続化されたLeiosエンドーサーブロックのマニフェストと本体を1時間ごとにクリーンアップし、0ではすべての履歴を保持します。起動時に最小値を検証し、クリーンアップワーカーが停止できない場合はシャットダウン時にストレージを保護します。
* 調整: Genesisピアの受け入れを調整し、広告されたチップがウォールクロック上で1つのGenesisウィンドウを超えて遅れている場合、入口ゲートを含めて拒否します。これにより、停止したフォークの採用を防ぎます。
* 設定: Badgerプロバイダーに`gcInterval`と`gcDiscardRatio`を設定しました。デフォルトはそれぞれ5分と0.5です。ロードモードではバリューログのクリーンアップを無効のままにし、ディスクサイズと回収済み容量のメトリクスを正しく報告します。
* 高速化: LinuxビルドとDockerイメージのジョブを通常のLinuxテスト後に開始できるようにしました。ただし、リリース作成では引き続きraceテストが必要です。
