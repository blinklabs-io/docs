## v0.70.13

**タイトル:** ストレージの耐障害性、ネットワーク互換性、ノードの可観測性を改善

**日付:** Not provided

**バージョン:** v0.70.13

**リリース:** [v0.70.13](https://github.com/blinklabs-io/dingo/releases/tag/v0.70.13)

このリリースでは、SQLiteストレージの保守、bootstrapの検証、ガバナンス互換性、プロトコル処理、ネットワーク設定、health monitoring、運用診断を改善しました。また、Cardano nodeの互換性要件を更新し、trusted Mithril importのパフォーマンスを向上させました。

### 推奨ネットワーク互換性 ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

**重要:** mainnet設定では`GenesisMode`を使用するようになり、Cardano node `11.1.0`以降が必要になりました。

### ✨ ハイライト

* SQLite WALの保守を改善し、専用connectionと`250 ms`のtimeoutを使用する定期的なbest effortの`TRUNCATE` checkpointを実行するようにしました。lifecycle変更中は安全に停止します。

* importしたreward snapshotに現在の`RewardStakeCalculationVersion`を記録し、新しいMithril bootstrapでaccounting-version validationを通過できるようにしました。

* consumed UTxOのretention floorより前にcore storageをtruncateしないようにし、valid queryに必要な履歴を保持するようにしました。

* `GetGenesisConfig`をcompactな`NtC 21+` layoutに更新し、古いcallerまたは直接呼び出すcallerにはlegacy encodingを引き続き使用するようにしました。

* typed DRep credential identityを保持し、metadata migration v16でnullableなgovernance proposal anchorを追加しました。SQLite migration expansionをatomicにし、conformance、replay state、peer trace selectionも改善しました。

* rollback後にoriginの途中から始まるfirst blockを拒否し、無効なchain restartをノードが受け入れないようにしました。

* Koiosに明示的なdial、TLS、response header、client timeoutを設定し、外部リクエストが定義済みの制限時間内に失敗するようにしました。

* reward live stakeのprepared statementを各transaction内でbounded retention付きでcacheし、statementの繰り返し準備を減らしながら、無期限に保持しないようにしました。

* valueがzeroのByron outputを受け入れつつ、`OutputNegativeByronError`によるnegative valueの拒否を継続するようにしました。

* Dijkstraでcaptured slotのVRF keyをelectするように修正し、既存のConwayの動作を維持しました。
