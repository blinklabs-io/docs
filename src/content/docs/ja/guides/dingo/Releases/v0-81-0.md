## v0.81.0

**タイトル:** 運用を簡素化し、信頼性を強化してネットワーク機能を拡張

**バージョン:** v0.81.0

**リリース:** [v0.81.0](https://github.com/blinklabs-io/dingo/releases/tag/v0.81.0)

Dingo v0.81.0では、ローカルネットワーク運用を簡素化し、クエリとスナップショット機能を拡張するとともに、同期と復旧を改善し、API、ストレージ、セキュリティの保護を強化しました。

### 推奨ネットワーク互換性 ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### ノード運用と開発ワークフロー
* 追加: 一時的または永続的な`--data-dir`状態、`--reset`、組み込み設定と鍵、genesis時間の更新、状態の検証とロック、設定生成、プロセスグループの終了処理を備えたワンコマンドの`dingo devnet`運用を導入しました。
* 更新: 適合性データベースのリセットでテーブルの未整理状態を検出し、プローブを再利用して方言ごとのクリーンアップを選択することで、繰り返しのリセット処理を減らしました。
* 修正: 脆弱性チェックがモジュールで宣言されたGoツールチェーンを使用するように修正しました。
* 整合: 生成されるHomebrewのタイトルをリポジトリの命名規則に合わせました。
* 改善: エントリーポイントの準備完了テストと診断を改善し、起動チェックを明確にしました。
* 修正: 設定読み込みで、Shelley genesisが存在する場合に`epochLength`をrandomness stabilisationおよびnonce windowと照合するようにしました。Shelleyのみの設定にも適用し、ByronとShelleyの両方のgenesisファイルが存在する場合だけsystem-startの不一致を確認することで、エラーの優先順位を保ちつつ有効な設定を変更しません。

### ガバナンス、台帳クエリ、プロトコル互換性
* 復元: インポートした期限切れの委員会更新について、正しい委員会、定足数、タイミングの状態での成立処理を復元し、曖昧なガバナンス証拠を拒否するようにしました。
* 修正: 固定されたShelleyデバッグ状態クエリが取得時点で回答し、運用証明書の読み取りを制限し、チェーンに安全なnonce処理を行うようにしました。
* 適用: ロールオーバー前にera遷移を適用し、入力eraのスナップショットとVRFの順序を修正しました。
* 追加: 台帳のtip、ステークプールパラメーター、提案されたプロトコルパラメーター更新に対するShelleyローカル状態クエリの回答を追加し、node-to-client version 21向けのコンパクトなgenesisエンコーディングと、保持されたリレー型情報を追加しました。

### ピア接続とリソース管理
* 導入: 疎なピアの切断と拒否をレート制限し、メトリクスを報告し、ライフサイクルのロックを調整するGenesis Density Disconnectorを導入しました。
* 分離: 受信と送信のピア予算を分離し、提供済みアクティビティを追跡し、アクティブな受信リレーをプルーニングから保護し、安定したセッションの頻繁な切断と再接続の動作を調整しました。
* 改善: 提供済みアクティビティの帰属を見直し、コールバック接続を識別するようにしました。
* 復旧: 接続された単独の遠隔ピアがcatch-up ceilingを超えて復旧できるようにし、チェーンの連続性が壊れた場合は復旧を取り消すようにしました。

### スナップショット、ライフサイクル、ストレージ運用
* 設定: スナップショットのコミット一時停止を既定で30秒に設定し、`0`を無制限として文書化し、タイムアウトの分類を改善し、ストレージのバッチ処理とインデックス再構築を追加しました。
* 追加: 相互TLS、独立したオペレーター認証、正常なシャットダウン、Unixの再起動サポート、状態報告を備えた、停止、再起動、状態確認用のオプションのリモートBarkライフサイクル制御を追加しました。
* 強化: Leiosのメモリと接続の安全性を改善し、接続元ごとの保留中アナウンスを16件、全体を128件に制限し、接続元の切断時にエントリを削除し、切断済みの接続元を拒否し、接続ごとに再試行を保持するようにしました。さらに、ストレージ交換中の永続化ライターのエンキュー、停止、リセットのライフサイクルをロックと世代安全なチャネルで同期し、候補の削除とepoch遷移に対する移行v39のトランザクション型Midnightロールバックジャーナル、アトミックなジャーナル消費、再起動に安全なロールバック、不完全なロールバックの再試行可能なエラー、切り詰め後のクリーンアップ、保存された整数の検証を追加しました。

### API、キャンセル、復旧
* 更新: Goツールチェーンを`1.26.9`に、`golang.org/x/net`を`v0.60.0`に更新して、脆弱性を修正しました。
* 制限: Blockfrost、Mesh、UTxO-RPC、MCPのリクエストを制限し、Blockfrostの範囲を包括的に扱い、末尾のCBORを拒否し、ストリーム、履歴、述語、参照を制限し、同時評価を制限し、キャンセルを伝播し、過負荷エラーをマッピングするようにしました。
* 移行: 保留中のヘッダーマーカーをblobストレージに移し、ロールバック動作と既存マーカーとの互換性を維持しました。
* 伝達: データベースとチェーンのAPIに呼び出し元のコンテキストを渡し、コミット対応のキャンセルとDNSタイムアウトを追加し、センチネルエラーを保持しました。
* 改善: epoch境界付近でat-tip復旧の巻き戻しを調整し、復旧メトリクスを追加しました。
