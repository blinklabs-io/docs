## v0.77.0

**タイトル:** ガバナンス、同期、APIの信頼性を強化

**日付:** 2026-10-02

**バージョン:** v0.77.0

**リリース:** [v0.77.0](https://github.com/blinklabs-io/dingo/releases/tag/v0.77.0)

Dingo v0.77.0では、ガバナンス処理、フォージングの安全性、報酬処理、API互換性、同期、検証を改善します。また、運用メトリクスを追加し、ConwayおよびDijkstraの動作に対する回帰テスト範囲を拡大します。

### 推奨ネットワーク互換性 ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### ガバナンスと報酬
* Conwayのガバナンス処理を修正し、エポック境界で両方が適用される場合に、`ENACT` アクションより先に `RATIFY` アクションを実行するようにしました。

* Conwayの投票権にアクティブな提案のデポジットを含め、ガバナンスの決定に意図したステークの表現を与えるよう拡張しました。

* Conwayの `UpdateCommittee` のしきい値処理を改良し、委員会の更新で正しい承認ルールとクォーラムルールを使用するようにしました。

* Dijkstraの子ガバナンスを回帰テストでカバーし、子提案が正しいガバナンス経路に従うことを検証するようにしました。

* 重複したガバナンス提案識別子に対するDijkstraの回帰テスト範囲を強化しました。

### フォージングと検証
* フォージングの判断を保護するため、チェーン先端を選択する前にプライマリチェーンの祖先関係を確認するようにしました。

* 適用されていないブロックを最大2個までにフォージングを制限し、安全でないローカルの先端を拡張する可能性を減らしました。

* ピアから報告された高さを照合してから、同期とフォージングの判断に使用するようにしました。

* `ForgePrimaryChainTipToleranceSlots` 設定を削除しました。フォージングでプライマリチェーンの祖先関係と未適用ブロックの保護策を直接適用するようになったためです。

### 報酬とデータ検証
* Dijkstraの報酬計算で、制定されたCIP-50の `maxPledgeLeverage` 値を適用するようにしました。

* 負のリーダー報酬を明示的に処理し、報酬計算で無効な結果が生成されないようにしました。

* 再起動と状態復元の経路で、負のリーダー報酬の結果を一貫して永続化するようにしました。

* 不正な固定長ハッシュを直ちに拒否し、無効な値が処理を通過し続けないようにしました。

### API互換性
* Kupoへのアクセスが必要なデプロイメント向けに、Kupo v2.12と互換性のあるオプションのKupo APIを導入しました。

* APIモードでAPIストレージ層を使用することを必須にし、Kupo APIを有効にする際のストレージ選択を明示的にしました。

* 要求されたスロットがまだ到達していない場合でもレスポンスを予測可能にできるよう、Kupo APIの将来スロットの動作を文書化しました。

* BlockfrostのDRep処理に有効期限の境界を含め、DRepが正確な有効期限スロットまでアクティブでいられるようにしました。

### 同期と運用の信頼性
* `gouroboros` v0.208.5を通じてPlutusマシンを再利用し、スクリプト評価中の繰り返しのセットアップを減らしました。

* キューに入れられた各ヘッダーで暗号検証結果を再利用し、ブロックフェッチ処理を効率化しました。

* ネットワークを利用できない場合の起動時リプレイ処理を復元し、ネットワーク接続なしでもローカルの復旧処理を進められるようにしました。

* キャッチアップ中の先端との差を測定し、ノードがネットワークの先端からどれだけ遅れているかを運用者が確認できるようにしました。

* write-ahead logのスナップショットを基に報酬のライブステークを安全に再構築し、復旧処理で一貫性のない状態ビューを使用しないようにしました。

* ライブステークの再構築中も報酬キャッシュの処理を維持し、再構築した状態とキャッシュ値の一貫性を保つようにしました。

### テストと品質
* 同期と台帳処理に関するベンチマークシナリオを強化し、パフォーマンス検証の信頼性を高めました。

* 修正された動作を保護するため、コンポーネント間の並行性と境界条件に対する回帰テスト範囲を拡大しました。
