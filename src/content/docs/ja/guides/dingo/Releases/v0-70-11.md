## v0.70.11

**タイトル:** トランザクション処理、ledgerの信頼性、運用準備を改善

**日付:** Not provided

**バージョン:** v0.70.11

**リリース:** [v0.70.11](https://github.com/blinklabs-io/dingo/releases/tag/v0.70.11)

このリリースでは、トランザクション送信の許容範囲、forge開始時の検証、ledgerの復旧、データベースアクセス、shutdown処理、Previewネットワークの運用を改善しました。また、将来のDMQメッセージ処理と認証に向けたスタンドアロンの基盤も追加しました。

### 推奨ネットワーク互換性 ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### ハイライト

* 重複したrequired signerについて、Preview BabbageおよびPV8 Plutusのbudget fixtureを固定し、評価済みredeemer budgetと宣言済みredeemer budgetが完全に一致することを検証するregression coverageを改善しました。

* TxSubmission V2で、advertised body sizeとwire sizeの差が32 bytes以内（両端を含む）であれば受け入れるようにし、aggregate budgetとadmission headroomにも同じ許容範囲を適用しました。これを超える差は引き続き拒否します。

* forging開始時のOpCert counter検証を、wall clockからの予測ではなく適用済みtipのslotとeraとの比較に改め、評価できないprotocol parameterも安全に処理するようにしました。

* 固定worker poolと復旧処理によって`GetUTxOWhole`のCBOR解決を高速化し、復旧不能なrowがある場合は不完全な結果ではなくエラーを返すようにしました。

* snapshot import中のpointer address stake positionを保持し、決定的な再起動を繰り返しても進展しない場合はledger pipelineを停止するようにしました。

* retention上限、TTL expiry、peerごとのFIFO cursor、deduplication、optional event、ID検証、clone保護を備えたCIP-0137 phase 1 DMQ `MessageMempool`をスタンドアロンで追加しました。
