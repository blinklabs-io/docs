## v0.70.11

**タイトル:** トランザクション処理、ledgerの信頼性、運用準備を改善

**日付:** Not provided

**バージョン:** v0.70.11

**リリース:** [v0.70.11](https://github.com/blinklabs-io/dingo/releases/tag/v0.70.11)

このリリースでは、トランザクション送信の許容範囲、forge開始時の検証、ledgerの復旧、データベースアクセス、shutdown処理、Previewネットワークの運用を改善しました。また、将来のDMQメッセージ処理と認証に向けたスタンドアロンの基盤も追加しました。

### 推奨ネットワーク互換性 ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### ハイライト

* 重複したrequired signerについて、Preview BabbageおよびPV8 Plutusのbudget fixtureを固定し、評価済みredeemer budgetと宣言済みredeemer budgetが完全に一致することを検証するregression coverageを改善しました。

* TxSubmission V2で、advertised body sizeとwire sizeの差が32 bytes以内（両端を含む）であれば受け入れるようにし、aggregate budgetとadmission headroomにも同じ許容範囲を適用しました。これを超える差は引き続き拒否します。

* forging開始時のOpCert counter検証を、wall clockからの予測ではなく適用済みtipのslotとeraとの比較に改め、評価できないprotocol parameterも安全に処理するようにしました。

* 固定worker poolと復旧処理によって`GetUTxOWhole`のCBOR解決を高速化し、復旧不能なrowがある場合は不完全な結果ではなくエラーを返すようにしました。

* snapshot import中のpointer address stake positionを保持し、決定的な再起動を繰り返しても進展しない場合はledger pipelineを停止するようにしました。

* retention上限、TTL expiry、peerごとのFIFO cursor、deduplication、optional event、ID検証、clone保護を備えたCIP-0137 phase 1 DMQ `MessageMempool`をスタンドアロンで追加しました。

* expiry、ID、stake、OpCert、KES、issue numberの検証とoverflow保護を備えたCIP-0137 phase 2 DMQ `Authenticator`をスタンドアロンで追加しました。

* `dingo-sundae-preview` exampleの`@types/node`依存関係を更新しました。

* read-only connectionでprotocol enactmentをprobeし、enactmentがpendingの場合だけwriterを取得することで、writerの競合を減らしました。

* `dingo-gov-lens` exampleで`pgx/v5`を`5.11.0`に更新しました。

* SQLでcredential UTxO stakeを集計し、MySQLの`BIGINT` castを正しく変換するようにしました。

* `GetUtxosByRefs` lookupを`tx_id`中心のindexed queryに変更し、filteringとoverflow validationを維持しました。

* malformed reference scriptとwitnessをdeterministic validation failureとして扱い、無限にretryせずrewindしてreintersectするよう復旧処理を強化しました。

* `skipRewardLiveStakeBackfillCheck`をYAML、CLI、environmentで設定できるようにし、defaultを`false`にしました。この設定は高コストなreward live stake consistency scanだけを省略し、consensus snapshot provenance guardは維持します。

* `dingo-blockfrost-explorer` exampleの`@types/node`依存関係を更新しました。

* SQLite driver implementationを`modernc.org/sqlite`に変更し、`sqlite` driver nameとbusyまたはlocked時の処理を維持しました。

* Koios parity reward discrepancyの判定をreward applicationまで延期し、それ以前の差異をreference lagとして扱うようにしました。

* BlockFetch rangeが指定されたend slotとhashに正確に到達することを要求し、invalid endpointを拒否し、不完全なrangeでは`BatchDone`を送らないようにしました。

* load下でのasynchronous ledger test waitを安定させました。

* per connectionのLeiosFetch admission capacityをatomicにreserveし、同時実行によるoversubscriptionを防ぎました。

* `bark` dependencyを`v0.2.0`に更新しました。

* phase 1 shutdown componentの停止を単一のshutdown deadline内に制限し、drainが確認できない場合はstorage resourceをcloseしないようにしました。

* Prometheusとprovision済みGrafana dashboardを含むPreview Koios parity Docker Compose stackを追加し、`KOIOS_PARITY_ENABLED`で制御できるようにしました。

* rollback cascade indexをcriticalとして扱い、Mithril sync cleanup中もdeferred index markerを保持し、起動時に不足しているcritical indexを修復するようにしました。

* migration testが既存の`modernc.org/sqlite` driverを使用するように更新しました。

* node parity watch modeに永続化cursor、blockごとのUTxO delta validation、定期およびpriority full checkpoint、full-check timeout、trusted local NtC timeout、2 GiBのLocalStateQuery bufferを追加しました。watchはincremental modeをdefaultとし、`--mode=full|incremental`、`--full-check-interval`、`--full-check-timeout`をサポートし、`--at-slot`と`--at-hash`を拒否します。`--at-hash`はdecode後に32 bytesちょうどである必要があり、historical checkの動作も明確にしました。

* blockごとのledger stageとBlockFetch decode latencyを計測するPrometheus histogramを追加しました。

* `LatestPoolOpCertSequence`から`COUNT(*)`を削除し、rowがない場合の動作を維持しました。

* rootの`pgx/v5` dependencyを`5.10.0`から`5.11.0`に更新しました。

* mainnet Conway PlutusV3のstored-output fixtureを導入し、script-context PlutusDataがblock decodingおよびdeclared budgetと一致することを検証できるようにしました。production behaviorは変更していません。

* `dingo-sundae-preview` exampleのViteを`8.2.2`から`8.3.0`に更新しました。

* `connectrpc.com/connect` dependencyを`1.20.0`から`1.21.0`へ拡張しました。

* JSON projectionを利用できない場合もmetadata label indexとCBORを保持し、labelを破棄したりrequestを失敗させたりせずnullのJSON valueを返すようにしました。

* ChainSync FindIntersectのwork budgetをconnectionごとに分離しました。

* `dingo-sundae-preview` exampleの`@sundaeswap/core`を`2.13.1`から`2.14.1`へ刷新しました。

* Docker nview imageを`0.15.0`から`0.15.1`へ引き上げました。

* `golang.org/x/sync`を`0.22.0`から`0.23.0`へ更新しました。

* snapshot manifest、Mithril download、zstd extractionのresourceに上限を設定し、`lifecycle.WithManifestMaxBytes`、`mithril.WithZstdLimits`、`BootstrapConfig.DownloadMaxBytes`、`SyncConfig.DownloadMaxBytes`などで設定できるようにしました。

* Conway redeemer dataを正規化して`serialiseData`がchain encodingと一致するようにし、`gouroboros`を`0.204.4`に更新しました。

* migration v14でmany-to-manyのcollateral transaction associationとrollback-safe cleanupを追加しました。

* NtCまたはNtNがdisconnectしたときに、idleなLeiosNotify requestとevent-log cursorを解放するようにしました。

* obsoleteなBlockfrost authenticationとtokenの案内を削除し、public API requestはanonymousで、TLSのみ任意で使用できることを明確にしました。
