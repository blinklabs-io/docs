## v0.87.0

**タイトル:** リソース安全性、ネットワーク、コンセンサス互換性を改善

**バージョン:** v0.87.0

**リリース:** [v0.87.0](https://github.com/blinklabs-io/dingo/releases/tag/v0.87.0)

**比較:** [v0.86.0...v0.87.0](https://github.com/blinklabs-io/dingo/compare/v0.86.0...v0.87.0)

Dingo v0.87.0では、リソース制御、ピアネットワーク、同期の安全性、APIの動作、設定のセキュリティ、コンセンサス互換性を改善しました。

### 推奨ネットワーク互換性 ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### 破壊的変更
* 制限: UTxO RPC `FollowTip`の履歴リプレイに、プロセス単位およびクライアント単位の同時実行数制限、ペーシング、履歴予算を適用しました。需要が設定済みの制限に達すると、サービスは`ResourceExhausted`を返します。
* 追加: YAML、環境変数、CLIオプションでDMQピアリスナー、トポロジー、最小および最大ピア数を設定できるようにしました。Dingoは起動前にこれらの設定を検証します。
* 変更: Meshのメンプール一覧で、プールが設定容量を超えた場合に不完全な先頭部分を返す代わりに、再試行可能なHTTP `503`を返すようにしました。一覧はトランザクションハッシュのみを返し、同時実行数にも上限を設けます。
* 修正: Blockfrostのアドレス概要でキャンセルを尊重し、エンリッチメントを制限するようにしました。リクエストが予算を超えるとHTTP `400`を返し、需要が容量に達するとHTTP `429`を返します。
* 保護: 生成されたdevnet APIをループバックにバインドし、状態、キー、ファイル操作がシンボリックリンクによるリダイレクトを追跡しないようにしました。
* 必須化: v0.87.0には、新しいByronおよびShelleyのジェネシスハッシュを同梱した`rc-2026w42`の再スピンが含まれるため、既存のMusashiチェーンデータベースは再利用できません。設定済みのデータベースを削除し、新しいMithrilスナップショットまたはジェネシスから同期を開始する必要があります。

### セキュリティと信頼性
* 検証: 認証済みトークンレジストリのアーカイブサイズとダイジェストを、Dingoがgzipおよびtarの内容を解析する前に検証するようにしました。
* 確認: ローカルImmutableDBのブロック本文ハッシュを検証してからブロックをインポートするようにしました。
* 制限: 展開後のMithril tarストリームの消費量に上限を設け、処理中のキャンセルを尊重するようにしました。
* 拒否: メタデータSQLiteの書き込み先行ログが`128 MiB`を超えている間はMCPの読み取りを拒否し、復旧後に読み取りを再開するようにしました。
* 正規化: Leiosのアナウンスヘッダーを重複排除と意味検証のために正規化し、リレーに使用するバイト列は保持するようにしました。

### API、同期、統合
* 更新: `google.golang.org/api`を`v0.304.0`に更新し、関連する依存関係を刷新しました。
* 修正: ジェネシスからの同期中に、将来のエポックのジェネシスオーバーレイパラメーターを予測する処理を修正しました。
* 必須化: 各トランザクション入力に1つのByron witnessを必須としました。
* 改訂: AWS SDKの設定と関連モジュールを刷新しました。
* 拡張: Bark `ArchiveService`に、設定可能なグローバルおよび呼び出し元単位の検索予算を追加しました。クラウドルックアップが予算を超える前に、サービスは`RESOURCE_EXHAUSTED`を返します。

### ストレージ、コンセンサス、セキュリティ
* 再構築: SQLiteとPostgreSQLのUTXO支出者インデックスを非NULLの部分インデックスとして再構築し、MySQLは変更しないようにしました。
* 導入: 選択可能なコンセンサスプロバイダーを導入し、Praosをデフォルトにしました。プロバイダーの識別情報を永続化し、その識別情報に一致しないスケジュールを拒否します。
* 移動: 台帳の待機処理をロックの外に移し、遅延中のヘッダー検証に上限を設け、Dingoがヘッダーを適用する際に再検証するようにしました。
* 固定: `crypto/x509`のセキュリティ修正のため、Goを`1.26.10`に固定しました。
* 検証: 競合するフォークのヘッダーをフォーク由来の候補ノンスで検証し、認証されていない祖先をピアの再利用なしで保留するようにしました。

### その他の変更
* 更新: Goビルドイメージを`ghcr.io/blinklabs-io/go:1.27.3-1`に更新し、ランタイムイメージとDebianスナップショットの固定値を刷新し、devnetとERAの`cardano-node`の固定値を更新しました。
* 修正: `GetPoolDistr2`と`GetStakeDistribution2`のCBORタグ`24`のエンコーディングを、裸の`PoolDistr`レイアウトを使用するように修正しました。デコーダーはこれらのレスポンスにそのレイアウトを使用する必要があります。
* 追加: `_FILE` CLI入力と環境変数入力でファイルベースのシークレット値を使用できるようにしました。Koiosおよびノードパリティ入力に検証、優先順位、競合ルールを適用し、無効または競合する設定では安全側で起動に失敗するようにしました。
* 待機: ローカルチェーンを拡張する遅延ヘッダーをキューに入れ、予測対象期間内のブロックを受け入れる前に未適用のローカル処理が完了するまで待機するようにしました。
* 強化: フォージしたブロックの自己検証前に未適用の祖先を待機し、Dingoが親に到達できない場合は判定されていないブロックを破棄するようにしました。
* 改善: 同期負荷の高い状況でもChainSync、LocalStateQuery、`GetUTxOWhole`を利用できるようにしました。`GetUTxOWhole`は、ページ単位の時点読み取り、ロールバック時の再試行、スナップショットの切り離しと再接続によって完全なUTxO結果を返します。ノードからクライアントへのロールフォワードは台帳への適用を待ち、エポック境界処理中はチップスナップショットを延期し、チェーン選択は拒否した広告済みチップを照合用に記録します。
* 再同期: 予測対象期間への受け入れ時にローカル処理がない場合、ピアをペナルティ対象にせず再同期するようにしました。
* 認証: ローカルBarkスナップショットのマニフェストを設定済みの信頼キーで認証し、必要に応じて認証済みクラウドミラーへフォールバックし、どちらも検証できない場合は安全側で失敗するようにしました。
* 維持: Alonzoの`extraConfig`コストモデルをConwayおよびDijkstra間で維持し、Musashiの`rc-2026w42`設定を更新し、`mithril.enabled`によるノード管理のMithril v2同期を有効化しました。さらに、LeiosにDijkstraの`block_transaction`と`is_valid`処理を適用し、ロールバック時のステーク検索を最適化し、gouroboros連携を更新しました。
* サニタイズ: トレーシングエンドポイントのエラーからuserinfo、クエリ、フラグメントに含まれる認証情報を除去するようにしました。
* 追加: DRepの登録解除保留状態に関する回帰テストを追加し、その遷移中もノードが正しい登録状態を維持できるようにしました。
* 公開: 検証済みの認証済みLeiosエンドーサーブロック取引をBlockfrostとUTxO RPCで一貫して公開し、データの欠落や不整合には検証エラーを返し、コンテキストのキャンセルを尊重するようにしました。
* 強化: ジェネシスからのpreprodノードパリティ検証に、エポックオラクル検索、セッションと再接続の処理、再試行、LocalStateQueryの入力バックプレッシャー、単一メッセージのChainSyncパイプライン、Koiosのタイムアウトを追加しました。
* 削除: Mithril v1バックエンドを削除したため、v1の設定とピンは使用できなくなりました。ブートストラップはv2専用となり、検証済みの付随状態またはダイジェストがない場合は安全側で失敗します。
* 秘匿: リモートImmutableDB読み込みURLのクエリ、フラグメント、userinfo、ラップされたエラー、`errors.As`の結果から認証情報を秘匿するようにしました。
* 検証: 起動時にDMQトポロジーJSONを読み込んで検証し、重複しないピアをログに記録し、ピアが0件の場合に警告し、未対応フィールドは警告して無視するようにしました。
* 無視: チェーン選択の同率判定で、未検証の広告済みフォーク高を無視するようにしました。
* 拡張: 期限切れ参照の限定的な照合範囲を、ローカルチップより先行するピア参照にも広げました。対象範囲はセキュリティパラメーターの2倍以内です。
* 有効化: 台帳署名の先行検証をデフォルトで有効にし、YAML、環境変数、CLIオプションから`ledgerValidateAheadEnabled`を制御できるようにしました。
* 移行: Homebrew、Ansible、cardano-up、Helmの下流コンシューマー更新を`publish.yml`から`release-fanout`へ移し、リリースが専用の配布フローで伝播するようにしました。
* 制限: MCPの`get_mempool_info`にデフォルト`10`、最大`50`の件数制限と保持バイト数の計上を追加しました。
* 遵守: Cardanoの`ConsensusMode` `PraosMode`に従い、MusashiではGenesisチェーン選択を無効にしました。
* 防止: 同一ブロック内でまとめて処理するライブステークが二重に計上されないようにしました。
* 調整: LeiosVotesの`RequestNext`値を`1`から`1000`までの包括的な範囲に制限しました。
* 導入: Meshの`/account/coins`読み取りに上限とキャンセルを適用し、カーソルページネーションを追加しました。完全な結果が1レスポンスに収まらない場合、クライアントはページネーションを要求する必要があります。要求しない場合はHTTP `400`を返し、同時実行数の枯渇時はHTTP `503`を返します。
* 修正: Byronのバージョンによって発生する境界処理でShelleyをスキップできないようにしました。
* 上限設定: MCPの`get_asset_info`スキャンを`50,000`行に制限し、4スロットの読み取り予算をリクエスト間で共有するようにしました。
