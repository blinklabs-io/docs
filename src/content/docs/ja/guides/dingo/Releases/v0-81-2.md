## v0.81.2

**タイトル:** スナップショットの完全性、同期、ストレージの信頼性を改善

**バージョン:** v0.81.2

**リリース:** [v0.81.2](https://github.com/blinklabs-io/dingo/releases/tag/v0.81.2)

Dingo v0.81.2では、スナップショットの検証、ストレージの信頼性、ピア同期を強化し、ブロックフェッチの復旧応答性を高める機能とオプトインのブロックフェッチ閾値を追加しました。

### 推奨ネットワーク互換性 ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### スナップショットの完全性とストレージ
* 検証: マイグレーションロックの保持中に報酬ステークスナップショットのプロヴェナンスを検証します。プロヴェナンスを検証できない場合、Dingoはスキーママイグレーション、バックフィル、その他のデータベースやジャーナルの変更を実行する前に起動を停止します。検証済みのgenesis、era、protocolパラメータを持ち、Leiosコンテキストを含まず、データベースを開くすべての経路でgenesis選択が一致するバージョン2スナップショットだけが計算バージョン3へ進みます。

### ストレージ、トポロジー、リカバリ
* 最適化: Mithrilバックフィル中のSQLite委員会認証クリーンアップを最適化し、各バッチを置き換え対象のIDに限定し、整数主キーで行を削除します。これにより、古い統計情報が原因の全テーブルスキャンを回避します。
* 可視化: ストレージ、イテレーター、タイムスタンプ、デコードのエラーを隠さずに表面化します。リストア、切り詰め、シャットダウンの各操作ではサブスクリプションの排出を制限します。トポロジーは`hotValency`を`valency`の別名として受け付け、`valency`を優先し、`warmValency`を検証します。ブートストラップのリカバリではスナップショット優先試行に上限を設け、SQLiteのキャンセル動作に必要な修正も適用します。

### ピア同期とブロックフェッチ
* 再同期: ChainSync接続がtipに遅れたり先行したりした場合に再同期し、切断されたヘッダーを受け入れ、最良のピアが利用できない場合でも古いカーソルを復旧します。
* 開始: 予測ホライズンの待機によって進行が遅れている場合、キューに入ったヘッダーのブロックフェッチを開始し、ディスパッチに失敗した場合に再同期します。
* 受け入れ: Dingoが構成済みのgenesisハッシュにチェーンを固定した場合、チェーンの起点で最初のepoch 0のpeer-relative Byron EBBを受け入れます。
* 有効化: オプトインの`BlockfetchLowWatermarkEnabled`設定を、YAMLでは`blockfetchLowWatermarkEnabled`、CLIでは`--blockfetch-low-watermark-enabled`、環境変数では`DINGO_BLOCKFETCH_LOW_WATERMARK_ENABLED`で有効にできます。設定の既定値は`false`です。有効にすると、Dingoはより大きなキュー閾値を待たず、1つのバッチ範囲がキューに入った時点でtipから離れた位置のブロックフェッチを開始します。
