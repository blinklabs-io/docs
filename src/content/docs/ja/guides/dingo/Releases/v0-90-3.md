## v0.90.3

**タイトル:** コンセンサスの正確性、APIの耐障害性、運用上の安全性を向上

**バージョン:** v0.90.3

**リリース:** [v0.90.3](https://github.com/blinklabs-io/dingo/releases/tag/v0.90.3)

**比較:** [v0.90.2...v0.90.3](https://github.com/blinklabs-io/dingo/compare/v0.90.2...v0.90.3)

Dingo v0.90.3では、エラの境界をまたぐステーク処理を改善し、APIとデータベース処理を制限し、ピアとダウンロードの安全性を高め、ノードおよびライブラリ利用者向けにLeiosと運用時の動作を改善しました。

### 推奨ネットワーク互換性 ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

#### コンセンサスと台帳
* 修正: エポック境界で同じルールのエラ変更が発生しても、SNAPポイントのステーク情報を保持するようにしました。ポインターステークの適用条件が変わる場合にだけ過去のステークを再構築し、Babbage から Conway への移行を含めて、同じポインターステーク判定を適用します。
* 追加: 移行先エポックの行が存在する前に、ハードフォークで選択された移行先エラを境界ステークの読み取りへ渡し、修正済みのステーク分布を再利用するようにしました。
* 改善: 台帳コンテキストの変更後に発生する一時的なローカル拡張ヘッダー検証エラーを、既存の制限時間内で再試行するようにしました。再試行が期限に達した場合はヘッダーを保留します。
* 導入: 中継されたLeios投票を認証期限まで受け付けつつ、ローカルで生成する投票をローカル投票期間内に制限するようにしました。
* 有効化: ステークがゼロのエポックについて、空のリーダースケジュールをキャッシュして永続化するようにしました。

#### API、データベース、性能
* 拡張: Leios のキーエポックスナップショットとリタイアメント検索に、マイグレーション v51 の複合インデックスと制限付きの seek および UNION 処理を追加し、データベース処理が無制限に拡大しないようにしました。
* 精緻化: Blockfrost のプールステーク集計で制限付き SQL 集計とネットワーク全体のアクティブプール合計を使用するようにしました。集計データを利用できない場合のフォールバックとオーバーフローエラーに対応し、共有受付では全体で4件、クライアントごとに2件のプール集計処理を許可します。容量に達した場合は `Retry-After: 1` とともに HTTP 429 を返します。
* 制限: Blockfrost のアセット詳細および一覧処理に共有受付、15秒の期限、キャンセルの伝播、SQL集計を適用しました。容量またはサービスの状態により再試行が必要な場合は `Retry-After` とともに HTTP 429 または503を返し、ライブUTxOが1,000,000件を超える要求は HTTP 400 を返します。
* 保護: クラウドミラーのマーカー読み取りと公開でマーカーのサイズを制限し、安全でないパスや置き換えられたパスを拒否するようにしました。

#### ネットワークと設定
* グループ化: Genesis の照合に使用する対象の、明示的な識別子を持たない送信ピアを、IPv4 の `/24`、IPv6 の `/64`、またはホスト名でグループ化するようにしました。明示的な制御用識別子は保持し、受信ピアと不明なピアは除外します。
* 再開: HTTP 416 の応答で検証可能なサイズを取得できない場合、Mithril のダウンロードを制限付きの完全リクエストで再開するようにしました。置き換えが成功するまで名前付きキャッシュを保持します。
* 拒否: 初期化時に `blockCacheSize=0` のオンディスク Badger 圧縮を拒否し、必要な設定を文書化しました。
* 定義: `TxSubmissionLogicVersion` の処理を追加し、値がない場合は V1 を既定値とし、V1 を受け付け、V2 または不明な値は設定読み込み時に拒否するようにしました。Dingo では、実装した戦略を従来のピア単位の受信送信として文書化しています。

#### 検証と devnet
* 更新: devnet txpump のイメージダイジェストを、エラタグ付きのトランザクションIDに対応するよう更新しました。
* 強化: conformance 入力を更新し、Conway CBOR の検証とレポートを強化しました。Linux Turbo は `TURBO_MAX_PROGRAMS=0` によりすべてのプログラムを既定で対象とし、`coverage.json` を検証します。
