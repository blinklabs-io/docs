## v0.70.4

**タイトル:** Leios処理、APIの信頼性、ノード運用を改善

**日付:** Not provided

**バージョン:** v0.70.4

このリリースでは、Dingoノードとライブラリ利用者向けに、Leios処理、peer discovery、データベース処理、APIレスポンス、ガバナンス状態、運用の信頼性を改善します。

### 推奨ネットワーク互換性 ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### ハイライト

* 改善: 自動検証で、独立したmainline push同士がキャンセルされないようにし、pull requestのチェックでは従来のキャンセル動作を維持しました。

* 追加: Leios closureのdouble consumptionに対するend to endカバレッジを追加しました。MusashiおよびHaskellに準拠するclosureでは、すでに消費された出力を許容し、CIPおよびranking blockの経路では引き続き`ErrUtxoConflict`を返します。

* 更新: Leios endorser block referenceが、完全なtransaction dataのBlake2b256 digestと完全なencoded sizeを使用するようにしました。

* 拡張: データベース移行の検証で、metadata seeding、memoization、artifact isolation、process単位のscratch directoryを対象にしました。

* 強化: peer sharingの応答数に上限を設け、無効なhostとportの値を除外し、ledgerのadmissionを通過して保持されたpeerだけを記録するようにしました。

* 整理: SQLite metadataの処理で移行済みmetadata templateを再利用し、従来のin memory動作を必要とするテスト向けに`Options.InMemoryMetadata`を追加しました。

* 延期: on chain keyがない場合のLeios voting activationを延期し、epoch transitionで再試行し、対象となるannouncementを決定的に再生して、古いin flight voteを破棄するようにしました。

* 統一: build configuration間でconformance cleanupを共有し、失敗後もすべてのcleanup callbackを実行して、cleanup failureをprocessのexit codeに反映するようにしました。
