## v0.90.0

**タイトル:** チェーン整合性、API制限、サービス運用を強化

**バージョン:** v0.90.0

**リリース:** [v0.90.0](https://github.com/blinklabs-io/dingo/releases/tag/v0.90.0)

**比較:** [v0.89.0...v0.90.0](https://github.com/blinklabs-io/dingo/compare/v0.89.0...v0.90.0)

Dingo v0.90.0では、フォージングとチェーン選択を強化し、同期回復を改善し、上限付きのUTxOおよびトランザクションAPIを追加し、容量と監視をより明確に管理できるようにしました。

### 推奨ネットワーク互換性 ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### コンセンサス、チェーン選択、同期
* 強化: フォージングとローカルブロック受け入れに、一貫性のある暗号検証済みの受け入れヘッダーフロンティアを必須にしました。受け入れ済みヘッダーが先行する場合は古い親からのフォージングを拒否し、スキップ理由として`admitted_header_ahead`を報告し、兄弟ブロック採用時にもフロンティアを再確認します。フォージギャップメトリクスはローカル先端ではなくネットワーク基準になりました。運用者は削除された`ForgePrimaryChainTipToleranceSlots`設定を使う連携を置き換え、プロバイダーに`PrimaryChainTipRelationAndHeader`の提供を実装する必要があります。遠い先端の相関確認と、停止したヘッダーのブロックフェッチ回復も、遅れたピアからの回復を改善します。
* 一括化: `WaitForTx`ストリームごとの既存トランザクションハッシュ検索を、コンテキストに束縛された1つの読み取りトランザクションにまとめました。大きな要求はSQLパラメータ上限に合わせて分割し、購読を検索より先に行う動作と要求順序を維持します。
* 分離: 外向きピア予約と内向き容量を分離し、`MaxInbound`を追加しました。`MinPeers`には外向きピアだけを数え、ハンドシェイク前に超過した内向きピアを拒否します。
* 整合: Genesisの相関確認で、トポロジーの`GroupID`ではなく接続済みアドレスグループを使うようにしました。稼働中のリモートピアから受け取ったアドレスも扱います。
* 置換: アドレスとトポロジーの相関識別子を、信頼できる台帳のプール制御識別子またはスナップショットのプール識別子に置き換えました。必要な証拠がない、または曖昧な場合は安全側に倒して失敗します。
* 制限: MCPの`get_utxos`と`get_utxos_by_asset`のオフセットを`10,000`までに制限し、共有SQLite読み取り容量を使うようにし、結果が切り詰められた場合に明示します。
* 移動: ブートストラップスロットと同期進捗の読み取りをピアガバナーのロック外で行い、ロック反転と関連するデッドロックを防ぎます。
* 更新: `cardano-configs`を`20261027-1`に更新し、DijkstraのEKGおよびPrometheusエンドポイントを`0.0.0.0`にバインドし、期限切れテストを決定的にしました。監視エンドポイントが全インターフェースで待ち受けるため、運用者はファイアウォールとネットワークアクセス制御を確認してください。
* 回復: 非所有者のバッファリングが満杯でフェッチが実行されていない場合、待機中のブロックフェッチを開始して停止したヘッダーキューを回復します。
* 保持: ローカル台帳が追いつく間、キャッチアップの行き過ぎたヘッダーを保持し、即時切断を避けます。限定された待機中も妥当性チェックを続けます。
* 認証: Genesisの相関確認に、生成元で検証された配信済みヘッダーの上限付き履歴を使い、ロールバックと切断時に履歴を消去し、昇格後にオブザーバーを再同期します。
* 抑制: 遅延ヘッダーの回復と昇格オブザーバーの再作成に30秒と10秒のクールダウンを設け、ローカル先端より低いピアの回復を省略します。
* 最適化: 正確なアドレスUTxOスキャンにキャンセル、SQL集約、インデックスを適用し、高カーディナリティの検索を改善しました。Blockfrostは予算超過時に`400`を返し、計算できない場合はページネーションの合計を省略できます。クライアントは予算エラーを処理し、合計の欠落を想定される応答として扱う必要があります。
* 追加: DevNetの検証に、`cardano-node`とのPlutus V3コンフォーマンス比較を追加しました。
* 算出: 稼働中のByron UTxO残高からByronからShelleyへのリザーブを算出し、稼働中のUTxOセットが空の場合のロールオーバーを拒否します。
* 改善: 受け入れ済みヘッダー処理に、キューのフラッシュの上限、オブザーバーの祖先関係と昇格回復の改善、安全なフォーク暗号のキャッシュ、blobのみのメンバーシップおよびブロック読み取り、Leios APIクロージャ行の一括処理、署名の事前検証を適用しました。ローカル再同期はピアの不安定性としてスコアリングされません。
* 固定: node-diversity-conformanceのledger-rulesリビジョンを`9d14fd8c`から`e02a9e1c`へ更新し、publishチェックとdocsparityテストで固定しました。コンフォーマンスコーパスは変更せず、DRepデポジットのマッピング範囲をフィクスチャ更新から分離しました。
* 更新: `gouroboros`を`0.216.1`に更新し、Musashi向けPlutus V4修正を適用しました。Musashiブロックのリプレイで、witness setのキー処理と`chooseData`のデコードを修正します。
* 抑制: アドミッションの再実行とコミット再確認で発生する重複peer-tip拒否について、ログ、メトリクス、コールバックをステージ済み候補ごとに1回だけ報告します。ステージされていない配信は配信ごとの報告を維持します。
* 許可: 独立したidentity groupの裏付けがある場合に限り、従来のキャッチアップ上限を越えた遠いフロンティアのチェーン選択を許可し、はるかに遅れたノードの古い参照の扱いを緩和しました。
* 分類: DRep登録デポジットのコンフォーマンス失敗を`IncorrectDepositDELEG`ではなく`IncorrectDepositDRep`として分類し、対象デポジットに合ったエラーを報告します。

### API、連携、サービス信頼性
* 効率化: ドキュメントのみのマージグループでは、分類に成功した後にTier 2ゲートを省略するようCIを整えました。すべての`docs/`アセットを含みますが、公開検証には成功した変更チェックが必要です。
* 更新: KES署名接続を要求ごとに新しく作成し、各署名応答後に閉じ、接続とハンドシェイクの失敗を数え、永続的なserve key購読を維持します。
* 無視: DMQがプロトコル終了による送信拒否をピア障害として扱わないようにしました。
* 終了: Mithrilの予算テストで一時ディレクトリを削除する前にチャンクフィードを閉じ、アクティブな読み取りとの競合を防ぎます。
* 調整: 6つのダッシュボードで、解放済みGoヒープをMMAP見積もりから除外しました。
* 伝播: Midnightの`end_block_hash`解決と`BlockByHash`にRPCコンテキストを渡し、`BlockNumberByHash`コールバックのシグネチャを更新しました。Midnight連携は新しいコンテキスト引数を受け取る必要があります。
* 拡張: 署名済みマニフェストのない公開アーカイブ、ETag再検証、mainnetとtestnetのレイアウト、アセットではないエントリの安全な処理をトークンレジストリでサポートしました。
* 検証: リモートImmutableDB読み取りを、リモート先端を含むチャンクで停止し、そのチャンクが先端まで到達しない場合に失敗するようにしました。リモートリーダーには正の`chunkSlots`値が必要です。
* 適用: バッチ化したUTxO RPC `ReadUtxos`要求で正確な`(tx_id, output_idx)`検索を行い、CBOR読み込み中に`MaxResponseBytes`を適用し、`ResourceExhausted`、`Canceled`、`DeadlineExceeded`を一貫して返します。クライアントは応答を設定上限内に収め、これらのステータスを明示的に処理してください。
* 保護: `go-jose/v4`を`4.1.6`に更新してJWKとJOSEの処理を強化しました。既定の4096ビットを超えるRSAキーを解析する場合は、事前に`MaxRSAModulusBits`を設定してください。
* 強化: DevNetの状態ディレクトリ作成で、コンポーネント走査の固定、シンボリックリンクと競合への保護、権限制限前のマーカー検証、プラットフォーム別の安全なパス処理を適用しました。運用者は信頼できる専用の状態パスを使い、シンボリックリンクを含むパス要素を避けてください。
* 計測: Barkの高さベース`FetchBlock`ストレージ処理で、境界解決、二分探索プローブ、古い末尾の再試行を計測し、予算が不足する場合は処理開始前に`ResourceExhausted`を返します。
* 束縛: UTxORPC `FetchBlock`の読み取りを要求コンテキストに束縛し、ブロック間でキャンセルを確認して、キャンセルと期限を`Canceled`および`DeadlineExceeded`に変換し、バルク容量を速やかに解放します。
* 秘匿: 設定と同期ログのトークンレジストリURLパスを秘匿します。有効なHTTP(S) URLではスキーム、ホスト、ポートだけを残し、HTTP(S)以外の値は完全に秘匿します。
* 直列化: ADAのみのBabbage LocalStateQuery UTxO出力を`cardano-node`と`cardano-ledger`が使用する従来の2要素配列形式で直列化します。アセット、データム、参照スクリプトを含む出力の形式は変わりません。
* 有効化: DMQピアリスナー、ピア管理、外向きダイヤル、トポロジー・パブリックルート・台帳SRV探索、送信元ごとの内向き上限、トピック別メトリクス、ピアダイヤル数を追加しました。ノードモードでは`n2nPort`と`maxPeers`を有効にするとDMQ相互運用が有効になるため、必要な場合は両方を設定してください。
* 強化: Mithrilのダウンロードのステージング、再開、保存で、排他的な部分ファイル、アトミック公開、シンボリックリンクと通常ファイル以外の拒否、所有済み単一リンクの再開確認、古いステージングの削除、共有空き容量リザーブ、失敗時のクリーンアップを適用しました。運用者は書き込み可能で、シンボリックリンクや共有部分ファイルに依存しないキャッシュパスを指定してください。
* 一括化: UTxORPC `ReadData`のデータム検索を1つのコンテキストに束縛された読み取りトランザクションにまとめて重複を除去し、初出順序を維持しながら、欠落、キャンセル、期限の扱いを一貫させました。
* 安定化: DMQピアマネージャーの再接続動作を、マネージャーが保持する接続を閉じて、別の接続で再接続が成功することを確認する形にしました。
* 実装: LocalStateQueryのプール状態と報酬の出所に関するクエリを実装し、ステークプールパラメータをポイント対応にしました。Dingoは未対応のデバッグおよびnon-myopicクエリに対して`ErrQueryNotAnswered`を返すため、呼び出し側は応答を待たずに返されたエラーを処理してください。
* 分離: APIメンプール検証用に別の上限付き容量を確保し、容量枯渇時はAPIのアドミッションを速やかに失敗させ、直接ピア送信向けに共有検証スロットを少なくとも1つ維持します。APIの飽和はMeshの`unavailable`とUTxORPCの`ResourceExhausted`に変換されます。
* 受け入れ: UTxORPC `ReadTx`を台帳検索前に共有バルク読み取り容量へ入れ、容量枯渇時は読み取りを行わず`ResourceExhausted`を返します。
* ストリーム化: Mesh `/account/coins`を1つのストレージスナップショットから上限付きページで配信し、完全な応答の意味とスナップショットの`block_identifier`を維持し、途中で失敗した場合は接続を終了します。運用者はアカウントコインのページサイズ、候補数、バイト数の設定を容量に合わせて調整できます。
* 整合: `gouroboros`を`0.216.0`に、`plutigo`を`0.10.0`に更新し、暗号関連の推移依存も更新しました。Plutus評価とより厳格なCBORデコードの動作を揃えます。
