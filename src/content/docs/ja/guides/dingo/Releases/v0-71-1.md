## v0.71.1

**タイトル:** ノードの信頼性、復旧、同期を改善

**日付:** 2026-09-22

**バージョン:** v0.71.1

**リリース:** [v0.71.1](https://github.com/blinklabs-io/dingo/releases/tag/v0.71.1)

このリリースでは、パリティチェック、ガバナンス検証、委員会の継続性、報酬処理、ブロック同期、データベース性能、復旧の安全性、オペレーター制御を改善しました。また、トークンレジストリのスナップショット、blobストレージ、フォーク処理、高分散時の報酬分配に対する保護機能を追加しました。

|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### ランタイムおよび運用面の改善
 
* 強化し、Koiosのパリティ集計チェックとプールチェックに個別のワーカーを割り当て、アカウント単位の遅いチェックを独立して実行できるようにしました。Dingoはフェーズごとに結果を永続化し、集計取得を共有し、コールバックを直列化し、厳格な失敗を正確に一度だけディスパッチします。

* 免除し、完全に解決済みのredeem-only Byronトランザクションをminimum fee要件の対象外にしました。mixed、empty、未解決のinputには通常のfee checkを引き続き適用します。

* 修正し、`UpdateCommittee` と `NoConfidence` のconformance validationがproductionのratification ruleに従うようにしました。これにはstake-weighted DRepおよびSPO vote、active proposal deposit、implicit vote routing、Conway bootstrap gateが含まれます。

* 維持し、`UpdateCommittee` の更新中に継続メンバーの`TermStartSlot`とcommittee authorizationまたはresignation stateを保持するようにしました。新規メンバーと再参加メンバーには新しいterm startを設定します。

* 改善し、reward stake reconstructionを決定的かつ読み取り専用にしました。retention pruningが結果を計算し、write phaseで結果をアトミックに保存するため、報酬の取りこぼしと不完全なrowを防ぎます。

* キャッシュし、`HardForkSummary`の値をpublication generationとhorizon anchorごとに保存して、読み取り専用データとして共有し、state変更時に無効化するようにしました。利用側はキャッシュされたsummaryを変更してはなりません。
