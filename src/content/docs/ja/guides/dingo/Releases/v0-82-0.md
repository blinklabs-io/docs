## v0.82.0

**タイトル:** プロトコルの信頼性、可観測性、開発者機能を改善

**バージョン:** v0.82.0

**リリース:** [v0.82.0](https://github.com/blinklabs-io/dingo/releases/tag/v0.82.0)

Dingo v0.82.0では、v0.81.3以降の変更として、プロトコル検証、同期、復旧、可観測性、クラウドストレージ、ガバナンス、開発者ワークフローを改善しました。

### 推奨ネットワーク互換性 ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### プロトコルと同期
* 改善: ChainSyncヘッダー検証で、ヘッダーの世代とポイントに結び付いた暗号検証結果を安全に再利用し、台帳とBlockFetchの受け入れ処理を一貫させました。
* 効率化: ドキュメントのみの変更では高コストなCIジョブを省略しつつ、ドキュメントの整合性検査と安全なフォールバックを維持しました。
* 強化: Genesisの密度ウィンドウ全体を保持し、ChainSyncの`AwaitReply`でアイドル状態のピアを監視し、BlockFetchの再試行と監視処理、ピアIDのクールダウンを改善し、関連経路にトレースを接続しました。
* 明確化: 決定的なConwayガバナンス提案の返却失敗を分類し、巻き戻しと再同期による復旧で一貫して処理できるようにしました。
* 保護: 署名付きEd25519マニフェスト、HTTPSの強制、正確なサイズとダイジェストの検証、明示的なロールバック方針でトークンレジストリのスナップショットを認証しました。トークンレジストリの設定では、HTTPS経由の認証済みスナップショットメタデータが必要です。
* 保持: インポートした運用証明書の境界カウンターを保持し、競合するカウンター値を拒否しました。
* 軽減: 委員会のプルーニングで古い統計情報に依存するSQLiteスキャンを避け、処理負荷を抑えました。
* 適用: ライブ処理、リプレイ、インポート、Mithrilのギャップ処理で、時代を考慮した`ParameterChange`とプロトコルパラメーターのドメイン検証を行いました。
* 明示化: コンテナのメトリクスバインドを明示し、ノードとMithrilのメトリクスに任意のBearer認証を追加しました。コンテナ環境ではメトリクスのバインドアドレスを明示的に設定する必要があります。
* キャッシュ: 対応するデータベースでガバナンス投票のSQLステートメントをキャッシュしました。

### 可観測性と復旧
* 導入: OpenTelemetryのトレース設定、スパン、サンプリング、リクエストコンテキストの伝播をサポート対象の処理に追加しました。
* 区別: インターセクション、復旧、再起動で、ハッシュ化されたスロットゼロのブロックと起点ブロックを区別しました。
* 制限: 永続スナップショットカタログ、認証済みクラウドマニフェスト、ページネーション、キャンセルによってBark診断の範囲を制限しました。
* 対応: Dijkstra Plutus V4の評価を有効にし、APIからDijkstraパラメーターを公開しました。
* 原子化: S3とGCSのクラウド復元を名前空間付きBlobと永続的な復旧機能で原子的に有効化しました。
* 伝播: Mithril同期と遅延インデックスにシグナルキャンセルを伝播し、中断した処理を安全に再開できるようにしました。

### Leios、ガバナンス、開発者ワークフロー
* 要求: 完全かつ検証済みのLeiosエンドーサー効果を採用またはコミット前に要求し、投票を対応するアナウンスに限定しました。
* 選択: 正しいSNAP境界でDijkstraのプールパラメーターを選択しました。
* 制限: mempoolオーバーレイの再構築に失敗した後の再試行を制限し、即時の反復処理を防ぎました。
* 保持: 資金付きdevnetフォーセットの認証情報をエクスポートし、再起動後も永続的なdevnet状態を保持しました。
