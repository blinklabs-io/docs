## v0.84.0

**タイトル:** ノードの信頼性、検証、コンフォーマンスツールを改善

**バージョン:** v0.84.0

**リリース:** [v0.84.0](https://github.com/blinklabs-io/dingo/releases/tag/v0.84.0)

Dingo v0.84.0では、v0.83.1と比較して、ローカルトランザクション送信、ネットワーク同期、台帳検証、運用上の安全性、リリースのコンフォーマンスレポートを改善しました。

### 推奨ネットワーク互換性 ⚠️

| ネットワーク             | 互換性 |
|-------------------------|--------|
| mainnet                 | ⛔     |
| preprod-testnet         | ✅     |
| preview-testnet         | ✅     |
| musashi                 | ✅     |

### 新機能とネットワーク動作
* 追加: 機能フラグで有効化できるCIP-0137 DMQローカル送信および通知サービスを、設定可能なUnixソケット経由で利用できるようになりました。`dmq.enabled`設定と`--dmq-enabled`フラグでサービスを制御し、設定を検証して各コンシューマーにメッセージを配信し、拒否理由を報告し、`dingo_dmq_*`メトリクスを公開します。
* 低減: 通常のノードとクライアント間の接続受け入れおよびピア切断メッセージをDEBUGに変更しました。予期しない切断エラーにはWARNを維持するため、障害を隠さずに通常のネットワーク動作のノイズを減らせます。
* 改善: 構文的に正しいものの未対応の不透明なLeiosアナウンスを無視し、形式が不正なCBORには引き続きペナルティを科すようにしました。
* 整理: 台帳への受け入れまでピアの先端を保留し、受け入れ後にのみセレクターから見える進行状況を進め、配信ウォーターマークを修正し、接続終了時にキューへ入ったLeiosフェッチ処理をキャンセルするようにしました。

### 破壊的変更
* 整合: リーダー資格とスケジューリングをCardano E34の有限算術に合わせました。スケジュールは形式v5で保存され、削除されたしきい値マージンヒストグラムは拒否の集計に置き換えられ、リプレイ時の暗号検証に上限が設定され、不正なLeiosフェッチのビットマップまたはペイロードの要素数は拒否されます。アップグレード前に永続化されたスケジュールを再生成し、メトリクスの利用側を更新してください。AndrewWestbergによる最初の貢献が含まれています。

### パフォーマンスと台帳の改善
* 効率化: 不変リプレイの効率を改善し、リプレイ中に必要な処理量を削減しました。
* 拡張: Dijkstra Perasおよび参照入力コストのパラメーターを検証、ガバナンス、クローン、クエリ全体に拡張し、オーバーレイを再構築した後にロールバックされたメンプールトランザクションのうち資格のあるものを復元するようにしました。
* 受け入れ: ポートのないDNSおよびSRVピアスナップショットリレーを`MultiHostName`エントリとして受け入れ、ポートのないIPリレーは引き続き拒否します。
* 制限: BarkアーカイブRPCトランスポートに上限を設定し、アーカイブリクエストがトランスポートリソースを無制限に消費できないようにしました。

### 検証と互換性
* 拒否: Leios Conwayフォールバックで末尾のCBORを拒否し、その他の点では有効なメッセージの後に追加データがあってもフォールバックが受け入れないようにしました。

### コンフォーマンスとリリースツール
* 標準化: CBORコンフォーマンスを固定され在庫確認済みの主要コーパスに統一し、スキーマと免除の処理を追加し、レポートアセットをgzip圧縮JSONに変更しました。
* 固定: 実行可能なリリース入力を固定し、リリース実行を再現可能にしました。
* 対応: Koiosの`proposal_refund`報酬とモデル化されていない報酬タイプを、厳密なパリティでモデル化しました。
* 公開: 4種類のリリースコンフォーマンスレポートを公開し、通常の変更検証からコストの高いコンフォーマンスレポート生成を削除しました。
* 保護: Mithrilアグリゲーターとコマンドのエラーテキストをターミナルおよびログに出力する前にエスケープし、エラーテキストによって出力構造が変更されないようにしました。
