## Dingo v0.94.2

**タイトル:** プロトコルの安全性、Leios の連携、サービスの信頼性を改善

**バージョン:** v0.94.2

**日付:** 2026-11-16

**リリース:** [v0.94.2](https://github.com/blinklabs-io/dingo/releases/tag/v0.94.2)

**比較:** [v0.94.1...v0.94.2](https://github.com/blinklabs-io/dingo/compare/v0.94.1...v0.94.2)

Dingo v0.94.2 は Cardano プロトコルの検証を強化し、Leios の連携を改善するとともに、API 結果の一貫性と運用上の回復力を高めます。

|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### プロトコルと API の動作
* 強化: 不正なトランザクションと補助データで、形式不正または null のコレクション値を拒否し、IPv6 ピアアドレスにビッグエンディアンのワードを使用し、`65540` バイトを超える TxSubmission の広告または返信本文を拒否することで、プロトコル検証を改善しました。Conway 前の重複した出金アカウントと Babbage の補助データインデックスでは、最後のエントリを使用するようになりました。
* 整列: Blockfrost、Mesh、UTxO RPC のレスポンスで、マルチアセットを未加工バイトの決定的な昇順に並べ替えるようにしました。Dingo は既存の保存行を読み取り時に並べ替え、ミントされたアセットには最初のスロットとトランザクション位置を使用し、決定的なタイブレークとオーバーフローに安全な順序付けを適用します。

### Leios の連携
* 追加: Leios エンドーサーブロック容量に委員会クォーラムのチェックを追加しました。デフォルトでは、クォーラムが成立する可能性がある場合に Leios と Musashi の mempool 容量に `25 MiB` を使用し、それ以外の場合は `1 MiB` を使用します。明示的に設定した容量は固定されます。クォーラムが成立しない、または解決できない場合、ノードはエンドーサーブロックのフォージをスキップし、`dingo_mempool_capacity_bytes` は現在の容量を報告します。
* 拡張: Leios の投票で、Cardano BLS のテキストエンベロープキーの JSON 配列に加え、単一のエンベロープまたは従来の raw hexadecimal scalar を受け入れるようにしました。空の配列は非投票リレーとして動作し、無効な要素がある場合はキーを読み込みません。キーセットは複数の委員会席とキーのローテーションをサポートします。Leios 投票だけが有効なロールの場合はマルチプール検証を緩和しますが、Leios のフォージ制限は維持します。
* 修正: 受信した Leios オファーが未通知、重複、immutable slot より古い、または無効な本文サイズを申告している場合に、該当する接続だけを閉じるようにしました。Dingo は有効なオファーを引き続き受け入れ、各接続で重複する送信オファーを抑制します。
