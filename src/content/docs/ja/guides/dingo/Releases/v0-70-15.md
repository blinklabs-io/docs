## v0.70.15

**タイトル:** ブートストラップ制御、ledgerの安全性、テストネット対応を強化

**日付:** 2026-09-19

**バージョン:** v0.70.15

**リリース:** [v0.70.15](https://github.com/blinklabs-io/dingo/releases/tag/v0.70.15)

このリリースでは、制御されたMithrilブートストラップ復旧を追加し、Primeテストネットの移植性を拡張し、ledger、database、connection、chain originの安全対策を強化しました。また、過去履歴の同期、検証効率、適合性テストの網羅性、ドキュメントの一貫性を改善しました。

### 推奨ネットワーク互換性 ⚠️

|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |
 
### ランタイムおよび運用面の改善
 
* 固定し、`Mithril.PinnedDigest`、`mithril.pinnedDigest`、`--mithril-pinned-digest`、`DINGO_MITHRIL_PINNED_DIGEST`によって新規ブートストラップのMithril artifactを厳密にピン留めしました。Dingoはv1およびv2 artifactを正確に取得し、再開時にピンを保持して検証し、catch-up中または中断されたimportに競合するピンがある場合はピンを拒否します。
 
* 改善し、treasuryとreserve transfer accounting（MIR）において、Alonzo以前のprotocol version 2〜4では、繰り返されるdistribution entryが以前の値を置き換えるようにしました。malformedまたはoverflowした境界について警告して破棄し、database documentationをaccountingの動作に合わせました。
 
* 強化し、過去履歴のMithril同期でmissingまたはinactiveのaccount rowとjournal withdrawalを受け入れるようにしました。live ingestionの検証は変更せず、accountの作成や再有効化も行いません。
 
* 拡張し、DRep depositの復旧で、記録値がない場合は現在のdepositを使用し、明示的に記録されたゼロは保持し、unsupportedまたはinvalidなstateを拒否し、nil valueによる失敗を回避するようにしました。

* 設定し、node-to-client（NtC）のconnection admission limitを、YAML、CLI、環境設定によってtotal connection数とIP addressごとに指定できるようにしました。cleanup pathではcleanupまたはcollisionの際にadmissionを正確に1回解放し、rejection metricを利用できるようにしました。

* 保護し、chain restartの検証でchain originにある最初のByron epoch boundary block（EBB）を設定済みのgenesis hashに固定し、epoch zeroと想定されるblock shapeを要求するようにしました。rollbackでoriginに戻った後にもこれらの検査を繰り返します。

* 修正し、hard-fork forecastのshapeを利用できない場合はDingoがfail closedし、依存する検証の前に待機し、cache-backed conversionを保持するようにしました。また、`ConsensusModeForEpoch`はunsupported resultではなくerrorを返すようにしました。

* 安定化し、Mithril state snapshot（`PState`）のimportでpending pool retirementをledger stateに取り込み、参照されるpoolとepochを検証し、synthetic retirement rowを書き込み、結果として生じるdatabase semanticsを文書化しました。
