## v0.92.2

**タイトル:** 性能、同期、プロトコルの信頼性を向上

**バージョン:** v0.92.2

**リリース:** [v0.92.2](https://github.com/blinklabs-io/dingo/releases/tag/v0.92.2)

**比較:** [v0.92.1...v0.92.2](https://github.com/blinklabs-io/dingo/compare/v0.92.1...v0.92.2)

Dingo v0.92.2では、データベースの効率、ロールバックからの復旧、プロトコル検証、台帳処理、Leiosコンテンツ配信、運用上の信頼性を改善しました。

### 推奨ネットワーク互換性 ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

#### データベースとストレージ
* 改善: `dingo_coin_sum`で実行スロットのトランザクション手数料を集計してSQLiteの手数料クエリを改善し、スロット範囲の包含、Leiosの選択、検証、オーバーフロー検出、トランザクションの可視性を維持しました。PostgreSQLとMySQLでは引き続き行をストリーミングします。
* 追加: `Config.LazyHotStatements`による頻繁なSQLステートメントの遅延準備をオプトインで有効にしました。テスト用SQLiteストアは書き込みプールを初めて使用するときに対象ステートメントを準備し、準備の失敗を記録してキャッシュなしの実行へフォールバックし、プランナー統計の更新後に遅延キャッシュを更新します。本番環境では遅延準備を無効のままにし、即時準備を既定値として維持します。

#### チェーン選択と復旧
* 更新: ロールバック後にPraosスケジュールを更新しました。ノードは現在の不変なエポックスケジュールを保持し、古い将来スケジュールを削除し、世代追跡で古い処理中の結果を拒否し、現在および次のnonce対応スケジュールを再計算します。
* 制限: 再起動後の消費済み入力の復旧を設定可能な範囲に制限し、既定値を1000ブロックにしました。IDのないレガシーチェックポイントでは完全な復旧を継続し、定期的なチェックポイント保存に失敗すると復旧を停止します。
* 限定: 受け入れるヘッダーのプロトコルバージョンを、erasサポートを有効にした最も高いメジャーバージョンまでに制限しました。TrustedReplayとMithrilの例外は維持し、ノードは拒否後に処理を巻き戻します。
* 保持: v55移行と凍結キー検証を通じて、インポートしたスナップショットの選出済みVRFキーを保持しました。保存されたキーのないレガシースナップショットは、削除されたブートストラップフォールバックを使わず安全側に失敗します。

#### 台帳とプロトコルの正確性
* 訂正: PV10以降のDRep登録解除で、前方委任状態から現在のターゲットを消去するようにしました。PV9は既存の動作を維持し、ノードは非アクティブなアカウントを変更しません。
* 一致: Mithril STM抽選の対数を `math.Log(1-phiF)` に合わせ、報告された浮動小数点の境界で落選するチケットを拒否しました。
* 更新: `gouroboros`依存関係をタグ付きバージョン `v0.218.2` に更新し、上流の検証および割り当ての変更をノードへ取り込みました。
* 適用: ノードが後続のクロージャを取得している間に、準備済みのLeios履歴プレフィックスを適用します。証明書を先に検証し、キャンセルを安全に処理し、信頼済み境界と不変境界を保持します。
* 省略: SQLiteロールバック中に変更のないガバナンス投票の復元を省略し、nullに安全なタプルおよびストレージクラス処理、非相関の孤立検出、決定的なLeios期限範囲を適用しました。
* 制約: `PRAGMA optimize(0x10012)`でSQLiteプランナーの増分分析を制約し、`analysis_limit`のサンプリングを維持しながら、無制限のスキャンを避け、プランナー統計を保持します。
