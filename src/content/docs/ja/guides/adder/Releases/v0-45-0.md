## v0.45.0

**タイトル:** ヘッドレス通知、トレイ更新、運用性の改善

**バージョン:** v0.45.0

**比較:** [v0.44.0...v0.45.0](https://github.com/blinklabs-io/adder/compare/v0.44.0...v0.45.0)

このリリースには、ヘッドレス通知連携、自動トレイ更新チェック、より明確な設定とフィルタリングの動作、標準化されたイベント名、拡充されたアーキテクチャとガバナンスのドキュメント、より安全な可観測性、信頼性の高いリリース配信が含まれます。

### ✨ ハイライト

* 追加 **ヘッドレス通知の出力と検証:** Adder は `notify-json` を通じて、バージョン付き NDJSON のステータスレコードと通知レコードを出力します。`adder notifications validate` コマンドは、厳密なバージョン付き通知設定と chainsync と設定の整合性を検証し、UI に依存しない通知ディスパッチはガバナンス投票の詳細をより具体的に示します。

* 改善 **トレイ更新の管理:** Adder は GitHub のリリースを毎週確認し、スキップしたバージョンと更新設定を記憶し、macOS と Windows のインストーラーのチェックサムを検証し、サポート対象外のプラットフォームではリリースページへのリンクを表示します。トレイには正しいアイコンと About の詳細も表示され、WebSocket のレスポンスを整理し、macOS サービスの有効化を改善します。

* 明確化 **設定の優先順位と永続保存:** 設定の優先順位は CLI の値、YAML の値、環境変数、デフォルト値の順です。明示的な CLI フラグが常に優先され、アトミックな保存が同時書き込み中も設定を保護します。

* 拡張 **フィルターとイベントのライフサイクル処理:** Adder は CLI から包括的なイベント種別フィルタリングを利用できるようにし、フィルターのライフサイクルをより安全に管理し、競合を想定したテストと、より安全な goroutine のセットアップを使用します。

* 精緻化 **Cardano イベントの照合:** 専用の照合ロジックが stake credential のない場合を安全に処理し、SPO の投票手続きを通じてプールを照合します。

* 有効化 **独立したチェーンロールバック通知:** `Chain rollbacks` 設定とウィザードのチェックボックスで、`Blocks minted` 通知とは別にロールバック通知を制御できるようになりました。

* 文書化 **アプリケーションアーキテクチャ:** 新しいアーキテクチャガイドでは、パイプラインとプラグインモデル、設定の優先順位、並行処理、シャットダウンの動作、adder-tray 連携について説明します。

* 導入 **複数ターゲットのトレイ監視:** Adder は Wallet、DRep、Pool、Asset、Policy ターゲットを、レート制限、バッチ処理、接続アラート、UI に依存しないディスパッチ、更新されたウィザード設定によって監視します。`engine.yaml` の `filter.cardano` 設定と従来の `Template` および `Param` の値は通知の照合に使用されなくなったため、照合ルールをトレイのターゲット設定へ移行する必要があります。

* 追加 **署名済み macOS パッケージのインストール:** Adder は CLI とトレイ向けに、署名および notarization 済みの `.pkg` インストーラーを生成します。ネイティブな `arm64` と `amd64` パッケージ、インストールスクリプト、Gatekeeper 検証、Makefile ターゲットも利用でき、ローカルビルドではオプションの ad-hoc 署名も引き続き利用できます。

* 拡充 **webhook と配信のテストカバレッジ:** テストは webhook の配信、シリアライズ、失敗、ライフサイクル、Discord のフォーマット、CLI ファクトリ、sink の動作をカバーします。

### ⚠️ イベント互換性

* 標準化 **公開イベント名:** DRep の登録、更新、退役イベントは `input.drep-registration`、`input.drep-update`、`input.drep-retirement` を使用します。以前の `chainsync.drep.*` 名に一致するフィルターを使用するコンシューマーは、フィルターを更新する必要があります。

* 拡張 **Telegram Bot API 10.2 互換性:** Telegram 連携に Bot API 10.2 のモデルとマーシャリングの修正が含まれます。

* 更新 **Telegram の再試行処理:** Telegram 連携は HTTP 429 応答の `retry_after` を尊重し、Bot API 10.3 のモデルを含みます。

* 強化 **Telegram のリッチメッセージアップロード:** ボットクライアントがリッチメッセージの添付ファイルとサムネイルのアップロードを処理し、typed nil 値と重複する `attach://` 名を早期に拒否し、JSON を正しくエスケープします。

* 改善 **Telegram の HTTP/2 回復性:** multipart リクエストを HTTP/2 `GOAWAY` 後の再試行用にバッファーし、空の multipart ボディを抑制し、未知の update バリアントを処理します。multipart のバッファーにより、アップロード中のメモリ使用量が増える場合があります。

### 💪 改善

* 強化 **運用上の可観測性:** 構造化フィールドとコンポーネント単位のロガーが、起動、chainsync、push、Telegram、webhook の出力を解釈しやすくします。Adder は機密性の高い FCM トークンを秘匿し、webhook の URL とペイロードをサニタイズします。

* 更新 **システム互換性ライブラリ:** Adder は `golang.org/x/sys` v0.46.0 を使用します。

* 改良 **lint の自動化:** `golangci-lint` アクションは v9.3.0 を使用するようになりました。

* 安定化 **タグ付きリリースの配信:** macOS ランナーを固定し、一部のジョブが失敗しても他のジョブを継続するマトリックスビルドを採用し、macOS のパッケージングと署名を分離し、部分的なビルド失敗後に最終処理を実行することで、タグ付きリリースの信頼性を高めます。

* 保護 **コンテナの公開:** Docker Hub と GitHub Container Registry への公開で、Docker ログインアクションは v4.5.1 を使用します。

* 整備 **コントリビューター向けドキュメントの指針:** `AGENTS.md` で、意味のあるインラインコメントと、エクスポートされた識別子に対する正確なドキュメントコメントの書き方を説明します。

* 整合 **Cardano 相互運用性:** Adder はデコードと相互運用性の修正を含む `github.com/blinklabs-io/gouroboros` v0.187.3 を使用するようになりました。

* 強化 **リリース成果物の証明:** 証明アクションは、リリース成果物とコンテナの証明に v4.2.1 を使用するようになりました。

* 更新 **プロトコルシリアライズのサポート:** Adder は `google.golang.org/protobuf` v1.36.12 を使用するようになりました。

### 🧪 テスト、CI、ドキュメント、リリースツール

* 最新化 **Java ワークフローのセットアップ:** Java ワークフローのアクションは `actions/setup-java` v5.3.0 を使用するようになりました。

* 更新 **テストと YAML ライブラリ:** Adder は testify v1.12.1 と間接依存の yaml.v3 v3.0.5 を使用するようになりました。

* 整理 **プラグインオプションの解析:** カンマ区切りのプラグインオプションでは前後の空白を無視するようになり、Cardano、イベント、chainsync のパーサーは YAML 形式のリストとインターセクトポイントをより一貫して処理し、Go ディレクティブはバージョン `1.26.0` を対象にします。

* 拡充 **ガバナンスのドキュメント:** `docs/governance.md` でガバナンスイベントを説明し、README のスキーマと例を実行時に出力される構造に合わせました。

* 改善 **Go ワークフローのセットアップ:** Go ワークフローは `actions/setup-go` v7.0.0 を使用するようになりました。

* 精緻化 **テスト依存関係の整理:** Adder は testify v1.12.0 を使用し、不要になったテスト依存関係を削除します。

* 強化 **成果物の証明ワークフロー:** リリースワークフローは `actions/attest` v4.2.2 を使用するようになりました。

* 更新 **リポジトリチェックアウトのワークフロー:** CI とリリースのワークフローは `actions/checkout` v7.0.0 を使用するようになりました。
