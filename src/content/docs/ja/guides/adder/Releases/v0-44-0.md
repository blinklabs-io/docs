## v0.44.0

**タイトル:** ヘッドレス通知、安全なログ、Cardano イベント処理の改善

**バージョン:** v0.44.0

JSON によるヘッドレス通知、明確で安全な運用ログ、Cardano イベントのマッチング拡張、予測可能な設定処理、堅牢なリリースワークフローを追加します。

### ✨ 主な変更点

- **構造化ログ:** アプリとプラグインでコンポーネント別のキー・値ログを出力します。Webhook URL を無害化し、FCM トークンを切り詰めるか秘匿し、本文の代わりにペイロード・応答サイズを記録します。

- **ヘッドレス JSON 通知:** `notify-json` からバージョン付き NDJSON の状態・通知レコードを取得できます。`adder notifications validate --config <path> [--json]` で設定を検証します。起動時に chainsync のネットワークとカスタムアドレスを検証し、`schemaVersion: 1` を必須にします。通知送信は UI に依存しません。

- **設定の優先順位と保存:** CLI が YAML より、YAML が環境変数より優先されます。アトミック保存で既存の設定ファイルを保護します。

- **Cardano マッチング:** matcher の型を分離し、プール SPO の投票手続きに対応します。stake 認証情報の欠落も安全に処理します。

- **独立したロールバック通知:** `Chain rollbacks` 設定で、他の通知カテゴリとは別に制御できます。

- **複数対象:** 対象リスト、レート制限、バッチ処理で複数対象へ通知します。旧フィルターも移行します。

- **macOS パッケージ:** 署名・公証済みパッケージに CLI、トレイアプリ、インストールスクリプト、`/usr/local/bin/adder` リンクを含めます。ローカルビルドは未署名または ad hoc 署名を選べます。

- **API サービス:** HTTP サービスに統合し、`/events` の Server-Sent Events と WebSocket の動作を維持します。API 文書のパスとベースパスも更新します。

- **トレイエディター:** 通知ルールと設定チェックボックスを編集できます。再起動せずに保存・即時適用し、回復可能なエラーを分かりやすく表示します。

- **通知配信:** 認証情報とプロジェクト ID を検証し、Firebase Cloud Messaging のエラーを表示します。10 秒のタイムアウトを適用し、通知・push 処理を正常終了します。

- **マルチプラットフォームイメージ:** 共通イメージマニフェストを公開し、各対応プラットフォームに適切なイメージを提供します。

### ⚠️ イベントの互換性

- **DRep 名:** 登録・更新・退任の公開イベント定数は、従来の `chainsync.drep.*` から `input.drep-registration`、`input.drep-update`、`input.drep-retirement` に変わります。利用側は新しい値へ更新してください。

### 💪 改善

- 接続、設定、フィルター、push/FCM、Webhook の診断を扱うトラブルシューティングガイドを追加します。

- イベントフィルターの検証を拡充し、プロセスを正常終了するための終了経路を見直します。

- Cardano・イベント・chainsync プラグインのカンマ区切りオプションは、各値の前後の空白を無視します。Go ディレクティブを `1.26.0` に更新します。

- ガバナンスイベントのスキーマとフィルターを文書化し、README のサンプルも同じ説明にそろえます。

- macOS runner を `macos-15` に固定し、独立したマトリクスジョブの完了を待ち、パッケージ作成と署名を分離します。一部ビルドが失敗してもドラフトリリースを確定します。

- FreeBSD パッケージからトレイアプリを除外します。

- `golang.org/x/sys` v0.47.0 を使用します。

- `golangci-lint` アクションを v9.3.0 に更新します。

- Docker ログインアクションを v4.6.0 に更新します。

- `gouroboros` v0.197.0 を使用します。

- リリースワークフローで `actions/attest` v4.2.2 を使用します。

- 不正なイベントでも Webhook がパニックせず、終了と再試行を連携して競合を防ぎます。

- カスタム logger のコンテキストを出力レコードへ一貫して伝播します。

- `GetAccountState`、運用証明書、Dijkstra redeemer に対応し、Dijkstra era と Leios の連携を更新します。検証を有効にしたパイプラインは、検証に合格しなかったブロックをエラーとして報告し、処理をスキップします。

- デコード・検証を厳格化し、Conway より前の MultiAsset 重複キーと Conway witness のタグ付き集合の重複を安全に扱います。不明な入力を明示的に報告し、KES・ledger の修正を取り込みます。

- トランザクションの有効期間の上下限を保持し、Byron 委任証明書の署名を検証します。

- Plutus のデコード・評価を強化し、性能を改善します。

- `golang.org/x/image` v0.45.0 と強化した画像デコーダーを使用します。

### 🧪 テスト、CI、ドキュメント、リリースツール

- プロトコルのシリアライズに protobuf v1.36.12 を使用します。

- Windows 署名・Java ワークフローで `actions/setup-java` v5.7.0 を使用します。

- testify v1.12.1 と yaml.v3 v3.0.5 を使用します。

- Go ワークフローで `actions/setup-go` v7.0.0 を使用します。

- テスト実行用に testify v1.12.0 を取り込みます。

- 成果物証明に `actions/attest` v4.2.2 を使用します。

- checkout ワークフローで `actions/checkout` v7.0.1 を使用します。

- Windows 署名を Java 17 から Java 21 に変更します。

- Telegram に `go-telegram/bot` v1.23.0 を使用します。

- Docker メタデータ生成に `docker/metadata-action` v6.2.0 を使用します。

- コンテナービルドに `docker/setup-buildx-action` v4.3.0 を使用します。

- Windows 成果物テストに `actions/upload-artifact` v7.0.1 を使用します。セルフホスト runner には Actions Runner v2.327.1 以降が必要です。

- プロトコルテストに `ouroboros-mock` v0.16.0 を使用します。

- ライブラリ入門キットに 3 つの実行可能サンプルを追加し、README から直接リンクします。

- CLI・トレイ用の署名済み MSI を提供し、スタートメニューとプログラムの追加と削除に統合します。ローカルビルドでは署名を省略でき、リリース自動化がインストーラーを公開します。
