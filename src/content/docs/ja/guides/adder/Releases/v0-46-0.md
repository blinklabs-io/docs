## v0.46.0

**タイトル:** ヘッドレス通知、より安全な設定、改善されたトレイ操作

**バージョン:** v0.46.0

**比較:** [v0.45.0...v0.46.0](https://github.com/blinklabs-io/adder/compare/v0.45.0...v0.46.0)

このリリースでは、ヘッドレス通知ワークフロー、設定の信頼性、イベント互換性、Cardano フィルタリング、トレイ更新、運用ログ、ガバナンスデータ処理を改善します。

### ✨ ハイライト

* 追加 **ヘッドレス通知の出力と検証:** Adder は `notify-json` を通じて、バージョン付き NDJSON のステータスレコードと通知レコードを出力できます。`adder notifications validate --config <path> [--json]` コマンドは通知設定をチェックし、起動時チェックは `--output notify-json` に対応する設定であることを確認します。古い通知の処理と UI に依存しないディスパッチにより、ヘッドレスコンシューマーは特定のインターフェースから独立して動作します。

* 明確化 **設定の優先順位と保存:** コマンドラインの値が YAML の値より優先され、YAML の値が環境変数より優先され、デフォルト値が最後に適用されます。Adder はアトミックな設定保存を直列化し、並行更新時により安全に同期します。

* 導入 **トレイ更新チェック:** トレイは毎週リリースを確認し、セマンティックバージョンの更新を検出し、適切なプラットフォームインストーラーを選択し、ダウンロードのチェックサムを検証し、スキップしたバージョンを記憶します。インストーラーがない場合はリリースページを開きます。トレイアイコンは正しく拡大縮小され、Adder はレスポンスのリソースをクリーンアップし、macOS サービスの有効化は一貫して動作します。

* 分離 **チェーンロールバック通知:** `Chain rollbacks` 設定とウィザードのコントロールで、`Blocks minted` 通知とは独立してロールバック通知を管理できるようになりました。

* 文書化 **アプリケーションアーキテクチャ:** アーキテクチャガイダンスで、処理パイプライン、プラグインモデル、設定の優先順位、並行処理、シャットダウン動作、トレイと API の連携について説明します。

* 改善 **Cardano プールフィルタリング:** プールフィルターが SPO の投票手続きに一致するようになり、stake credential がない場合に一致したり安全でないアクセスを発生させたりしなくなりました。

* 拡張 **運用ログ:** 構造化フィールドとコンポーネント単位のロガーにより、起動、チェーン同期、push、Telegram、webhook の出力を解釈しやすくなりました。Adder はログ内の機密性の高い FCM トークンと webhook の URL およびペイロードを秘匿します。

* 整理 **プラグインオプションの解析:** Cardano フィルター、イベントタイプ、ChainSync の交差点に指定するカンマ区切り値で、前後の空白と空の項目を無視するようになりました。これにより YAML のブロック形式リストでも設定値が正しく一致し、空の交差点値は `--input-chainsync-intersect-tip` で設定された動作に従います。

* 追加 **複数ターゲットのトレイ監視:** セットアップウィザードで複数のウォレット、DRep、プール、アセット、ポリシーを監視でき、デスクトップ通知はレート制限と集約に対応します。Adder は既存のトレイフィルターを構造化された新しい設定へ移行し、接続アラートをすぐに通知します。

* 提供 **署名済み macOS インストーラー:** リリースパッケージは Adder のトレイアプリと CLI を `/Applications` にまとめてインストールし、リリース用の認証情報がある場合は Gatekeeper に対応する署名済み・公証済みアーティファクトを提供します。インストーラーは、可能な場合に無関係なコマンドを置き換えず `/usr/local/bin/adder` も作成します。

* 調整 **Telegram 配信の再試行:** Telegram のロングポーリングがレート制限を受けた場合、Telegram が示す `retry_after` の時間を待ってから再試行するため、早すぎる再試行を減らします。

* 強化 **API サーバーの信頼性:** Adder は Gin の代わりに Go `net/http` を使用し、ミドルウェアを通じた SSE と WebSocket のストリーミングを維持します。構造化されたアクセスログを記録し、panic から復旧し、サーバーのタイムアウトを適用します。

* 明確化 **API ドキュメントのパス:** API クライアントは `/ping`、`/healthcheck`、`/events` にルートからアクセスでき、`/v1/fcm` と `/v1/qrcode` は `/v1` 配下に残ります。Swagger は `/swagger/` で利用できます。

* 検証 **FCM トークン入力:** API リクエストは処理前に `fcmToken` を検証します。

* 強化 **Telegram multipart アップロード:** Telegram 出力は HTTP/2 GOAWAY 応答を再試行でき、フィールドのない呼び出しでは空の multipart ボディを抑制し、リクエストフィールドをより正確に数えます。バッファリングされたアップロードでは、より多くのメモリを使用する場合があります。

* 導入 **管理対象プラグインのライフサイクル:** カスタム Go プラグインの作成者は `plugin.ManagedPlugin` ライフサイクル契約と共有実装 `plugin.Base` に移行する必要があります。従来のライフサイクル配線は機能しなくなります。

* 安定化 **パイプラインの処理順序:** Adder はプラグイン間の接続を検証し、コンシューマーをプロデューサーより先に起動し、設定されたフィルター順序を維持して、コンポーネントを逆順に停止します。

* 伝播 **プラグインの致命的な失敗:** 致命的な失敗が発生すると、パイプラインがすぐに停止し、パイプラインの状態から失敗したコンポーネントとエラーを確認できます。

* 停止 **キャンセル中の ChainSync 再接続:** パイプラインの停止時に、ChainSync は接続ハンドシェイクと再接続の試行を終了します。

* 終了 **シャットダウン中の UTxORPC 再接続:** パイプラインの停止時に、UTxORPC は再試行間の待機を終了します。

* 中断 **キャンセル中の Push 配信:** パイプラインの停止時に、Push 通知のトークン取得と FCM 送信を停止します。

* 防止 **キャンセル後の webhook 再試行:** パイプラインの停止時に webhook 配信の再試行を終了し、キャンセルを配信エラーとして報告しません。

* 一致 **選択したネットワークに対する ChainSync のエポック:** ChainSync の状態が、設定されたネットワークの era 境界からエポック番号を計算するようになりました。

* 拒否 **失敗した WebSocket アップグレード:** クライアントが WebSocket アップグレードを要求した場合、イベントストリーミングは SSE に暗黙に切り替えず、WebSocket エラーを返します。

* 削除 **従来のログ設定:** Adder は `--logging-level` と関連するトップレベルのログ設定を受け付けません。Adder は選択した出力のログを `output.log.level` または `--output-log-level` で制御します。

* 表示 **About のバージョンメタデータ:** トレイの About ダイアログに、実行中のバージョンとコミットのメタデータを Adder 内で表示します。

* 設定 **macOS のログイン時起動:** ウィザードのステップ4で、ログイン時または再起動時の自動起動を有効化または無効化し、サービス状態を確認して、ログイン項目の設定を開けるようになりました。

* 改善 **macOS の launchctl 管理:** トレイの起動エージェントとログイン項目を同期し、登録、起動、削除の状態をより確実に報告します。

* 追加 **macOS アンインストーラー:** アンインストーラーがトレイアプリと自動起動の設定を削除します。オプションの `--purge` または `--all` モードでは設定とログのデータも削除します。

* 導入 **アプリ内通知ルールエディター:** トレイメニューから、Wallet、DRep、Pool、Asset、Policy のターゲット、通知カテゴリー、`Monitor Everything` を編集できます。保存したルールは保持され、トレイを再起動せずにすぐ反映されます。大文字と小文字を区別しない重複ターゲットを拒否し、再接続の警告が発生してもエディターを開いたまま再試行できます。

* 提供 **署名済み Windows インストーラー:** `x64` と `arm64` 向けの MSI パッケージは CLI とトレイをまとめてインストールし、Start Menu と `Add/Remove Programs` に統合され、`Scheduled Task` を登録しません。

### ⚠️ イベント互換性

* 標準化 **DRep イベント名:** DRep の登録、更新、退役イベントが `input.drep-registration`、`input.drep-update`、`input.drep-retirement` を使用するようになりました。以前の名前を使用するイベントコンシューマーはフィルターを更新する必要があります。

* 更新 **生成 API 連携:** 生成された OpenAPI モジュールを `github.com/blinklabs-io/adder/openapi` からインポートできるようになりました。

* 強化 **webhook イベント処理:** 形式不正または未知のイベントが webhook 出力で panic を引き起こさなくなりました。Adder はエラーをプラグインエラーチャネルに渡し、終了と再試行を安全に調整します。

### 💪 改善

* 保持 **ガバナンスのデポジット値:** ガバナンス証明書のデポジットが、符号付き64ビット整数に制限されず、符号なし64ビット値の全範囲を保持するようになりました。

* 防止 **トレイプロセスの蓄積:** トレイから起動したフォルダー、URL、インストーラーが非同期で完了するようになり、子プロセスが残り続けることを防ぎます。

### 📚 ドキュメント

* 公開 **ライブラリ例:** 公開ドキュメントサイトで、製品ガイダンスとともに Adder ライブラリの例を参照できるようになりました。

* 整備 **ガバナンスイベントリファレンス:** `input.governance` のフィールド、サポートされるアクションタイプ、ネストされた構造、フィルタリング例をドキュメントで説明し、スキーマ例を出力されるイベントデータに合わせました。

* 実現 **Dingo パイプライン検証:** Docker と macOS のワークフローは、Cardano のプレビューネットワーク上で共有接続を使って Adder と Dingo を接続し、Adder がチェーンの最新位置から再開することを検証します。ローカル実行ではコンテナログの増加も制限します。

* 整備 **トラブルシューティングガイド:** ドキュメントで接続、設定、フィルター、FCM、webhook の診断、一般的なエラーメッセージ、Go 1.26 の `GOEXPERIMENT=goroutineleakprofile` を使用した goroutine リークのプロファイリングを説明します。
