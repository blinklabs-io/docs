## v0.46.0

**タイトル:** ヘッドレス通知、より安全な設定、改善されたトレイ操作

**バージョン:** v0.46.0

**比較:** [v0.45.0...v0.46.0](https://github.com/blinklabs-io/adder/compare/v0.45.0...v0.46.0)

このリリースでは、ヘッドレス通知ワークフロー、設定の信頼性、イベント互換性、Cardano フィルタリング、トレイ更新、運用ログ、ガバナンスデータ処理を改善します。

### ✨ ハイライト

* 追加 **ヘッドレス通知の出力と検証:** Adder は `notify-json` を通じて、バージョン付き NDJSON のステータスレコードと通知レコードを出力できます。`adder notifications validate --config <path> [--json]` コマンドは通知設定をチェックし、起動時チェックは `--output notify-json` に互換性のある設定を確認します。古い通知の処理と UI に依存しないディスパッチにより、ヘッドレスコンシューマーは特定のインターフェースから独立して動作します。

* 明確化 **設定の優先順位と保存:** コマンドラインの値が YAML の値より優先され、YAML の値が環境変数より優先され、デフォルト値が最後に適用されます。Adder はアトミックな設定保存を直列化し、並行更新時により安全に同期します。

* 導入 **トレイ更新チェック:** トレイは毎週リリースを確認し、セマンティックバージョンの更新を検出し、適切なプラットフォームインストーラーを選択し、ダウンロードのチェックサムを検証し、スキップしたバージョンを記憶します。インストーラーがない場合はリリースページを開きます。トレイアイコンは正しく拡大縮小され、Adder はレスポンスのリソースをクリーンアップし、macOS サービスの有効化は一貫して動作します。

* 分離 **チェーンロールバック通知:** `Chain rollbacks` 設定とウィザードのコントロールで、`Blocks minted` 通知とは独立してロールバック通知を管理できるようになりました。

* 文書化 **アプリケーションアーキテクチャ:** アーキテクチャガイダンスで、処理パイプライン、プラグインモデル、設定の優先順位、並行処理、シャットダウン動作、トレイと API の連携について説明します。

* 改善 **Cardano プールフィルタリング:** プールフィルターが SPO の投票手続きに一致するようになり、stake credential がない場合に一致したり安全でないアクセスを発生させたりしなくなりました。

* 拡張 **運用ログ:** 構造化フィールドとコンポーネント単位のロガーにより、起動、チェーン同期、push、Telegram、webhook の出力を解釈しやすくなりました。Adder はログ内の機密性の高い FCM トークンと webhook の URL およびペイロードを削減します。

### ⚠️ イベント互換性

* 標準化 **DRep イベント名:** DRep の登録、更新、退役イベントが `input.drep-registration`、`input.drep-update`、`input.drep-retirement` を使用するようになりました。以前の名前を使用するイベントコンシューマーはフィルターを更新する必要があります。

* 更新 **生成 API 連携:** 連携から生成された OpenAPI モジュールを `github.com/blinklabs-io/adder/openapi` からインポートできるようになりました。

### 💪 改善

* 保持 **ガバナンスのデポジット値:** ガバナンス証明書のデポジットが、符号付き64ビット整数に制限されず、符号なし64ビット値の全範囲を保持するようになりました。

* 防止 **トレイプロセスの蓄積:** トレイから起動したフォルダー、URL、インストーラーが非同期で完了するようになり、子プロセスが残り続けることを防ぎます。

### 📚 ドキュメント

* 公開 **ライブラリ例:** 公開ドキュメントサイトで、製品ガイダンスとともに Adder ライブラリの例を参照できるようになりました。
