## v0.47.0

**タイトル:** イベント配信の拡張、堅牢な運用、Cardano サポート

**バージョン:** v0.47.0

**比較:** [v0.46.0...v0.47.0](https://github.com/blinklabs-io/adder/compare/v0.46.0...v0.47.0)

このリリースでは、イベント配信と Cardano ネットワークのサポートを拡張し、可観測性、設定の安全性、通知制御、webhook の耐久性、デスクトップの信頼性を改善します。

### ✨ ハイライト

* **運用状況を可視化:** 構造化ログフィールド、コンポーネント単位のロガー、メトリクス、一貫したログシステムにより、起動、同期、配信、webhook の動作を把握しやすくなりました。Adder はログに書き込む前に FCM トークンを短縮し、webhook URL をサニタイズします。

* **ガバナンスデポジットを完全保持:** DRep と投票委任のデポジットは、符号付き整数へ縮小されず、符号なし64ビット値を保持します。更新されたデポジットスキーマをガバナンスイベントで使用するため、連携先は完全な値の範囲を処理できます。

* **ヘッドレス通知を追加:** `notify-json` 出力と通知検証コマンドにより、トレイを使わずに自動化できます。バージョン付き通知設定は厳格な検証を行い、UI に依存しないトレイ通知と投票メッセージ内のガバナンスアクション ID により、通知連携の予測可能性が向上します。

* **トレイプロセスの蓄積を防止:** トレイから起動したプログラムが正常終了するため、フォルダー、URL、インストーラーの操作を繰り返しても子プロセスが残りません。

### 💪 改善

* **デスクトップ通知を更新:** 通知ライブラリが beeep 0.11.3 を使用し、現在のデスクトップ連携の動作に対応します。

* **システム互換性を更新:** システムインターフェースの依存関係が x/sys 0.46.0 を使用し、現在のオペレーティングシステムの動作への対応を改善します。

* **ライブラリ例をホスト型ドキュメントへ移行:** Adder の例がドキュメントサイトに掲載され、ライブラリ利用者がガイダンスを一元管理された場所で確認できるようになりました。

* **Signal 配信を導入:** Signal 出力が signal-cli JSON-RPC と厳格なエンドポイントおよび受信者の検証を使用し、受信者ごとに成功を確認してリダイレクトを拒否します。新しい `docs/signal.md` ガイドで設定を説明します。

* **モックチェーンのサポートを更新:** ouroboros-mock 依存関係がバージョン 0.20.4 を使用し、ローカルおよび自動化されたチェーンテストに対応します。

* **リンティングの自動化を効率化:** Go の lint ワークフローが golangci-lint-action 9.3.0 を使用し、開発パイプラインで現在のチェックを実行します。

* **macOS 公開を強化:** ビルドが macos-15 ランナーを使用し、失敗後も独立したビルドを継続し、パッケージ化と署名を分離して、部分的なビルド失敗後にリリースを完了します。

* **コンテナ公開を保護:** Docker レジストリ認証が docker/login-action 4.5.1 を使用します。

* **Cardano ネットワーク互換性を拡大:** 現在の Cardano プロトコルライブラリが DijkstraNet をサポートし、最新の gouroboros 0.219.0 と plutigo 0.12.1 の動作を Adder に取り込みます。

* **コントリビューター向けガイダンスを文書化:** `AGENTS.md` がコメントの書き方を説明し、プロジェクトのガイダンスを一貫して保てるようになりました。

* **イベントフィルタリングとシャットダウンを検証:** 包括的なイベントフィルターのカバレッジと改善されたシャットダウン処理により、フィルタリング動作を検証しやすくなり、パイプラインをより確実に終了できます。

* **設定の優先順位と保存を明確化:** CLI 設定が YAML 設定より優先され、YAML 設定が環境変数より優先されます。並行する `SaveAtomic` 操作は設定変更を永続的に保持します。

* **チェーンのデコードと進行状況の追跡を修正:** gouroboros 0.187.3 の更新により Dijkstra と Leios のデコードが修正され、ChainSync カーソルの永続化により、再起動したプロセスが保存済みの位置から再開できます。

* **Cardano のマッチングをリファクタリング:** Matcher の変更により、stake credential がない場合を安全に処理し、SPO の投票手続きを正しいプールに一致させます。

* **webhook 配信を強化:** 上限付きで再起動後も安全に復旧できる SQLite 配信が `state-path` と `max-pending` をサポートし、安定した配信 ID による少なくとも1回の配信、状態ファイルの厳格な検証、webhook の健全性とキュー上限を提供します。`docs/webhook-durability.md` ガイドで耐久性のある配信モデルを説明します。

* **Adder のアーキテクチャを文書化:** パイプラインとプラグインのトポロジー、ライフサイクル、コアとプラグインの設定優先順位、並行処理、シャットダウン、adder-tray/API 連携について専用のガイダンスを追加しました。

* **トレイの自動更新チェックを追加:** トレイが GitHub のリリースを毎週確認し、スキップしたバージョンを記憶します。macOS と Windows では `.pkg` と `.msi` のダウンロードをチェックサムで検証し、Linux と FreeBSD ではパッケージがない場合にリリースページを開きます。関連する信頼性の修正により、トレイの動作も改善します。

* **DRep イベント名を変更:** DRep の登録、更新、退任イベントが `input.drep-registration`、`input.drep-update`、`input.drep-retirement` を使用するようになり、エクスポートされたイベント型定数によって連携先が安定した識別子を利用できます。

* **Telegram 制御を有効化:** 認証されたオペレーターがチャットで `/status`、`/settings`、`/notify` を使用できます。`settings-file` は設定を永続化し、パイプラインの状態を報告します。

* **カンマ区切りの入力を整理:** フィルターと ChainSync の交差点が前後の空白と空の項目を無視するようになり、Adder は Go 1.26 でビルドされます。

* **確認応答付き Kafka イベントを配信:** Kafka 出力が `acks=all`、固定された `adder.events` キー、イベントごとの同期配信、TLS と認証情報の検証、シャットダウン時のキャンセルを使用します。

* **ClickHouse 分析イベントをバッチ処理:** 出力が JSONEachRow として `adder_events_v1` 行を書き込み、100 イベントまたは 1 秒でフラッシュし、タイムスタンプを検証します。自動再試行は行いません。

* **Prometheus メトリクスを公開:** Adder が `/metrics` エンドポイントを提供し、運用監視用のパイプラインカウンターと処理ヒストグラムを公開します。

* **RabbitMQ 配信を確認:** RabbitMQ 出力が公開メッセージを確認し、成功した配信が意図したルートに到達するよう、必須のルーティングを要求します。

* **構造化されたトレイ監視を導入:** トレイが複数の通知先をサポートし、その構造化された定義を保存します。既存の `filter.cardano` 設定は機能しなくなるため、アップグレード前に新しい監視対象設定へ移行してください。

* **macOS パッケージを強化:** Adder が `.pkg` インストーラーに署名して公証を行い、配布前に Gatekeeper で検証します。

* **PostgreSQL イベント履歴を追加:** PostgreSQL 出力でイベント履歴を記録できるようになり、出力済みイベントを永続的に確認できます。

* **Discord 配信を拡張:** Discord 出力が `bot token`、`application`、`guild`、`channel`、`event types` を受け付け、`Gateway v10` 経由でイベントを送信します。`/adder-status` と `/adder-recent` の応答を `ephemeral` に保ち、設定した `guild` 以外からの操作を無視します。設定した `guild` 内でも `channel` を限定し、他の channel には制限メッセージを返します。Adder は `rate limit`、再接続、シャットダウンを処理し、直近5件のイベントをメモリに保持します。

* **Slack 配信を洗練:** Slack 出力が `HTTPS` webhook URL を検証し、選択した `event types` を `JSON` または `text` として送信し、メッセージサイズ制限を適用します。失敗した配信を上限付きで再試行し、エラーを設定済みのエラーチャネルへ報告します。

* **Matrix 配信を拡張:** Matrix 出力が設定済みの `homeserver`、`access token`、`room IDs` を使用して、選択した `event types` を Matrix API 経由で送信します。room を検証し、サイズ制限を適用して、失敗した配信を上限付きで再試行します。

* **プラグインのライフサイクルとログ設定を明確化:** カスタムプラグインは `plugin.Base` と `ManagedPlugin` へ移行し、パイプラインを決定的に開始、停止、連結します。終端エラーを一貫して伝播し、キャンセル時には再接続と通知の処理を停止します。ネットワークに応じた epoch 計算もイベント処理を改善します。移行時は `logging.level` などのトップレベル設定を `output.log.level` または `--output-log-level` に置き換えてください。

* **上限付き webhook 診断を強化:** webhook 配信は通信エラーと HTTP 408、429、5xx の応答だけを再試行し、上限付きの指数バックオフと `Retry-After` 待機時間を使用します。Prometheus メトリクス `adder_webhook_http_attempts_total{status_class}`、`adder_webhook_delivery_outcomes_total{outcome}`、`adder_webhook_http_attempt_duration_seconds` が、ステータスクラス別の HTTP 試行、配信結果、各試行の所要時間を記録します。`/healthcheck` はサニタイズ済みの `checks[]` に稼働時間、終端エラーの有無、コンポーネントの役割・インデックス・状態を示し、機密設定やエラー文字列を公開せず、200/503 のプローブ動作を維持します。

* **トレイの更新案内を明確化:** プラットフォームとアーキテクチャに一致するインストーラーがない場合、更新ダイアログが macOS と Windows に適した次の手順を示し、**リリースページを開く**アクションを維持します。Linux と FreeBSD では従来の一般的な案内を表示します。

* **トレイの自動起動設定を有効化:** セットアップウィザードでログイン時または再起動時の自動起動を設定できます。macOS の launch agent と Login Items を同期し、サービス登録で発生する一時的な起動競合を再試行します。About ダイアログにはバージョンと commit メタデータを表示し、アンインストーラーでは任意の完全削除を選択できます。

* **アプリ内通知ルール編集を導入:** トレイでウォレット、DRep、プール、アセット、ポリシーのルールを作成・管理し、通知カテゴリを選択できます。変更を永続化して即時に反映し、削除を確認できるほか、致命的でないエラーから復旧できます。

### 🔧 追加の変更

* **リリースの証明を維持:** 証明ワークフローが actions/attest 4.2.1 を使用し、現在のアーティファクト検証に対応します。

* **RPC 連携を有効化:** connectrpc 依存関係がバージョン 1.21.0 を使用し、現在のリモートプロシージャコールの動作に対応します。

* **Chain rollback の設定を分離:** `Chain rollbacks` 通知設定が独立して動作し、他のチェーン通知を変更せずに有効化または無効化できるようになりました。

* **トレイ表示を最新化:** Fyne 依存関係がバージョン 2.8.2 を使用し、デスクトップインターフェースに対応します。

* **プロトコルサポートを整合:** gouroboros 依存関係がバージョン 0.216.2 を使用し、Adder を現在の Cardano プロトコル動作に合わせます。

* **イベント配信の選択肢を拡張:** Core NATS が設定を厳格に検証し、成功を報告する前に各イベントをフラッシュして、最大1回の配信を行います。その他の出力には Telegram、Slack、Discord、Matrix、RabbitMQ、MQTT、Google Pub/Sub、Postgres、ClickHouse、Elasticsearch、S3、AWS、Redis、Kafka があり、管理対象の顧客ルーティングと実行時の再読み込みに対応します。

* **protobuf のサポートを更新:** Adder が protobuf 1.36.12 を使用します。

* **生成された OpenAPI パッケージを公開:** 生成コードとインポートが `github.com/blinklabs-io/adder/openapi` を使用するようになりました。利用者は以前のモジュールパスへの参照を更新する必要があります。

* **テスト依存関係の互換性を改善:** 間接的な YAML 依存関係が testify とともに更新されます。

* **Java ビルド設定を更新:** リリースワークフローが更新された setup-java アクションを使用します。

* **Go ワークフローの互換性を拡張:** リリースワークフローが更新された setup-go アクションを使用します。

* **kugo 連携を調整:** Adder が更新された kugo 依存関係を使用します。

* **テストアサーションを標準化:** 別の testify 更新により、アサーションツールが現在のテストスイートと整合します。

* **RPC サポートを整合:** connectrpc 依存関係がバージョン 1.21.1 を使用します。

* **Plutigo の暗号化を更新:** Plutigo がバージョン 0.7.1 と更新された x/crypto 依存関係を使用します。

* **アーティファクト証明を更新:** 証明ワークフローが actions/attest 4.2.2 を使用します。

* **Plutigo のサポートを更新:** Plutigo 依存関係がバージョン 0.11.5 を使用します。

* **checkout ワークフローのサポートを拡張:** checkout アクションが更新されたバージョンを使用します。

* **Windows 署名を調整:** Windows リリースの署名が Java 21 を使用します。

* **Telegram ボット連携を改善:** 更新された go-telegram/bot により、ボット連携が改善します。

* **Telegram ボット依存関係を調整:** 追加の go-telegram/bot 更新により、Telegram の依存関係解決が最新になります。

* **リリースメタデータを最新化:** metadata-action ワークフローが更新されたバージョンを使用します。

* **Cardano ライブラリのバージョンを記録:** gouroboros 0.193.0 と plutigo 0.3.0 がサポート対象のプロトコルスタックに整合します。

* **Go モジュールツールを更新:** x/mod 0.42.0 と x/tools 0.51.0 により、依存関係と開発ツールを最新に保ちます。

* **暗号化ライブラリを強化:** Plutigo 0.6.1 と更新された x/crypto ライブラリにより、暗号化の互換性を改善します。

* **ベンチマークとプロファイリングのガイダンスを文書化:** パフォーマンス調査に専用のガイダンスを追加し、サポート対象外の HTTP pprof トラブルシューティング手順をリリースから除外します。

* **Dingo 検証アセットを有効化:** Preview と N2C の検証アセットが macOS のソケットワークフローをサポートします。

* **Telegram ボットのバージョンを固定:** Adder が現在のボット連携の動作に対応するため、go-telegram/bot 1.24.0 を使用します。

* **システム互換性を更新:** x/sys 依存関係がバージョン 0.49.0 を使用し、現在のオペレーティングシステムの動作に対応します。

* **NATS 連携を更新:** nats.go 1.55.0 により、NATS イベント配信を最新に保ちます。

* **webhook 検証を拡張:** 追加のテストで webhook 配信の動作を検証します。

* **コンテナビルドを改善:** buildx ワークフローアクションが現在のコンテナビルド操作をサポートします。

* **アーティファクトのランナー要件を明確化:** `upload-artifact` ワークフローが互換性のあるランナーを要求するようになりました。

* **API の動作を検証:** API テストのカバレッジを拡張し、サービス全体のエンドポイント動作を検証しやすくします。

* **btcec 互換性を更新:** Plutigo 0.10.1 が更新された btcec ライブラリで動作し、現在の暗号化互換性に対応します。

* **MQTT 5 配信を追加:** MQTT 出力が MQTT バージョン5のクライアントと配信設定をサポートします。

* **モックチェーンのサポートを整合:** ouroboros-mock 0.19.0 により、ローカルおよび自動化されたチェーンテストを最新に保ちます。

* **gouroboros のバージョンを更新:** gouroboros 0.209.0 により、プロトコル処理を最新に保ちます。

* **S3 アーカイブ出力を提供:** Adder が出力したイベントを Amazon S3 にアーカイブできるようになりました。

* **管理対象顧客ルーティングを導入:** `--managed-config-dir` でオプトインする管理モードが有効になり、`--managed-*` 設定を検証し、マニフェスト、顧客、認証情報ファイルを許可された範囲に限定します。認証付きプライベートループバック API により、再読み込み、状態、健全性、メトリクスを操作できます。顧客ごとおよび宛先ごとの上限付きキュー、破棄イベントの追跡、宛先検証、ログおよび webhook アダプターの制御、設定変更の原子的な適用にも対応します。従来モードがデフォルトです。

* **API サーバーを `net/http` へ移行:** SSE と WebSocket のイベントストリーミングを維持しながら、標準 API を利用します。ルートに `/ping`、`/healthcheck`、`/events`、バージョン付きルートに `/v1/fcm` と `/v1/qrcode` を提供し、`/swagger/` で Swagger を公開します。構造化アクセスログ、パニックからの復旧、リクエストタイムアウト、`fcmToken` の明示的な検証にも対応します。

* **Amazon SQS と SNS の配信を有効化:** AWS のデフォルト認証情報検出を使用し、設定とメッセージサイズを検証します。FIFO のメッセージグループおよび重複排除設定に対応し、`10-second` リクエスト制限を適用し、イベントを再送しません。

* **webhook イベント処理を強化:** 不正なイベントのエラーをプラグインのエラーチャネルへ送り、パニックを防ぎます。シャットダウン中は再試行を停止し、ライフサイクルの安全策で競合状態を防止します。

* **Telegram 連携を拡張:** Telegram クライアントが EffectiveUser と EffectiveChat のヘルパーを公開し、インラインクエリーハンドラーと Bot API 10.4 のウィジェットをサポートします。コマンド照合の精度、Bot.ID の正確性、マルチパートリクエスト処理の一貫性も改善します。

* **ビルド要件を更新:** Adder は Go 1.26.11 を必要とし、Docker ビルドは Go 1.27.4 を使用します。

* **フィルターガイダンスを追加:** README の例でアドレス、プール、DRep のフィルターを示し、AND/OR の動作とフラグから環境変数および YAML への対応関係を説明します。ガバナンスのフィルタリングと CIP-0129 DRep ID の正規化も扱います。

* **署名済み Windows インストーラーを提供:** x64 と arm64 の `.msi` パッケージに CLI とトレイを含め、スタートメニューのショートカットとアンインストールメタデータを作成し、スケジュールタスクを使用しません。トレイはログファイルを書き込み、パニックから復旧し、単一インスタンスを維持し、サービスのライフサイクルを管理し、`/events?replay=` の再生制御に対応します。Explorer リンクと通知の照合も修正します。

* **プッシュ通知を改善:** プッシュ設定でサービスアカウントのパスと空でない `project_id` が必須になり、リクエストは10秒でタイムアウトします。シャットダウンと配信のエラーも確実に伝播します。
