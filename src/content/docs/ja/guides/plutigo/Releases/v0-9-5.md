## v0.9.5

**タイトル:** 評価の安全性とデータ処理を改善

**バージョン:** v0.9.5

**リリース:** [v0.9.5](https://github.com/blinklabs-io/plutigo/releases/tag/v0.9.5)

**比較:** [v0.9.4...v0.9.5](https://github.com/blinklabs-io/plutigo/compare/v0.9.4...v0.9.5)

このリリースでは、上限付き評価を改善し、組み込み関数の解析をプロトコル制限に合わせ、リポジトリ自動化を強化し、Value のコスト計算を修正し、保持されたデコード済みプログラムの破損を防ぎます。

### 評価の安全性

* 改良した `serialiseData`、`equalsData`、`unValueData` のサイズ計算は、反復トラバーサルの早い段階で予算下限を確認し、キャンセルを尊重し、正確な最終コストを適用します。大きすぎるデータグラフは完全なトラバーサル前に `BudgetError` で停止でき、キャンセルは元のコンテキストエラーを保持し、不正なデータはパニックを起こさず `ErrCodeInvalidArgument` を返します。

### 組み込み関数の互換性

* 精緻化した組み込み関数の解析は、11 未満のゼロ以外のプロトコルメジャーで組み込み値を `case` 分析すると `ErrCodeCaseOnBuiltinUnavailable` を返します。一方、コンストラクターと既存のバイト文字列定数の動作は引き続き利用できます。Semantics D および E では、4096 バイトを超える `writeBits` のバイトペイロードを拒否し、パーサーは `verifyEd25519Signature` の別名として `verifySignature` を受け入れます。

### 自動化の安全性

* 強化したリポジトリ自動化は、再利用可能なワークフローと NilAway を正確なリビジョンに固定し、ワークフローの権限を限定し、Makefile の format コマンドと clean コマンドを堅牢にします。コンフォーマンス更新ツールはダイジェストを検証し、上限と許可リストを適用し、ロールバックできる状態で変更をステージします。リプレイコーパスの前処理はサイズ、件数、デコード後のバイト数に上限を設け、デコード済みケースをキャッシュし、キャンセルを尊重します。

### Value のコスト計算

* 正確にした Value のコスト計算は、不変のキャッシュ済みメトリクスとディープコピーアクセサーによってサイズ依存のコストを修正します。CEK の Value 組み込み関数はこれらのメトリクスを使用し、`AssetCount` と `unionValue` は実際の Value サイズに基づいて課金します。未初期化の Value はコスト計算前に失敗し、`AssetCount` は `valueDataMaxSize` を超える Value を受け入れます。エクスポート対象から `Value.Entries` フィールドを削除したため、そこから Value を直接構築していた既存コードは `syn.NewValue` とそのアクセサーへ移行する必要があります。

### デコーダーの所有権

* 安全にしたデコーダーの所有権は、`DeBruijnDecoder.Decode` が独立して所有するプログラムを返すようにし、後続のデコードが保持済みの結果を書き換えることを防ぎます。アリーナを再利用する場合に限り、結果が次のデコードまで有効であることを確認したうえで `DecodeBorrowed` を使用し、並行呼び出し間でデコーダーを共有しないでください。以前に `Decode` のアリーナ再利用に依存していた呼び出し側では、割り当てが増える場合があります。
