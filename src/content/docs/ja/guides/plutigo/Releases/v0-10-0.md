## v0.10.0

**タイトル:** 評価器を強化し、Plutigo を PV11 に対応

**バージョン:** v0.10.0

**リリース:** [v0.10.0](https://github.com/blinklabs-io/plutigo/releases/tag/v0.10.0)

**比較:** [v0.9.11...v0.10.0](https://github.com/blinklabs-io/plutigo/compare/v0.9.11...v0.10.0)

### 推奨ネットワーク互換性 ⚠️

| ネットワーク | 互換性 |
|---|---|
| mainnet | ⛔ |
| preprod-testnet | ✅ |
| preview-testnet | ✅ |
| musashi | ✅ |

このリリースでは、リソース枯渇とコンセンサスの不一致に対する評価およびデータ処理の堅牢性を強化し、`cardano-node` 11.1.3（PV11）との互換性を検証しました。また、インテグレーションの移行方法を提供し、ランタイム動作を変更せずに `btcec/v2` 依存関係を更新しました。

### 評価器の安全性と互換性

* 強化: パニックからの復旧と `RunScriptContext` に基づく評価により、リソース枯渇とコンセンサスの不一致に対する評価器の耐性を高めました。
* 追加: ゼロ幅 FLAT メモ化に加え、スクリプト処理中のリソース使用量を制限するための字句解析器、パーサー、FLAT varint の上限を設けました。
* 導入: 構造共有する `Value` ヘルパーと永続ランタイムリストにより、評価の堅牢性を高めました。
* 適用: 一貫した署名検証のため、libsodium strict Ed25519 検証を取り入れました。
* 整合: PV11 の組み込み関数引数の上限と、データおよびリスト操作の段階的なコストを含む、チャージしてから確認する予算セマンティクスを適用しました。
* 改善: `DefaultSlippage=200` による De Bruijn slippage のバッチ処理により、評価の一貫性を高めました。

### データ処理

* 反復的なデコードと走査によって CBOR の処理を改善し、再帰的な走査に依存せず深くネストされたデータを処理できるようにしました。
* サポートされていない表現がデータ処理に入ることを防ぐため、CBOR タグ `1401` と long head bignum タグをデフォルトで拒否するようにしました。
* JSON 入力サイズと整数の桁数を制限し、これらの上限を設定するオプションを提供しました。
* `Integer` と `ByteString` の CBOR アンマーシャリングを厳格化し、入力検証を強化しました。
* 入力に最初のアイテムの後の追加データが含まれる場合に、末尾のバイト列を無視して単一の CBOR アイテムをデコードできるようにしました。

### 評価とインテグレーション

* 最終結果を展開せずにその結果を検証する、ユニット結果のチェックを追加しました。
* トークン `Value` のオーバーフローを報告し、サポートされている範囲を超える値をインテグレーションで検出できるようにしました。
* コンテキストを考慮したスクリプト実行のため、評価のエントリーポイントを `RunScriptContext` を使うように更新しました。
* 一貫した表現で評価できるよう、評価前に `data.Normalize` を使ってデータムとレデーマーを正規化するようにしました。
* サポートされていないタグのデフォルト拒否や JSON 入力の上限など、より厳格な CBOR デコードに対応するようインテグレーション処理を更新しました。
* チャージしてから確認する予算セマンティクスと、このリリースのデータおよびリストの段階的なコストを反映するよう、`BudgetError` フィールドの解釈を変更しました。

### 依存関係のメンテナンス

* `github.com/btcsuite/btcd/btcec/v2` を `v2.5.0` から `v2.5.1` に更新し、対応する `go.mod` と `go.sum` のエントリも更新しました。
* 間接依存関係の `secp256k1/v4` を `v4.4.0` から `v4.4.1` に更新しました。ランタイム動作に変更はありません。
