## v0.26.0 - プロファイルのセキュリティ、可観測性、運用制御を強化

**バージョン:** v0.26.0

### 概要

このリリースでは、プロファイルの分離と認証情報の保護を強化し、運用メトリクスとレディネスの動作を改善しました。起動と公開の信頼性を高め、トランザクション手数料、TLSバンドル、Confidential Spaceキーの新しい制御を追加しました。

### 推奨ネットワーク互換性 ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi              | ✅         |

### ✨ 新機能

* ラベル17のサーベイ履歴キャッシュに上限を追加し、最大20,000行または32 MiBまで保持します。上限を超えた場合はHTTP 503を返します。

* プロファイルごとのKES署名時間をPrometheusヒストグラムで監視できるよう改善しました。

* メトリクスのリッスンアドレスを設定できるようにし、デフォルトをループバックアドレスにしました。ワイルドカードのリッスンアドレスでもレディネス処理が動作します。

* プロファイルごとのガード、キー、署名アクティビティをPrometheusメトリクスで確認できるよう拡張しました。

* リモートKESのキーのステージングとインストールをmTLSピン留めの制御ロールで保護し、リモートのキー削除操作はローカルのみで実行するようにしました。

* サーベイの最終ラベルページをデコード済みのまま再利用し、同じページを複数回デコードしないようにしました。

* 起動時の一時的な最初のPostgreSQL接続エラーを最大20秒間再試行することで、起動の信頼性を高めました。

* スロットガードによる拒否警告に、クライアントを識別できる構造化された詳細を追加しました。

* Capabilityの失効を即時に反映し、クラッシュ後も保持するようにしました。

* オリジンをまたぐウォレット作成および復元リクエストを拒否するようにしました。

* `/readyz`に上限付きのキャッシュプローブを追加しました。プローブは10秒ごとに実行し、3秒のタイムアウトと鮮度ウィンドウを使用します。

* 署名者インベントリのアテステーションをプロファイルに紐付けました。

* オペレーショナル証明書の許可を呼び出し元ごとに、リモート署名をプロファイルごとに制限しました。

* キーに紐付くコネクターのペアリングと、1回だけ使用できる署名済みチャレンジおよびセッションチケットを追加しました。

* 公開時にプレリリースの分類とサフィックスを保持するようにしました。

* プールのコールドキーを1回だけインポートするConfidential Spaceワークフローを追加しました。

* `--tls-secret`でSecret ManagerのTLSバンドルを受け付けるようにしました。

* `tx build --max-fee`を追加し、デフォルトの上限を2,000,000 lovelaceにしました。

* `bursa-confidential-space-key/3`エンベロープとインポートプロトコル`/2`を使用し、Confidential Spaceのコールドキーをプロファイルごとに分離しました。

* Windows amd64 MSYS2 cgo公開時の`PATH`を修正し、必要なツールを見つけられるようにしました。
