## v0.23.0 - プロファイル対応署名、永続的なカストディ、強化されたKES制御

- **バージョン:** v0.23.0
- **比較:** [v0.22.0...v0.23.0](https://github.com/blinklabs-io/bursa/compare/v0.22.0...v0.23.0)

### 概要

このリリースでは、プロファイル対応の署名とストレージ、Nitroの認証と運用証明書カストディ、KESエージェント制御、Armoryの移行とシミュレーション、認証・ストレージ・コネクターの動作を改善します。

### 推奨ネットワーク互換性 ⚠️

|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### ✨ 新機能

* Confidential Spaceに繰り返し指定できる`--profile`と`--create-profile-counter`オプションを追加し、Cloud Storageカウンターと署名レスポンスをプロファイルごとに分離しました。プロファイルを検証し、不明または一致しないプロファイルを拒否し、設定されたプロファイル規則に従う場合だけ起動時にカウンターを作成します。
* Nitroのカストディを強化し、プロビジョニング権限と署名権限を分離しました。`/v1/challenge`による一度限りの署名認証、再読み込みとプロビジョニングのリプレイ対策、非ワールド書き込み可能な`--socket-mode`、Secrets Managerに保存する封印済み運用証明書カウンター、同一ペイロードを同じカウンターで再署名する動作、永続化失敗時の復旧動作、バージョン付き状態の安全なダウングレード指針を提供します。
* KESエージェントに任意の`none`アテステーションプロバイダー、平文のアテステーション済みトランスポート、条件付きクライアント証明書認証、公開の`kesagent/wire`フレーム処理ヘルパーを追加しました。スロットごとに1つのヘッダーを強制し同一リトライだけを許可し、低いスロットと不一致を拒否します。ハンドシェイクは全体64件、送信元ごと4件に制限し、ヘルス、レディネス、メトリクス、複数プロファイル、共有ストレージに対応します。
* SOPSに任意のプロファイル結合、プロファイル単位のルーティングと署名者レコードを導入しました。カウンターリセットは`--profile`でプロファイルを選択でき、従来のプロファイルなしレコードには`--unprofiled`を使用できます。既存レコードの移行手順も示します。
