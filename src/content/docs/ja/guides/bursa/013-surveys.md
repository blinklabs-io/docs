# CIP-179サーベイ

## 概要

このガイドでは、BursaウォレットでCIP-179サーベイとポールを閲覧し、回答、作成、取消、結果確認を行う方法を説明します。ウォレットは組み込みノードからオンチェーンデータを読み取ります。サーベイの閲覧や検索では外部サービスに接続しません。

ウォレットはガバナンスアクションに関連付けられたサーベイも表示します。封印済み回答を公開する場合だけ、公開ビーコンリレーへの接続について明示的な同意を求めます。

## 前提条件

- 閲覧には、サーベイ履歴を照会できる状態の組み込みノードが必要です。
- 回答、作成、取消には、完全同期したノードとローカルシードで署名できるウォレットが必要です。
- ウォレットは履歴を読み取り中にも一覧を表示できます。読み取りが完了するまで、一部のサーベイだけが表示される場合があります。

## ウォレット操作

### サーベイを閲覧、検索する

1. ウォレットのサーベイ画面を開きます。
2. タイトル、説明、またはサーベイIDで検索します。
3. `open`、`closed`、`cancelled` のいずれかで状態を絞り込みます。
4. サーベイを選択して詳細を開きます。

一覧には、対象ロール、回答期限のエポック、設問数、封印の有無、所有状態、ガバナンスアクションとの関連を表示します。ページ切り替えで一致したサーベイを確認できます。

ノードがCIP-179履歴を読み取っている間は、読み取り済みの内容だけを表示します。画面に一部結果の表示が示された場合、読み取りの完了後に再読み込みすると、追加のサーベイを確認できます。

### ガバナンスアクションから開く

ガバナンス画面でサーベイに関連付けられたアクションを選択すると、そのサーベイの詳細を直接開けます。関連付けはCIP-108アンカードキュメント内のCIP-179サーベイリンクで判定します。

関連付けはサーベイを見つけるための案内だけを提供します。関連付けによって回答可能なロールは変わりません。サーベイ一覧APIで `linked=true` を指定すると、ガバナンスアクションに関連付けられたサーベイだけを取得できます。

### 詳細と結果を確認する

詳細画面には、説明、状態、回答期限、対象ロール、所有者、サーベイID、設問定義を表示します。サーベイが取消済みでない場合、ウォレットはロールごとの回答数、設問ごとの集計、除外した回答を結果に含めます。

取消済みサーベイは結果を集計しません。封印済み回答が残っている場合、公開時刻を過ぎるまで該当回答を結果に反映できません。

### サーベイに回答する

1. 状態が `open` のサーベイを開きます。
2. ウォレットが保持する認証情報に対応する回答ロールを選択します。
3. 回答する設問を選び、設問の形式に従って値を入力します。
4. 回答を確認し、表示された確認フローで署名と送信を実行します。

ウォレットは、サーベイが許可するロールのうち、現在のウォレットで扱えるロールだけを回答欄に表示します。ノードは回答トランザクションの署名とロールを確認します。対象ロールをウォレットが扱えない場合や、ノードが現在の台帳状態でロールを確認できない場合、回答できません。

カスタム形式の設問には、このウォレットUIから回答できません。必須のカスタム設問を含むサーベイは回答できません。任意の設問は回答を保留できますが、すべての設問を保留した回答は公開できません。

封印済みサーベイでは、ウォレットがこの端末上で回答を暗号化します。設定された公開時刻を過ぎると、ビーコンを使って回答を公開できます。

回答の送信、サーベイの作成、取消では、ウォレットは直ちに送信せず、保留中トランザクションのプレビューを表示します。既存の確認フローで内容を確認してから署名と送信を実行してください。

### サーベイを作成する

1. サーベイ一覧で新規サーベイを選択します。
2. タイトル、説明、対象ロール、回答期限のエポックを入力します。
3. 設問を追加し、各設問の形式を設定します。
4. 必要に応じて、表示用ドキュメントのURIと内容を指定します。
5. 必要に応じて、封印の公開ラウンドとパディングサイズを指定します。
6. 作成内容を確認し、保留中トランザクションを署名して送信します。

作成したサーベイはオンチェーンデータとして公開されます。送信後、ノードが新しいブロックを読み取ると一覧と詳細に表示します。

### サーベイを取り消す

所有するサーベイの詳細画面で、状態が `open` のときに取消を選択します。取消には完全同期したノードと、サーベイを所有するローカルシードウォレットが必要です。取消内容を確認して署名と送信を実行してください。

### 封印済み回答を公開する

1. 詳細画面で公開時刻を確認します。
2. 公開時刻を過ぎた後に、封印済み回答の公開欄を開きます。
3. 次のいずれかを選択します。
   - `api.drand.sh` から公開ビーコンを取得することに同意します。ウォレットはこの操作のときだけ外部リレーに接続します。
   - 公開ラウンドのビーコン署名を16進数で貼り付けます。この方法では外部リレーに接続しません。
4. 回答を公開し、詳細を再読み込みして結果を確認します。

同意もビーコンの貼り付けも指定しない場合、ウォレットは公開を実行しません。取消済みサーベイの回答は集計しないため、公開対象になりません。

## ウォレットAPIリファレンス

### `GET /wallet/surveys`

組み込みノードから検出したサーベイの概要を、ページ単位で返します。クエリパラメーターは次のとおりです。

| パラメーター | 説明 |
| --- | --- |
| `q` | タイトル、説明、またはサーベイIDに対する検索文字列。 |
| `status` | `open`、`closed`、`cancelled` のいずれかで状態を絞り込みます。 |
| `linked` | `true` を指定すると、ガバナンスアクションに関連付けられたサーベイだけを返します。 |
| `page` | 取得するページ番号。 |
| `count` | 1ページに含める件数。 |

レスポンスは次の形式です。

```json
{
  "surveys": [
    {
      "id": "<transaction-hash>:<index>",
      "tx_hash": "<transaction-hash>",
      "index": 0,
      "title": "サーベイのタイトル",
      "description": "サーベイの説明",
      "owner": "<credential-hash>",
      "owner_script": false,
      "roles": [0, 4],
      "end_epoch": 123,
      "status": "open",
      "sealed": false,
      "questions": 2,
      "linked_actions": ["<governance-action-id>"],
      "owned": true
    }
  ],
  "total": 1,
  "page": 1,
  "count": 20,
  "partial": true
}
```

`surveys` の各項目は概要です。`roles` は回答可能なロールコード、`end_epoch` は回答期限、`linked_actions` は関連するガバナンスアクションIDを示します。`owned` が `true` の場合、現在のウォレットが所有者です。

履歴の読み取りが継続中でも、APIは読み取り済みの一覧を返します。この場合だけ `partial` を `true` に設定します。読み取りが完了した場合、`partial` は省略します。

ノードがサーベイ履歴を照会できない状態では、ノード状態ゲートがリクエストを拒否します。入力やノードのエラーはJSONの `error` フィールドで返します。

### `GET /wallet/surveys/{id}`

指定したサーベイの概要に、`definition` と結果の `tally` を加えて返します。`definition` にはタイトル、説明、対象ロール、回答期限、封印設定、設問、任意の表示用アンカーを含めます。`tally` にはロールごとの回答数、封印中の回答数、設問ごとの集計、除外した回答を含めます。

取消済みサーベイには `tally` を含めません。詳細取得は履歴の読み取りが完了するまで待機し、読み取り中は結果を返しません。

存在しない、または有効でないサーベイIDには `404 Not Found` を返します。履歴の読み取り中は `503 Service Unavailable` を返します。ノードが利用できない場合も、ノード状態に応じたエラー応答になります。

### `POST /wallet/surveys/respond`

回答トランザクションのプレビューを作成します。リクエスト本文には次のフィールドを指定します。

```json
{
  "survey": "<transaction-hash>:<index>",
  "role": 4,
  "answers": [
    {
      "kind": 1,
      "question": 0,
      "choice": 1
    }
  ]
}
```

`survey` は対象サーベイID、`role` は回答ロールコード、`answers` は設問ごとの回答配列です。回答形式に応じて、各回答は `choice`、`indices`、`number`、`pairs` のいずれかを使います。APIは保留中トランザクションのプレビューを返し、ウォレットは確認フローで署名と送信を行います。

完全同期したノードがない場合や、ローカルシードで署名できるウォレットがない場合、書き込み操作は実行できません。無効なリクエストには `400 Bad Request`、対象が見つからない場合には `404 Not Found` を返します。

### `POST /wallet/surveys/create`

新しいサーベイを公開するトランザクションのプレビューを作成します。リクエスト本文には次のフィールドを指定します。

```json
{
  "title": "サーベイのタイトル",
  "description": "サーベイの説明",
  "roles": [0, 4],
  "end_epoch": 123,
  "questions": [],
  "anchor_uri": "https://example.com/survey",
  "anchor_document": "<presentation-document>",
  "seal": {
    "round": 123456,
    "padding_size": 1024
  }
}
```

`title`、`description`、`roles`、`end_epoch`、`questions` はサーベイ定義です。`anchor_uri` と `anchor_document` は任意の表示用ドキュメントです。`seal` も任意で、指定すると `round` の公開ビーコンで回答を公開する封印設定を作成します。

APIは保留中トランザクションのプレビューを返します。ウォレットは確認フローで内容を確認してから署名と送信を行います。

### `POST /wallet/surveys/cancel`

サーベイを取り消すトランザクションのプレビューを作成します。

```json
{
  "survey": "<transaction-hash>:<index>"
}
```

`survey` に取消対象のサーベイIDを指定します。APIは保留中トランザクションのプレビューを返します。所有者のウォレットだけが所有するサーベイを取り消せます。

### `POST /wallet/surveys/{id}/reveal`

封印済み回答を公開し、更新後のサーベイ詳細と結果を返します。リクエスト本文には、公開ビーコンを取得する同意、または貼り付けたビーコンを指定します。

```json
{
  "consent": true
}
```

または、外部リレーへの接続を避ける場合は次の形式を使います。

```json
{
  "beacon": "<beacon-signature-hex>"
}
```

`consent` を指定すると、ウォレットは公開ラウンドのビーコンを公開リレーから取得します。`beacon` を指定すると、その署名を使い、リレーには接続しません。同意もビーコンも指定しない場合、APIは `403 Forbidden` を返します。

サーベイIDが存在しない場合は `404 Not Found`、入力が無効な場合は `400 Bad Request` を返します。履歴の読み取り中は `503 Service Unavailable` を返します。公開時刻前の回答や検証できないビーコンは公開できません。

## エラーと状態の確認

- `open` は回答を受け付ける状態です。回答期限を過ぎると `closed` になります。
- `cancelled` は所有者が取り消した状態です。取消済みサーベイは結果を集計しません。
- 一覧の `partial: true` は、ノードが履歴を読み取り中であることを示します。読み取り完了後に再試行してください。
- `404 Not Found` は、サーベイIDが存在しないか有効でないことを示します。
- `400 Bad Request` は、リクエストを解釈できないことを示します。
- `403 Forbidden` は、封印済み回答の公開に同意またはビーコンが必要なことを示します。
- `503 Service Unavailable` は、詳細取得や公開が履歴の読み取り完了を待っていることを示します。
- ノードが照会可能または完全同期の条件を満たさない場合、対応するノード状態ゲートが操作を拒否します。
