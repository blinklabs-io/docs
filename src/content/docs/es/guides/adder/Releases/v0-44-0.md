## v0.44.0

**Título:** Notificaciones sin interfaz, registros más seguros y mejoras de eventos Cardano

**Versión:** v0.44.0

Esta versión incorpora notificaciones JSON sin interfaz, registros operativos más claros y seguros, más filtros de eventos Cardano, configuración predecible y flujos de publicación más resistentes.

### ✨ Aspectos destacados

- **Registros estructurados:** Los componentes y plugins utilizan registros de clave/valor con su propio contexto. Se sanea la URL de los webhooks, se truncan u ocultan los tokens FCM y se registran los tamaños de mensajes y respuestas en lugar de sus cuerpos.

- **Notificaciones JSON sin interfaz:** `notify-json` produce registros NDJSON versionados de estado y notificaciones. `adder notifications validate --config <path> [--json]` comprueba los ajustes. El inicio valida la red chainsync y la dirección personalizada; se exige `schemaVersion: 1`. El envío ya no depende de una interfaz de usuario.

- **Prioridad y guardado:** La CLI tiene prioridad sobre YAML y YAML sobre el entorno. El guardado atómico protege los archivos de configuración existentes durante las actualizaciones.

- **Filtros Cardano:** Se separan los tipos de comparadores, se admiten procedimientos de voto de SPO de pools y se gestionan de forma segura las credenciales de stake ausentes.

- **Retrocesos independientes:** La preferencia `Chain rollbacks` controla esas notificaciones por separado de las demás categorías.

- **Varios objetivos:** Las notificaciones utilizan listas de objetivos, límites de frecuencia y agrupación por lotes. Se migran los filtros antiguos.

- **Paquetes macOS:** Los paquetes firmados y notarizados incluyen CLI, aplicación de bandeja, scripts y el enlace `/usr/local/bin/adder`. Las compilaciones locales pueden no firmarse o usar firma ad hoc.

- **Servicio API:** El servicio HTTP conserva los eventos enviados por servidor y el comportamiento WebSocket de `/events`. La documentación utiliza las rutas y la ruta base actualizadas.

- **Editor de bandeja:** Permite editar reglas y casillas de preferencias. Guarda y aplica los cambios sin reiniciar y presenta con mayor claridad los errores recuperables.

- **Entrega de notificaciones:** Se validan credenciales e identificadores de proyecto, se muestran errores Firebase Cloud Messaging, se aplican tiempos de espera de 10 segundos y se cierran ordenadamente los manejadores de notificación y push.

- **Imágenes multiplataforma:** Se publica un manifiesto de imagen compartido para que cada plataforma compatible reciba su imagen correspondiente.

### ⚠️ Compatibilidad de eventos

- **Nombres DRep:** Las constantes públicas cambian a `input.drep-registration`, `input.drep-update` e `input.drep-retirement` para registro, actualización y baja, en lugar de `chainsync.drep.*`. Los consumidores deben utilizar los nuevos valores.

### 💪 Mejoras

- La guía de resolución de problemas cubre conexiones, configuración, filtros, push/FCM y webhooks.

- Se amplían las comprobaciones de filtros y se revisa la ruta de apagado para terminar el proceso de forma limpia.

- Las opciones de plugins Cardano, eventos y chainsync ignoran espacios alrededor de los valores separados por comas. La directiva Go pasa a `1.26.0`.

- Los esquemas y filtros de eventos de gobernanza tienen documentación propia, que también utiliza el ejemplo del README.

- Las publicaciones fijan macOS a `macos-15`, permiten terminar los trabajos independientes, separan empaquetado y firma y finalizan los borradores tras fallos parciales de compilación.

- Los paquetes FreeBSD dejan de incluir la aplicación de bandeja.

- Se utiliza `golang.org/x/sys` v0.47.0.

- La acción `golangci-lint` pasa a v9.3.0.

- La acción de inicio de sesión Docker pasa a v4.6.0.

- Se utiliza `gouroboros` v0.197.0.

- Las publicaciones utilizan `actions/attest` v4.2.2.

- Los webhooks gestionan eventos mal formados sin pánico y coordinan el apagado con los reintentos para evitar condiciones de carrera.

- El contexto de los loggers personalizados se propaga de forma coherente a los registros emitidos.

- Se admite la consulta `GetAccountState`, certificados operativos y redeemers Dijkstra. Se actualizan la era Dijkstra y Leios. Las canalizaciones con validación informan de un error y omiten los bloques que no superan la validación.

- Se refuerzan la decodificación y la validación, la tolerancia de claves MultiAsset duplicadas anteriores a Conway y de conjuntos etiquetados de testigos Conway, los errores de entradas desconocidas y las correcciones KES y del ledger.

- Se conservan los límites del intervalo de validez de las transacciones y se verifican las firmas de certificados de delegación Byron.

- La integración Plutus utiliza decodificación y evaluación reforzadas y mejoras de rendimiento.

- Se utiliza `golang.org/x/image` v0.45.0 con decodificadores de imágenes reforzados.

### 🧪 Pruebas, CI, documentación y publicación

- La serialización de protocolos utiliza protobuf v1.36.12.

- La firma Windows y los flujos Java utilizan `actions/setup-java` v5.7.0.

- Se utilizan testify v1.12.1 y yaml.v3 v3.0.5.

- Los flujos Go utilizan `actions/setup-go` v7.0.0.

- Se incorpora testify v1.12.0 para la ejecución de pruebas.

- Las atestaciones de publicación utilizan `actions/attest` v4.2.2.

- Los flujos de checkout utilizan `actions/checkout` v7.0.1.

- La firma Windows utiliza Java 21 en lugar de Java 17.

- Telegram utiliza `go-telegram/bot` v1.23.0.

- Los metadatos Docker utilizan `docker/metadata-action` v6.2.0.

- Las compilaciones de contenedores utilizan `docker/setup-buildx-action` v4.3.0.

- Las pruebas de artefactos Windows utilizan `actions/upload-artifact` v7.0.1. Los runners propios requieren Actions Runner v2.327.1 o posterior.

- Las pruebas de protocolo utilizan `ouroboros-mock` v0.16.0.

- El paquete inicial de biblioteca incluye tres ejemplos ejecutables, con enlaces directos desde el README.

- Se publican MSI firmados para CLI y bandeja con integración en Inicio y Agregar o quitar programas. Las compilaciones locales pueden omitir la firma; la automatización publica los instaladores.
