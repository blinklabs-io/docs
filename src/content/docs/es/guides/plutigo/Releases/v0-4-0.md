## v0.4.0 (25 de agosto de 2026)

**Título:** Adaptar las etiquetas de constructor a las variantes y reforzar las dependencias

**Fecha:** 25 de agosto de 2026

**Versión:** v0.4.0

Esta versión adapta las etiquetas de constructor a cada variante mediante cambios de API pública y ejecución. También incorpora validación y gestión de datos mal formados de los proyectos originales, refuerza dependencias y limpia el formato.

### ✨ Novedades

Los consumidores Go controlan explícitamente el ancho y la representación de las etiquetas entre variantes Plutus y formatos de serialización.

- **Etiquetas según la variante:** Usa `data.NewConstr` con `uint64` o `data.NewConstrFromBigInt` para enteros arbitrarios. `data.Constr.Tag` pasa a `*big.Int`, y `syn.Constr.Tag` a `uint64`. Las variantes A a C aceptan enteros arbitrarios; D y E requieren valores no negativos que quepan en Word64. CBOR impone el rango Word64, JSON conserva enteros arbitrarios y FLAT utiliza `uint64` con comprobaciones de desbordamiento. Las etiquetas nil equivalen a cero.

### 🔧 Correcciones

Las actualizaciones de dependencias y formato siguientes no modifican las API, opciones, configuración ni comportamiento de ejecución locales de Plutigo; los cambios de etiquetas se describen arriba.

- **Entradas criptográficas:** `github.com/cloudflare/circl` pasa de `v1.6.4` a `v1.6.5`, incorporando validación y una gestión más estricta de errores de datos mal formados, sin modificar el código local.
- **Verificación:** `github.com/consensys/gnark-crypto` pasa de `v0.20.1` a `v0.21.0` y la dependencia indirecta `github.com/bits-and-blooms/bitset` de `v1.24.4` a `v1.24.6`, con mejoras de seguridad, verificación y validación de entradas del proyecto original, sin modificar el código local.
- **Criptografía:** `golang.org/x/crypto` pasa de `v0.54.0` a `v0.55.0` e incorpora refuerzos de seguridad y correcciones sin cambiar API, opciones ni configuración locales.
- **CBOR mal formado:** `github.com/fxamacker/cbor/v2` pasa de `v2.9.2` a `v2.9.3` y corrige un posible pánico al convertir datos CBOR mal formados a `time.Time`. Plutigo utiliza CBOR para PlutusData y no tiene referencias a `time.Time`.
- **Formato del internador de términos:** El type switch de `syn/builder.go` elimina paréntesis redundantes para cumplir `gofumpt`, sin cambiar la ejecución.

### 📋 Información importante

Los consumidores Go deben actualizar el código que construye o lee etiquetas. Usa `data.NewConstr` para etiquetas `uint64` no negativas y `data.NewConstrFromBigInt` para enteros arbitrarios. Ten en cuenta el cambio de `data.Constr.Tag` de `uint` a `*big.Int` y de `syn.Constr.Tag` de `uint` a `uint64`.

### 🙏 Agradecimientos

Gracias por usar Plutigo.
