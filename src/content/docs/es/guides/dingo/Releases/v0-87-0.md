## v0.87.0

**Título:** Mejorar la seguridad de los recursos, la red y la compatibilidad del consenso

**Versión:** v0.87.0

**Versión publicada:** [v0.87.0](https://github.com/blinklabs-io/dingo/releases/tag/v0.87.0)

**Comparación:** [v0.86.0...v0.87.0](https://github.com/blinklabs-io/dingo/compare/v0.86.0...v0.87.0)

Dingo v0.87.0 mejora los controles de recursos, la red entre pares, la seguridad de la sincronización, el comportamiento de las API, la seguridad de la configuración y la compatibilidad del consenso.

### Compatibilidad de red recomendada ⚠️

| Red                 | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### Cambios importantes
* Limitó la reproducción histórica de `FollowTip` en la RPC de UTxO con límites de concurrencia del proceso y de cada cliente, regulación del ritmo y presupuestos de historial. El servicio ahora devuelve `ResourceExhausted` cuando la demanda alcanza un límite configurado.
* Añadió el listener de pares DMQ, la topología y la configuración de los límites mínimo y máximo de pares mediante YAML, variables de entorno y opciones de CLI. Dingo valida estos ajustes antes del inicio.
* Devolvió `503` HTTP reintentable al listar la mempool de Mesh cuando un pool supera su capacidad configurada, en lugar de devolver un prefijo incompleto; los listados ahora solo devuelven hashes de transacciones y aplican una concurrencia limitada.
* Cambió los resúmenes de direcciones de Blockfrost para respetar la cancelación, limitar el enriquecimiento y devolver `400` HTTP cuando las solicitudes superan su presupuesto o `429` HTTP cuando la demanda alcanza la capacidad.
* Vinculó las API de devnet generadas a loopback y bloqueó que las operaciones de estado, claves y archivos siguieran redirecciones mediante enlaces simbólicos.
