## v0.47.0

**Título:** Recorrido inverso de la cadena e indexación histórica más fiable

**Versión:** v0.47.0

**Fecha:** 21 de mayo de 2026

- Se puede recorrer la cadena hacia atrás desde un punto elegido hasta el origen.
- Los operadores pueden configurar el tiempo de inactividad tras el cual una conexión chainsync se considera bloqueada.
- Se agiliza la resolución de claves de direcciones durante la indexación histórica de la API. SQLite actualiza sus datos de planificación antes de esa indexación y tras importar o reanudar Mithril.
- Se amplían las verificaciones de retiros del tesoro, caducidad de propuestas y aplicación de decisiones de gobernanza.
- Las descargas Mithril detectan periodos prolongados de inactividad, reintentan y continúan desde el punto alcanzado.
- Las solicitudes WaitForTx terminan al alcanzar un límite de tiempo del servidor si la transacción no aparece.
- La selección de puntos de sincronización incluye el límite de confianza de Mithril como ancla de recuperación.
- La indexación histórica de la API tras Mithril omite escrituras de offsets que ya existen.
- El modo de almacenamiento API conserva salidas gastadas para consultas históricas, incluso después de la limpieza y poda.
- Los eventos chainsync cuyo orden es crítico aplican contrapresión y entrega bloqueante en lugar de descartar actualizaciones del búfer.
- Se publican las notas de v0.46.4. Se aplican los procedimientos habituales de actualización de versiones de corrección.
