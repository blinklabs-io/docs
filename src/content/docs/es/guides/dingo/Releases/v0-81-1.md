## v0.81.1

**Título:** Mejorar el rendimiento del libro mayor, la sincronización, el almacenamiento y la fiabilidad de la API

**Versión:** v0.81.1

**Versión publicada:** [v0.81.1](https://github.com/blinklabs-io/dingo/releases/tag/v0.81.1)

Dingo v0.81.1 mejora el procesamiento del libro mayor, la sincronización, el almacenamiento y las protecciones de la API para el nodo y la biblioteca de Dingo. También refuerza la distribución de versiones, el comportamiento de la gobernanza y la visibilidad operativa.

### Compatibilidad de red recomendada ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### Operaciones del nodo y distribución de versiones
* Añadió el ajuste `ledgerApplyRowBatchingEnabled`, desactivado de forma predeterminada, en la configuración, la CLI y las variables de entorno para permitir la agrupación opcional de escrituras de ledger no validadas que sean aptas en el almacenamiento principal.
* Garantizó que los manifiestos de la imagen principal se publiquen solo después de que las compilaciones de imágenes finalicen correctamente, estableciendo una verificación de compilación para los artefactos de la versión.
* Restauró las donaciones de las instantáneas Mithril de Conway en las épocas de anclaje.

### Almacenamiento y procesamiento del libro mayor
* Optimizó los planes agrupados de gasto de UTxO en SQLite para usar búsquedas puntuales y mantuvo las sentencias específicas de SQLite fuera de las cachés de otros dialectos de base de datos.
* Validó las superposiciones pendientes de cuenta y estado y el recuento de bytes retenidos del mempool, y gestionó explícitamente la indisponibilidad estable.
* Mejoró la paginación portable y la reproducción de migraciones, el mantenimiento de SQLite, las consultas de UTxO solo para activos y las alertas operativas.
* Almacenó en caché las sentencias SQL de uso frecuente y evitó errores de sentencias SQLite entre conexiones.

### Sincronización y operaciones de red
* Aplazó los encabezados de ChainSync que superan el horizonte previsto sin usarlos para seleccionar cadenas o para blockfetch, y sin penalizar a los pares.
* Reinició blockfetch cuando la cola de encabezados alcanzó su capacidad y resincronizó con un motivo de fallo explícito si la recuperación falló.
* Evitó que los pares leios-fetch ausentes incrementaran el contador de detención del ledger.

### API, configuración y gobernanza
* Limitó la concurrencia de RPC UTxO unarios, los bytes de respuesta y las lecturas del mempool con valores predeterminados de `MaxConcurrentBulkRequests=32`, `MaxResponseBytes=16 MiB`, `MaxMempoolItems=1000` y `BulkResponseWriteTimeout=30s`, y reforzó el registro de solicitudes.
* Reforzó la instalación de claves de DevNet, rechazó bytes CBOR finales en las API públicas, canceló las búsquedas de `WaitForTx` agotadas y limitó los índices de lotería de Mithril.
* Incorporó la opción `LedgerPrefetchAheadEnabled`, desactivada de forma predeterminada, en la CLI, las variables de entorno y la configuración.
* Corrigió el ciclo de vida de DRep de Conway, la limpieza de delegaciones, la gestión de la transición PV10 y el análisis del estado del ledger.
