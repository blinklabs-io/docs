## v0.77.0

**Título:** Fortalecer la gobernanza, la sincronización y la fiabilidad de la API

**Fecha:** 2026-10-02

**Versión:** v0.77.0

**Versión publicada:** [v0.77.0](https://github.com/blinklabs-io/dingo/releases/tag/v0.77.0)

Dingo v0.77.0 mejora el procesamiento de la gobernanza, la seguridad de la forja, el manejo de recompensas, la compatibilidad de la API, la sincronización y la validación. También añade métricas operativas y amplía la cobertura de regresión para el comportamiento de Conway y Dijkstra.

### Compatibilidad de red recomendada ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### Gobernanza y recompensas
* Corrigió el procesamiento de la gobernanza de Conway para que las acciones `RATIFY` ocurran antes que las acciones `ENACT` cuando ambas se aplican en un límite de época.

* Amplió el poder de voto de Conway para incluir los depósitos de propuestas activas y proporcionar a las decisiones de gobernanza la representación de participación prevista.

* Refinó el manejo del umbral de `UpdateCommittee` de Conway para que las actualizaciones del comité utilicen las reglas correctas de aprobación y quórum.

* Añadió pruebas de regresión para la gobernanza secundaria de Dijkstra que verifican que las propuestas secundarias sigan la ruta de gobernanza correcta.

* Protegió la cobertura de regresión de Dijkstra para los identificadores duplicados de propuestas de gobernanza.

### Forja y validación
* Reforzó las decisiones de forja al comprobar la ascendencia de la cadena primaria antes de seleccionar una punta de cadena.

* Limitó la forja a un máximo de dos bloques no aplicados, reduciendo la posibilidad de extender una punta local insegura.

* Corroboró los informes de altura de los pares antes de utilizarlos para orientar las decisiones de sincronización y forja.

* Eliminó la configuración `ForgePrimaryChainTipToleranceSlots` porque la forja ahora aplica directamente las salvaguardas de ascendencia de la cadena primaria y de bloques no aplicados.

### Recompensas y validación de datos
* Aplicó el valor promulgado `maxPledgeLeverage` de CIP-50 al calcular las recompensas de Dijkstra.

* Gestionó explícitamente las recompensas negativas de los líderes para que los cálculos de recompensas no produzcan resultados no válidos.

* Conservó de forma coherente los resultados de recompensas negativas de los líderes en las rutas de reinicio y restauración del estado.

* Rechazó de inmediato los hashes malformados de longitud fija en lugar de permitir que los valores no válidos continuaran durante el procesamiento.

### Compatibilidad de la API
* Introdujo una API opcional compatible con Kupo v2.12 para las implementaciones que necesitan acceso a Kupo.

* Exigió que el modo API utilice el nivel de almacenamiento de la API, haciendo explícita la selección de almacenamiento al activar la API de Kupo.

* Documentó el comportamiento de las ranuras futuras de la API de Kupo para que las respuestas sigan siendo predecibles cuando aún no ha llegado una ranura solicitada.

* Incluyó el límite de expiración en el manejo de DRep de Blockfrost, permitiendo que un DRep permanezca activo hasta su ranura exacta de expiración.

### Sincronización y fiabilidad operativa
* Reutilizó las máquinas de Plutus mediante `gouroboros` v0.208.5, reduciendo la configuración repetida durante la evaluación de scripts.

* Agilizó el procesamiento de blockfetch al reutilizar los resultados de verificación criptográfica para cada encabezado en cola.

* Restauró el manejo de la reproducción durante el inicio cuando la red no está disponible, permitiendo que el trabajo de recuperación local continúe sin conexión de red.

* Midió la diferencia con la punta durante la puesta al día para que los operadores puedan observar cuánto se mantiene el nodo por detrás de la punta de la red.

* Reconstruyó de forma segura la participación activa de recompensas alrededor de las instantáneas del registro de escritura anticipada para que la recuperación no utilice una vista de estado incoherente.

* Conservó el manejo de la caché de recompensas durante las reconstrucciones de participación activa, manteniendo coherentes los valores almacenados en caché con el estado reconstruido.

### Pruebas y calidad
* Reforzó los escenarios de referencia de sincronización y procesamiento del libro mayor para hacer más fiables las comprobaciones de rendimiento.

* Amplió la cobertura de regresión para la concurrencia entre componentes y las condiciones límite que protegen el comportamiento corregido.
