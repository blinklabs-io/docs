## v0.213.6

**Título:** Mejorar la admisión del protocolo, el manejo de consultas y la obtención de transacciones

**Versión:** v0.213.6

Esta versión mejora la admisión de mensajes del protocolo, corrige el manejo de consultas Shelley filtradas, actualiza la obtención de transacciones para el formato de conexión de Leios y actualiza la dependencia de Plutigo.

### Cambios incompatibles

* Cambió `MsgBlockTxs` para que solo contenga transacciones. La API elimina los campos `Point` y `Bitmaps`, y `NewMsgBlockTxs` ahora acepta únicamente transacciones. La carga útil de conexión usa `[4, [* tx]]` y envuelve cada transacción en la etiqueta 24 alrededor de una cadena de bytes definida que contiene un `block_transaction`. El cliente LeiosFetch valida la cantidad de transacciones devueltas frente a la cantidad de mapas de bits solicitados y rechaza los envoltorios con formato incorrecto o las transacciones vacías. El README del protocolo hace referencia a la versión candidata `2026w42` de Leios.

### Correcciones de errores

* Mejoró la admisión de mensajes entrantes al vincularla a la generación de agencia del par, reservar capacidad de respuesta canalizada para las solicitudes pendientes y volver a tomar una instantánea del estado aplazado antes de admitir mensajes posteriores. El protocolo ahora rechaza de forma determinista las respuestas adicionales coalescidas y conserva el orden legítimo de la canalización.

* Corrigió la decodificación de consultas Shelley filtradas mediante diseños de conexión explícitos y conjuntos de pools tipados. El decodificador de consultas rechaza los filtros con formato incorrecto que contienen más de un conjunto de pools, mientras `Client.GetPoolState` y `Client.GetPoolDistr` codifican correctamente los argumentos `StrictMaybe (Set PoolId)` para todos los pools y para los pools seleccionados.
