## v0.220.2

**Título:** Mejorar la compatibilidad del protocolo y la validación de entradas

**Fecha de lanzamiento:** 2026-11-15

**Versión:** v0.220.2

Esta versión mejora la compatibilidad del protocolo, protege los decodificadores frente a datos excesivamente grandes o malformados, amplía la compatibilidad del libro mayor por era, actualiza las API de consulta del estado local y renueva las dependencias.

### Correcciones de errores

* Mejoró la seguridad del envío de transacciones al añadir `Config.MaxTxSize` y `WithMaxTxSize`, limitar los cuerpos de `ReplyTxs` antes de decodificar el libro mayor y rechazar anuncios de `ReplyTxIds` que superen el límite fijo `MaxTxSizeBytes` de 65 540 bytes. El límite configurado solo se aplica a los cuerpos de `ReplyTxs`.
* Reforzó la validación de racionales al comprobar los componentes sin procesar antes de decodificar, limitar los arreglos racionales a 10 elementos y limitar la reducción euclidiana a 96 pasos.
* Corrigió el intercambio de pares IPv6 al codificar y decodificar las palabras de dirección en orden big-endian en los diseños CBOR v11/v12 y v13 o posteriores. La codificación IPv4 no cambia.
* Igualó la codificación de datos de `GetGovState` del nodo para las consultas del estado local.
* Conservó el último importe para las cuentas de recompensa de retiros duplicadas anteriores a Conway, mientras mantiene el rechazo estricto de duplicados en Conway y Dijkstra.
* Rechazó las colecciones de bloques obligatorias con null o undefined al exigir mapas para los conjuntos de datos auxiliares y arreglos para las colecciones de transacciones inválidas. Las colecciones vacías definidas e indefinidas siguen siendo válidas, y los datos auxiliares de una transacción independiente aún pueden ser null.

### Cambios incompatibles

* Cambió la API de consulta de estado local de recompensas no myopic para usar entradas tipadas `NonMyopicMemberRewardsKey` y devolver claves de monedas y credenciales con orden CBOR canónico compatible con el nodo.

### Cambios adicionales

* Renovó la dependencia de Plutigo a v0.12.1.
* Actualizó la dependencia `x/crypto` a v0.59.0.
* Habilitó el comportamiento de último valor gana para índices de datos auxiliares duplicados de Babbage, mientras mantiene el rechazo estricto de duplicados en Conway.
