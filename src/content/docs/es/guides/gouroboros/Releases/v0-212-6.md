## v0.212.6

**Título:** Mejorar la decodificación del ledger y la compatibilidad de dependencias

**Versión:** v0.212.6

Esta versión alinea la validación del código de cadena de los testigos de arranque con las eras de la red y actualiza las bibliotecas criptográficas y CBOR para incorporar correcciones del proyecto upstream y un comportamiento de decodificación más estricto.

### Cambios incompatibles
* Mejoró la decodificación de los testigos de arranque para que el requisito de un código de cadena de 32 bytes se aplique según la era de la red. Las transacciones de Dijkstra ahora rechazan códigos de cadena de 31 y 33 bytes con `bootstrap witness chain code must be 32 bytes`, mientras que las claves públicas siguen teniendo 32 bytes y las firmas siguen teniendo 64 bytes. Esto mantiene alineados el comportamiento de decodificación de transacciones y el consenso.

### Cambios adicionales

* Actualizó `github.com/consensys/gnark-crypto` de `0.21.0` a `0.22.0`, junto con `bitset` y la configuración de versión de Go de `1.26.5` a `1.26.8`. La actualización incluye correcciones de parámetros criptográficos y generadores procedentes del proyecto upstream, cambios de compatibilidad que afectan a los artefactos generados y correcciones de validación y seguridad.

* Actualizó `github.com/fxamacker/cbor/v2` de `2.9.4` a `2.9.6` en `go.mod` y `go.sum`. La actualización elimina las entradas obsoletas de mapas de Go para claves y valores CBOR `null`, establece las interfaces en `nil` para los valores CBOR `null` e indefinidos y puede mostrar errores de decodificación más estrictos.
