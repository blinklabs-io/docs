## v0.204.4

**Título:** Normalizar los datos de transacción visibles para los scripts

**Versión:** v0.204.4

La versión v0.204.4 normaliza los datos de datum y redeemer antes de que los reciban los scripts, alineando la salida de `serialiseData` con la codificación canónica de cardano-ledger. La corrección evita fallos de ejecución cuando los scripts encuentran diferencias entre codificaciones de datos de longitud definida e indefinida, y mantiene las claves `DatumHash` basadas en los bytes originales.

### 🐛 Correcciones

* Corrigió **la codificación de datum y redeemer visible para los scripts:** Los scripts reciben ahora codificación canónica de los contextos de script comunes y los datos de propósito de script.

* Refinó **la representación de datums inline:** Las entradas resueltas de V1 y V2 y las cargas de datums inline de Babbage ahora exponen datos normalizados.

* Mejoró **la evaluación de scripts de Conway:** Las rutas de evaluación y los redeemers de ScriptContextV3 usan ahora codificación canónica visible para los scripts.

* Normalizó **el manejo de datos de scripts de Dijkstra:** Los datums inline y de guardia de V4 y las rutas de evaluación normalizan ahora los datos antes de la ejecución del script.

* Conservó **la identidad de los hashes de datum:** Las claves `DatumHash` siguen usando los bytes originales del datum, aunque se normalicen los datos visibles para los scripts.

* Actualizó **la dependencia de datos de scripts:** gOuroboros y sus módulos de ejemplo usan ahora plutigo v0.6.1 para proporcionar el comportamiento de normalización canónica.

* Amplió **la cobertura de normalización:** Las pruebas y el fixture CBOR de Voting verifican ahora el manejo canónico de los datos visibles para los scripts.
