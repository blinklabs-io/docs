## v0.10.1

**Title:** Correct Plutus V4 evaluation and add scoped FLAT execution

**Version:** v0.10.1

**Release:** [v0.10.1](https://github.com/blinklabs-io/plutigo/releases/tag/v0.10.1)

**Comparison:** [v0.10.0...v0.10.1](https://github.com/blinklabs-io/plutigo/compare/v0.10.0...v0.10.1)

### Recommended Network Compatibility ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

This release corrects Plutus V4 evaluation behavior, adds allocation scaling coverage, and provides a scoped FLAT execution path with explicit compatibility checks for callers.

### Evaluator Compatibility
* Corrected Plutus V4 `chooseData` evaluation to use six arguments, removed the V4 only seventh `Value` branch, aligned builtin arity handling with the reference evaluator, and fixed six argument case applications. Scripts that depend on the removed seventh `Value` branch now fail and require migration.

### Allocation Safeguards
* Added allocation scaling coverage for hexadecimal bytestrings, strings, escaped newlines, and nested pair literals; the test enforces an 8x allocation cap when inputs scale from 1x to 4x.

### Scoped FLAT Execution
* Introduced `cek.RunFlat` for scoped FLAT De Bruijn decoding and evaluation. It can skip full term structure validation for sufficiently small inputs, reports decoder scope errors, batches step budget accounting, caches repeated `UnConstrData` conversions and builtin force counts, tightens frame accounting, reworks structural validation budgets, and clears stale decoder arena references after failed decodes. `RunFlat` preserves tested results, errors, and remaining `ExBudget`; callers must check the ledger language, builtin availability, and execution time version before use.
