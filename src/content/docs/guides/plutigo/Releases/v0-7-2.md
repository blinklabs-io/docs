## v0.7.2 (September 21, 2026)

**Title:** Defer execution checks and align evaluation behavior

**Date:** September 21, 2026

**Version:** v0.7.2

**Release:** [v0.7.2](https://github.com/blinklabs-io/plutigo/releases/tag/v0.7.2)

**Comparison:** v0.7.1...v0.7.2

This release improves reference script handling, keeps evaluation behavior consistent, aligns validation with phase two rejection rules, and updates the CBOR decoder for safer map handling.

### 🔧 Fixes

* Improved **script version handling:** Well formed reference scripts can now be stored and decoded when their declared term version is not yet supported for execution. Execution accepts term versions `1.0.0` and `1.1.0` subject to the existing Van Rossem `1.1.0` and PV11 rule, while decoding checks only ledger language availability and still rejects unsupported versions before evaluation. Constructors at version `1.1.0` or later now receive support handling.

* Simplified **evaluation behavior:** The language version now selects shared immutable definitions for builtins without arguments, replay cases decode once during validation and reuse that result during execution, and nested name scopes resolve the nearest binding before restoring the enclosing binding.

* Corrected **phase two validation:** Short cost model lists now assign `math.MaxInt64` to missing parameters so affected builtins exhaust their budget instead of using compiled in defaults. PV11 now rejects constants whose encoded type tag exceeds 32, and Schnorr verification returns false for out of range `r` or `s` values.

### 📦 Additional Changes

* Updated **CBOR safety:** The decoder now uses `github.com/fxamacker/cbor/v2` `2.9.4`, which includes an upstream fix for a potential panic when affected CBOR maps contain key values that cannot be compared.
