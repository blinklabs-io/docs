## v0.11.5

**Title:** Improve evaluator reuse and reference compatibility

**Version:** v0.11.5

**Release date:** 2026-11-06

**Release:** [v0.11.5](https://github.com/blinklabs-io/plutigo/releases/tag/v0.11.5)

**Comparison:** [v0.11.4...v0.11.5](https://github.com/blinklabs-io/plutigo/compare/v0.11.4...v0.11.5)

This release improves evaluator memory retention, repeated BLS12-381 decompression, input validation, budget handling, text parsing, and reference-compatible behavior.

### Reduce Retained Evaluation Memory

* Improved reusable CEK machine memory after deep evaluations by clearing used frame data and limiting retained frame stack capacity to 4,096 entries. Subsequent shallow evaluations continue to run correctly on the reused machine.

### Reuse Valid BLS12-381 Decompressions

* Added a bounded cache shared across the process and safe for concurrent use, with 64 shards and up to 64 entries per shard for successful 48-byte BLS12-381 G1 decompressions. The evaluator charges the budget and validates the exact input length before lookup, does not cache invalid decodes, and returns copied points so later mutations cannot alter cached values.

### Align Reference Behavior and Run Limits

* Updated out-of-range `Constr` tag encoding to match reference behavior; enforced 1,024 constructor field and 32 constant type tag limits at every protocol major version with early constant header rejection; required callers to set budgets explicitly before each run on reused CEK machines; aligned string escape parsing and pretty-printing with reference rules, including rejection of the Unicode escape form; and hardened pointer handling and arena sizing.
