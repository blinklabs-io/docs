## v0.9.6

**Title:** Allow trusted ledger data to bypass the aggregate node cap

**Version:** v0.9.6

**Release:** [v0.9.6](https://github.com/blinklabs-io/plutigo/releases/tag/v0.9.6)

**Comparison:** [v0.9.5...v0.9.6](https://github.com/blinklabs-io/plutigo/compare/v0.9.5...v0.9.6)

### Recommended Network Compatibility ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

This release lets scripts use large ledger-supplied inline datums without having those trusted values rejected by the aggregate PlutusData node cap.

### Reliability

* Improved trusted ledger data handling through `Machine.RunContextWithTrustedDataArguments(ctx, term, arguments...)`, which wraps supplied `PlutusData` arguments as trusted data constants while continuing to validate surrounding terms and applications. Trusted constants do not count toward the aggregate `maxDischargeWork` PlutusData node cap, while the existing `Run` and `RunContext` behavior remains unchanged because those methods pass no trusted data. The new path rejects nil or cancelled contexts, typed-nil data, too many arguments, and malformed builtin tags.
