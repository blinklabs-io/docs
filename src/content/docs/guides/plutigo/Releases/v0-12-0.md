## v0.12.0

**Title:** Share list storage with the evaluator

**Version:** v0.12.0

**Release date:** 2026-11-08

**Release:** [v0.12.0](https://github.com/blinklabs-io/plutigo/releases/tag/v0.12.0)

**Comparison:** [v0.11.6...v0.12.0](https://github.com/blinklabs-io/plutigo/compare/v0.11.6...v0.12.0)

This release reduces unnecessary allocation while the evaluator processes lists and clarifies the ownership rules for the data and protocol list APIs.

### Reduce Evaluator Allocations

* Improved evaluator efficiency for lists built with `mkCons` by using lazy persistent storage for list, map, and constructor data instead of eagerly copying contiguous slices; values materialize only when operations require size or cost information.
* Preserved the cons-cell representation when `unListData`, `unMapData`, and `unConstrData` decompose values and when `case` matches on `Data`, keeping these operations constant time.

### Validate Evaluator Inputs

* Validated evaluator allocations against defined bounds and standardized invalid data failures as `TypeError`, making evaluator behavior more predictable.

### Migrate Data Access APIs

* Standardized `data.List`, `data.Map`, and `data.Constr` access around `Items()`, `Pairs()`, and `Fields()` methods, replacing direct access to exported fields; use `Len()` for list and map lengths and `NumFields()` for constructor field counts.
* Added `data.WrapList`, `data.WrapMap`, and `data.WrapConstr` to transfer ownership of existing slices without copying, while the existing constructors continue to copy their input slices.
* Clarified the ownership contract: wrapper functions take ownership, and callers must not modify slices returned by accessors.
* Updated `syn.ProtoList` to use `List()` and `Len()` and added `syn.WrapProtoList` for ownership transfer.
