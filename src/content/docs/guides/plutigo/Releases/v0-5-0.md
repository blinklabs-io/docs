## v0.5.0

**Title:** Align compatibility checks and expand Plutus language support

**Version:** v0.5.0

This release aligns builtin availability with the Plutus ledger language and Cardano protocol, expands V4 and serialization support, strengthens program validation, and improves handling of large or bounded inputs.

### ✨ What's New

* Clarified **builtin availability:** Plutigo now checks each builtin against the selected Plutus ledger language and Cardano protocol major instead of applying the PV11 global unlock. The protocol boundaries are Alonzo 5, Vasil 7, Valentine 8, Chang 9, Plomin 10, and Dijkstra 12. V4 batches require protocol major 12, while protocol major 0 uses language only. CEK execution and conformance checks use the same availability matrix.
* Expanded **V4 language support:** Plutigo now includes authoritative V4 cost model parameter names and the `multiIndexArray`, `policies`, and `assetCount` builtins with stable tags 101 to 103. The V4 builtins remain unavailable until protocol activation. `multiIndexArray` accepts typed arrays or lists, requires nonnegative int64 indices, checks bounds, and limits each request to 1,024 indices. V4 parameter ordering no longer aliases V3, so execution budgets can differ.
* Preserved **V1 and V2 `consByteString` behavior:** Large positive and negative integer prefixes now use floored modulo 256 reduction for SemanticsVariantD, matching the V1 and V2 variants. V3 and later variants C and E continue to require values from 0 through 255.

### 🔧 Fixes

* Validated **Plutus programs with context:** Context aware parsing and decoding now check supported UPLC versions 1.0.0 and 1.1.0, builtin availability by ledger language and protocol, unavailable builtins in unevaluated branches, the UPLC 1.1.0 requirement for `Constr` and `Case` syntax, and the PV11 and later limit of 1,024 constructor fields. Replay decoding now uses the same context.

### ⚡ Performance

* Optimized **large integer decoding:** FLAT large integers now accumulate directly in native `big.Word` storage with a `uint64` fast path. The decoder scales linearly with bounded allocation while preserving truncation behavior.

### 📦 Additional Changes

* Extended **supported universe types:** FLAT now provides stable tags for BLS12-381 G1, G2, and Miller loop values, plus array and value types, with byte identical round trips. `ProtoArray` and `Value` types support parser and pretty printer workflows; CEK execution preserves array and value identity, validates canonical `Value` entries, and rejects unsupported standalone BLS payloads. `Machine.RunContext(ctx, term)` provides synchronous cancellation, `valueData` accepts at most 40,000 entries, and CBOR bytestring leaves or chunks are limited to 64 bytes with `DecodeLimitError` for violations.

### 📋 What You Need to Know

Programs that parse, decode, or execute Plutus terms should supply ledger language and protocol context so version and builtin availability rules apply consistently. V4 builtins are unavailable until activation and require protocol major 12; consumers that process large values should also handle the documented size limits and `DecodeLimitError`.

### 🙏 Thank You

Thank you for using Plutigo.
