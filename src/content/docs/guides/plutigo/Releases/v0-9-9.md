## v0.9.9

**Title:** Reject non-canonical Value constants

**Version:** v0.9.9

**Release:** [v0.9.9](https://github.com/blinklabs-io/plutigo/releases/tag/v0.9.9)

**Comparison:** [v0.9.8...v0.9.9](https://github.com/blinklabs-io/plutigo/compare/v0.9.8...v0.9.9)

### Recommended Network Compatibility ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

This release requires public UPLC text parsing and Flat decoding to reject non-canonical `Value` constants instead of normalizing them.

### Parsing

* Improved public UPLC text parsing through `Parse` and `ParseWithContext` so it rejects non-canonical `Value` constants rather than normalizing them.

### Decoding

* Strengthened Flat decoding so it rejects non-canonical `Value` constants rather than normalizing them.

### Validation

* Corrected handling for malformed `Value` literals with duplicate or out-of-order policy or token keys, empty inner token maps, zero-quantity entries, or quantities outside the signed 128-bit range.

### Compatibility

* Updated compatibility behavior so clients that relied on malformed `Value` literals being accepted and normalized now receive parse or decoding errors.

For reference, see [PR #493](https://github.com/blinklabs-io/plutigo/pull/493).
