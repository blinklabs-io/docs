## v0.10.0

**Title:** Harden evaluator and align Plutigo with PV11

**Version:** v0.10.0

**Release:** [v0.10.0](https://github.com/blinklabs-io/plutigo/releases/tag/v0.10.0)

**Comparison:** [v0.9.11...v0.10.0](https://github.com/blinklabs-io/plutigo/compare/v0.9.11...v0.10.0)

This release strengthens evaluation and data processing against resource exhaustion and consensus divergence, with conformance verified against `cardano-node` 11.1.3 (PV11). It also adds migration options for integrations and updates the `btcec/v2` dependency without changing runtime behavior.

### Evaluator Security and Conformance

* Improved evaluator resilience against resource exhaustion and consensus divergence with panic recovery and `RunScriptContext` based evaluation.
* Added zero width FLAT memoization plus lexer, parser, and FLAT varint limits to bound resource use during script processing.
* Added structurally shared `Value` helpers and persistent runtime lists to make evaluation more robust.
* Enforced libsodium strict Ed25519 verification for consistent signature validation.
* Applied PV11 bounded builtin arguments and charge then check budget semantics, including piecewise costs for data and list operations.
* Added De Bruijn slippage batching with `DefaultSlippage=200` to improve evaluation consistency.

### Data Processing

* Improved CBOR handling with iterative decoding and walking so deeply nested data can be processed without relying on recursive traversal.
* Rejected CBOR tag `1401` and long head bignum tags by default to prevent unsupported representations from entering data processing.
* Added caps for JSON input size and integer digit count, with configuration options for integrations that need to set these limits.
* Tightened `Integer` and `ByteString` CBOR unmarshalling to enforce stricter input validation.
* Added single item CBOR decoding that can ignore trailing bytes when an input contains additional data after the first item.

### Evaluation and Integration

* Added unit result checking that validates the final result without expanding it.
* Added token `Value` overflow reporting so integrations can detect values that exceed supported bounds.
* Updated evaluation entry points to use `RunScriptContext` for context aware script execution.
* Normalized datums and redeemers through `data.Normalize` before evaluation to provide a consistent representation.
* Updated integration handling for stricter CBOR decoding, including the default rejection of unsupported tags and bounded JSON input.
* Updated `BudgetError` interpretation to reflect charge then check budget semantics and the release's piecewise data and list costs.

### Dependency Maintenance

* Updated `github.com/btcsuite/btcd/btcec/v2` from `v2.5.0` to `v2.5.1`, along with the corresponding `go.mod` and `go.sum` entries.
* Updated the indirect `secp256k1/v4` dependency from `v4.4.0` to `v4.4.1` without changing runtime behavior.
