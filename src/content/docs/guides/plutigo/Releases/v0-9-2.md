## v0.9.2

**Title:** Harden parsing and data normalization

**Version:** v0.9.2

**Release:** [v0.9.2](https://github.com/blinklabs-io/plutigo/releases/tag/v0.9.2)

**Comparison:** v0.9.1...v0.9.2

**Date:** 2026-10-11

### Recommended Network Compatibility ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

This release strengthens input validation for embedded NUL characters, prevents typed nil data containers from causing panics during normalization, and adds licensing attribution to the Go source files.

### Breaking Changes

* Improved input validation so `syn.Parse` and `ParseWithContext` reject valid prefixes followed by embedded U+0000 or trailing text instead of accepting only the prefix. Embedded U+0000 remains preserved in string literals, skipped in comments, and rejected in byte strings. Applications that relied on U+0000 to truncate input must update their inputs.

### Reliability

* Protected `data.Normalize` from dereferencing typed nil `*Constr`, `*Map`, and `*List` values. The function now returns those inputs unchanged instead of causing nil pointer panics, while preserving the existing behavior for nil `*Value` inputs.

### Additional Changes

* Added the standard Blink Labs Apache 2.0 copyright header to 137 Go files for licensing attribution and compliance maintenance, without changing runtime or API behavior.
