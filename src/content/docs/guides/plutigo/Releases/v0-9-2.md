## v0.9.2

**Title:** Harden parsing and data normalization

**Version:** v0.9.2

**Release:** [v0.9.2](https://github.com/blinklabs-io/plutigo/releases/tag/v0.9.2)

**Comparison:** v0.9.1...v0.9.2

**Date:** 2026-10-11

### Recommended Network Compatibility ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

This release distinguishes embedded NUL characters from the end of input, prevents typed nil data containers from causing normalization panics, and adds licensing attribution to the Go source files.

### Breaking Changes

* Improved parser validation so `syn.Parse` and `ParseWithContext` reject valid prefixes followed by embedded U+0000 or by trailing text instead of accepting only the prefix. The parser preserves U+0000 in string literals, skips it in comments, and rejects it in byte strings. Applications that relied on U+0000 to truncate input must update their inputs.

### Reliability

* Protected data normalization from nil pointer panics when it receives typed nil `*Constr`, `*Map`, or `*List` values. `data.Normalize` now returns those values unchanged, while nil `*Value` behavior remains unchanged.

### Additional Changes

* Added the standard Blink Labs Apache 2.0 copyright header to 137 Go files, strengthening licensing attribution and compliance without changing runtime or API behavior.
