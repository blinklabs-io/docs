## v0.9.5

**Title:** Improve evaluation safety and data handling

**Version:** v0.9.5

**Release:** [v0.9.5](https://github.com/blinklabs-io/plutigo/releases/tag/v0.9.5)

**Comparison:** [v0.9.4...v0.9.5](https://github.com/blinklabs-io/plutigo/compare/v0.9.4...v0.9.5)

### Recommended Network Compatibility ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

This release improves bounded evaluation, aligns builtin parsing with protocol limits, strengthens repository automation, corrects value cost accounting, and prevents retained decoded programs from being corrupted.

### Evaluation safety

* Improved `serialiseData`, `equalsData`, and `unValueData` sizing so iterative traversal checks lower budget bounds early, honors cancellation, and applies the exact final cost. Oversized data graphs can now stop with `BudgetError` before full traversal, cancellation preserves the original context error, and malformed data returns `ErrCodeInvalidArgument` instead of causing a panic.

### Builtin compatibility

* Refined builtin parsing for nonzero protocol majors before major 11: case analysis on builtin values now returns `ErrCodeCaseOnBuiltinUnavailable`, while constructors and existing byte string constant behavior remain available. Semantics D and E now reject `writeBits` byte payloads above 4096 bytes, and the parser accepts `verifySignature` as an alias for `verifyEd25519Signature`.

### Automation safety

* Strengthened repository automation by pinning reusable workflows and NilAway to exact revisions, narrowing workflow permissions, and hardening Makefile format and clean commands. The conformance updater now verifies digests, enforces bounds and an allowlist, and stages changes with rollback. Replay corpus preprocessing enforces size, count, and decoded byte limits, caches decoded cases, and honors cancellation.

### Value accounting

* Corrected size dependent value costs with immutable cached metrics and deep copy accessors. CEK value builtins now use those metrics; `AssetCount` and `unionValue` charge according to actual value size; uninitialized values fail before costing; and `AssetCount` accepts values beyond `valueDataMaxSize`. Existing code that constructs values through the exported `Value.Entries` field must migrate to `syn.NewValue` and its accessors because that field is no longer available.

### Decoder ownership

* Returned independently owned programs from `DeBruijnDecoder.Decode`, preventing retained results from changing after later decodes. Use `DecodeBorrowed` for arena reuse only when results remain valid until the next decode, and do not share a decoder across concurrent calls. Callers that previously depended on `Decode` arena reuse may see more allocations.
