## v0.9.4

**Title:** Improve validation and execution safety

**Version:** v0.9.4

**Release:** [v0.9.4](https://github.com/blinklabs-io/plutigo/releases/tag/v0.9.4)

**Comparison:** [v0.9.3...v0.9.4](https://github.com/blinklabs-io/plutigo/compare/v0.9.3...v0.9.4)

### Recommended Network Compatibility ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

This release strengthens Plutus version validation, bounds diagnostics for invalid inputs, and makes CEK evaluation safer for malformed caller-supplied terms.

### Compatibility

* Improved phase-one validation so Plutus V1–V3 programs reject Plutus V4-only `data.Value` constructors inside constants, including nested composite constants. The validation reports `Value data is not available in Plutus V<n>` and continues to accept these constructors for Plutus V4 during `ParseWithContext` and `DecodeWithContext`.

### Diagnostics

* Refined invalid input handling by charging relevant builtin costs before returning errors and limiting diagnostics for invalid large integers and invalid UTF-8. Integer errors report sign and bit length; UTF-8 errors report input length instead of rendering full input contents.

### Reliability

* Hardened CEK evaluation by validating caller-constructed terms before execution, returning `ErrCodeTypeMismatch` for malformed terms or constants instead of panicking. Validation, discharge, and cloning honor cancellation and bounded structural and scalar work.
