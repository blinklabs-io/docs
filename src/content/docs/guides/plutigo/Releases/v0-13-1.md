## v0.13.1

**Title:** Reject Value data constants consistently

**Version:** v0.13.1

**Release date:** 2026-11-19

**Release:** [v0.13.1](https://github.com/blinklabs-io/plutigo/releases/tag/v0.13.1)

**Comparison:** [v0.13.0...v0.13.1](https://github.com/blinklabs-io/plutigo/compare/v0.13.0...v0.13.1)

### Recommended Network Compatibility ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

This release rejects Value-form PlutusData, represented by CBOR tag `1401` or `V [...]`, consistently across parsing, program validation, and FLAT encoding. It also detects cycles in caller-constructed `ProtoPair` graphs during validation.

### Reject Value Data During Parsing

* Fixed parsing so Value-form PlutusData no longer succeeds.

### Reject Value Data During Program Validation

* Improved validation for ledger languages V1–V4 so `ValidateProgram` rejects Value-form PlutusData with `errValueData`.

### Reject Value Data Before FLAT Encoding

* Prevented FLAT encoding from serializing Data constants that contain Value-form PlutusData, avoiding bytes that cannot round trip.

### Detect Cycles in ProtoPair Graphs

* Added active-path cycle detection for caller-constructed `ProtoPair` graphs, with validation returning `errCyclicPair` for cyclic graphs.

### Breaking Change for Value Data Workflows

* Changed Value-form data handling: workflows that use these constants must replace them with supported PlutusData forms before parsing, program validation, or FLAT encoding.
