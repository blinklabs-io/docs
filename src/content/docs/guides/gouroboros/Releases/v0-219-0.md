## v0.219.0

**Title:** Add one-shot chain intersection and improve validation performance

**Version:** v0.219.0

This release adds one-shot chain intersection for idle ChainSync clients, improves bootstrap witness handling, and reduces phase 2 Plutus validation time.

### New Features

* Added `Client.Jump(points []pcommon.Point)` for a one-shot `FindIntersect` operation without syncing. The method returns the intersection point, server `Tip`, a `found` boolean, and an error. It reports `ErrSyncInProgress` while a sync loop runs or `MsgRequestNext` remains unanswered, serializes concurrent operations, drains stale ready signals, and supports calling `Sync` after `Jump`.

### Bug Fixes

* Corrected witness validation by counting computable `BootstrapWitness` address roots as provided key hashes for required signers, Shelley key hash inputs, and key-locked collateral. Byron missing-bootstrap errors remain distinct.

### Performance

* Reduced per-transaction phase 2 validation time by 6.3% in the supplied 532-transaction benchmark by keying the Plutus program cache with a per-process seeded `maphash` key. The cache clones script bytes to validate collisions, compares bytes safely, reduces mutex contention, and treats collisions as misses without replacing existing entries.
