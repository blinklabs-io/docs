## v0.218.3

**Title:** Improve protocol compatibility and transaction validation

**Version:** v0.218.3

This release improves ChainSync throughput, protocol decoding, ledger validation, Plutus compatibility, native-script signatures, and Leios endorser-block handling.

### Bug Fixes

* Updated the Plutigo dependency from `v0.11.4` to `v0.12.0` and switched Plutus data access to read-only methods. The reference decoder now accepts at most 32 constant tags and 1024 constructor fields.
* Improved ChainSync throughput on high latency connections by maintaining a sliding `RequestNext` window and refilling it to `PipelineLimit` while preserving callback backpressure. Fixed a shutdown race during reintersect.
* Allowed Mary outputs with a positive asset quantity to fall below `MinUtxoValue`; asset-free outputs and outputs containing only zero quantities still undergo minimum coin validation.
* Preserved phase 2 invalid Dijkstra transaction handling by skipping value conservation and cross-level duplicate-input checks while always enforcing treasury donation compatibility with Plutus V1 and V2.
* Rejected unsupported Dijkstra body fields during Plutus V1 through V3 transaction info construction and script validation with `UnsupportedFeatureError`. Key-hash guards and starting balance intervals remain available, and Plutus V4 bypasses this restriction.
