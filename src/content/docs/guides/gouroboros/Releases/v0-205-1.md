## v0.205.1

**Title:** Bound committee terms at ratification and widen expiry epochs

**Version:** v0.205.1

This release updates the Conway governance API to support wider committee expiry epochs and adds constitutional committee term checks at epoch boundary ratification. Callers must use `uint64` expiry values, and over limit proposals remain valid for UTxO transaction admission until ratification evaluates the term bound.

### 💥 Breaking Changes

* Updated **committee expiry epoch types:** `UpdateCommitteeGovAction.CredEpochs` and `NewUpdateCommitteeGovAction` now use `uint64` map values instead of `uint`. Callers must update their types, and expiry values at or above 2^32 no longer narrow on 32 bit builds.

### ✨ New Features

* Added **committee term limit capability:** `common.CommitteeMaxTermLengthProvider` lets Conway and Dijkstra protocol parameters expose the constitutional maximum committee term. Implementations report unavailable limits safely, including when the parameter value is nil.

* Introduced **committee term ratification validation:** `conway.ValidateCommitteeTerm(action, pp, currentEpoch)` checks proposed expiry epochs against the constitutional maximum and returns `CommitteeTermLimitUnavailableError` or `CommitteeTermTooLongError` when appropriate.

### 🐛 Bug Fixes

* Refined **committee term boundary handling:** The ratification check uses wrapping `uint64` addition for `currentEpoch + maxTermLength` and sorts proposed terms before selecting an offending credential, producing consistent results at numeric boundaries.

* Clarified **committee proposal timing:** Committee term limits do not apply during UTxO transaction validation. Over limit proposals can pass transaction admission and remain subject to the term check when epoch boundary ratification occurs.
