## v0.208.1

**Title:** Strengthen protocol validation and compatibility

**Version:** v0.208.1

This release improves connection reliability, separates proposal validation concerns, strengthens transaction submission checks, expands era compatibility, and standardizes gOuroboros branding.

### Features
* Improved connection reliability by processing incoming messages in smaller steps, applying byte limits to each protocol state, admitting peer initiated and pipelined messages only when permitted, and checking message submission request counts and windows. Deployments can set `MaxUnacknowledgedMessageIDs`; it defaults to `100`.
* Refined proposal handling so generic checks and decoding accept protocol-only proposals whose system tags fall outside ledger-state length or ASCII rules. `ValidateSystemTags` still applies those checks when ledger state is available.

### Compatibility and Breaking Changes
* Strengthened transaction submission validation for transaction IDs, request and reply correlation, transaction eras, body sizes, advertised-size tolerance, ordering, concurrency, and shutdown state.
* Verified compatibility with 12-field Dijkstra and Leios extended headers, corrected the required transaction-body CBOR keys from Shelley through Babbage, and encoded an empty metadata set as `{}`.

### Additional Changes
* Standardized gOuroboros branding across agent guides and corrected the README logo alternative text.
