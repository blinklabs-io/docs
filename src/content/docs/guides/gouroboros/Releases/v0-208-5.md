## v0.208.5

**Title:** Improve state query compatibility, Plutus validation performance, and pledge leverage validation

**Version:** v0.208.5

This release improves current node to client local state query compatibility, reduces repeated setup during Plutus validation, and lets Dijkstra pledge leverage validation accept a broader range of values.

### Bug Fixes
* Fixed current node to client local state query `GetGenesisConfig` decoding for NtC 21 and later by encoding the `A0`, `Rho`, `Tau`, and `DecentralizationParam` rational pairs with CBOR tag 30. Decoding accepts both tagged and bare pairs, while NtC 20 and earlier retains the legacy layout.
* Expanded Dijkstra `maxPledgeLeverage` validation to accept any non-negative bounded rational, including zero and values outside `[1,10000]`, while continuing to reject negative values. `CalculateRewards` continues to support `[1,10000]`.

### Performance
* Improved Conway and Dijkstra validation performance for Plutus V1 through V4 by reusing bounded evaluation contexts and CEK machines between evaluations when safe. Budget enforcement remains active, and the evaluator discards a machine after a panic.
