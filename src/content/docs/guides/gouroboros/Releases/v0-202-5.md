## v0.202.5 (September 2, 2026)

**Title:** Refine ledger validation and protocol reliability

**Date:** September 2, 2026

**Version:** v0.202.5

This release improves era-specific transaction validity, validates Conway and Dijkstra ledger state more strictly, preserves protocol results during shutdown, and rejects duplicate encoded data.

### 💪 Improvements

* Improved **validity interval encoding:** Transactions with only an upper validity bound now encode that bound as exclusive in Conway and later eras, while Alonzo and Babbage retain closed upper bounds.

* Updated **transaction information APIs:** `StrictValidityUpperBoundForTransaction` now provides the strict upper-bound behavior, and `NewTxInfoV1` and `NewTxInfoV2` use updated signatures. Applications that call these constructors must update their arguments to match.

* Strengthened **certificate accounting:** Conway and Dijkstra certificate deposits and refunds now match recorded ledger state through `StakeCredentialDepositState`, preventing transactions from using inconsistent deposit values.

* Corrected **withdrawal and deregistration accounting:** Withdrawals must leave a zero reward balance, and legacy stake credential deregistration now uses the recorded deposit amount.
