## v0.206.1

**Title:** Bound peer responses and strengthen validation
**Title:** Limit peer responses and improve validation

**Version:** v0.206.1

This release limits peer sharing responses, expands ledger verification coverage without changing production behavior, and rejects malformed pool relay data during decoding.

### Bug Fixes
* Fixed **SharePeers response limits:** The server now limits each reply to the requested number of peers and to `MaxSharedPeers=230`, while `MaxPendingMessageBytes=5,760` caps pending response data. The client rejects an over-limit reply with `ErrTooManyPeersShared`, and protocol-limit documentation and tests cover these boundaries.
* Fixed **SharePeers response limits:** The server limits each reply to the requested number of peers, up to `MaxSharedPeers=230`, and `MaxPendingMessageBytes=5,760` limits pending response data. The client rejects a reply above those limits with `ErrTooManyPeersShared`, and protocol-limit documentation and tests cover these boundaries.

### Additional Changes

* Expanded **ledger verification coverage:** Tests exercise real mainnet Conway fixtures through the production `NewBlockFromCbor`, `VerifyBlock`, `VerifyKes`, and `VerifyKesComponents` paths to validate block body hashes, VRF data, and KES data. This release adds coverage without changing production behavior.
* Expanded **ledger verification coverage:** Tests use real mainnet Conway fixtures with the production `NewBlockFromCbor`, `VerifyBlock`, `VerifyKes`, and `VerifyKesComponents` paths to validate block body hashes, VRF data, and KES data. This release adds coverage without changing production behavior.

* Hardened **pool relay decoding:** The CBOR decoder now rejects IPv4 byte strings unless they contain exactly `4` bytes, IPv6 byte strings unless they contain exactly `16` bytes, and null `dns_name` values for hostname relay types. It reports `ErrPoolRelayAddressWidth` or `ErrPoolRelayMissingHostname`, while validation tests and pool registration certificate tests cover these cases.
