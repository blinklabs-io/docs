## v0.201.1 (August 26, 2026)

**Title:** Improve responder behavior and stake registration validation

**Date:** August 26, 2026

**Version:** v0.201.1

This release keeps unconfigured Leios requests pending, rejects duplicate Conway stake registrations, strengthens validation sequencing coverage, and keeps transaction submission replies synchronized during responder protocol replacement.

### 💪 Improvements

* Refined **unconfigured Leios responders:** Block, BlockTxs, BlockRange, and RequestNext requests remain pending without a response or connection-level protocol error when callbacks are not configured. The Busy timeout is disabled for unconfigured votes callbacks. Configured callback errors, transport failures, and invalid vote parameters continue to surface.

* Corrected **duplicate Conway stake registrations:** Transactions that register an already registered stake credential or register the same credential more than once now fail with `StakeCredentialAlreadyRegisteredError`. A deregistration followed by registration in the same transaction remains allowed, and the ledger tracks credential type and hash independently.

* Expanded **stake registration sequencing coverage:** Ledger regression tests now verify that duplicate registration errors take precedence over unregistered pool or DRep targets and that delegation after a same-transaction deregistration is rejected.

* Stabilized **transaction submission replies:** Transaction ID and transaction body reply handling now accesses the current responder protocol safely while protocol replacement occurs, preserving reply delivery during concurrent restarts.
