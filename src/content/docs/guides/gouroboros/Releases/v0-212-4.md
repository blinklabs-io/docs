## v0.212.4

**Title:** Require canonical ledger tuple encoding

**Version:** v0.212.4

This release makes ledger CBOR decoding reject fixed shape tuple values that use indefinite length arrays or include trailing CBOR bytes.

### Breaking Changes

* Improved ledger decoding by requiring fixed shape tuple fields to use definite length CBOR arrays and contain no trailing CBOR bytes. This applies to execution units, redeemer keys and values, voting procedures, governance IDs and anchors, Conway proposal procedures, the Conway protocol parameter execution costs field, and Mary transaction output values. Dijkstra voting procedures still accept indefinite length arrays, and selected protocol parameter execution unit tags remain permissive. Transaction and block parsing can now reject previously accepted non canonical encodings.
