## v0.204.0

**Title:** Make DRep deposit validation fail closed

**Version:** v0.204.0

This release makes DRep deposit handling safer by rejecting deregistration when the recorded deposit is absent, using recorded deposits for refunds when available, distinguishing complete credentials during in-transaction registration, and propagating lookup errors during delegation validation.

### 💪 Improvements

* Improved **DRep deregistration checks:** The ledger now rejects a deregistration when the registered DRep has no recorded deposit and returns `DRepDepositStateInconsistentError`, preventing a refund without deposit state.

* Applied **recorded deposits to refunds:** When a DRep deposit is present, refund comparisons now use the recorded amount.

* Distinguished **complete in-transaction DRep credentials:** Lookups now use the credential type and 28-byte hash, so key and script credentials with matching hashes remain separate.

* Propagated **DRep lookup errors during delegation validation:** Lookup errors now reach callers instead of appearing as unregistered DReps.

* Added **deposit edge case coverage:** Automated tests now verify fail closed behavior when a deposit is absent and refunds based on recorded deposits.

### ⚠️ Breaking changes and migration

* Changed **DRep registration construction:** `DRepRegistration.Deposit` now accepts a pointer to the deposit. Implementations that construct DRep registrations must provide a pointer when a recorded deposit exists and `nil` when the deposit is absent.
