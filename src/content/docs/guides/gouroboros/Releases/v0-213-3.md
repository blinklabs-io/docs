## v0.213.3

**Title:** Align consensus leader eligibility with Cardano's finite E34 predicate

**Date:** 2026-10-16

**Version:** v0.213.3

This release aligns consensus leader eligibility with Cardano's pinned finite E34 arithmetic, adds mode-specific CPraos and TPraos evaluation, and removes the previous threshold API.

### New Features

* Introduced `NewLeaderEligibility(poolStake, totalStake, f, mode)` with CPraos and TPraos modes for preparing leader eligibility evaluation.

* Aligned leader selection with Cardano's finite E34 predicate instead of the former ideal real number threshold, using a bounded comparator and BELOW-only election to follow the pinned finite arithmetic.

* Enabled immutable prepared evaluators with `CheckCertifiedNatural` and `CheckVRFOutput`; leader election and header validation now use the evaluator and the mode-specific VRF natural derivation.

* Cached prepared evaluator states in a bounded, mutex-protected 4096-entry least recently used cache.

### Bug Fixes

* Validated active-slot coefficient domains, clamped pool stake values above total stake, and returned an ineligible zero result for zero stake.

* Maintained VRF proof and output validation for positive-stake searches with nonpositive coefficients while keeping those searches ineligible.

* Rejected slots above `math.MaxInt64` before constructing VRF input.

### Breaking Changes

* Removed the former `threshold.go` API and `LeaderElectionResult.Threshold`. Callers using `CertifiedNatThreshold`, `IsVRFOutputBelowThreshold`, related mode variants, or `Threshold` must migrate to the leader eligibility evaluator APIs.

### Additional Changes

* Refreshed tests, conformance fixtures, benchmarks, and allocation regression coverage for finite E34 leader eligibility.

* Recognized AndrewWestberg's first contribution to gOuroboros.
