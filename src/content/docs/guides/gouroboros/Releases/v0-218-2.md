## v0.218.2

**Title:** Improve transaction validation and ledger compatibility

**Version:** v0.218.2

This release improves transaction envelope handling, verification configuration, decoder strictness, genesis JSON compatibility, legacy Plutus translation, and Dijkstra performance.

### Bug Fixes

* Improved Alonzo-family transaction envelope handling by accepting canonical three-component envelopes without `IsValid`, using canonical transaction-size sizing, classifying transaction eras more reliably, and rejecting malformed shifted `IsValid` forms.
* Corrected Byron bootstrap output attribute sizing to count decoded HD derivation-path payload bytes and unknown attribute values only, excluding CBOR framing, keys, and network magic while preserving the 64-byte limit.
* Tightened decoder validation by rejecting 64-bit CBOR map heads for Babbage outputs and Conway redeemers, requiring ascending Byron attribute keys, and applying version 12 bounded-rational checks to specified Dijkstra parameter fields.
* Counted stake registration deposits and deregistration refunds for phase 2 invalid Alonzo and Babbage transactions.
* Fixed bootstrap native-script witness hashes by using the Byron address root and skipping malformed roots.
* Revised genesis JSON validation and normalization for Shelley, Alonzo, and Conway to align with the reference behavior. Genesis JSON inputs must now satisfy required fields and numeric bounds, use supported aliases, handle repeated keys correctly, and use canonical numeric forms.
* Rejected Babbage map-form outputs that omit address key `0` or value key `1`, with Conway regression coverage preserving the same validation expectation.
* Aligned legacy Plutus V1 and V2 withdrawal ordering and Byron filtering, and added `GenesisKeyDelegation` and MIR certificate translation.

### Breaking Changes

* Added `VerifyConfig.MaxKesEvolutions` and `SkipKesEvolutionsValidation`. Verification now requires an explicit nonzero KES configuration unless validation is skipped and enforces the Shelley `maxKESEvolutions` bound in `VerifyBlock`; `VerifyBlockLocal` remains unchanged.

### Performance

* Reduced allocations for cached Dijkstra transaction hashes without changing hash behavior.
