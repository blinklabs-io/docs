## v0.208.2

**Title:** Improve pipeline reliability and Plutus V4 compatibility

**Version:** v0.208.2

This release makes out-of-order block processing more predictable, aligns Plutus V4 guard data with reference behavior, and validates full-width UTxO-RPC rational boundaries.

### Improvements
* Improved out-of-order block handling by waiting for pending capacity before assigning sequence numbers, rejecting over-limit items before retention, allowing `MaxPendingBlocks: 0` to disable the limit, and delivering fatal `ErrPendingLimitExceeded` errors without blocking. ChainSync now stops rollback after a failed drain and returns `protocol.ErrProtocolShuttingDown` during shutdown without invoking the rollback callback.

### Compatibility and Breaking Changes
* Updated Plutus V4 required-guard map ordering so script credentials precede key credentials and same-type credentials sort by credential bytes, matching the reference behavior and making the order deterministic for scripts.
* Removed the concrete Dijkstra V4 subtransaction index from top-level and guarded child contexts by encoding it as absent. Scripts and tools that read this field must handle an absent value.

### Additional Changes
* Expanded validation coverage for full-width UTxO-RPC rationals across Shelley, Alonzo, and Conway to confirm exact `int32` and `uint32` boundaries and reject out-of-range values in Conway voting thresholds.
