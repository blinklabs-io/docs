## v0.213.1

**Title:** Strengthen validation and protect derived key material

**Version:** v0.213.1

This release strengthens block, transaction, protocol, and cryptographic validation while limiting resource growth during composite CBOR map key processing.

### Bug Fixes

* Fixed block body verification so it consumes the complete outer transaction array and rejects trailing CBOR or non-CBOR bytes.

* Corrected phase two validation across Alonzo through Dijkstra by executing required Plutus scripts and requiring execution outcomes to match `TxIsValid`, with deterministic handling for unexpected success and malformed reference scripts.

* Improved reward recipient allocation validation by comparing each operator and delegator allocation by `RewardCredential`, rejecting missing, additional, substituted, and credential kind mismatches instead of comparing totals only.

* Matched ChainSync intersection replies only when the slot and hash exactly matched an offered `FindIntersect` point tied to a pending request; unsolicited or unoffered replies now return errors without callbacks or tip publication.

### Security

* Added secure wiping for temporary KES and VRF derived key material on success and error paths while preserving returned outputs.

* Hardened KES signing key validation by checking key depth and exact data length before signing, updating, or deriving public keys; malformed keys now return errors or `nil` rather than panic, while cached public keys remain available after zeroization.

* Strengthened Byron SSC payload validation to reject malformed payloads before processing.

* Bounded composite CBOR map key hashing by accumulating identity digests during nested map and array decoding, preserving duplicate key detection while preventing repeated subtree traversal from causing unbounded CPU and allocation growth.
