## v0.210.0

**Title:** Strengthen protocol limits and expand ledger access

**Version:** v0.210.0

This release strengthens protocol input and connection resource limits, expands Plutus script evaluation access, and improves Babbage datum handling and documentation.

### Improvements
* Improved protocol safety by bounding KES decoding depth at `MaxDepth` 63, KeyGen depth at `MaxKeyGenDepth` 12, handshake Propose and Confirm pending messages at `5,760` bytes, and keep-alive active-state messages at `65,535` bytes; the release documents these limits and tests boundary and oversized inputs.
* Added a default `64 MiB` connection-wide muxer ingress budget with `SetIngressBudget`, `IngressBudget`, `IngressInUse`, and `ErrIngressOverflow`; per-role budget extensions and `PendingReceiveByteBudget` accounting support controlled backpressure. Node-to-client ChainSync receives use an `8 MiB` pending receive budget, and protocol limits documentation and tests verify backpressure and release behavior.

### New Features
* Expanded Plutus script evaluation access through exported `conway.EvaluatePlutusScripts` with optional budget semantics and `dijkstra.EvaluatePlutusScripts` returning per-redeemer consumed ExUnits across sub-transactions, guarding scripts, and V4 contexts; the release also exports `ApplyConwayRefScriptFeeDefaults`, uses shared validation checks, and returns an error for nil Conway transactions.

### Additional Changes
* Clarified Babbage datum handling with nil-safe `IsDatumHash` and `IsInlineDatum` predicates, documented Plutus Data constructor tag ranges and how they differ from ledger sum-type list decoding, and added byte-preserving CBOR round-trip tests.
