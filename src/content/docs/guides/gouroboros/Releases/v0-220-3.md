## v0.220.3

**Title:** Improve protocol compatibility and ledger validation

**Release date:** 2026-11-16

**Version:** v0.220.3

This release expands protocol compatibility for node-to-node and node-to-client connections, strengthens era-aware transaction and ledger validation, and improves chainsync and reference-script accounting.

### Bug Fixes

* Updated `ouroboros-mock` to v0.21.2 and routed embedded consensus fixtures through a test hook so fixture coverage remains available without an import cycle.
* Enforced era-specific rules for duplicate transaction-metadata labels: Conway and Dijkstra reject duplicate top-level labels, while pre-Conway eras keep the last value and preserve original CBOR.
* Simplified `GetConstitution` and `GetRatifyState` results by returning the era value directly instead of a one-element wrapper.
* Refined Dijkstra per-block reference-script accounting so it counts only top-level transactions, outputs, and collateral returns.
* Enabled node-to-node chainsync `RollForward` for Byron EBB and main blocks with correct block type handling.
* Aligned committee-members local-state-query decoding with the `cardano-ledger` `Sum` and `StrictMaybe` wire formats and returned the era value directly.
* Prevented stale chainsync readiness signals by retiring `RequestNext` before returning ranges.
* Preserved spent inputs during block reference-script UTxO accumulation and treated `ErrUtxoNotFound` as an expected absence.
* Standardized `MultiAsset` policy and asset iteration and added unordered helpers so order-insensitive validation avoids sorting.
* Accepted node-to-client Dijkstra `CertRBs` with inlined endorser-block transactions by applying node-to-client body hash, size, and transaction validation.
