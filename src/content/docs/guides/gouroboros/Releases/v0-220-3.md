## v0.220.3

**Title:** Improve protocol compatibility and ledger validation

**Version:** v0.220.3

This release improves protocol compatibility across node-to-node and node-to-client connections, strengthens era-specific transaction and ledger validation, and improves chainsync and reference-script handling.

### Bug Fixes

* Updated `ouroboros-mock` to v0.21.2 and routed embedded consensus fixtures through a test hook, preserving fixture coverage without an import cycle.
* Enforced era-specific duplicate transaction-metadata label rules: Conway and Dijkstra reject duplicate top-level labels, while pre-Conway eras retain the last value and preserve the original CBOR.
* Simplified `GetConstitution` and `GetRatifyState` results by unwrapping their single era wrapper.
* Refined Dijkstra per-block reference-script accounting to count only top-level transactions and top-level outputs or collateral returns.
* Enabled node-to-node chainsync `RollForward` for Byron EBB and main blocks with correct block type handling.
* Aligned committee-members local-state-query decoding with `cardano-ledger` `Sum` and `StrictMaybe` wire formats and unwrapped the era result.
* Prevented stale chainsync readiness signals and waited for `RequestNext` retirement before returning ranges.
* Preserved spent inputs while accumulating block reference-script UTxO and handled absent UTxOs through `ErrUtxoNotFound` aware logic.
* Standardized `MultiAsset` policy and asset iteration and added unordered helpers for order-insensitive validation without sorting.
* Accepted node-to-client Dijkstra `CertRBs` with inlined endorser-block transactions using node-to-client body hash, size, and transaction validation.
