## v0.220.4

**Title:** Improve consensus performance and protocol validation

**Release date:** 2026-11-18

**Version:** v0.220.4

This release improves consensus performance, validates active leader assignments and Conway transaction data more precisely, strengthens chain selection and peer sharing behavior, and clarifies ledger parameter compatibility.

### Performance

* Improved Byron PBFT state updates by sharing an append-only log and advancing the newest state in constant time without copying or recounting the issuer window. Branch and rollback behavior remains unchanged. At `k=2160`, the stated benchmark improved from about 12,500 ns, 65,536 B, and 1 allocation to about 105 ns, 153 B, and 0 allocations.

### Breaking Changes

* Corrected non-Byron block issuer validation to use the active leader distribution snapshot through `VerifyConfig.LeaderPoolVrfKeyHash`. Issuer validation callers must provide this callback; retired or not yet active VRF rotated pools still validate when the slot snapshot includes them.

* Updated Praos chain selection to compare operational certificate issue numbers when the slot and cold issuer match, choosing the higher number before comparing VRF output. `ChainTip` implementations must now provide `IssuerVkey()` and `OpCertSequenceNumber()`.

* Enforced a five slot equal height VRF distance limit for Conway and later candidate switching through `PreferCandidate` and `PreferredCandidate`. `PraosChainSelector` now exposes `ProtocolMajor`, older preferred switching methods are deprecated, and custom `ChainSelector` implementations must add the new methods.

* Renamed Dijkstra parameter 55 to the canonical `RefInputsCostPerMultiAssetByte` and `refInputsCostPerMultiAssetByte` names while retaining `RefInputsCostPerMultiAssetPolicy` as a deprecated alias. Conflicting alias values are rejected, and CBOR key 55 remains unchanged; configurations should use the canonical names without conflicting aliases.

### Bug Fixes

* Rejected malformed present Conway optional transaction body fields when their CBOR major types do not match the expected types before typed decoding. Omitted fields and valid zero, array, and map encodings remain accepted, while malformed null, undefined, and other wrong types are rejected.

* Restored Conway DRep deregistration refunds in phase two invalid value conservation to the certificate amounts rather than recorded deposits. Certificate deposit rules continue to apply phase gated agreement validation.

* Prevented `Client.GetPeers` from sending a mini protocol 10 `ShareRequest` when local peer sharing is disabled; it now returns `ErrPeerSharingDisabledLocally` first. Servers continue to answer incoming requests with empty `SharePeers`, preventing `UnknownMiniProtocol` resets.
