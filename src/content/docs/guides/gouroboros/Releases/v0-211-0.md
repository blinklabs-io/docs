## v0.211.0

**Title:** Improve validation safety and protocol integration

**Version:** v0.211.0

This release improves transaction validation safety, connection lifecycle notifications, typed state results, and fee calculation accuracy while updating the Plutigo dependency.

### New Features

* Improved transaction validation by prechecking Ed25519 witness signatures before ledger-state checks, reusing each transaction's result across validation, and adding signature and message scanner benchmarks with workflows that compare benchmark results between the base and head versions.
* Added optional server callbacks for connection initialization and completion that receive connection IDs; the server accepts `Init` without a legacy `InitFunc`, runs notifications before deprecated callbacks, and preserves legacy errors.
* Defined typed epoch-state debug results with `DebugEpochStateResult` and `DebugNewEpochStateResult`, preserving era-specific raw CBOR, consistently unwrapping `QueryIfCurrent` responses, and returning errors for empty wrappers.

### Improvements

* Hardened malformed message handling by checking LeiosFetch vote requests and LocalTxMonitor next-transaction CBOR shapes before allocation, limiting memory use for invalid input while preserving valid encodings.
* Bounded custom decoder allocations with diagnostic parsing limits and cumulative budgets, bounded `RawBytes` spans, mode limits for `Value`, early Leios reference-count validation, and omission of diagnostics when budgeted parsing fails.
* Corrected Byron fee calculations with 128-bit intermediate arithmetic and exact ceiling division, saturating only when the final result exceeds `uint64`.

### Additional Changes
* Updated the `github.com/blinklabs-io/plutigo` dependency from `v0.8.0` to `v0.8.1`.
