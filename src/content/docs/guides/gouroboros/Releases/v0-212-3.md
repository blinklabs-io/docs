## v0.212.3

**Title:** Improve CBOR decoding and update Plutigo

**Version:** v0.212.3

This release improves in-memory and nested ledger CBOR decoding efficiency, clarifies input slice handling and error count behavior, and updates Plutigo to v0.9.1.

### Improvements

* Improved CBOR decoding by reading directly from the caller-provided byte slice, reducing allocations and CPU overhead during in-memory and nested ledger decoding. For destinations whose `UnmarshalCBOR` methods retain raw CBOR, the decoder no longer copies input bytes; applications must treat the input slice as immutable while the decoded value is in use. `*cbor.Value` remains an exception and keeps its own copy. `Decode` now returns `n == 0` on errors, so applications must check `err` before using the consumed-byte count. API documentation covers `Decode`, `DecodeStrict`, `DecodeLenient`, `DecodeLedgerMap`, and ledger `New*FromCbor` constructors.

### Additional Changes

* Updated Plutigo from `v0.8.1` to `v0.9.1` and refreshed the Plutus V4 constructor-limit test to expect `too many term list items: limit is 1024` for constructors with 1025 fields. This dependency update changes no production code paths.
