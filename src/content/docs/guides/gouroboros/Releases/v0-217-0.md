## v0.217.0

**Title:** Add same-connection chainsync controls and improve ledger processing

**Version:** v0.217.0

This release adds explicit chainsync lifecycle controls, relaxes nested Shelley metadata validation, improves ledger proof selection and Plutus processing, and aligns DMQ encodings with dmq-node 0.7.2.1.

### New Features

* Added exported `Client.Reintersect(points)` and `Client.StopAfterDrain(ctx)` for clean same-connection transitions. Both methods wait for outstanding `MsgRequestNext` replies to drain before sending `MsgFindIntersect` or `MsgDone`, respectively.

### Bug Fixes

* Removed the 64-level nesting limit from the Shelley UTxO metadata validator while retaining the 64-byte limits for text and bytes leaves.
* Corrected pool proof domains to follow ledger state.
* Aligned DMQ local reply and reject reason CBOR encodings with the decoding expectations of dmq-node 0.7.2.1.

### Performance

* Improved cached Plutus script preparation by using `cek.PrepareProgram` and sizing entries with `PreparedProgram.RetainedBytes`; the release also updates `plutigo` to v0.11.1. These changes reduce work during cache misses and improve memory accounting.
* Memoized hashes for large Plutus V1 through V4 scripts so repeated hashing uses a bounded cache without changing hash outputs.
* Reused pooled CEK machines for repeated budgets, reducing machine creation and arena churn.
