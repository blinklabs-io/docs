## v0.217.0

**Title:** Add chainsync lifecycle controls and improve ledger processing

**Version:** v0.217.0

This release adds explicit chainsync lifecycle controls, relaxes nested Shelley metadata validation, improves ledger proof selection and Plutus processing, and aligns DMQ encodings with dmq-node 0.7.2.1.

### New Features

* Added exported `Client.Reintersect(points)` and `Client.StopAfterDrain(ctx)` for clean same connection transitions. Both wait for outstanding `MsgRequestNext` replies to drain before sending `MsgFindIntersect` or `MsgDone`, respectively.

### Bug Fixes

* Removed the 64 level nesting limit from the Shelley UTxO metadata validator while retaining the 64 byte limits for text and bytes leaves.
* Corrected pool proof domain selection to use ledger state.
* Aligned DMQ local reply and reject reason CBOR encodings with the decoding expectations of dmq-node 0.7.2.1.

### Performance

* Improved cached Plutus script preparation with `cek.PrepareProgram`, sized cache entries with `PreparedProgram.RetainedBytes`, and updated `plutigo` to v0.11.1, reducing cache miss work and improving memory accounting.
* Memoized hashes for large Plutus V1 through V4 scripts in a bounded cache while preserving hash outputs.
* Reused pooled CEK machines when budgets repeat, reducing machine recreation and arena churn.
