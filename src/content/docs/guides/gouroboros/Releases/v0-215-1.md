## v0.215.1

**Title:** Improve protocol validation, resource bounds, and era compatibility

**Version:** v0.215.1

**Release Date:** 2026-10-26

This release improves resource safety across network protocols, strengthens transaction and certificate validation across Cardano eras, and expands compatibility for pipelined requests and transaction monitoring.

### New Features

* Improved muxer ingress handling by budgeting retained segments by their actual cost and clearing queue references after use, which limits memory retained during sustained traffic.
* Updated `github.com/blinklabs-io/plutigo` from `0.9.7` to `0.9.10`.
* Enforced Alonzo `MaxCollateralInputs` so transactions cannot exceed the era's collateral input limit.
* Bounded allocations while BlockFetch parses raw headers, preventing input data from requesting unbounded memory.
* Secured MessageSubmission reply authentication by committing the authentication result atomically.
* Compared Dijkstra collateral return assets for ADA-only inputs, and recognized Muhtasim-Munif-Fahim's first contribution to gOuroboros.
* Resolved Dijkstra reference scripts across transaction levels and validated the associated datum and script at each level.
* Preserved ordered certificate state transitions and reservations for active VRF keys.
* Accepted pipelined LeiosFetch `Block` and `BlockTxs` requests while retaining request bounds and response ordering.
* Validated Byron transactions against UTxO state, witnesses, value conservation, fees, and block-local double spends; ledger state and `ByronTxFeePolicy` are now required for this validation.
* Enforced signed block-body size and zero execution-unit limits.
* Encoded era-tagged LocalTxMonitor transaction IDs and added `HasTxForEra` for era-specific transaction lookup.
* Rejected Conway certificates in pre-Conway eras.
