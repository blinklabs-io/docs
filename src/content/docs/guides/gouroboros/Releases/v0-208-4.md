## v0.208.4

**Title:** Improve protocol range delivery and muxer responsiveness

**Version:** v0.208.4

This release improves BlockFetch and ChainSync range delivery across same-slot Byron boundaries and keeps the muxer responsive when one protocol consumer falls behind.

### Bug Fixes
* Fixed BlockFetch ranges that cross a Byron epoch boundary from an EBB to the first main block in the same slot. Validation still requires the requested slot bounds, the correct endpoint identity, and the previous-hash chain, and it rejects later blocks after the requested end even when they share its slot.
* Restored ChainSync delivery for valid one-block ranges after `RequestNext` and same-slot ranges with different Byron block hashes. ChainSync now treats a point as the tip only when both its slot and hash match, accepts a block only when its slot is strictly later for the one-block case, and avoids another `RequestNext` when the intersect is already at or beyond the tip.

### Additional Changes
* Improved muxer responsiveness with bounded ingress queues and forwarders for each protocol and role, so a slow BlockFetch consumer no longer stalls keep-alive traffic or other protocols. `Muxer.SetIngressLimit`, `Muxer.SetIngressBackpressure`, optional `Muxer.SetMetrics`, `ProtocolConfig.IngressLimit`, and protocol ingress hooks provide configuration and observability. Each protocol read pass handles at most 10 queued segments; estimated BlockFetch requests add the estimate, 10 percent, and one maximum-size message to the ingress allowance, while unestimated ranges apply backpressure. If a per-role queue overflows, the connection terminates with `muxer.ErrIngressOverflow`; unregister and `Stop` or `Register` races also receive safer handling.
