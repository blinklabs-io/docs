## v0.213.0

**Title:** Expand protocol compatibility and validation safeguards

**Version:** v0.213.0

This release expands node to client compatibility, adds query and transaction monitoring capabilities, aligns Dijkstra and Leios behavior with the 2026w41 release candidate, and strengthens validation, resource limits, message handling, and CI output safety.

### New Features

* Added node to client protocol versions `22` and `23`, gated Shelley local state queries on the negotiated version, exposed new query APIs and types, added wire versions for `LedgerPeerSnapshot` and peer kind requests, aligned codec behavior, and limited nested `GetCBOR` decoding.

* Correlated MessageSubmission requests with replies, validated request IDs, counts, and windows, preserved pending requests when sending failed, and documented request and reply rules.

* Matched LocalTxMonitor replies to active queries, required `HasTx` IDs to contain exactly 32 bytes, and unblocked waiting calls safely during shutdown.

* Accepted pipelined TxSubmission2 `RequestTxIds` and `RequestTxs` while non blocking replies remained in flight and preserved reply ordering.

### Breaking Changes

* Improved consensus header validation by requiring authoritative operational certificate counter state, rejecting rollbacks and CPraos skips, and returning the next counter only after complete validation. Applications providing consensus state must now supply this authoritative counter state.

* Required authoritative block type binding and ordered stateful validation in the pipeline, rejected ambiguous or unvalidated peer block paths, stopped ChainSync and BlockFetch progress from advancing past invalid data, and changed shutdown and error behavior to stop invalid progress.

* Aligned Dijkstra and Leios with 2026w41 release candidate behavior, including endorser block encoding, stricter certification and proof of possession validation, Plutus V4 list encodings, `TopTxInfo`, and updated CDDL and vectors.

* Hardened consensus validation so it failed closed when authoritative epoch, governance, future pool, or protocol parameter state was unavailable, and added typed errors for these unavailable state conditions.

### Security

* Bounded LeiosVotes `Vote` messages at 256 bytes, capped pending receive bytes at 16 KiB, applied backpressure, and avoided duplicate raw CBOR retention.

* Applied collection and nesting preflight bounds and request scoped response budgets across protocol decoders, updated LeiosFetch and LeiosNotify wire behavior with quit and cancel messages, and added allocation regression coverage.

* Enforced `MaxDepth` and `MaxArrayItems` in Cardano diagnostic formatters, and elided deeply nested or high cardinality data instead of rendering it without bounds.

### Additional Changes

* Authenticated and deduplicated DMQ and local message notifications, bounded decoding, cloned queued messages, and improved connection and protocol shutdown behavior.

* Secured CI benchmark comments by safely escaping output, neutralizing mentions, applying size bounds, and truncating oversized content.
