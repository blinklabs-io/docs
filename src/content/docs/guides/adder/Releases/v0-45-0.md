## v0.45.0

**Title:** Headless notifications, tray updates, and operational improvements

**Version:** v0.45.0

**Compare:** [v0.44.0...v0.45.0](https://github.com/blinklabs-io/adder/compare/v0.44.0...v0.45.0)

This release adds a headless notification integration, automatic tray update checks, clearer configuration and filtering behavior, standardized event names, expanded architecture and governance documentation, safer observability, and more reliable release delivery.

### ✨ Highlights

* Added **headless notification output and validation:** Adder now emits versioned NDJSON status and notification records through `notify-json`. The `adder notifications validate` command checks strict versioned notification settings, chainsync and configuration consistency, and UI independent notification dispatch provides more specific governance vote details.

* Improved **tray update management:** Adder now checks GitHub releases weekly, remembers skipped versions and update preferences, verifies installer checksums for macOS and Windows, and links to the release page on unsupported platforms. The tray also presents corrected icons and About details, cleans up WebSocket responses, and improves macOS service activation.

* Clarified **configuration precedence and durable saves:** CLI values override YAML values, YAML values override environment variables, and defaults apply last. Explicit CLI flags remain authoritative, while atomic saves protect configuration during concurrent writes.

* Expanded **filter and event lifecycle handling:** Adder now wires comprehensive event type filtering through the CLI, manages filter lifecycles more safely, and uses race oriented tests with safer goroutine setup.

* Refined **Cardano event matching:** Adder now keeps matcher logic organized, avoids missing stake credential failures, and matches pools through SPO voting procedures.

* Enabled **independent chain rollback notifications:** The `Chain rollbacks` preference and wizard checkbox now control rollback notifications separately from `Blocks minted` notifications.

* Documented **application architecture:** New architecture guidance explains the pipeline and plugin model, configuration precedence, concurrency, shutdown behavior, and adder-tray integration.

### ⚠️ Event Compatibility

* Standardized **public event names:** DRep registration, update, and retirement events now use `input.drep-registration`, `input.drep-update`, and `input.drep-retirement`. Consumers that match the former `chainsync.drep.*` names must update their filters.

### 💪 Improvements

* Strengthened **operational observability:** Structured fields and component scoped loggers now make startup, chainsync, push, Telegram, and webhook output easier to interpret. Adder redacts sensitive FCM tokens and sanitizes webhook URLs and payloads.

* Updated **system compatibility libraries:** Adder now uses `golang.org/x/sys` v0.46.0.

* Refreshed **lint automation:** The `golangci-lint` action now uses v9.3.0.

* Stabilized **tagged release delivery:** Pinned macOS runners, non fast fail matrix builds, separate macOS packaging and signing, and finalization after partial build failures make tagged releases more reliable.

* Secured **container publishing:** The Docker login action now uses v4.5.1 for Docker Hub and GitHub Container Registry publishing.

* Established **contributor documentation guidance:** `AGENTS.md` now explains how to write meaningful inline comments and accurate documentation comments for exported identifiers.

* Aligned **Cardano interoperability:** Adder now uses `github.com/blinklabs-io/gouroboros` v0.187.3 with decoding and interoperability fixes.

* Hardened **release artifact attestations:** The attestation action now uses v4.2.1 for release artifacts and container attestations.

* Upgraded **protocol serialization support:** Adder now uses `google.golang.org/protobuf` v1.36.12.
