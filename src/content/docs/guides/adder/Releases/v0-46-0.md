## v0.46.0

**Title:** Headless notifications, safer configuration, and improved tray operations

**Version:** v0.46.0

**Compare:** [v0.45.0...v0.46.0](https://github.com/blinklabs-io/adder/compare/v0.45.0...v0.46.0)

This release improves headless notification workflows, configuration reliability, event compatibility, Cardano filtering, tray updates, operational logging, and governance data handling.

### ✨ Highlights

* Added **headless notification output and validation:** Adder can emit versioned NDJSON status and notification records through `notify-json`. The `adder notifications validate --config <path> [--json]` command checks notification settings, while startup checks confirm that `--output notify-json` has a compatible configuration. Stale notification handling and UI neutral dispatch keep headless consumers independent of a specific interface.

* Clarified **configuration precedence and saves:** Command line values take precedence over YAML values, YAML values take precedence over environment variables, and defaults apply last. Adder also serializes atomic configuration saves and synchronizes them more safely during concurrent updates.

* Introduced **tray update checks:** The tray checks for releases weekly, detects semantic version updates, selects the appropriate platform installer, verifies download checksums, remembers skipped versions, and opens the release page when no installer is available.

* Separated **chain rollback notifications:** The `Chain rollbacks` preference and wizard control now manage rollback notifications independently from `Blocks minted` notifications.

* Documented **application architecture:** Architecture guidance explains the processing pipeline, plugin model, configuration precedence, concurrency, shutdown behavior, and tray and API integration.

* Improved **Cardano pool filtering:** Pool filters now match SPO voting procedures, while missing stake credentials no longer match or cause unsafe access.

* Expanded **operational logging:** Structured fields and component specific loggers make startup, chain synchronization, push, Telegram, and webhook output easier to interpret. Adder reduces sensitive FCM tokens and webhook URLs and payloads in logs.
