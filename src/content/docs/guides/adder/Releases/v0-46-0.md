## v0.46.0

**Title:** Headless notifications, safer configuration, and improved tray operations

**Version:** v0.46.0

**Compare:** [v0.45.0...v0.46.0](https://github.com/blinklabs-io/adder/compare/v0.45.0...v0.46.0)

This release improves headless notification workflows, configuration reliability, event compatibility, Cardano filtering, tray updates, operational logging, and governance data handling.

### ✨ Highlights

* Added **headless notification output and validation:** Adder can emit versioned NDJSON status and notification records through `notify-json`. The `adder notifications validate --config <path> [--json]` command checks notification settings, while startup checks confirm that `--output notify-json` has a compatible configuration. Stale notification handling and UI neutral dispatch keep headless consumers independent of a specific interface.

* Clarified **configuration precedence and saves:** Command line values take precedence over YAML values, YAML values take precedence over environment variables, and defaults apply last. Adder also serializes atomic configuration saves and synchronizes them more safely during concurrent updates.

* Introduced **tray update checks:** The tray checks for releases weekly, detects semantic version updates, selects the appropriate platform installer, verifies download checksums, remembers skipped versions, and opens the release page when no installer is available. Tray icons scale correctly, Adder cleans up response resources, and macOS service activation behaves consistently.

* Separated **chain rollback notifications:** The `Chain rollbacks` preference and wizard control now manage rollback notifications independently from `Blocks minted` notifications.

* Documented **application architecture:** Architecture guidance explains the processing pipeline, plugin model, configuration precedence, concurrency, shutdown behavior, and tray and API integration.

* Improved **Cardano pool filtering:** Pool filters now match SPO voting procedures, while missing stake credentials no longer match or cause unsafe access.

* Expanded **operational logging:** Structured fields and component specific loggers make startup, chain synchronization, push, Telegram, and webhook output easier to interpret. Adder reduces sensitive FCM tokens and webhook URLs and payloads in logs.

* Refined **plugin option parsing:** Comma-separated Cardano filter, event type, and ChainSync intersection values now ignore surrounding whitespace and empty entries, so YAML block-formatted lists match configured values correctly. Empty intersection values follow the behavior configured by `--input-chainsync-intersect-tip`.

* Added **multi-target tray monitoring:** The setup wizard supports multiple wallets, DReps, pools, assets, and policies, with rate-limited and batched desktop notifications. Existing tray filters migrate to the new structured configuration, and connection alerts remain immediate.

* Delivered **signed macOS installers:** Release packages install the Adder tray app and CLI together in `/Applications`, with signed and notarized artifacts for Gatekeeper when release credentials are available. The installer also creates `/usr/local/bin/adder` when possible without replacing an unrelated command.

* Adjusted **Telegram delivery retries:** Telegram output now waits for Telegram's `retry_after` duration when long polling encounters rate limiting, reducing premature retries.

* Enhanced **API server reliability:** Adder now uses Go `net/http` instead of Gin, keeps SSE and WebSocket streaming through middleware, records structured access logs, recovers from panics, and applies server timeouts.

* Clarified **API documentation paths:** API clients now reach `/ping`, `/healthcheck`, and `/events` at the root, while `/v1/fcm` and `/v1/qrcode` remain under `/v1`; Swagger is available at `/swagger/`.

* Validated **FCM token input:** API requests now validate `fcmToken` before processing.

* Improved **Telegram multipart uploads:** Telegram output can retry HTTP/2 GOAWAY responses, avoids empty multipart bodies for calls without fields, and counts request fields more accurately. Buffered uploads can use more memory.

* Introduced **the managed plugin lifecycle:** Custom Go plugin authors must migrate to the `plugin.ManagedPlugin` lifecycle contract and the shared `plugin.Base` implementation; legacy lifecycle wiring no longer works.

* Made **processing order predictable:** Adder validates plugin connections, starts consumers before producers, preserves the configured filter order, and stops components in reverse order.

* Propagated **terminal plugin failures:** A terminal failure now stops the pipeline promptly and makes the failing component and error available through the pipeline status.

* Stopped **ChainSync reconnects during cancellation:** ChainSync now ends connection handshakes and reconnect attempts when the pipeline shuts down.

* Halted **UTxORPC reconnects during cancellation:** UTxORPC now ends its reconnect backoff when the pipeline shuts down.

* Ended **Push delivery during cancellation:** Push notification token requests and FCM sends now stop when the pipeline shuts down.

* Prevented **Webhook retries after cancellation:** Webhook delivery stops retrying when the pipeline shuts down and does not report cancellation as a delivery error.

* Matched **ChainSync epochs to the selected network:** ChainSync status now calculates epoch numbers from the configured network's era boundaries.

* Rejected **failed WebSocket upgrades:** Event streaming now returns WebSocket errors instead of silently falling back to SSE when a client requests a WebSocket upgrade.

* Removed **legacy logging settings:** Adder no longer accepts `--logging-level` or related top-level logging settings. Adder now controls selected output logging through `output.log.level` or `--output-log-level`.

* Displayed **About version metadata:** The tray About dialog now shows the running version and commit metadata inside Adder.

* Configured **macOS login startup:** Wizard Step 4 now lets operators enable or disable automatic launch at login or reboot, view service status, and open Login Items settings.

* Improved **macOS launchctl management:** Adder now synchronizes the tray launch agent with Login Items and reports registration, startup, and removal status more reliably.

* Added **a macOS uninstaller:** The uninstaller removes the tray apps and autostart setup, while optional `--purge` or `--all` modes also remove configuration and log data.

* Introduced **an in-app notification rule editor:** A tray menu item opens an editor for Wallet, DRep, Pool, Asset, and Policy targets, notification categories, and `Monitor Everything`. Saved rules remain in place, take effect immediately without restarting the tray, reject case-insensitive duplicate targets, and keep the editor available when a reconnect warning occurs.

* Provided **signed Windows installers:** MSI packages for `x64` and `arm64` install both the CLI and tray, add Start Menu and Add/Remove Programs integration, and do not register a `Scheduled Task`.

### ⚠️ Event Compatibility

* Standardized **DRep event names:** DRep registration, update, and retirement events now use `input.drep-registration`, `input.drep-update`, and `input.drep-retirement`. Event consumers that use the former names must update their filters.

* Updated **generated API integration:** Integrations can now import the generated OpenAPI module from `github.com/blinklabs-io/adder/openapi`.

* Hardened **webhook event handling:** Malformed or unknown events no longer cause webhook output to panic. Adder sends the errors through the plugin error channel and coordinates shutdown and retry handling safely.

### 💪 Improvements

* Preserved **governance deposit values:** Governance certificate deposits now preserve the full unsigned 64 bit value range instead of limiting values to signed 64 bit integers.

* Prevented **tray process buildup:** Folders, URLs, and installers launched from the tray now finish asynchronously, avoiding lingering child processes.

* Hardened **Windows tray operation:** The tray records diagnostics in its Windows log file, recovers startup panics, permits only one instance per session, and manages service registration, process identity, and restarts more reliably.

* Corrected **tray event and notification behavior:** Initial event connections can receive live events without buffered replay, reconnects restore replay, explorer links open the correct transaction or block on the selected network, and followed pools and DReps receive only relevant notifications with the correct governance vote.

* Disabled **the tray in FreeBSD release artifacts:** FreeBSD `amd64` and `arm64` packages now ship without the tray component.

* Resolved **a `crypto/x509` vulnerability in tray downloads:** Builds now use Go `1.27.3` and require Go `1.26.10`.

### 📚 Documentation

* Published **library examples:** The published documentation site now hosts Adder library examples alongside the product guidance.

* Outlined **governance event reference:** Documentation now describes `input.governance` fields, supported action types, nested structures, and filtering examples, with schema examples aligned to emitted event data.

* Enabled **Dingo pipeline validation:** Docker and macOS workflows connect Adder to Dingo through a shared connection on Cardano's preview network and verify that Adder resumes at the chain tip, while local runs limit container log growth.

* Consolidated **troubleshooting guidance:** The documentation now covers connection, configuration, filter, FCM, and webhook diagnostics, common error messages, and Go 1.26 goroutine leak profiling with `GOEXPERIMENT=goroutineleakprofile`.

* Specified **filter and governance examples:** The README now maps `--filter-address`, `--filter-pool`, and `--filter-drep` to their environment variables and configuration keys, explains comma-separated values and AND/OR behavior, and documents governance event matching for stake and payment addresses plus bech32 and hexadecimal DRep identifiers.
