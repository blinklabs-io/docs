## v0.47.0

**Title:** Expanded event delivery, resilient operations, and Cardano support

**Version:** v0.47.0

**Compare:** [v0.46.0...v0.47.0](https://github.com/blinklabs-io/adder/compare/v0.46.0...v0.47.0)

This release expands event delivery and Cardano network support while improving observability, configuration safety, notification control, webhook durability, and desktop reliability.

### ✨ Highlights

* Improved **operational visibility:** Structured log fields, component-specific loggers, metrics, and a consistent logging system make startup, synchronization, delivery, and webhook activity easier to understand. Adder also truncates FCM tokens and sanitizes webhook URLs before writing them to logs.

* Preserved **full governance deposits:** DRep and vote delegation deposits now retain unsigned 64-bit values without narrowing them to signed integers. Governance events use the updated deposit schema so integrations can process the complete range.

* Added **headless notifications:** The `notify-json` output and a notification validation command support automation without a tray. Versioned notification configuration enforces strict validation, while UI-neutral tray notifications and governance action IDs in vote messages make notification integrations more predictable.

* Prevented **tray process buildup:** Programs launched from the tray now finish cleanly, so repeated folder, URL, and installer actions do not leave child processes running.

### 💪 Improvements

* Updated **desktop notifications:** The notification library now uses beeep 0.11.3 for current desktop integration behavior.

* Refreshed **system compatibility:** The system interface dependency now uses x/sys 0.46.0, improving support for current operating system behavior.

* Moved **library examples to hosted documentation:** Adder's examples now live on the documentation site, giving library users a single maintained location for guidance.

* Introduced **Signal delivery:** The Signal output uses signal-cli JSON-RPC with strict endpoint and recipient validation, checks success for each recipient, and rejects redirects. The new `docs/signal.md` guide explains the configuration.

* Upgraded **mock chain support:** The ouroboros-mock dependency now uses version 0.20.4 for more current local and automated chain testing.

* Streamlined **linting automation:** The Go lint workflow now uses golangci-lint-action 9.3.0 for current checks in the development pipeline.

* Strengthened **macOS publishing:** Builds use macos-15 runners, continue independent builds after a failure, separate packaging from signing, and finalize releases after partial build failures.

* Secured **container publishing:** Docker registry authentication now uses docker/login-action 4.5.1.

* Expanded **Cardano network compatibility:** Current Cardano protocol libraries add DijkstraNet support and carry the latest gouroboros 0.219.0 and plutigo 0.12.1 behavior into Adder.

* Documented **contributor guidance:** `AGENTS.md` now explains how contributors should write comments so project guidance remains consistent.

* Tested **event filtering and shutdown:** Comprehensive event filter coverage and a refined shutdown routine make filtering behavior easier to verify and pipeline termination more reliable.

* Clarified **configuration precedence and saves:** CLI settings take priority over YAML settings, which take priority over environment variables. Concurrent `SaveAtomic` operations now preserve configuration changes durably.

* Corrected **chain decoding and progress tracking:** The gouroboros 0.187.3 updates fix Dijkstra and Leios decoding, while ChainSync cursor persistence lets a restarted process resume from its stored position.

* Refactored **Cardano matching:** Matcher changes handle missing stake credentials safely and match SPO voting procedures to the correct pool.

* Hardened **webhook delivery:** Bounded, restart-safe SQLite delivery supports `state-path` and `max-pending`, provides at-least-once delivery with stable delivery IDs, validates state files strictly, and exposes webhook health and queue bounds. The `docs/webhook-durability.md` guide describes the durable delivery model.

* Documented **the Adder architecture:** Pipeline and plugin topology, lifecycle, core and plugin configuration precedence, concurrency, shutdown, and adder-tray/API integration now have dedicated guidance.

* Added **automatic tray update checks:** The tray checks GitHub releases weekly, remembers skipped versions, verifies `.pkg` and `.msi` downloads with checksums on macOS and Windows, and opens the release page on Linux and FreeBSD when a package is unavailable. Related reliability fixes improve tray operation.

* Renamed **DRep event names:** DRep registration, update, and retirement events now use `input.drep-registration`, `input.drep-update`, and `input.drep-retirement`; exported event type constants provide stable identifiers for integrations.

* Enabled **Telegram controls:** Authorized operators can use `/status`, `/settings`, and `/notify` in chat, while `settings-file` persists preferences and reports pipeline status.

* Trimmed **comma-separated inputs:** Filters and ChainSync intersect points now ignore surrounding whitespace and empty entries, and Adder builds with Go 1.26.

* Delivered **acknowledged Kafka events:** Kafka output uses `acks=all`, the fixed `adder.events` key, synchronous per-event delivery, TLS and credential validation, and cancellation during shutdown.

* Batched **ClickHouse analytics events:** The output writes `adder_events_v1` rows as JSONEachRow, flushes 100 events or after 1 second, validates timestamps, and does not retry automatically.

* Exposed **Prometheus metrics:** Adder now serves a `/metrics` endpoint with pipeline counters and a processing histogram for operational monitoring.

* Confirmed **RabbitMQ delivery:** RabbitMQ output now confirms published messages and requires mandatory routing so successful delivery reaches the intended route.

* Introduced **structured tray monitoring:** The tray supports multiple notification targets and persists their structured definitions. Existing `filter.cardano` settings no longer work; migrate them to the new monitoring target configuration before upgrading.

* Hardened **macOS packaging:** Adder signs and notarizes `.pkg` installers and verifies them with Gatekeeper before distribution.

* Added **PostgreSQL event history:** PostgreSQL output can now record event history for durable inspection of emitted events.

### 🔧 Additional Changes

* Maintained **release attestations:** The attestation workflow now uses actions/attest 4.2.1 for current artifact verification.

* Enabled **RPC integration:** The connectrpc dependency now uses version 1.21.0 for current remote procedure call behavior.

* Separated **Chain rollback preferences:** The `Chain rollbacks` notification setting now operates independently, so it can be enabled or disabled without changing other chain notifications.

* Modernized **tray presentation:** The Fyne dependency now uses version 2.8.2 for the desktop interface.

* Aligned **protocol support:** The gouroboros dependency now uses version 0.216.2, keeping Adder aligned with current Cardano protocol behavior.

* Extended **event delivery choices:** Core NATS validates configuration strictly, flushes each event before reporting success, and delivers at most once. Other output choices include Telegram, Slack, Discord, Matrix, RabbitMQ, MQTT, Google Pub/Sub, Postgres, ClickHouse, Elasticsearch, S3, AWS, Redis, and Kafka, with managed customer routing and runtime reloads.

* Updated **protobuf support:** Adder now uses protobuf 1.36.12.

* Exposed **the generated OpenAPI package:** Generated code and imports now use `github.com/blinklabs-io/adder/openapi`; consumers must update references to the previous module path.

* Refined **test dependency compatibility:** Indirect YAML dependencies now update alongside testify.

* Upgraded **Java build setup:** The release workflow now uses the updated setup-java action.

* Raised **Go workflow compatibility:** The release workflow now uses the updated setup-go action.

* Adjusted **kugo integration:** Adder now uses the updated kugo dependency.

* Standardized **test assertions:** A separate testify update aligns assertion tooling with the current test suite.

* Aligned **RPC support:** The connectrpc dependency now uses version 1.21.1.

* Updated **Plutigo cryptography:** Plutigo now uses version 0.7.1, together with an updated x/crypto dependency.

* Refreshed **artifact attestations:** The attestation workflow now uses actions/attest 4.2.2.

* Upgraded **Plutigo support:** The Plutigo dependency now uses version 0.11.5.

* Raised **checkout workflow support:** The checkout action now uses its updated version.

* Adjusted **Windows signing:** Windows release signing now uses Java 21.

* Improved **Telegram bot integration:** An updated go-telegram/bot release improves bot integration.

* Refined **Telegram bot dependencies:** A further go-telegram/bot update keeps Telegram dependency resolution current.

* Modernized **release metadata:** The metadata-action workflow now uses its updated version.

* Expanded **Cardano compatibility:** The Cardano libraries now include gouroboros 0.193.0 and plutigo 0.3.0 behavior.

* Added **Go module tooling updates:** x/mod 0.42.0 and x/tools 0.51.0 keep dependency and developer tooling current.

* Strengthened **Plutigo cryptography:** Plutigo 0.6.1 and the updated x/crypto library improve cryptographic compatibility.

* Documented **benchmark and profiling guidance:** The release adds performance investigation guidance and removes unsupported HTTP pprof troubleshooting instructions.

* Enabled **Dingo validation assets:** Preview and node to chain validation assets now support the macOS socket workflow.

* Raised **Telegram bot compatibility:** Adder now uses go-telegram/bot 1.24.0 for current bot integration behavior.
