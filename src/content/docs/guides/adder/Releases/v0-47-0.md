## v0.47.0

**Title:** Expanded event delivery, resilient operations, and Cardano support

**Version:** v0.47.0

**Compare:** [v0.46.0...v0.47.0](https://github.com/blinklabs-io/adder/compare/v0.46.0...v0.47.0)

This release expands event delivery and Cardano network support while improving observability, configuration safety, notification control, webhook durability, and desktop reliability.

### ✨ Highlights

* Improved **operational visibility:** Structured log fields, component specific loggers, metrics, and a consistent logging system make startup, synchronization, delivery, and webhook activity easier to understand. Adder also truncates FCM tokens and sanitizes webhook URLs before writing them to logs.

* Preserved **full governance deposits:** DRep and vote delegation deposits now retain unsigned 64 bit values without narrowing them to signed integers. Governance events use the updated deposit schema so integrations can process the complete range.

* Added **headless notifications:** The `notify-json` output and a notification validation command support automation without a tray. Versioned strict notification configuration, UI neutral tray notifications, and governance action IDs in vote messages make notification integrations more predictable.

* Prevented **tray process buildup:** Programs launched from the tray now finish cleanly, so repeated folder, URL, and installer actions do not leave child processes running.

### 💪 Improvements

* Updated **desktop notifications:** The notification library now uses beeep 0.11.3 for current desktop integration behavior.

* Refreshed **system compatibility:** The system interface dependency now uses x/sys 0.46.0, improving support for current operating system behavior.

* Moved **library examples to hosted documentation:** Adder's examples now live on the documentation site, giving library users a single maintained location for guidance.

* Introduced **Signal delivery:** The Signal output uses signal-cli JSON-RPC with strict endpoint and recipient validation, checks success for each recipient, and rejects redirects. The new `docs/signal.md` guide explains the configuration.
