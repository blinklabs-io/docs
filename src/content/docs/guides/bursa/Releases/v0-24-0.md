## v0.24.0 - More reliable readiness checks, secure KES profiles, and updated dependencies

- **Date:** 2026-11-12
- **Version:** 0.24.0
- **Comparison:** [v0.22.0...v0.24.0](https://github.com/blinklabs-io/bursa/compare/v0.22.0...v0.24.0)

### Summary

This release improves PostgreSQL readiness checks, adds profile selection controls for KES attestation, updates the Go toolchain and container images, and refreshes the `gouroboros` and `plutigo` dependencies.

### Recommended Network Compatibility ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi              | ✅         |

### ✨ New Features

* Added optional `kes_vkey` and profile selectors to KES agent attestation requests, enabling multi-profile attested listeners and binding admitted sessions to the selected profile. The service rejects ambiguous or mismatched selectors, and cross-profile signing from an admitted session returns `ErrProfileMismatch`.

### 🔒 Security

* Resolved PostgreSQL readiness probe contention by assigning each probe record an 8-byte cryptographically random hexadecimal suffix, using that unique key for readiness updates, and rolling back the transaction so probe rows do not persist; SQLite behavior remains unchanged.
* Strengthened toolchain maintenance by updating the Go directive in the root, `armory`, `openapi`, and `ui` modules from `1.26.10` to `1.26.11`, aligning CI workflows with `1.26.x` or the `go.mod`/`ui/go.mod` version files, and updating Docker Go images from `ghcr.io/blinklabs-io/go:1.27.3-1` to `ghcr.io/blinklabs-io/go:1.27.4-1`; this addresses the reported `govulncheck` `net/http` vulnerability and reduces workflow drift.

### Additional Changes

* Refreshed `github.com/blinklabs-io/gouroboros` from `v0.218.0` to `v0.219.0` and `github.com/blinklabs-io/plutigo` from `v0.11.5` to `v0.12.1`, bringing Bursa onto the specified upstream library versions.
