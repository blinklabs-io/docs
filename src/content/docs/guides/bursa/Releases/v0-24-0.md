## v0.24.0 - More reliable readiness checks, secure KES profiles, and updated dependencies

- **Date:** 2026-11-12
- **Version:** 0.24.0
- **Comparison:** [v0.22.0...v0.24.0](https://github.com/blinklabs-io/bursa/compare/v0.22.0...v0.24.0)

### Summary

This release makes PostgreSQL readiness checks more reliable, adds profile selection to KES attestation, updates the Go toolchain and container images, and refreshes the `gouroboros` and `plutigo` libraries.

### Recommended Network Compatibility ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi              | ✅         |

### ✨ New Features

* Added optional `kes_vkey` and profile selectors to KES agent attestation requests. Bursa can now serve multiple attested profiles, bind each admitted session to its selected profile, reject ambiguous or mismatched selectors, and return `ErrProfileMismatch` when a session attempts to sign for another profile.

### 🔒 Security

* Resolved contention among PostgreSQL readiness checks by giving each record a unique 8-byte random hexadecimal suffix. Bursa uses that key for readiness updates and rolls back the database transaction, so checks leave no rows behind; SQLite behavior remains unchanged.
* Strengthened toolchain security and workflow consistency by updating Go directives in the root, `armory`, `openapi`, and `ui` modules from `1.26.10` to `1.26.11`; CI now uses `1.26.x` or the `go.mod`/`ui/go.mod` version files, and Docker Go images now use `ghcr.io/blinklabs-io/go:1.27.4-1` instead of `ghcr.io/blinklabs-io/go:1.27.3-1`. This addresses the reported `govulncheck` `net/http` vulnerability and reduces workflow drift.

### Additional Changes

* Refreshed `github.com/blinklabs-io/gouroboros` from `v0.218.0` to `v0.219.0` and `github.com/blinklabs-io/plutigo` from `v0.11.5` to `v0.12.1`, keeping Bursa aligned with these library versions.
