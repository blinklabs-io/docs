## v0.22.0 - Stronger signing safeguards, Armory controls, and wallet security

- **Date:** 2026-11-07
- **Version:** 0.22.0
- **Comparison:** [v0.21.1...v0.22.0](https://github.com/blinklabs-io/bursa/compare/v0.21.1...v0.22.0)

### Summary

This release adds an attested Armory signer, improves signing previews and transaction validation, strengthens host and wallet protection, expands signer configuration, and improves CLI compatibility with Cardano tooling.

### Recommended Network Compatibility ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi              | ✅         |

### ✨ New Features

* Improved the Armory signer by adding USB armory SE050 support with a required profile and verification of a pinned Ed25519 identity key.
* Enabled SOPS signer backends to load encrypted JSON key envelopes from a local directory, validate file names and sizes, avoid blocking on Unix FIFOs, and reject simultaneous `path` and `secret_prefix` settings.
* Permitted timelock scripts to specify both `timelock_after` and `timelock_before` when the first bound precedes the second, generating a native script that enforces both bounds while continuing to reject invalid ranges.
* Added on-chain counter handling for operational certificate requests: the signer uses `chain_counter + 1`, applies a repeatable floor, reports `issue_counter`, and rejects lower counters.
* Clarified pool registration terms before signing by showing pledge, cost, margin, VRF key hash, optional Leios key, relays, and metadata; unknown relay types block signing, and IPv6 addresses include unambiguous ports.
* Corrected exported policy key envelopes to use `cardano-cli`-compatible payment type strings while preserving policy prefixes and loading legacy formats.
* Refined CLI script examples with valid 28-byte, 56-character hexadecimal key hashes and instructions for obtaining them.
* Secured signer quickstart credentials with private files and directories, a generated JWT secret, and credential exports scoped to a subshell.
* Expanded transaction fee estimation with `bursa tx decode --witness-count` and `--byron-witness-count`; the output now accounts for future vkey and Byron witnesses and reports the estimate in `min_fee_note`.
* Established a signed, hash-chained Armory signing log on microSD with SE050 head verification, authenticated `/v1/signlog` reads, and host or offline verification tools; Armory refuses to sign when the log is unavailable, inconsistent, full, or unable to append.
* Introduced the `confidential-space-workload` command and signer backend with TLS 1.3 mutual authentication, wrapped-key persistence, Cloud KMS protection, Cloud Storage issue counters, and stricter attestation checks.
* Enabled optional attested remote signing for KES in sign mode through TLS 1.3 mutual authentication, nonce-bound attestation, and provider verification.
* Extended the CLI with `bursa tx build`, `bursa tx submit`, and JSON `bursa query pool`, `stake-address`, `utxo`, and `tip` commands; local node queries now support balancing, deposits, refunds, witness details, and explicit rejection reporting.
* Delivered SE050 backed Armory signing and provisioning firmware for pool operations, with policy evaluation, host tools, and separate signing and provisioning images.
* Added `bursa signer counter-reset` with dry-run and `--yes` modes, SQLite and PostgreSQL administrative reset support, generation fencing, and documented failover and failback behavior.
* Enforced an unsigned integer `ttl` in Armory signed transaction bodies and validated validity start and network ID values before signing.
* Authenticated discovered DEX pools by verifying Minswap markers and locked reserves, binding inline datum recovery to the authoritative output, and excluding unsupported legacy protocols.
* Unified testnet, Cardano mainnet, and Prime mainnet service in `NETWORK=multi` Armory images with per-scope host keys, authenticated inventory, scope authorization, cold-key ownership, and `POST /wipe/cold`.
* Carried verified Armory signing summaries through attested protocol mode 2 negotiation, with a one-time version 1 fallback and log and audit propagation.
* Verified exact encoded transaction body bytes and era values during attested signing, checked body hashes, and supported profile-bound `binding_signature` responses with legacy transaction-hash fallback.
* Pinned pool VRF keys, metadata, and parameter bounds per profile through authenticated `/provision/pins` and `armory-pool pins-request` operations, with policy enforcement and audit hash prefixes.

### 🔒 Security

* Required Armory mainnet builds to authenticate with a registered host key before signing; other networks remain unchanged.
* Rejected Confidential Space sign requests that provide backend profiles or `opcert-next`/`chain_counter`; unsupported inventory profiles return HTTP 400 without consuming a nonce or advancing the durable counter.
* Verified transaction effects before connector and offline signing, showing complete effects in approval views and blocking unresolved or unsupported effects.
* Validated transaction effects before multisig signing, cosigning, or submission, preventing keystore unlock and broadcasting when effects cannot be decoded or remain incomplete.
* Restricted Windows SQLite wallet databases and sidecars to the owner with access checks that reject insecure ownership, directory, and reparse paths, including during sidecar recreation.
* Prevented iOS contact backup exposure by keeping address book data in memory and returning HTTP 503 for mutations when backup exclusion fails.
* Hardened Armory HTTP handling with bounded request timeouts and no more than eight concurrent accepted connections; host challenges now use HMAC tags, expire after 60 seconds, resist flood eviction, and cannot be replayed.
* Updated the JOSE library from `4.1.4` to `4.1.6`, adding bounds for RSA JWK parsing and stronger JOSE validation.
* Protected Armory pool registration end-to-end flows by keeping signing keys out of command arguments and working directories, applying private permissions, and cleaning up temporary keys.
* Held the Armory Bluetooth module in reset before networking and made startup reporting fail when the reset cannot be maintained.

### Additional Changes

* Configured each Armory firmware build for one network, enforcing the mainnet chain, validating `NETWORK` and `CHAIN` parameters, producing chain-specific artifacts, and reporting the selected chain at startup.
* Scoped restrictive permissions to decoded Apple `.p12` files during release packaging so app bundles retain usable default permissions.
* Updated the Cloud KMS client from `1.32.0` to `1.36.1`.
* Refreshed the validator library to `10.30.6`, including upstream validation changes and new validator tags.
* Upgraded the AWS Secrets Manager SDK from `1.50.1` to `1.50.8`, incorporating upstream client and model fixes.
* Corrected macOS release signing identity comparison to compile on current toolchains while preserving failure behavior when no identity is available.
* Stabilized KES provider failure testing by using a loopback TCP connection and removing a timing delay.
