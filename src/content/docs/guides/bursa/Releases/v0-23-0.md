## v0.23.0 - Profile-aware signing, durable custody, and stronger KES controls

- **Version:** 0.23.0
- **Comparison:** [v0.22.0...v0.23.0](https://github.com/blinklabs-io/bursa/compare/v0.22.0...v0.23.0)

### Summary

This release adds profile-aware signing and storage, strengthens Nitro authorization and operational certificate custody, expands KES agent controls, improves Armory migration and simulation workflows, and tightens authentication, storage, and connector behavior.

### Recommended Network Compatibility ⚠️

### ✨ New Features

* Added repeatable `--profile` and `--create-profile-counter` options for Confidential Space, with isolated Cloud Storage counters and profile-bound signing responses. Bursa validates profiles, refuses unknown or mismatched values, and creates counters at startup only when the configured profile rules allow it.
* Strengthened Nitro custody by separating provisioning and signer authorities, using one-time `/v1/challenge` signing authorization, and hardening reload and provisioning replay handling. Operators can set a non-world-writable `--socket-mode`; sealed operational certificate counters persist in Secrets Manager, identical payloads can be re-sign​ed at the same counter, persistence failures expose recovery behavior, and versioned state guidance covers safe downgrades.
* Expanded the KES agent with an optional `none` attestation provider, plaintext attested transport, conditional client-certificate authentication, and public `kesagent/wire` framing helpers. The agent permits one header per slot with identical retries, refuses lower slots and equivocation, limits handshakes to 64 globally and four per source, and exposes health, readiness, and metrics while supporting multiple profiles and shared storage.
* Introduced optional SOPS profile binding with profile-scoped routing and signer records. Counter resets can select a profile with `--profile` or target legacy unprofiled records with `--unprofiled`, and migration guidance explains how to move existing records.
* Improved Armory operations with staged host-key migration and fail-closed handling, clearer host authentication, transport, and route reporting, and corrected operator documentation. `armory-sim -network multi` now supports multi-image bootstrap rules while rejecting `-chain` together with `-network multi`.
* Secured access and recovery paths by requiring configured `jwt_audience` values and matching `aud` claims for signer and API bearer tokens, rejecting misspelled signer subcommands, protecting the actual SQLite database and sidecars when encoded URI paths are used, cancelling queued work for revoked connector authorities, and preserving active accounts during locked vault TPM changes.

### Additional Changes

* Updated release operations by retrying macOS stapler actions, refreshing embedded UI dependencies and the Go, AWS, Google, gRPC, and Plutigo modules, and updating the GitHub Actions login and setup actions.
