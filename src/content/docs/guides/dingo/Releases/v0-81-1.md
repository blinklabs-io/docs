## v0.81.1

**Title:** Improve ledger performance, synchronization, storage, and API reliability

**Version:** v0.81.1

**Release:** [v0.81.1](https://github.com/blinklabs-io/dingo/releases/tag/v0.81.1)

Dingo v0.81.1 improves ledger processing, synchronization, storage, and API safeguards for the Dingo node and library. It also strengthens release delivery, governance behavior, and operational visibility.

### Recommended Network Compatibility ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### Node operation and release delivery
* Added the default off `ledgerApplyRowBatchingEnabled` setting across configuration, CLI, and environment variables, enabling optional batching for eligible unvalidated ledger writes in core storage.
* Ensured main image manifests publish only after image builds succeed, providing a successful build gate for release artifacts.
* Restored Conway Mithril snapshot donations at anchor epochs.

### Storage and ledger processing
* Optimized SQLite batched UTxO spend plans to use point lookups and kept SQLite only statements out of caches for other database dialects.
* Validated pending account and state overlays and retained byte mempool accounting, and handled stable unavailability explicitly.
* Improved portable pagination and migration replay, SQLite maintenance, asset only UTxO queries, and operational alerts.
* Cached hot SQL statements while preventing cross connection SQLite statement errors.

### Synchronization and network operation
* Deferred ChainSync headers beyond the forecast horizon without using chain selection or block fetch and without penalizing peers.
* Restarted block fetch when the header queue reached capacity and resynchronized with an explicit failure reason when recovery failed.
* Prevented missing Leios fetch peers from increasing the ledger halt counter.

### APIs, configuration, and governance
* Bounded unary UTxO RPC concurrency, response bytes, and mempool reads with defaults of `MaxConcurrentBulkRequests=32`, `MaxResponseBytes=16 MiB`, `MaxMempoolItems=1000`, and `BulkResponseWriteTimeout=30s`; request logging now applies the same safeguards.
* Hardened DevNet key installation, rejected trailing CBOR bytes in public APIs, canceled timed out `WaitForTx` lookups, and bounded Mithril lottery indexes.
* Introduced the default off `LedgerPrefetchAheadEnabled` option across the CLI, environment variables, and configuration.
* Corrected Conway DRep lifecycle behavior, delegation cleanup, PV10 transition handling, and ledger state parsing.
