## v0.75.0

**Title:** Improve synchronization, validation, and node operations

**Date:** 2026-10-01

**Version:** v0.75.0

**Release:** [v0.75.0](https://github.com/blinklabs-io/dingo/releases/tag/v0.75.0)

Dingo v0.75.0 improves from-genesis synchronization, replay and rollback validation, ledger and database processing, peer selection, Leios boundary handling, and operational observability. It also expands coverage and clarifies state migration and database behavior.

### Recommended Network Compatibility ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### Synchronization and validation improvements
* Fixed Byron from-genesis synchronization by validating the first block against the queued header chain and deferring headers beyond the era horizon instead of treating them as peer faults.

* Improved entrypoint signal test handling for slow startup and exit conditions during full-suite and race runs.

* Expanded coverage for required Plutus spending datums and protocol-version-aware Conway V3 `TxInfo` during live and replay block application, protecting validation expectations without changing production behavior.

* Added a bounded LRU cache for Plutus evaluation contexts keyed by language, protocol version, cost model, and synthetic V2 state. `LedgerState` and `LedgerView` now reuse matching contexts instead of repeatedly constructing them.

* Updated Byron validation to use adopted protocol parameters after replay, rollback, and fork events. Dingo skips size and fee checks when parameter adoption is unknowable and explicitly rejects Byron-era snapshot restoration.

### Database, governance, and cross-era processing

* Suppressed false per-pool Koios stake mismatches for epochs while Koios has not published `pool_history` by applying a 12-hour grace window and returning one incomplete `KoiosFault` result.

* Removed issue and tracker references from the architecture and database documentation and added documentation parity enforcement.

* Batched block input UTxO prefetches into one query per validated block, removed spent entries safely, and fell back to point reads when a batch query failed.

* Scoped rollback pool updates to affected pools, added dialect-specific joined update generation, and improved query metrics.

* Aligned raw block UTxO offset persistence and transaction validation across eras, including Dijkstra validity and collateral-return rules and strict handling of invalid transaction indexes.

### Governance, networking, and state handling

* Compacted old credited reward rounds in background jobs, deferred RATIFY and SNAP work after epoch-boundary commits, preserved governance proposal membership until drop, and added observability and query improvements.

* Clarified Leios endorser-block blob keys, write conditions, deduplication behavior, commit boundaries, and synthetic block production handling in the database documentation.

* Stabilized peer-governor behavior by preventing gossip churn from draining the hot set, adding bounded cold redials below `MinHotPeers`, and adding peer-selection metrics.

* Corrected MemPack decoding for deduplicated and empty asset names and documented migration implications for already imported state.

### Testing and observability

* Consolidated Go test files from 1,299 to 640 and corrected related build constraints, imports, licensing, lint directives, and references.

* Added metrics for block-application latency and batch size for each committed batch, with Grafana panels.

* Deferred Leios certificate checks across epoch boundaries until the successor epoch becomes available.
