## v0.88.0

**Title:** Improve snapshot security, protocol compatibility, and service reliability

**Version:** v0.88.0

**Release:** [v0.88.0](https://github.com/blinklabs-io/dingo/releases/tag/v0.88.0)

**Comparison:** [v0.87.1...v0.88.0](https://github.com/blinklabs-io/dingo/compare/v0.87.1...v0.88.0)

Dingo v0.88.0 strengthens snapshot integrity, transport authorization, local state compatibility, resource protection, chain validation, and service reliability.

### Recommended Network Compatibility ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### Security and data integrity
* Added authenticated cloud snapshot mirroring that verifies declared payload sizes and SHA-256 digests, rejects unsigned snapshots, symlinks, and replaced entries, uploads payloads before manifests, and stages verified files for destinations that only support directory uploads.
* Restricted inbound topology privileges to the exact transport identity, including address and port, so host-only NAT or proxy matches no longer inherit trust or valency.
* Secured unkeyed local restores by requiring private trusted snapshot paths and protecting payload, metadata, and manifest writes from directory replacement; snapshot creation now returns `ErrSnapshotDirectoryReplaced` when replacement occurs.
* Validated peer fork headers against retained candidate ancestry and operational certificate state, retained deferred headers until validation, and cleared candidate caches during rollback.
* Limited all node-to-client LocalStateQuery request ingress, including trusted listeners, to `1 MiB` and refused oversized requests before reassembly.

### Compatibility and protocol behavior
* Prevented Dijkstra transactions from reusing an active or future pool's BLS voting key, including keys from pending registrations.
* Restored legacy Shelley `GetPoolDistr` local-state queries with point-aware stake snapshots and the correct bare-map `GetCBOR` encoding.
* Maintained reward live-stake running totals during historical backfill and treated missing totals for live UTxO staking keys as an invariant error.
* Cached and coalesced Mithril public catalog requests, added per-client download admission limits, and enforced a 30-second grace period with a `64 KiB/s` minimum rate; malformed registrations return `400`, while pruned snapshots return `409`.
* Accelerated Blockfrost mempool address queries with an indexed address-to-transaction map, four global and one per-client admission slots, and `429` responses with `Retry-After: 1` when the service exhausts capacity; results include chained transactions.
* Refined byte-exact CBOR conformance checks to compare reserialized bytes with expected bytes without normalization, while non-byte-exact rules retain normalization and exact mismatches report a distinct reason.
* Pinned Mesh v1.4.15 and Kupo v2.12 API contracts. Mesh errors now return HTTP `500` with retry information in the response body, Mesh `/account/coins` returns the complete UTxO set without pagination metadata, and Kupo aligns slot-0 selectors, uint64 output indexes, strict mutation decoding, and missing datum, script, checkpoint, and script-language responses as JSON `null`.
* Aligned Blockfrost OpenAPI v0.1.93 behavior with route, query, and response conformance checks; empty `/pools` responses now encode as `[]` instead of `null`.
* Corrected 32-bit integer-width handling across ledger, UTxO RPC, configuration, Mithril, Ouroboros, and node parity paths, with `GOARCH=386` vet coverage and boundary tests.

### Resource controls and service operations
* Isolated Bark cloud catalog scans from the catalog gate, published results only when the scan generation matched the current generation, and applied destination-scoped exponential backoff from 30 seconds to 5 minutes.
* Required a verified client certificate for `StreamOperationProgress`, limited streams to 32 globally and four per certificate, and closed streams after 15 minutes with `DeadlineExceeded`.
* Closed trusted-local node-to-client idle sessions after two minutes by default while active protocol work and ChainSync `AwaitReply` suspend the idle deadline.
* Streamlined inbound node-to-node admission by converting reservations into connections atomically and releasing capacity exactly once.
* Added persisted cursors and 64-row keyset pages to off-chain metadata pointer discovery, eventually rescanned in-place updates, and safely skipped `NULL` anchors.
* Created a new `0644` regular file for `DINGO_LOG_FILE` without following symlinks, captured standard output and error, and rejected existing targets, symlinks, and FIFOs.
* Bounded transaction submission across Mesh `/construction/submit`, UTxO RPC `SubmitTx` and `EvalTx`, and internal submission paths by coordinating submission slots with metadata read capacity. External requests reserve capacity before decoding, busy capacity returns retriable or resource-exhausted errors, internal callers wait or honor cancellation, and peer validation stops when a peer disconnects. The built-in UTxO RPC provider now binds to `127.0.0.1` when `Host` is empty; remote access requires explicit host configuration.
* Standardized outbound HTTP `User-Agent` values as `dingo/<version> (<GOOS>/<GOARCH>)`. A valid `DINGO_HTTP_USER_AGENT` can override the default, invalid overrides are ignored, existing request headers take precedence, and component-specific `userAgent` settings remain authoritative.
* Rejected oversized transactions before decoding and before the mempool mutation gate when an applicable era-specific `MaxTxSize` is available; unknown or unapplied limits continue to defer to ledger validation.

### Consensus and distribution updates
* Upgraded bundled nview and txtop container images from `0.16.0` to `0.17.0` with updated pinned digests.
* Expanded Musashi and Leios local-state compatibility with `GetStakePoolState`, Praos2 `GetChainDepState`, the corrected Shelley genesis layout for node-to-client v21 through v23, persisted BLS registration epochs, and gouroboros v0.213.10.
* Capped BlockFetch point validation at 32 concurrent lookups, returned `NoBlocks` before database work when validation reached capacity, and preserved the per-connection failed-lookup budget while rotating missing points.
* Emitted `SlotBattleEvent` after security-depth settlement, calculated `Won` from canonical chain membership, and retried after lookup failures.
* Improved the live-loop ingest harness so it reaches the chain tip immediately, making synchronization tests more reliable.
* Refined ledger-rules conformance reports so they no longer serialize corpus or totals, updated the NDC ledger revision, and refined predicate mapping.
* Forecast successor-era parameters across the Conway to Dijkstra boundary during applied-tip header verification; Leios DevNet now validates the transition at epoch 1.
