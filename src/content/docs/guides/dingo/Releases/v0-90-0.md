## v0.90.0

**Title:** Strengthen chain integrity, API limits, and service operations

**Version:** v0.90.0

**Release:** [v0.90.0](https://github.com/blinklabs-io/dingo/releases/tag/v0.90.0)

**Comparison:** [v0.89.0...v0.90.0](https://github.com/blinklabs-io/dingo/compare/v0.89.0...v0.90.0)

Dingo v0.90.0 strengthens forging and chain selection, improves synchronization recovery, adds bounded UTxO and transaction APIs, and gives operators clearer capacity and monitoring controls.

### Consensus, chain selection, and synchronization
* Strengthened forging and local block admission by requiring a coherent, cryptographically verified admitted header frontier. Dingo now refuses stale parent forging when the admitted header is ahead, reports `admitted_header_ahead` as the skip reason, and rechecks the frontier during sibling adoption. The forge gap metric is now relative to the network rather than the local tip. Operators must replace integrations that use the removed `ForgePrimaryChainTipToleranceSlots` setting and update providers to supply `PrimaryChainTipRelationAndHeader`. Far tip corroboration and stalled header block fetch recovery also improve recovery when peers fall behind.
* Batched existing transaction hash lookups for each `WaitForTx` stream in one context bound read transaction, chunks large requests to stay within SQL parameter limits, and preserves subscription before lookup and the original request order.
* Separated the outbound peer reserve from inbound capacity by adding `MaxInbound`. Only outbound peers count toward `MinPeers`, and Dingo rejects excess inbound peers before the handshake.
* Aligned Genesis corroboration with connected address groups instead of topology `GroupID`, including address information received from live remote peers.
* Replaced address and topology corroboration identities with trusted ledger pool control identities or snapshot pool identities. Dingo now fails closed when the required evidence is missing or ambiguous.
* Limited MCP `get_utxos` and `get_utxos_by_asset` requests to offset `10,000`, routed them through shared SQLite read capacity, and reported when a result is truncated.
* Moved bootstrap slot and synchronization progress reads outside the peer governor lock, preventing lock inversion and related deadlocks.
* Updated `cardano-configs` to `20261027-1`, bound Dijkstra EKG and Prometheus endpoints to `0.0.0.0`, and made expiry testing deterministic. Operators should review firewall and network access controls because monitoring endpoints now listen on all interfaces.
