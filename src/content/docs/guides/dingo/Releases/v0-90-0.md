## v0.90.0

**Title:** Strengthen chain integrity, API limits, and service operations

**Version:** v0.90.0

**Release:** [v0.90.0](https://github.com/blinklabs-io/dingo/releases/tag/v0.90.0)

**Comparison:** [v0.89.0...v0.90.0](https://github.com/blinklabs-io/dingo/compare/v0.89.0...v0.90.0)

Dingo v0.90.0 strengthens forging and chain selection, improves synchronization recovery, adds bounded UTxO and transaction APIs, and gives operators clearer capacity and monitoring controls.

### Recommended Network Compatibility ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### Consensus, chain selection, and synchronization
* Strengthened forging and local block admission by requiring a coherent, cryptographically verified admitted header frontier. Dingo now refuses stale parent forging when the admitted header is ahead, reports `admitted_header_ahead` as the skip reason, and rechecks the frontier during sibling adoption. The forge gap metric is now relative to the network rather than the local tip. Operators must replace integrations that use the removed `ForgePrimaryChainTipToleranceSlots` setting and update providers to supply `PrimaryChainTipRelationAndHeader`. Far tip corroboration and stalled header block fetch recovery also improve recovery when peers fall behind.
* Batched existing transaction hash lookups for each `WaitForTx` stream in one context bound read transaction, chunks large requests to stay within SQL parameter limits, and preserves subscription before lookup and the original request order.
* Separated the outbound peer reserve from inbound capacity by adding `MaxInbound`. Only outbound peers count toward `MinPeers`, and Dingo rejects excess inbound peers before the handshake.
* Aligned Genesis corroboration with connected address groups instead of topology `GroupID`, including address information received from live remote peers.
* Replaced address and topology corroboration identities with trusted ledger pool control identities or snapshot pool identities. Dingo now fails closed when the required evidence is missing or ambiguous.
* Limited MCP `get_utxos` and `get_utxos_by_asset` requests to offset `10,000`, routed them through shared SQLite read capacity, and reported when a result is truncated.
* Moved bootstrap slot and synchronization progress reads outside the peer governor lock, preventing lock inversion and related deadlocks.
* Updated `cardano-configs` to `20261027-1`, bound Dijkstra EKG and Prometheus endpoints to `0.0.0.0`, and made expiry testing deterministic. Operators should review firewall and network access controls because monitoring endpoints now listen on all interfaces.
* Recovered stalled header queues by starting queued block fetch when non owner buffering fills and no fetch is active.
* Held catch up overshoot headers while the local ledger catches up instead of disconnecting immediately. The bounded wait continues to enforce plausibility checks.
* Authenticated Genesis corroboration with a bounded history of producer verified delivered headers, cleaned that history during rollback and disconnect, and resynchronized observers after promotion.
* Bounded deferred header recovery and promoted observer recycling with 30 second and 10 second cooldowns, and skipped recovery for peers below the local tip.
* Optimized exact address UTxO scans with cancellation, SQL aggregation, and indexes for high cardinality queries. Blockfrost now returns `400` when a query exceeds its budget, and pagination may omit totals when Dingo cannot compute them. Clients should handle the budget error and treat missing totals as an expected response.
* Added Plutus V3 conformance comparisons against `cardano-node` for DevNet validation.
* Calculated Byron to Shelley reserves from the live Byron UTxO balance and rejected rollover when the live UTxO set is empty.
* Modernized admitted header processing with bounded queued flushes, stronger observer ancestry and promotion recovery, cached safe fork cryptography, blob only membership and block reads, batched Leios API closure rows, signature preverification, and local resynchronization that no longer counts as peer instability.
* Pinned the node diversity conformance ledger rules from `9d14fd8c` to `e02a9e1c` for publish checks and documentation parity tests, keeping the conformance corpora unchanged and separating DRep deposit mapping coverage from the fixture update.
* Upgraded `gouroboros` to `0.216.1` and applied the Musashi Plutus V4 correction, fixing witness set key handling and `chooseData` decoding during Musashi block replay.
* Corrected duplicate peer tip rejection handling during admission replay and commit rechecks so logs, metrics, and callbacks report once for each refused staged candidate while unstaged deliveries remain per delivery.
* Permitted far frontier chain selection beyond the former catch up ceiling only when an independent identity group corroborates it, and relaxed stale reference handling for far behind nodes.
* Classified DRep registration deposit conformance failures as `IncorrectDepositDRep` instead of `IncorrectDepositDELEG`, making the reported failure match the affected deposit type.

### APIs, integrations, and service reliability
* Streamlined CI handling for documentation only merge groups by skipping tier 2 gates after successful classification, including all `docs/` assets. Publish verification still requires a successful changes check.
* Refreshed KES signing connections for each request, closed them after each signing response, counted connection and handshake failures, and retained persistent serve key subscriptions.
* Ignored DMQ send refusals caused by protocol shutdown when Dingo evaluates peer failures.
* Closed Mithril chunk feeds before removing temporary directories in the budget test, preventing cleanup from racing with active reads.
* Adjusted six dashboards to exclude released Go heap from the MMAP estimate.
* Propagated RPC context through Midnight `end_block_hash` resolution and `BlockByHash`, and updated the `BlockNumberByHash` callback signature. Midnight integrations must accept the new context parameter.
* Expanded token registry support to public archives without signed manifests, ETag revalidation, mainnet and testnet layouts, and safe handling of entries that are not assets.
* Validated remote ImmutableDB reads by stopping at the chunk containing the remote tip and failing when that chunk does not reach the tip. Remote readers now require a positive `chunkSlots` value.
* Enforced exact `(tx_id, output_idx)` lookup for batched UTxO RPC `ReadUtxos` requests, applied `MaxResponseBytes` while loading CBOR, and returned `ResourceExhausted`, `Canceled`, and `DeadlineExceeded` consistently. Clients should size responses within the configured limit and handle these status codes explicitly.
* Secured JWK and JOSE processing by upgrading `go-jose/v4` to `4.1.6`. RSA keys larger than the default 4096 bit modulus limit require `MaxRSAModulusBits` before parsing.
* Hardened DevNet state directory creation with fixed component traversal, symlink and race protection, marker validation before permission restriction, and platform specific secure path handling. Operators should use a trusted, dedicated state path and avoid symlinked path components.
* Metered Bark height based `FetchBlock` storage work, including bound resolution, binary search probes, and stale tail retries, and returned `ResourceExhausted` before work begins when the budget is insufficient.
* Bound UTxORPC `FetchBlock` reads to the request context, checked cancellation between blocks, mapped cancellation and deadlines to `Canceled` and `DeadlineExceeded`, and released bulk capacity promptly.
* Redacted token registry URL paths in configuration and synchronization logs. Valid HTTP(S) URLs retain only their scheme, host, and port, while non HTTP(S) values receive full redaction.
* Serialized ADA only Babbage LocalStateQuery UTxO outputs with the legacy two element array encoding used by `cardano-node` and `cardano-ledger`; outputs with assets, datums, or reference scripts retain their existing encoding.
* Enabled DMQ peer listeners, peer management, outbound dialing, topology, public root, and ledger SRV discovery, inbound limits by source, topic labeled metrics, and peer dial counters. Node mode activates DMQ interoperability when `n2nPort` and `maxPeers` are enabled, so operators should configure both values when the feature is required.
* Hardened Mithril download staging, resume, and storage with exclusive partial files, atomic publication, refusal of symlinks and non regular files, owned single link resume checks, stale staging cleanup, shared free space reserves, and failure cleanup. Operators should provide a writable cache path that does not rely on symlinked or shared partial files.
* Batched and deduplicated UTxORPC `ReadData` datum lookups in one context bound read transaction while preserving first seen order and consistent handling of missing data, cancellation, and deadlines.
* Stabilized DMQ peer manager redial behavior by closing the manager held connection and verifying that a distinct connection succeeds on redial.
* Implemented LocalStateQuery pool state and reward provenance queries and made stake pool parameters point aware. Unsupported debug and non myopic queries now fail explicitly with `ErrQueryNotAnswered`, so callers must handle the error instead of waiting for an unanswered result.
* Reserved separate bounded capacity for API mempool validation, failed API admission quickly when that capacity was exhausted, and preserved at least one shared validation slot for direct peer submissions. API saturation maps to Mesh `unavailable` and UTxORPC `ResourceExhausted`.
* Admitted UTxORPC `ReadTx` through shared bulk read capacity before ledger lookup, returning `ResourceExhausted` without reading when capacity is exhausted.
* Streamed Mesh `/account/coins` responses in bounded pages from one storage snapshot, preserved complete response semantics and the snapshot `block_identifier`, and aborted the connection after a mid stream failure. Operators can tune the account coins page size, candidate, and byte settings for available capacity.
* Updated `gouroboros` to `0.216.0` and `plutigo` to `0.10.0` with their transitive cryptography dependencies, aligning Plutus evaluation and stricter CBOR decoding behavior.
