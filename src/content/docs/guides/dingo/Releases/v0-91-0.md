## v0.91.0

**Title:** Improve tracing, observability, performance, and operations

**Version:** v0.91.0

**Release:** [v0.91.0](https://github.com/blinklabs-io/dingo/releases/tag/v0.91.0)

**Comparison:** [v0.90.5...v0.91.0](https://github.com/blinklabs-io/dingo/compare/v0.90.5...v0.91.0)

Dingo v0.91.0 improves tracing across nodes, operational visibility, node parity configuration, database performance, container builds, protocol validation, and documentation quality.

### Recommended Network Compatibility ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

#### Node synchronization and chain selection
* Added authenticated delivery recovery for Genesis data, allowing the node to resume delivery after authentication failures.
* Improved Limit on Eagerness progress at immutable tips, keeping chain selection moving when the tip cannot change.
* Fixed operational certificate retry behavior when verification contexts change, allowing the node to resume validation with the new context.
* Corrected superseding pool retirement and VRF key lookup, keeping replacement handling aligned with the active pool state.
* Genesis corroboration defaults to zero peers, which disables the corroboration gate. Set a positive `genesisBootstrap.corroborationPeers` value to enable it.

#### Catch-up and state access
* Added batching for idle catch-up work, reducing unnecessary processing while the node waits for new blocks.
* Improved prepared sync-state reads, making repeated state access more efficient.
* Fixed Mesh balance-read admission and cancellation, so pending requests release resources correctly.
* Stabilized electing VRF memoization with rollback fencing, keeping cached decisions consistent after rollback.

#### API and metadata handling
* Exposed Blockfrost `Retry-After` through CORS responses, allowing clients to follow server-provided retry timing.
* Reused verified Blockfrost transaction counts, avoiding redundant count requests.
* Batched validated-block API index writes and made each flush atomic, rolling it back when a write failed.
* Preserved metadata labels for deep and non-JSON values, retaining raw CBOR and representing unavailable JSON as null.
* Kept container-valued metadata map keys in CBOR only, avoiding invalid JSON representations.

#### Protocol and ledger validation
* Pinned deferred governance ratification to the correct boundary, keeping delayed decisions aligned with the governing era.
* Folded imported reward credits exactly once, preventing duplicate credits during repeated processing.
* Optimized committee-scale BLS validation and cached verified keys, reducing repeated cryptographic work.
* Validated Conway rules on networks that start in Dijkstra, keeping protocol checks aligned with network era configuration.
* Corrected scheduled Dijkstra hard-fork timing and era history, ensuring transitions follow configured schedules.

#### Build reliability
* Restored Docker builds that require `gnupg`, keeping the container build available when package signing tools are needed.

#### Tracing and observability
* Added block tracing that derives a shared trace identity from each block hash, replaces the old span names with a stage-based taxonomy, connects stage, transaction admission, catch-up, Mithril, and database lifecycle spans across nodes, and correlates logs. Optional OTLP log and metric export use `OTEL_LOGS_EXPORTER` and `OTEL_METRICS_EXPORTER`; `OTEL_RESOURCE_ATTRIBUTES` and `OTEL_SERVICE_NAME` define service resources, SQL spans appear only for sampled traces, and `DINGO_TRACING_ALWAYS_SAMPLE_POOLS` provides the always sampled pool allowlist used by the tracing dashboard.
* Removed observer-demoted peers from Limit on Eagerness candidates, so observability-only peers no longer constrain chain selection.

#### API, node parity, and database performance
* Projected Blockfrost block output and fee totals directly from SQL when SQL supports these projections, avoiding the need to load full transactions while preserving decimal-safe totals and fallback behavior.
* Configured Koios `/tx_info` batching with `--koios-tx-info-batch-size` and `--koios-tx-info-concurrency`; the defaults remain 40 hashes per request and 8 concurrent requests, with validation and improved request scheduling.
* Optimized epoch output totals with index-friendly slot-range selection, consistent deferral and rollback of API-mode closure address rows, and lower overhead for SQLite insert-result paths while preserving identifiers and cancellation.
* Reused SQLite scratch values for exact bigint sums and added a fast path for 64-bit decimal strings while retaining exact wide-decimal behavior.
* Preserved SQLite transaction identity, conflict handling, replay behavior, rollback, and cancellation by using captured transaction insert results.
* Streamlined transaction writes by batching API-mode Leios closure address rows until flush and reducing SQLite UTxO insert-result overhead while preserving repair behavior.

#### Protocol validation and build operations
* Strengthened Mithril genesis certificate verification by binding aggregate keys and protocol-parameter hashes to the signed message.
* Selected the legacy BLS_SIG proof domain for canonical DijkstraNet and BLS_POP for other and private chains across startup, replay, and validation.
* Updated pinned `ca-certificates` and `libssl3` versions and the Debian snapshot date so builds continue to resolve required packages.
* Switched Docker runtime and Antithesis stages to live Debian repositories and unpinned packages, and installed PostgreSQL client 16 from the signed live `pgdg` repository after fingerprint verification instead of archived package downloads.
* Improved CI and Docker module downloads by falling back from `https://proxy.golang.org` to `direct` when proxy transport errors occur.

#### Documentation
* Reformatted repository Markdown prose to 80 columns and corrected rendering behavior without changing the documented meaning.
