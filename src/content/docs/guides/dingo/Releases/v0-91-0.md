## v0.91.0

**Title:** Improve tracing, observability, performance, and operations

**Version:** v0.91.0

**Release:** [v0.91.0](https://github.com/blinklabs-io/dingo/releases/tag/v0.91.0)

**Comparison:** [v0.90.5...v0.91.0](https://github.com/blinklabs-io/dingo/compare/v0.90.5...v0.91.0)

Dingo v0.91.0 improves tracing across nodes, operational visibility, node parity configuration, database performance, container builds, protocol validation, and documentation quality.

### Recommended Network Compatibility ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

#### Tracing and observability
* Added block tracing that derives a shared trace identity from each block hash, connects stage, transaction admission, catch-up, Mithril, and database lifecycle spans across nodes, correlates logs, supports optional OTLP log and metric export, honors service resource settings, records SQL spans only for sampled traces, and provides a tracing dashboard with an allowlist for always sampled pools.
* Removed observer-demoted peers from Limit on Eagerness candidates, so observability-only peers no longer constrain chain selection.

#### APIs and data access
* Accelerated catch-up by applying gathered blocks after a 250 millisecond idle period when no additional work can arrive, while retaining the one second limit for active streams.
* Exposed `Retry-After` to browser clients from allowed origins when Blockfrost admission requests receive HTTP 429 responses; disallowed origins remain blocked.
* Reused verified transaction data for repeated Blockfrost transaction counts, rechecking manifest and body integrity while preserving fallback errors.
* Batched address, history, witness, and metadata index writes for each validated block in API mode and rolled them back atomically when the final flush failed.

#### Ledger, governance, and metadata
* Retained labels for deeply nested or non-JSON metadata by indexing the raw CBOR while representing unavailable JSON fields as `null`.
* Kept container-valued metadata map keys in indexed CBOR and excluded them from JSON output.
* Anchored deferred governance ratification to the committed boundary proposal and DRep state, making expiry and orphan removal deterministic.
* Folded reward credits covered by imported balances exactly once and drained remaining covered outputs before checkpointing, avoiding duplicate or stale credit state.

#### Era compatibility and performance
* Optimized committee BLS key processing through parallel decoding, efficient aggregation, and bounded verified-key caching without changing certificate validation.
* Supported Conway transaction validation on networks that start in Dijkstra by deriving the required embedded Conway parameters consistently across related validation paths.
* Honored scheduled Dijkstra hard fork epochs at genesis, avoiding premature block forging and keeping era history, Leios runtime gating, and genesis stake warming aligned.
* Reused prepared synchronization-state reads in supported SQL backends during write transactions while retaining fresh reads and avoiding separate read-pool contention.
* Bounded current-tip account balance reads with bulk admission and cancellation; saturated requests return `ErrUnavailable`, and canceled requests stop database work and error responses. `MeshLedgerState.UtxosByAddress` now accepts `context.Context`.
* Memoized stable electing VRF key hash lookups with rollback generation fencing, reducing repeated work during synchronization and header validation without using stale hashes.

#### Container builds
* Enabled PostgreSQL repository key verification in Docker builds by installing `gnupg` first, restoring amd64 and arm64 image builds.
