## v0.82.1

**Title:** Prevent oversized transactions during database recovery

**Version:** v0.82.1

**Release:** [v0.82.1](https://github.com/blinklabs-io/dingo/releases/tag/v0.82.1)

Dingo v0.82.1 improves legacy database recovery by rebuilding the inventory of retained blocks in bounded batches. No application changes are required for this patch release.

### Recommended Network Compatibility ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### Database recovery
* Improved startup and commit-timestamp recovery for legacy databases by rebuilding the inventory of retained blocks in bounded batches. This prevents transaction size limit failures when one transaction cannot hold every index entry. Large datasets retain correct inventory counts, oldest slots, successor relationships, and lookups, while initialization removes stale inventory keys.
