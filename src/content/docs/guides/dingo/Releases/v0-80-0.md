## v0.80.0

**Title:** Improve state recovery, query accuracy, security, and operations

**Version:** v0.80.0

**Release:** [v0.80.0](https://github.com/blinklabs-io/dingo/releases/tag/v0.80.0)

Dingo v0.80.0 improves state recovery and loading, governance queries, node security, block production operations, peer resource controls, and release automation. It also strengthens ledger validation and protects long running database and pipeline work from inconsistent state or stalled processing.

### State recovery and loading
* Improved state imports by validating UTxO-HD settings first and atomically clearing post-anchor epoch, reward, nonce, network, and donation data before importing ledger state.
* Added resumable remote ImmutableDB loading for `dingo load` over HTTPS or loopback HTTP, with ordered chunks and tip and hash verification.
* Removed stale post-anchor reward journals when Mithril restores credentials, keeping restored reward state consistent.
* Preserved non-Byron slot zero nonce state during rollback, preventing valid nonce data from being lost.
* Halted authoritative reward rollover when the required reward basis is unavailable, avoiding unsupported state transitions.

### Security and validation
* Rejected non-regular secret key, operational certificate, and vote signing paths, and limited key envelopes to 1 MiB.
* Enforced HTTPS origin, redirect, DNS address, port, and proxy policies for Bark archive downloads.
* Rejected typed nil protocol parameters with a clear validation result instead of allowing a panic.
* Refused invalid classic PPUP proposals and corrected negative rational fee underflow handling.
* Bounded Mithril certificate chains, message sizes, signer counts, STM counts, and weighted verification work to limit resource consumption.
