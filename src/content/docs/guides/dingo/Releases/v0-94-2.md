## Dingo v0.94.2

**Title:** Improve protocol safety, Leios coordination, and service reliability

**Version:** v0.94.2

**Date:** 2026-11-16

**Release:** [v0.94.2](https://github.com/blinklabs-io/dingo/releases/tag/v0.94.2)

Dingo v0.94.2 strengthens Cardano protocol validation, improves Leios coordination, makes API results more consistent, and increases operational resilience.

### Protocol and API behavior
* Improved protocol validation by rejecting malformed or null collection values in invalid transactions and auxiliary data, using big-endian words for IPv6 peer addresses, and rejecting TxSubmission advertisements or reply bodies larger than `65540` bytes. Duplicate pre-Conway withdrawal accounts and Babbage auxiliary-data indexes now use the last entry.
* Sorted multi-assets in deterministic ascending raw-byte order across Blockfrost, Mesh, and UTxO RPC responses. Dingo sorts existing stored rows when it reads them, while minted assets use their first slot and transaction position with deterministic tie breaking and overflow-safe ordering.

### Leios coordination
* Added committee quorum checks for Leios endorser-block capacity. By default, Leios and Musashi mempool capacity uses `25 MiB` when quorum is possible and `1 MiB` otherwise; an explicitly configured capacity remains fixed. The node skips endorser-block forging when quorum is impossible or unresolved, and `dingo_mempool_capacity_bytes` reports the current capacity.
* Expanded Leios voting to accept JSON arrays of Cardano BLS text-envelope keys, as well as a single envelope or legacy raw hexadecimal scalar. An empty array runs as a non-voting relay, invalid elements prevent key loading, and key sets support multiple committee seats and key rotation. Multi-pool validation relaxes when Leios voting is the only enabled role, while Leios forging restrictions remain.
* Closed only the offending connection when a received Leios offer is unannounced, repeated, older than the immutable slot, or claims an invalid body size. Valid offers continue through validation, and the node suppresses duplicate outgoing offers per connection.

### Operations and service performance
* Kept the node running after daily Koios quota exhaustion when `--koios-parity-strict` is enabled. The node records the HTTP `429` response as an error and retries, while persistence failures remain fatal; the `/tx_info` path follows the same recoverable behavior.
* Completed Badger and SQL metadata storage closure after shutdown or request deadlines, with progress and warning logs. Supervisors must allow `shutdownTimeout` plus close time, `SIGKILL` can still interrupt a wedged close, and remote restart waits for shutdown to finish.
* Accelerated Blockfrost pool list queries by caching active lists for each chain tip and narrowing retiring and retired queries with an index. Optional `maxConcurrentPoolLists` and `maxConcurrentPoolListsPerClient` limits return HTTP `429` with `Retry-After: 1`, while client cancellations remain silent.
