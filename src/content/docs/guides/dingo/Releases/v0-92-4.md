## v0.92.4

**Title:** Improve access, protocol safety, and synchronization

**Version:** v0.92.4

**Release:** [v0.92.4](https://github.com/blinklabs-io/dingo/releases/tag/v0.92.4)

**Comparison:** [v0.92.3...v0.92.4](https://github.com/blinklabs-io/dingo/compare/v0.92.3...v0.92.4)

Dingo v0.92.4 restores selected HTTP access, improves ledger and synchronization reliability, strengthens input and network protections, and updates runtime and dependency support.

### Recommended Network Compatibility ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

#### APIs and service access
* Restored anonymous plaintext HTTP access for Blockfrost transaction submission and evaluation, MCP endpoints, Bark services, Prometheus `/metrics`, and Mithril registration and closure APIs. Legacy authentication, tokens, and mutual TLS no longer gate these endpoints; rate limiting, origin checks, request validation, and network layer protection for exposed listeners remain required.
* Added bounded admission and 15 second deadlines to Blockfrost pool and epoch block list endpoints. Out of range paging now returns efficiently, and overloaded requests receive `429` or `503` with `Retry-After`.
* Resolved Blockfrost, Mesh, and Midnight heights by chain number rather than storage IDs, including sparse IDs, duplicate Byron heights, applied tips, and pagination fixes.

#### Ledger and protocol correctness
* Corrected stake reward processing when an epoch's first block arrives late by replaying the previous reward round, correcting reward pots and fee carry-forward while preserving Byron prefix handling and rollback deterministic boundary processing.
* Rejected oversized CBOR tag-30 rationals before typed decoding, applying protocol version and `MaxTxSize` aware limits to reduce CPU exhaustion risk.
* Advanced forge validation state to the candidate slot, including validation-only epoch boundary effects and reference-script checks.

#### Synchronization and node parity
* Streamed bounded, chain ordered `/tx_info` fetching during node parity from genesis chain reads and improved wait diagnostics.
* Persisted node parity boundary captures across restarts, waited for in progress captures, validated artifacts, and cleaned up safely.
* Made Koios `/account_list` crawling durable and resumable with persisted cursors and partial pages, completion promotion, drift handling, and longer timeouts.

#### Network interoperability
* Stabilized DMQ interoperability tests by waiting based on the last accepted pool message, avoiding `SigTooFrequent` failures.
* Embedded the prime mainnet Cardano configuration, topology, and genesis files and added validation coverage.
* Prevented stale advertised peers from occupying Genesis mode ingress slots and added recycler eviction.

#### Operations and dependencies
* Updated Go to 1.26.11, tied workflows to `go.mod`, refreshed the Docker builder image and cache namespaces, and addressed the reported `net/http` vulnerability.
* Enabled opt in `DINGO_LOG_FILE_APPEND=true` behavior to reuse existing regular log files while preserving permissions, inserting a newline for torn lines, and rejecting symlinks and non regular files; default exclusive create behavior remains unchanged.
* Secured the crypto dependency by updating `golang.org/x/crypto` to a fixed revision that addresses the reported vulnerability.
* Stabilized the lone owner Ouroboros deadline test with a fake clock.
* Refreshed AWS SDK credentials from 1.20.9 to 1.20.16.
* Aligned `gouroboros` with v0.219.0 and `plutigo` with v0.12.1, including Dijkstra validation behavior and Plutus data API changes.
