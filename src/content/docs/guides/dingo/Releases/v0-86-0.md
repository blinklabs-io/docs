## v0.86.0

**Title:** Improve validation, security, and synchronization reliability

**Version:** v0.86.0

**Release:** [v0.86.0](https://github.com/blinklabs-io/dingo/releases/tag/v0.86.0)

Dingo v0.86.0 improves ledger validation, synchronization safety, API protection, storage recovery, conformance reporting, and operational performance compared with v0.85.0.

### Recommended Network Compatibility ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### Breaking changes
* Changed Genesis corroboration to run by default. An explicit opt out is now required to disable it.
* Enforced Leios certification timing and epoch boundaries, and required a forger timing checker for certification.
* Limited block ExUnits during historical synchronization so the node rejects blocks that exceed the permitted resource budget.
* Required verified TLS for remote PostgreSQL and MySQL metadata connections, and rejected `tls=skip-verify` for snapshot and restore operations.
* Secured remote Blockfrost mutation routes with token authentication, while local access uses loopback defaults and remote authenticated access requires TLS.
* Disabled gRPC `Health` and `Watch` streaming for UTxO RPC, Bark, and Midnight. Unary `Check` remains available, and Midnight retains `List`.
* Bounded MCP sessions and SQLite tools, Kupo match streams, Midnight RPCs, Blockfrost DRep requests, and UTxO RPC `ReadTx` input and error handling; `ReadTx` now validates transaction hashes.

### Security and reliability
* Hardened remote block ingestion with rewind on failure, block span validation, body hash verification, and panic safe decoding.
* Restricted Mithril and npm download destinations, verified ancillary manifests before extraction, and enforced download and extraction budgets.
* Protected snapshot trust key loading with no follow behavior, ownership and permission checks, and a 1 KiB size limit.
* Validated Praos headers during ImmutableDB replay and load, failed closed when verification inputs were missing, safely rewound rejected blocks, preserved manual recovery causes, and avoided unnecessary marker cleanup.
* Parallelized replay header verification with bounded workers while preserving cancellation errors.
* Bounded rollback intent recovery input and added a bounded metadata store read.
* Bound ChainSync header selection, trusted history, and replay admission to the ledger’s current header-crypto verification generation while invalidating stale suffixes and preserving verified ancestry.
* Isolated snapshot verification by accepting only SQLite metadata and Badger blob manifests before provider resolution.

### Fixes and enhancements
* Improved conformance reports to match NDC schemas, evaluated textual UPLC programs, refined decode classification, and updated plutigo to v0.9.10.
* Corrected exact transaction input queries by using the composite index.
* Aligned CBOR, ledger rules, UPLC, and turbo report schemas with NDC and added pinned corpus validation.
* Retained Koios pool fetch progress across retries.
* Restored Genesis forecast corroboration with a temporary witness.
* Reconciled stale Mithril governance proposals.
* Capped and cancelled large UTxO and state materialization, and corrected the `GetCBOR` response shape.
* Improved verified ImmutableDB entry loading by hashing and parsing each entry once, with a 16 MiB size limit.

### Performance and benchmarks
* Replaced the LeiosDB throughput benchmark with a latency benchmark and added new flags.
* Introduced an opt in Badger garbage collection benchmark and documentation.
* Increased Mithril immutable archive workers from 16 to 32.
* Reduced Leios transaction serving allocations by capping decoded views at available capacity and giving each response its own buffers; changed the Core Leios Badger value threshold to 1 KiB unless overridden; and added cached read, CPU profile, heap profile, and `bench-leios-db-cached` options.
* Added a sanitized default Core Mithril PGO profile and Makefile rebuild tracking.
* Raised Mithril v2 immutable archive workers from 32 to 48 and scaled related connection and in flight capacity.

### Synchronization and dependencies
* Preserved and correctly bound the staged far frontier proof.
* Prepared persisted era history before Midnight backfill.
* Updated `grpcreflect` to v1.3.1.
* Upgraded `smithy-go` to v1.28.5.
* Reused one serialized ChainSync tip connection per Dingo endpoint in the DevNet harness and reconnected after errors.
* Improved built in `Value` constant validation by updating plutigo from v0.9.7 to v0.9.9; the validator now rejects non canonical forms.
* Aligned `connectrpc.com/connect` with v1.21.1, updating it from v1.21.0.
