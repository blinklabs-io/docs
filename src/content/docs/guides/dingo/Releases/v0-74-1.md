## v0.74.1

**Title:** Bound ingress resources and strengthen ledger validation

**Date:** 2026-09-30

**Version:** v0.74.1

**Release:** [v0.74.1](https://github.com/blinklabs-io/dingo/releases/tag/v0.74.1)

This release limits resource exposure during ingress, improves database metadata reporting, and strengthens ledger data validation and regression coverage.

### Recommended Network Compatibility ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### Ingress and database improvements

* Improved ingress resource controls by bounding decode caches and peer header history in bytes, removing rejected blocks from cache, limiting and coalescing Leios vote and announcement verification within fixed windows, and separating trusted local Node-to-Client admission from remote quotas. Operators can configure `--max-trusted-local-ntc-conns` or `DINGO_MAX_TRUSTED_LOCAL_NTC_CONNS`; non-positive values use the default of `100`. Buffered-byte metrics distinguish trusted local and remote clients.

* Updated Bark `GetDatabaseInfo` responses to report the configured database storage tier in the `Tier` field, including values such as `core` and `api`.

### Ledger validation and test coverage

* Rejected imported committee quorum values outside the inclusive `[0,1]` range during ledger-state import and added malformed Conway and Dijkstra decoding regression coverage.

* Expanded regression coverage for Conway and Dijkstra `ParameterChange` values, including zero values, integer widths, domain and tag boundaries, and cost-model language ID limits.

* Strengthened regression coverage for auxiliary-data decoding and validation from Shelley through Conway, including index bounds, era-specific formats and Plutus languages, unknown fields, and malformed Plutus scripts.

* Verified Leios persistence queue reservation cleanup across panic unwinding, manifest and complete installation races, and concurrent byte-budget admission. Default behavior remains unchanged because the hook is nil by default.
