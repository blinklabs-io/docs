## v0.73.0

**Title:** Improve validation, recovery, and node resilience

**Date:** 2026-09-25

**Version:** v0.73.0

**Release:** [v0.73.0](https://github.com/blinklabs-io/dingo/releases/tag/v0.73.0)

Dingo is a Cardano blockchain node and API provider for direct use, and a Go library documented through [`go doc`](https://pkg.go.dev/cmd/go#hdr-Show_documentation_for_package_or_symbol) and [pkg.go.dev](https://pkg.go.dev/github.com/blinklabs-io/dingo). This release improves ledger and governance validation, protects synchronization and recovery workflows, and adds clearer controls for node operations.

### Recommended Network Compatibility ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### Validation and governance improvements

* Improved invalid and empty input handling with nil safety checks, so Dingo fails safely instead of dereferencing missing values. ([Change details](https://github.com/blinklabs-io/dingo/pull/4707))

* Strengthened sequential Conway committee certificate validation, preventing a transaction from repeating a resignation or resigning and then authorizing the same member. ([Change details](https://github.com/blinklabs-io/dingo/pull/4711))

* Stabilized node parity reconnect tests with gated listeners, improving confidence in reconnect behavior. ([Change details](https://github.com/blinklabs-io/dingo/pull/4693))

* Aligned Byron transaction and end of bootstrap block validation with cardano-ledger behavior, including serialized size and unknown attribute limits, positional witnesses, repeated input set semantics, fee and Lovelace bounds, canonical address roots, end of bootstrap block ordering, and deterministic replay recovery. ([Change details](https://github.com/blinklabs-io/dingo/pull/4710))

* Prevented Conway and Dijkstra parameter changes from accepting protocol version key `14`, and removed that key during enactment. ([Change details](https://github.com/blinklabs-io/dingo/pull/4699))

* Hardened Mithril backfill recovery by failing closed on malformed blocks and offset failures, preserving the last committed checkpoint, and reporting missing historical withdrawal accounts as errors. ([Change details](https://github.com/blinklabs-io/dingo/pull/4473))

* Added the informational `pool_zero_stake` Koios parity category when a complete reward snapshot proves that a registered pool reached zero stake; Dingo retains fail closed classifications when the snapshot is incomplete. ([Change details](https://github.com/blinklabs-io/dingo/pull/4692))

* Recognized an explicitly empty Conway genesis committee as authoritative during committee validation. ([Change details](https://github.com/blinklabs-io/dingo/pull/4517))

* Refined test database connections with the updated SQLite data source name, keeping SQLite-based test runs aligned with the supported configuration. ([Change details](https://github.com/blinklabs-io/dingo/pull/4713))

* Corrected Conway governance and committee semantics by distinguishing a valid zero quorum from SQL `NULL`, handling RATIFY without a committee, rejecting expired actions and duplicate removals, preserving canonical Plutus V3 ordering, and adapting Byron witness dependencies. ([Change details](https://github.com/blinklabs-io/dingo/pull/4704))

### Reliability, recovery, and synchronization

* Ensured Unix Badger close operations wait for the directory lock to release with a bounded best-effort wait; Windows close operations continue without this wait. ([Change details](https://github.com/blinklabs-io/dingo/pull/4671))

* Made `LedgerView.GetAdaPots` safe to call without a panic while the error-returning method continues to return `ErrNotImplemented`. ([Change details](https://github.com/blinklabs-io/dingo/pull/4511))

* Adjusted peer tip staleness checks to use the selector clock, keeping freshness decisions tied to the clock that selects peers. ([Change details](https://github.com/blinklabs-io/dingo/pull/4677))

* Persisted and replayed a bounded rollback undo outbox before chain truncation, providing at-least-once delivery for rollback work. ([Change details](https://github.com/blinklabs-io/dingo/pull/3910))

* Included entering epoch `extraEntropy` in epoch nonce calculations for epoch rollover, header verification, and startup recovery. ([Change details](https://github.com/blinklabs-io/dingo/pull/4518))

### Node operations and dependencies

* Added Genesis Limit on Patience for ChainSync with a default capacity of `1000` and a leak rate of `5` tokens per second. Dingo now emits a corresponding event and metric, recycles peers that exceed the limit, and exposes `genesisBootstrap.limitOnPatienceEnabled`, `genesisBootstrap.limitOnPatienceCapacity`, and `genesisBootstrap.limitOnPatienceRate` through CLI, configuration, and environment settings. ([Change details](https://github.com/blinklabs-io/dingo/pull/4686))

* Updated the gouroboros dependency to `v0.207.4`. ([Change details](https://github.com/blinklabs-io/dingo/pull/4714))

* Removed Windows automated checks, builds, and release artifacts from the supported release workflow. ([Change details](https://github.com/blinklabs-io/dingo/pull/4701))
