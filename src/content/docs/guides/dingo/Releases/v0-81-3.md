## v0.81.3

**Title:** Improve peer reliability, conformance, and query recovery

**Version:** v0.81.3

**Release:** [v0.81.3](https://github.com/blinklabs-io/dingo/releases/tag/v0.81.3)

Dingo v0.81.3 improves peer connection handling, Conway conformance reporting, certified block processing, object storage integrations, and local state query recovery.

### Recommended Network Compatibility ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### Peer connectivity
* Improved inbound peer connection stability by tracking flap history for each normalized transport identity, limiting repeated short sessions per host, grouping scoped IPv6 addresses by `/64`, preserving active cooldowns after the observation window expires, and keeping unrelated peers behind the same NAT separate.

### Conformance and validation
* Added a Conway CBOR conformance command that validates and normalizes CBOR, emits a JSON report in `cardano-cbor-dataset` format, and publishes a dated report as a tag release asset. Release publishing can require exactly one report. Validation and recovery also improve Byron checks, transaction output index limits, governance cost model language ID checks, Byron epoch 0 EBB handling, block fetch low watermark configuration, and related recovery behavior.

### Certified block processing
* Corrected certified apply fixtures with the required VRF and operational certificate data, keeping Leios certification scenarios aligned with valid block metadata.
* Ensured the node applies endorser blocks only after certificate verification on every network. The node rejects or waits for missing or invalid certified dependencies instead of applying unverified blocks, and metrics no longer record an unavailable outcome.

### Storage and observability
* Updated the AWS SDK S3 manager to `v1.23.13`, the S3 service to `v1.114.2`, and related indirect modules, keeping object storage integrations current.
* Refined OpenTelemetry Go and the OTLP HTTP trace exporter at `v1.47.0`, adding upstream logs modules and an exporter response size option.

### Release automation
* Hardened optional conformance report uploads to handle releases without a report on Bash 3.2.

### Query recovery
* Restored LocalStateQuery continuity by reopening expired views at the acquired point or snapshotted tip, retrying queries, preserving pruning pins, and canceling reopen waits on disconnect. Rollback and pruning cases that cannot reopen continue to fail.
