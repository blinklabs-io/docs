## v0.70.16

**Title:** Protect rollback state and improve network reliability

**Date:** Not provided

**Version:** v0.70.16

**Release:** [v0.70.16](https://github.com/blinklabs-io/dingo/releases/tag/v0.70.16)

This release updates Dingo from v0.70.15 to v0.70.16. It strengthens rollback and transaction safety, connection lifecycle handling, block synchronization, transaction submission, Mithril processing, database migration, retrieval security, release validation, and test coverage.

### Runtime and operational improvements

* Improved rollback safety by persisting `consumed_utxo_prune_floor` and rejecting ledger or lifecycle rollbacks and truncations below hard-deleted consumed UTxO data before mutation. Peer and replay recovery now resynchronizes or clamps safely and exposes a clamp metric. Operators must truncate at or above the floor or bootstrap a new node.

* Added a pending transaction barrier and transaction completion callback so rollback waits for uncommitted writes, deferred events publish only after transaction completion, and rollback restoration remains safe.

* Protected replacement connections by associating ChainSync, Leios serving waiters, LocalStateQuery pins, and LeiosNotify cleanup with their owning connection, preventing stale close callbacks from affecting replacement connections that reuse a connection identifier.

* Corrected BlockFetch recovery by tying batches to rollback generations, discarding superseded bodies, tracking applied block progress accurately, validating endpoints, and returning `BatchDone` at normal completion without closing the transport.

* Preserved typed LocalTxSubmission rejection causes for Conway and Dijkstra, classified infrastructure failures generically, encoded empty-input errors by era, and kept sessions open for representable rejects.
