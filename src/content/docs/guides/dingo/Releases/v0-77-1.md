## v0.77.1

**Title:** Improve storage, synchronization, Mithril recovery, and Dijkstra support

**Date:** 2026-10-03

**Version:** v0.77.1

**Release:** [v0.77.1](https://github.com/blinklabs-io/dingo/releases/tag/v0.77.1)

Dingo v0.77.1 improves SQLite recovery space management, blockfetch delivery, Mithril state repair, Dijkstra script fee calculation, reward-credit queries, and network data validation. It also updates `gouroboros` to v0.209.0 and expands regression coverage for Dijkstra and Conway behavior.

### Recommended Network Compatibility ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### Storage and data handling
* Limited retained SQLite write-ahead log space to 64 MiB after a reset through `journal_size_limit`, while active writes and readers can exceed that limit and `TRUNCATE` can reduce an idle log to zero.

* Aligned Byron balance, fee-value subtraction, and created-UTxO metrics with outputs 0 through 65,535 in the Word16-indexed `Produced()` view while continuing to validate later outputs, and updated `gouroboros` to v0.209.0.

### Synchronization and recovery
* Streamlined blockfetch ledger publishing with bounded per-connection FIFO forwarding that preserves order and reports overflow, backpressure, and keep-alive timeout metrics.

* Repaired legacy Mithril reward state when the certified tip is an ancestor of the local tip by preserving verified tail blocks, rebuilding derived metadata, and refusing states older than the stable anchor.

### Dijkstra and governance
* Expanded Dijkstra Plutus V4 context and `required_top_level_guards` regression coverage, helping verify existing validation behavior.

* Calculated Dijkstra reference script fees with the protocol stride and multiplier, using Conway fallbacks where required, and covered Plutus V4 cost model behavior.

* Verified that imported ratified `UpdateCommittee` actions take effect at the next epoch boundary through regression coverage.

### Efficiency and integrity
* Reduced SQLite scans when claiming reward credits by selecting IDs through the pending index and reading rows by primary key.

* Improved Mithril archive handling by ordering digest leaves numerically, removing unusable fully downloaded archives after verification or extraction failures, preserving partial downloads and cancellations, and tightening aggregate signature parsing.
