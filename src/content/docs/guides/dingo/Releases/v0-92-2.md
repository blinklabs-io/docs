## v0.92.2

**Title:** Improve performance, synchronization, and protocol reliability

**Version:** v0.92.2

**Release:** [v0.92.2](https://github.com/blinklabs-io/dingo/releases/tag/v0.92.2)

**Comparison:** [v0.92.1...v0.92.2](https://github.com/blinklabs-io/dingo/compare/v0.92.1...v0.92.2)

Dingo v0.92.2 improves database efficiency, rollback recovery, protocol validation, ledger processing, Leios content delivery, and operational reliability.

#### Database and storage
* Improved SQLite fee queries by aggregating execution slot transaction fees with `dingo_coin_sum`, preserving inclusive slot ranges, Leios selection, validation, overflow detection, and transaction visibility; PostgreSQL and MySQL continue streaming rows.
* Added opt-in lazy preparation for hot SQL statements through `Config.LazyHotStatements`. Test SQLite stores now prepare eligible statements on first write-pool use, memoize preparation failures, fall back to uncached execution, and refresh lazy caches after planner statistics; production keeps eager preparation disabled by default.

#### Chain selection and recovery
* Refreshed Praos schedules after rollback. The node preserves the current immutable epoch schedule, removes stale future schedules, rejects stale in-flight results through generation tracking, and recomputes current and next nonce-ready schedules.
* Bounded consumed-input recovery after restart to a configurable window with a default of 1000 blocks. Identity-less legacy checkpoints still receive full recovery, and recovery stops when periodic checkpoint persistence fails.
* Limited accepted header protocol versions to the maximum major version supported by enabled eras for live and historical peer processing. TrustedReplay and Mithril exemptions remain, and rejection still rewinds processing.
* Preserved elected VRF keys in imported snapshots through the v55 migration and frozen key validation. Legacy snapshots without the stored key now fail closed instead of using the removed bootstrap fallback.
