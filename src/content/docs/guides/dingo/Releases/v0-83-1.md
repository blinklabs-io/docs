## v0.83.1

**Title:** Improve ledger validation, recovery, and storage reliability

**Version:** v0.83.1

**Release:** [v0.83.1](https://github.com/blinklabs-io/dingo/releases/tag/v0.83.1)

Dingo v0.83.1 improves ledger validation, protocol support, recovery behavior, remote storage safety, and database performance compared with v0.83.0.

### Recommended Network Compatibility ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### Ledger and protocol validation
* Improved strict from genesis Preprod parity by applying network specific Koios pre staking boundaries through epoch 5 on Preprod and through epoch 1 by default, so null active stake values receive the correct handling.
* Validated the elected pool VRF key at the applied ledger tip, using a snapshot or effective registration when the primary record is unavailable.
* Updated the block pipeline and Leios protocol support through the `gouroboros` v0.213.1 integration. Dingo now uses the updated verification behavior, supports `GetStakeDistribution2`, accepts the current Leios message shapes, and supports transaction references up to `uint32` sizes.
* Added database migration v44 to repair committee term starts that renewal operations stamped incorrectly.

### Synchronization and recovery
* Strengthened Leios historical backfill by selecting an appropriate source and evicting delivery log entries safely.
* Refined boundary era handling by deriving eras from ledger state and aligning validation with block forging.
* Retried forged block self validation across ledger transitions and skipped blocks that could not be verified without reporting false validation failures.
* Verified rollback points against the local primary chain before escalating recovery.
* Restored ledger consistency during catch up imports by rolling back metadata written after the anchor point.

### Storage and operational reliability
* Expanded remote ImmutableDB destination checks across redirects and DNS resolution, disabled ambient proxies, and enforced aggregate limits for transfers, cache, free space, and concurrent work.
* Optimized fresh Mithril API bootstrap classification and finalized planner statistics reliably.
* Accelerated SQLite deferred index rebuilds with bulk load settings and UTxO batching.

### Mempool and peer management
* Preserved rolled back transactions in the mempool while evicting transactions confirmed by a block.
* Rejected peers registered for rollback when they had fallen too far behind the local chain.
