## v0.84.0

**Title:** Improve node reliability, validation, and conformance tooling

**Version:** v0.84.0

**Release:** [v0.84.0](https://github.com/blinklabs-io/dingo/releases/tag/v0.84.0)

Dingo v0.84.0 improves local transaction submission, network synchronization, ledger validation, operational safety, and release conformance reporting compared with v0.83.1.

### Recommended Network Compatibility ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### New features and network behavior
* Added a feature-flagged CIP-0137 DMQ local submission and notification service over a configurable Unix socket. The `dmq.enabled` setting and `--dmq-enabled` flag control the service, which validates its configuration, delivers messages to each consumer, reports rejection reasons, and exposes `dingo_dmq_*` metrics.
* Lowered routine node-to-client connection acceptance and peer hangup messages to DEBUG while retaining WARN for unexpected closure errors, making normal network activity less noisy without hiding failures.
* Ignored syntactically valid but unsupported opaque Leios announcements while continuing to penalize malformed CBOR.
* Staged peer tips until ledger admission, advanced selector-visible progress only after acceptance, corrected delivery watermarks, and cancelled queued Leios fetch work when a connection closes.

### Breaking changes
* Aligned leader eligibility and scheduling with Cardano E34 finite arithmetic. The update stores schedules in format v5, replaces the removed threshold margin histogram with rejection accounting, bounds replay cryptographic validation, and rejects malformed Leios fetch bitmap or payload cardinality. Regenerate persisted schedules and update metric consumers before upgrading. AndrewWestberg made a first contribution with this update.

### Performance and ledger improvements
* Improved immutable replay efficiency, reducing the work required during replay.
* Expanded Dijkstra Peras and reference input cost parameters across validation, governance, cloning, and queries, and restored eligible rolled-back mempool transactions after rebuilding the overlay.
* Accepted portless DNS and SRV peer snapshot relays as `MultiHostName` entries while continuing to reject portless IP relays.
* Bounded Bark archive RPC transport so archive requests cannot consume unbounded transport resources.

### Validation and compatibility
* Rejected trailing CBOR in the Leios Conway fallback, preventing the fallback from accepting extra data after an otherwise valid message.

### Conformance and release tooling
* Standardized CBOR conformance on a pinned, inventory-verified primary corpus, added schema and waiver handling, and changed report assets to gzipped JSON.
* Pinned executable release inputs to make release execution reproducible.
* Modeled Koios `proposal_refund` rewards and unmodeled reward types in strict parity.
* Published four release conformance report types and removed expensive conformance report generation from routine change validation.
* Escaped Mithril aggregator and command error text before terminal and log output, so error text cannot change output structure.
* Redacted public health diagnostics and remote `ImmutableDbPath` credentials while returning stable health reason codes.
* Aligned CBOR and ledger reports and allowed the shared Conventional Commits workflow exception to SHA pinning.
* Refreshed SQLite planner statistics every minute between epoch rollovers to keep query planning current.
* Preserved conformance assets and partial reports when generators fail, added per-generator timeouts, and changed the UPLC turbo report schema and default bounds.
