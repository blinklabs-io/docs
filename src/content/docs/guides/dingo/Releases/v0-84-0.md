## v0.84.0

**Title:** Improve node reliability, validation, and conformance tooling

**Version:** v0.84.0

**Release:** [v0.84.0](https://github.com/blinklabs-io/dingo/releases/tag/v0.84.0)

Dingo v0.84.0 improves local transaction submission, network synchronization, ledger validation, operational safety, and release conformance reporting compared with v0.83.1.

### Recommended Network Compatibility ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### New features and network behavior
* Added a feature flagged DMQ local submission and notification service over a configurable Unix socket. The `dmq.enabled` setting and `--dmq-enabled` flag control the service, which validates its configuration, delivers messages to each consumer, reports rejection reasons, and exposes `dingo_dmq_*` metrics.
* Lowered routine node to client connection acceptance and peer hangup messages to DEBUG while retaining WARN for unexpected closure errors, making normal network activity less noisy without hiding failures.
* Ignored syntactically valid but unsupported opaque Leios announcements while continuing to penalize malformed CBOR.
* Staged peer tips until ledger admission, advanced selector visible progress only after acceptance, corrected delivery watermarks, and cancelled queued Leios fetch work when a connection closes.

### Breaking changes
* Aligned leader eligibility and scheduling with Cardano E34 finite arithmetic. Persisted schedules now use format v5, the removed threshold margin histogram is replaced by rejection accounting, replay cryptographic validation is bounded, and malformed Leios fetch bitmap or payload cardinality is rejected. Regenerate persisted schedules and update metric consumers before upgrading.
