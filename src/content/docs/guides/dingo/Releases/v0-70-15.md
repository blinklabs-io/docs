## v0.70.15

**Title:** Strengthen bootstrap control, ledger safety, and testnet readiness

**Date:** 2026-09-19

**Version:** v0.70.15

**Release:** [v0.70.15](https://github.com/blinklabs-io/dingo/releases/tag/v0.70.15)

This release adds controlled Mithril bootstrap recovery, expands Prime testnet portability, and strengthens ledger, database, connection, and chain-origin safeguards. It also improves historical synchronization, validation efficiency, conformance coverage, and documentation consistency.

| musashi             | ✅         |

### Highlights
* Added pinned Mithril fresh bootstrap artifacts through `Mithril.PinnedDigest`, `mithril.pinnedDigest`, `--mithril-pinned-digest`, and `DINGO_MITHRIL_PINNED_DIGEST`; exact v1 and v2 retrieval now works, resumed imports preserve and validate durable pins, and the node rejects pins during catch-up or when an interrupted import uses a conflicting pin.

* Improved Koios coverage documentation checks by validating the `ARCHITECTURE.md` coverage table in both directions against the supported coverage matrix, with parser safeguards and aligned documentation, Makefile, and README scope.

* Refined MIR accounting so repeated pre-Alonzo distribution entries for protocol majors 2 through 4 replace prior values, while malformed or overflowing boundaries are discarded with warnings and the related database documentation stays accurate.

* Strengthened historical Mithril backfill to tolerate missing or inactive account rows and journal withdrawals without changing live-ingestion validation or creating or reactivating accounts.

* Expanded DRep deposit recovery to use the current deposit when the recorded value is absent, preserve an explicitly recorded zero, reject unsupported or invalid states, and avoid typed nil failures.
* Configured NtC admission limits for total connections and per IP address through YAML, CLI, and environment settings, released admission exactly once during cleanup or collisions, and added rejection metrics.

* Secured chain restart validation by anchoring the first Byron EBB at chain origin to the configured genesis hash, requiring epoch zero and the expected EBB shape, and repeating these checks after rollback to origin.

* Expanded database backed stake address adapter coverage to exercise its persisted behavior more fully.

* Corrected hard fork forecast handling so unavailable forecast shapes fail closed, dependent verification waits for valid data, cache backed conversions remain available, and `ConsensusModeForEpoch` reports errors instead of returning an unsupported result.

* Stabilized Mithril PState imports by bringing pending pool retirements into ledger state, validating referenced pools and epochs, writing synthetic retirement rows, and documenting the resulting database row semantics.
* Separated conformance profiles for ledger rules, deterministic consensus, and reference nodes, enforced corpus and scenario counts, improved diagnostics, and corrected coverage documentation.

* Made Mithril idle timeout checks deterministic so timeout validation produces repeatable results.

* Bounded committee authorization pruning by a live immutable slot derived from `securityParam`, suspended pruning when that slot is unknown, invalidated the pruning state after rollback, and documented the syncer behavior.

* Persisted `reward_snapshot.excluded_active_stake` and required exact stake reconciliation when that value is tracked, while preserving legacy behavior for older snapshots with a `NULL` value.

* Rejected Alonzo and Babbage MIR transactions when ordered, epoch scoped accumulated deltas become negative, including deltas from pending history and separate reserves or treasury pots.
