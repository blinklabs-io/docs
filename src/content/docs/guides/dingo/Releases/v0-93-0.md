## v0.93.0

**Title:** Improve storage efficiency, signing operations, chain selection, and test reliability

**Version:** v0.93.0

**Release:** [v0.93.0](https://github.com/blinklabs-io/dingo/releases/tag/v0.93.0)

**Comparison:** [v0.92.4...v0.93.0](https://github.com/blinklabs-io/dingo/compare/v0.92.4...v0.93.0)

Dingo v0.93.0 reduces database write churn, expands remote signing operations, improves pagination and chain selection, and strengthens time conversion, era handling, credential management, and validation workflows.

### Recommended Network Compatibility ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

#### Database and storage
* Improved SQLite stake and reward index updates with migration v59, narrower live stake and certificate upserts, prepared statements for only changed columns, and overlay keep pool updates. The node now avoids unnecessary database writes during ledger processing.

#### Remote signing
* Added remote Bursa KES agent signing with a selectable TLS or plain connection. Nonce bound admission, reused sessions, signature validation, resend handling, preconnection, and validated configuration improve reliability and let operators choose transport settings explicitly.

#### Governance and pagination
* Streamlined nonempty DRep pagination by deriving `total_count` with `COUNT(*) OVER ()` on returned rows, allowing delegation aggregation to run once. The node keeps a separate count query only for pages outside the available range.

#### Chain selection
* Anchored observed chain selection frontiers at chainsync session intersections with parent and boundary safeguards, improving decisions at synchronization boundaries.

#### Security workflow
* Moved `govulncheck` out of pull request, merge, and release gates and into a weekly scheduled or manually dispatched workflow, keeping vulnerability checks available without making those delivery workflows wait for every scan.

#### Time conversion
* Extended Alonzo Plutus slot time conversion linearly beyond the forecast horizon with overflow protection, while later eras retain bounded conversion behavior.

#### Validation reliability
* Stabilized the node parity boundary redelivery test by shortening test only waits, making boundary behavior checks more deterministic.

#### Testing integrations
* Added an opt in Antithesis SDK build tag shim for environments that need it, while leaving default builds unchanged.

#### Ledger classification
* Derived immutable `IsEbb` values from the decoded era tag instead of slot and epoch heuristics, keeping EBB classification consistent at era boundaries.

#### KES agent operations
* Enabled in place KES agent sign mode credential reload through `SIGHUP`, optional stable file polling, validation, reload metrics, and offers for newer operational certificates. Operators can refresh signing credentials without restarting the node when reload is configured.
