## v0.90.3

**Title:** Improve consensus correctness, API resilience, and operational safeguards

**Version:** v0.90.3

**Release:** [v0.90.3](https://github.com/blinklabs-io/dingo/releases/tag/v0.90.3)

**Comparison:** [v0.90.2...v0.90.3](https://github.com/blinklabs-io/dingo/compare/v0.90.2...v0.90.3)

Dingo v0.90.3 improves stake handling across era boundaries, bounds API and database work, strengthens peer and download safety, and refines Leios and operational behavior for node and library users.

#### Consensus and ledger
* Fixed epoch-boundary stake handling so same-rule era changes retain the existing SNAP-point stash. Dingo now reconstructs historical stake only when pointer-stake eligibility changes, including Babbage to Conway transitions, and applies one consistent pointer-stake rule.
* Added the hard-fork-selected incoming era to boundary stake reads before the incoming epoch row exists, allowing corrected stake distributions to be reused.
* Improved local-extension header verification by retrying transient failures after ledger context changes within the existing bounded wait and parking headers when retries expire.
* Introduced certification-deadline handling for relayed Leios votes while keeping locally produced votes within the local vote window.
* Enabled caching and persistence of empty leader schedules for zero-stake epochs.

#### API, database, and performance
* Expanded Leios key-epoch snapshot and retirement lookups with migration v51 composite indexes and bounded seek and UNION logic, preventing unbounded database work.
* Refined Blockfrost pool stake aggregation with bounded SQL aggregates and network-wide active-pool totals. Fallback handling covers unavailable aggregate data and overflow errors; shared admission allows four global and two per-client pool aggregate operations, returning HTTP 429 with `Retry-After: 1` when capacity is full.
* Bounded Blockfrost asset detail and listing work with shared admission, a 15-second deadline, cancellation propagation, and SQL aggregation. Requests return HTTP 429 or 503 with `Retry-After` when capacity or service availability requires a retry, and requests exceeding 1,000,000 live UTxOs return HTTP 400.
* Secured cloud mirror marker reads and publication by bounding marker size and rejecting unsafe or replaced paths.
