## v0.87.1

**Title:** Improve synchronization reliability, resource controls, and observability

**Version:** v0.87.1

**Release:** [v0.87.1](https://github.com/blinklabs-io/dingo/releases/tag/v0.87.1)

**Comparison:** [v0.87.0...v0.87.1](https://github.com/blinklabs-io/dingo/compare/v0.87.0...v0.87.1)

Dingo v0.87.1 improves catch-up reliability, peer synchronization, resource limits, external data handling, and operational visibility without changing the upstream Kupo v2.12 response contract.

### Recommended Network Compatibility ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### Reliability and synchronization
* Reduced ledger catch-up write amplification by giving each catch-up pass a bounded retry budget and each gap its own cap, while keeping the worst-case lock time bounded.
* Updated the node communication library to v0.213.11, preventing pipelined messages from causing intermittent node parity protocol errors and timeouts.
* Reported canceled and expired contexts from node parity Dingo queries so callers can detect them with `errors.Is` and cache-hit behavior remains stable.
* Allowed headers whose parents already wait in the local queue to undergo local verification when peer ancestry is unavailable, while Dingo continues to withhold headers with unknown parents.

### Data validation and external integrations
* Refined Koios reward checks to compare pool totals with per-account member rows only after complete account coverage, treating pool-history disagreement as informational and avoiding false parity failures from cached or forfeited totals.
* Prevented intermittent DevNet governance input failures by skipping wallet UTxOs already consumed by pending mempool transactions.
* Bounded Kupo `/matches` resource use with page-scoped snapshots of 512 rows, raised global concurrent streams from two to three while retaining one stream per client, preserved the Kupo v2.12 response contract, and exposed Kupo headers through CORS for allowed origins.
* Stabilized Genesis and Mithril catch-up by holding uncorroborated headers for up to five seconds before re-intersecting, admitting peer tips only against the live applied tip, ignoring stale advertised tips, and handling hashed slot-zero frontiers correctly.

### Resource controls and query behavior
* Limited local transaction validation to each connection lifetime, shared an eight-slot in-flight budget, canceled queued work after disconnects, and rejected new work when the budget was full.
* Reworked historical stake and expiration queries to keep SQLite cursor use bounded, added coverage across database dialects, and updated `modernc.org/sqlite` to v1.61.0; the measured gated query now uses about 551 cursors instead of more than 3,000.
* Tolerated Koios data gaps by retrying pool history per pool, reporting unpublished history as incomplete, handling deeply nested transaction information, and retrying missing transaction hashes for bounded intervals.
* Strengthened release and development operations with tiered code review and merge queue checks, release tag verification against merge queue gates without rerunning tests after integration, and a scheduled or manually dispatched DevNet block workflow.

### Catch-up and operational stability
* Classified unpublished Koios pool history as nonfatal reference lag and rate-limited refetching so temporary publication delays do not cause repeated work.
* Closed test ordering and race gaps, improved `FreePort` allocation and lifecycle diagnostics, and added synchronization points that reduce intermittent CI failures.
* Replayed primary-chain blocks ahead of the ledger before copying immutable data, verified block bodies during the replay, and prevented Mithril bootstrap gaps.
* Serialized node parity ChainSync callbacks with reconnect-session retirement to prevent stale callbacks and reconnect races.

### Observability and API admission
* Added `prepare`, `commit`, and `deferred_header_verify` ledger-stage metrics and corrected apply-stage sampling so dashboards attribute block application latency accurately.
* Corrected npm release-host DNS validation to accept public IPv4 and mapped IPv4 addresses while continuing to reject restricted, mixed, and empty results.
* Named hand-written block-apply SQL statements and prepared hot statements, replacing unknown query metrics with stable names.
* Rooted accepted ChainSync header tips in the local chain, cleared stale tips after rejection or drop paths, and treated same-slot competing tips as unapplied work.
* Enforced bounded Blockfrost address and account history reads with shared admission capacity, returned HTTP `400` for histories over the budget and HTTP `429` when admission is full, and corrected exact-history paging accounting.
* Introduced broader resource controls for Core sync, UTxO filtering, Mithril decoding, FindIntersect, and MCP payload parsing: the Badger memtable defaults to `512 MiB`, exact-address filtering is more efficient, Mithril zstd decoding has a memory budget, FindIntersect resolves points from metadata without block-body reads, Blockfrost account work supports cancellation and admission control, and `evaluate_tx` and `calculate_min_utxo` parsing accepts at most `128 KiB` with bounded parse slots.
