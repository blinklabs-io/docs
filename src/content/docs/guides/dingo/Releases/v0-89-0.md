## v0.89.0

**Title:** Improve consensus, synchronization, and operational security

**Version:** v0.89.0

**Release:** [v0.89.0](https://github.com/blinklabs-io/dingo/releases/tag/v0.89.0)

**Comparison:** [v0.88.1...v0.89.0](https://github.com/blinklabs-io/dingo/compare/v0.88.1...v0.89.0)

Dingo v0.89.0 expands consensus and DMQ capabilities, improves synchronization and data processing, strengthens local secret and snapshot protection, and adds clearer operational metrics.

### Recommended Network Compatibility ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### Consensus, networking, and observability
* Added the CIP-0177 Tachys consensus provider with provider-specific networking identity, schedule v7, validation, rollback handling, and DevNet support.
* Introduced DMQ node-to-node submission through `sig-submission` v2 with keep-alive and bounded message validation.
* Preserved explicit Leios mempool capacities and applied a `25 MiB` Musashi default when capacity remains unset.
* Exposed the Leios ranking-block kind and verified endorser block arrival metrics for clearer block processing visibility.
* Stopped treating late Leios votes as peer misbehavior, preventing delayed protocol messages from causing unwarranted peer penalties.
* Selected shared peers with a salted hash over an `823` second window, capped at `10` peers.
* Resynchronized promoted observers before the ledger tip and intersected at the ledger tip during Genesis corroboration.

### Synchronization and data processing
* Added bounded ChainSync deferred-header and resynchronization metrics.
* Measured ledger block adoption delay at the tip to show how quickly applied blocks reach the ledger.
* Decoded Mithril stream chunks ahead of batch application with bounded ordered cancellation.
* Separated Mithril signature-body read admission from verification slots, allowing each workload to use its own capacity.
* Counted implicit Mithril archive directories against extraction limits and the extraction budget.
* Skipped Blockfrost metadata pages beyond the available range and propagated cancellation through the request.
* Ran trusted-batch spent-UTxO pruning every `16` batches and drained pruning before catch-up resumed.
* Bulk-wrote trusted-batch transaction and live-stake overlay rows, with conflict fallback for concurrent changes.

### Security and reliability
* Batch-authenticated DMQ peer replies with atomic admission behavior, so a batch enters the peer set only when authentication admits it as a whole.
* Authorized DMQ against the electing stake distribution at the wall-clock slot and classified unavailable stake state as indeterminate.
* Enforced trusted ownership and non-writable ancestor paths for Unix `_FILE` secret and token files, including symlink and time-of-check to time-of-use checks.
* Made local snapshots owner-private with Unix `0700` directory and `0600` file permissions and owner-only Windows ACLs.
* Redacted URL fragments from entrypoint startup and debug output.

### Integrations and dependencies
* Removed Koios URL userinfo from errors so credentials do not appear in reported failures.
* Updated `klauspost/compress` from `1.20.0` to `1.20.3`.
* Raised the AWS S3 SDK from `1.114.2` to `1.114.5`.
* Upgraded `go-winio` from `0.6.2` to `0.6.4` and updated its transitive `logrus` dependency.
* Aligned `gouroboros` with `v0.215.1` and refreshed its fixtures.
