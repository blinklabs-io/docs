## v0.90.1

**Title:** Improve chain recovery, backfill, and interoperability

**Version:** v0.90.1

**Release:** [v0.90.1](https://github.com/blinklabs-io/dingo/releases/tag/v0.90.1)

**Comparison:** [v0.90.0...v0.90.1](https://github.com/blinklabs-io/dingo/compare/v0.90.0...v0.90.1)

Dingo v0.90.1 improves chain selection after reconnects, adds mainnet from genesis support, and makes backfill, peer discovery, ledger queries, and protocol services more resilient under bounded capacity.

### Recommended Network Compatibility ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### Consensus, chain selection, and peer operations
* Improved Genesis mode chain selection after short reconnects from the same peer identity. Dingo retains the peer's frontier state for a bounded period and expires it when the peer does not reconnect. [Details](https://github.com/blinklabs-io/dingo/pull/5760)
* Enabled node parity from genesis on `--network mainnet` and added `--skip-utxo` for runs that do not need UTxO comparison. Mainnet now uses Koios, while reward and account comparisons remain unavailable for that network. [Details](https://github.com/blinklabs-io/dingo/pull/5758)
* Added `genesisBootstrap.controlGroups` for trusted independent relay operators, including canonical defaults when genesis hashes match, explicit empty-list behavior, validation, and fail-closed handling for conflicts. [Details](https://github.com/blinklabs-io/dingo/pull/5774)
* Prevented duplicate unresolved topology peers when relay names resolve later while preserving dormant bootstrap behavior. [Details](https://github.com/blinklabs-io/dingo/pull/5775)

### APIs, backfill, and protocol services
* Preserved cumulative SQL transaction byte accounting through metadata flushes and enforced backfill limits at transaction boundaries of 200 blocks or 32 MiB. [Details](https://github.com/blinklabs-io/dingo/pull/5794)
* Raised the default API backfill batch size from 100 to 200. [Details](https://github.com/blinklabs-io/dingo/pull/5767)
* Bounded Leios transaction replies by the existing protocol ingress limit, resumed partial bitmap fetches correctly, and reported clear errors when a transaction could not be fetched. [Details](https://github.com/blinklabs-io/dingo/pull/5754)
* Placed Blockfrost `GET /accounts/{stake_address}/addresses` in the shared whole-history admission pool. Saturated requests return `429` with `Retry-After: 1`, and Dingo validates pagination before admission. [Details](https://github.com/blinklabs-io/dingo/pull/5753)

### Ledger and storage reliability
* Served Byron UTxO outputs in legacy Shelley encoding for LocalStateQuery responses. [Details](https://github.com/blinklabs-io/dingo/pull/5763)
* Made Mithril reward live-stake rebuilds resumable with durable cursor checkpoints. [Details](https://github.com/blinklabs-io/dingo/pull/5749)
* Limited queued API backfill metadata batches to 5,000 rows or an estimated 32 MiB payload and flushed batches mid-block when either limit was reached. [Details](https://github.com/blinklabs-io/dingo/pull/5773)
* Projected minimal current-pool VRF state for header verification with fallback behavior when the projection is unavailable. [Details](https://github.com/blinklabs-io/dingo/pull/5786)
