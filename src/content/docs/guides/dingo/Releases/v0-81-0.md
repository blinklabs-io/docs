## v0.81.0

**Title:** Simplify operations, improve synchronization, and strengthen network reliability

**Version:** v0.81.0

**Release:** [v0.81.0](https://github.com/blinklabs-io/dingo/releases/tag/v0.81.0)

Dingo v0.81.0 simplifies local network operation, expands query and snapshot capabilities, improves synchronization and recovery, and strengthens API, storage, and security safeguards.

### Recommended Network Compatibility ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### Node operation and developer workflows
* Added one-command `dingo devnet` operation with temporary or persistent `--data-dir` state, `--reset`, embedded configuration and keys, refreshed genesis time, state validation and locking, generated configuration, and process-group shutdown.
* Updated conformance database resets to detect dirty tables, reuse probes, and select dialect-specific cleanup, reducing repeated reset work.
* Corrected vulnerability checks to honor the Go toolchain declared by the module.
* Aligned generated Homebrew titles with the repository's naming conventions.
* Improved entrypoint readiness tests and diagnostics for clearer startup checks.

### Governance, ledger queries, and protocol compatibility
* Restored imported expired committee update enactments with the correct committee, quorum, and enactment timing state, while rejecting ambiguous governance evidence.
* Corrected pinned Shelley debug state queries so they answer at the acquired point with bounded operational certificate reads and chain-safe nonce handling.
* Applied era transitions before rollover and corrected incoming-era snapshot and VRF ordering.
* Added Shelley local state query answers for the ledger tip, stake pool parameters, and proposed protocol parameter updates, along with compact genesis encoding for node-to-client version 21 and preserved relay type information.

### Peer connectivity and resource management
* Introduced a Genesis Density Disconnector that rate limits sparse peer disconnections and denials, reports metrics, and coordinates lifecycle locking.
* Separated inbound and outbound peer budgets, tracked served activity, protected active inbound relays from pruning, and adjusted stable session flapping behavior.
* Corrected served activity attribution so it identifies the callback connection.
* Enabled a connected lone far peer to recover past the catch-up ceiling and revoke the recovery when chain continuity breaks.

### Snapshot, lifecycle, and storage operations
* Set the snapshot commit pause to 30 seconds by default, documented `0` as unbounded, improved timeout classification, and added storage batching and index rebuild support.
* Added optional remote Bark lifecycle controls for stopping, restarting, and checking status with mutual TLS, separate operator authorization, graceful shutdown, Unix restart support, and status reporting.
