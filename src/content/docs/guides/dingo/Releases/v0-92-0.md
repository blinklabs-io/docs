## v0.92.0

**Title:** Improve synchronization, consensus reliability, and ledger performance

**Version:** v0.92.0

**Release:** [v0.92.0](https://github.com/blinklabs-io/dingo/releases/tag/v0.92.0)

**Comparison:** [v0.91.0...v0.92.0](https://github.com/blinklabs-io/dingo/compare/v0.91.0...v0.92.0)

Dingo v0.92.0 improves synchronization, consensus validation, ledger processing, Mithril imports, and operational visibility.

### Recommended Network Compatibility ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

#### Breaking changes
* Updated metadata APIs to require a context, so callers must provide one when pruning reward state. Bounded adaptive batches now check for cancellation between batches.

#### Synchronization and storage
* Expanded default Leios timing windows from one second by the configured Shelley genesis slot duration, rounding up to preserve the intended wall clock duration. Explicit timing overrides remain unchanged, including on networks with subsecond slots.
* Increased single pass verified immutable entry reads from 16 MiB to 128 MiB, reducing double reads during Mithril imports while retaining bounded fallback verification.
* Improved peer continuity by revalidating retained fork ancestry after consensus context changes, sharing transaction scoped ledger state, and advertising peer addresses only after verified outbound connectivity.
* Tuned Mithril synchronization to use Badger's 1 KiB value threshold in Core and API modes. Larger API mode block bodies now use the value log, while explicit thresholds continue to override the default.

#### Consensus and chain validation
* Hardened Leios vote validation by rejecting votes from seats without verified keys, deduplicating repeated drops, and returning `ErrUnknownSignerKey` when certificate validation lacks a signer key.
* Aligned Leios voting key expiry with the selected committee epoch so key aging follows the reference behavior.
* Refined hard fork forecasts to follow ratification ordering, delaying action precedence, and enactment preconditions.
* Corrected same slot Byron epoch boundary rollback classification using the durable ledger tip, restoring the correct UTxO effects.

#### Ledger processing and observability
* Enabled Limit on Eagerness Prometheus gauges to remain nonblocking during ledger transitions by returning the last stable value when needed.
* Propagated context cancellation through chain membership, forecast horizon, fork anchor, and trusted batch operations instead of treating cancelled reads as absent data.
* Optimized Dijkstra phase two success caching for transactions with redeemers, avoiding cache churn for script free transactions.
* Streamlined pending reward credit aggregation to one pass per large live stake read, used a covering index where supported, and kept autocommit reads snapshot consistent.

#### Recovery and peer operations
* Preserved consumed UTxO history while deferred reward inputs remained pending, capped pruning, and failed closed on invalid pending state.
* Recognized completed in flight ledger block processing during chainsync plateau detection and handled ledger replacement and slot zero progress correctly.
* Enforced configured chain checkpoints on peer headers before candidate processing and recycled mismatching connections.
* Bounded at tip recovery to a cached immutable K block floor across retries.
* Delayed forged Leios endorser blocks until announcing headers arrived and bounded pending offers to eight.

#### Storage and runtime
* Protected snapshot deletion by limiting `DeleteSnapshot` to actual snapshot directories with a regular manifest and preserving internal `.dingo-` entries.
* Rejected sparse Mithril archive members and encoded ledger state snapshots over 1 GiB, and used bounded snapshot reads.
* Updated Plutigo integration to v0.11.6 with bounded per evaluation hash caching while preserving budget charging order.

#### Development and documentation
* Strengthened accelerated devnet outage tests by requiring fresh multi node agreement above a post recovery watermark.
* Stabilized DMQ peer manager replacement validation by waiting for lost connections to clear before replacement checks.
* Added README network synchronization and runtime resource baselines for Dingo v0.90.5 across Preview, Preprod, and Mainnet Core, API, and Mithril modes, using an em dash for uncaptured values.
* Recorded measured Preview and Preprod API v0.91.0 runtime and storage baselines and clarified Core and API version notation in the README.
