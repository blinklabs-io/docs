## v0.83.0

**Title:** Improve synchronization, storage, and operational controls

**Version:** v0.83.0

**Release:** [v0.83.0](https://github.com/blinklabs-io/dingo/releases/tag/v0.83.0)

Dingo v0.83.0 improves synchronization, ledger state handling, service reliability, storage efficiency, and operational controls compared with v0.82.1.

### Synchronization and recovery
* Reduced misleading error noise during synchronization by logging expected `errValidationSnapshotChanged` overlay rebuild deferrals at DEBUG instead of ERROR, while preserving retry cooldown behavior.
* Corrected epoch boundary pool registration handling during Mithril imports by preserving staged re-registrations, storing current and staged records with registration indexes, and applying effective or deferred VRF ownership correctly. Deployments must apply database migration v43 for these changes.
* Added a Genesis mode Limit on Eagerness that caps selection and header delivery at the candidate intersection, pauses held peers, resolves density standoffs, exposes LoE gauges and `eagerness_held` observability, and cancels waits during shutdown.
* Enhanced Blockfrost query scalability by moving pagination for extended pools, retiring pools, DReps, and asset holders into storage, propagating request cancellation, and persisting and backfilling `utxo_address` metadata for consistent pagination.
* Isolated header mismatch tracking per connection with synchronization, so only the offending connection reaches persistent fork resynchronization thresholds.
