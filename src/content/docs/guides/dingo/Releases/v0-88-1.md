## v0.88.1

**Title:** Improve peer synchronization and ledger processing

**Version:** v0.88.1

**Release:** [v0.88.1](https://github.com/blinklabs-io/dingo/releases/tag/v0.88.1)

**Comparison:** [v0.88.0...v0.88.1](https://github.com/blinklabs-io/dingo/compare/v0.88.0...v0.88.1)

Dingo v0.88.1 improves peer retention during deferred header recovery and makes eligible trusted batch ledger updates more efficient while preserving the resulting persisted state.

### Recommended Network Compatibility ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### Peer synchronization
* Improved peer recovery by keeping a peer connected when another peer applies a withheld header to the canonical chain. The node aligns the peer's chain position without reconnecting or resynchronizing, preserves delivery accounting, and cancels the recovery result if a rollback could move that position backward.
* Restored peer retention for an undelivered deferred header when the local chain already contains its matching block. The node resolves the header immediately, aligns the peer's chain position, and preserves ordinary recovery for delivered headers, forks, and rollback races.

### Ledger processing
* Accelerated eligible trusted batch updates in SQLite core storage by using a temporary per batch UTxO view, preloading required data, writing net changes, and replaying live stake data behind a read barrier. The node preserves the same persisted state as standard processing, returns to standard processing after uniqueness conflicts, and records each fallback in `dingo_ledger_trusted_batch_overlay_fallbacks_total`.
