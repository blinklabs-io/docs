## v0.88.1

**Title:** Improve peer synchronization and ledger processing

**Version:** v0.88.1

**Release:** [v0.88.1](https://github.com/blinklabs-io/dingo/releases/tag/v0.88.1)

**Comparison:** [v0.87.1...v0.88.1](https://github.com/blinklabs-io/dingo/compare/v0.87.1...v0.88.1)

Dingo v0.88.1 improves peer retention during deferred header recovery and makes eligible trusted batch ledger updates more efficient while preserving the resulting persisted state.

### Recommended Network Compatibility ⚠️

| Network             | Compatible |
|---------------------|------------|

| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### Peer synchronization
* Improved peer recovery so the node keeps a peer connected when another peer applies a withheld header to the canonical chain, moves the peer cursor into alignment without reconnecting or resynchronizing, preserves delivery accounting, and cancels the recovery result when a rollback could otherwise move the cursor backward.
* Restored peer retention when the local chain already contains a matching block for an undelivered deferred header: the node resolves the header immediately, aligns the peer cursor, and keeps the standard recovery behavior for delivered headers, forks, and rollback races.

### Ledger processing
* Accelerated eligible trusted batch updates in SQLite core storage with a batch scoped temporary UTxO view that preloads needed data, writes only net changes, and replays live stake data behind a read barrier. The node preserves the same persisted state as standard processing, returns to that path after uniqueness conflicts, and records each fallback in `dingo_ledger_trusted_batch_overlay_fallbacks_total`.
