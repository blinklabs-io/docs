## v0.94.1

**Title:** Improve Leios reliability and historical state

**Version:** v0.94.1

**Release:** [v0.94.1](https://github.com/blinklabs-io/dingo/releases/tag/v0.94.1)

**Comparison:** [v0.94.0...v0.94.1](https://github.com/blinklabs-io/dingo/compare/v0.94.0...v0.94.1)

Dingo v0.94.1 improves Leios data handling, offer timing, historical stake reconstruction, pool status reads, and Unix socket setup.

### Recommended Network Compatibility ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

#### Leios data and synchronization
* Preserved certified Leios endorser-block records while applying their certifying ranking block, writing the `em` and `et` records before the `ec` marker and repairing stored bytes when they differ. Retention pruning now skips failed immutable point lookups unless the node uses the unconfigured fallback.
* Deferred Leios offer-driven manifest and transaction fetches until the node observes an election or validates a slot against its cache. Early offers now remain in bounded TTL pending-offer state and replay after election observation without blocking saturated queues.
* Added checks that outgoing Leios endorser-block offers lead the immutable tip. The node drops offers when the check fails or immutable lookup fails. `CardanoNodeConfig.LeiosMinOfferLead` now defaults to `3600` slots, while Leios DevNet sets it to `30`.

#### Historical state and pool status
* Corrected historical boundary stake reconstruction by using `account_import_baseline`, so baselined credentials use historical values instead of rewritten live account rows.
* Included Conway genesis delegation rows with `certificate_id=0` in historical stake reconstruction and corrected PostgreSQL genesis account insertion.
* Introduced migration v67 with materialized per-pool state in `pool_current_state` and `pool_current_event`. Transactional refreshes, horizon-aware reads, `GetPoolStatus`, and single read transactions now provide consistent pool status access.

#### Operations and reliability
* Improved shutdown validation by waiting for the Badger garbage collector stop signal before releasing resources. Production behavior remains unchanged.
* Accepted Unix socket parents writable by group or other users when the parent has the sticky bit and updated the permission remediation guidance.
