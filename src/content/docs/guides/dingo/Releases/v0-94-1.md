## v0.94.1

**Title:** Improve Leios reliability and historical state

**Version:** v0.94.1

**Release:** [v0.94.1](https://github.com/blinklabs-io/dingo/releases/tag/v0.94.1)

**Comparison:** [v0.94.0...v0.94.1](https://github.com/blinklabs-io/dingo/compare/v0.94.0...v0.94.1)

Dingo v0.94.1 improves Leios data handling, offer timing, historical stake reconstruction, pool status reads, and Unix socket setup.

### Recommended Network Compatibility ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

#### Leios data and synchronization
* Preserved certified Leios endorser block records while applying their certifying ranking block, writing the `em` and `et` records before the `ec` marker and repairing stored bytes when they differ. Retention pruning now skips when immutable point lookup fails, except for the unconfigured fallback.
* Deferred Leios offer driven manifest and transaction fetches until the node observes an election or verifies a slot against its cache. Early offers now remain in bounded time limited pending state and replay after election observation without blocking saturated queues.
* Added immutable tip lead checks to outgoing Leios endorser block offers. The node drops offers that fail the lead check or immutable lookup. `CardanoNodeConfig.LeiosMinOfferLead` now defaults to `3600` slots, while Leios DevNet sets it to `30`.

#### Historical state and pool status
* Corrected historical boundary stake reconstruction by using `account_import_baseline`, so baselined credentials do not fall back to rewritten live account rows.
* Included Conway genesis delegation rows with `certificate_id=0` in historical stake reconstruction and corrected PostgreSQL genesis account insertion.
* Introduced migration v67 with materialized `pool_current_state` and `pool_current_event` records for each pool. Transactional refreshes, horizon aware reads, `GetPoolStatus`, and single read transactions now provide consistent pool status access.

#### Operations and reliability
* Improved shutdown validation by waiting for the Badger garbage collector stop signal before releasing resources.
* Accepted group or other writable Unix socket parents when the sticky bit is set and updated the permission remediation guidance.
