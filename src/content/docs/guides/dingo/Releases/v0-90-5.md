## v0.90.5

**Title:** Improve node parity, protocol compatibility, performance, and operations

**Version:** v0.90.5

**Release:** [v0.90.5](https://github.com/blinklabs-io/dingo/releases/tag/v0.90.5)

**Comparison:** [v0.90.4...v0.90.5](https://github.com/blinklabs-io/dingo/compare/v0.90.4...v0.90.5)

Dingo v0.90.5 improves node parity workflows, protocol compatibility, transaction processing, peer operations, and development network validation.

### Recommended Network Compatibility ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

#### Node parity and synchronization
* Added `node-parity from-genesis` support for `--boundary-capture-dir`, kept chainsync sessions alive, captured UTxOs before boundary processing, and retried transient Koios `/tx_info` failures. These workflows can now capture boundary data and continue through temporary transaction information failures.
* Removed Allegra-redeemed Byron UTxOs during node parity reconstruction and included bounded mismatch samples, making discrepancies easier to inspect without unbounded output.

#### Networking and consensus
* Granted ingress slots to peers that can corroborate Genesis data, allowing those peers to participate while corroboration runs.
* Emitted 10-field Praos headers on Dijkstra chains that do not use Leios and gated Leios block forging to applicable chains.
* Enforced CIP-164 wall clock timing for Leios votes and updated the related VoteManager and header event interfaces to carry the revised timing behavior.

#### Transaction processing and Plutus evaluation
* Cached conversions from `TxInfo` to `PlutusData` across Alonzo, Babbage, and Conway and added benchmark coverage across all three eras, allowing repeated conversions to use cached results.
* Encoded structured Conway `LocalTxSubmission` rejection causes, including typed ledger failures and Plutus reconstruction context; clients now receive specific reason data.
* Reused cached transaction signature verification results when available, avoiding repeat verification for transactions with a known result.
* Retained successful Conway and Dijkstra Plutus phase two evaluations for reuse, avoiding repeated evaluation of the same successful result.
* Stored MIR pending rewards per `LedgerView`, allowing repeated reads within a view to use the cached reward state.

#### Development networks and configuration
* Expanded PV10 and PV11 Plutus bounded argument devnet conformance coverage, accelerated the PV11 specification, and validated `DEVNET_SPEC_OVERRIDE` values before use.
* Removed default Genesis control groups and changed default `genesisBootstrap.corroborationPeers` from `1` to `0`, so default configurations no longer assign a corroboration peer.

#### Operations and dependencies
* Updated `gouroboros` to v0.217.0.
* Counted peer transition and churn metrics on every state change, keeping operational metrics aligned with peer state changes.
* Refreshed Musashi and operational Grafana dashboards with updated monitoring coverage.
