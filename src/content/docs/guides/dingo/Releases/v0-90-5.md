## v0.90.5

**Title:** Improve node parity, consensus, performance, and operations

**Version:** v0.90.5

**Release:** [v0.90.5](https://github.com/blinklabs-io/dingo/releases/tag/v0.90.5)

**Comparison:** [v0.90.4...v0.90.5](https://github.com/blinklabs-io/dingo/compare/v0.90.4...v0.90.5)

Dingo v0.90.5 improves node parity workflows, protocol compatibility, transaction processing, peer operations, and development network validation.

### Recommended Network Compatibility ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

#### Node parity and synchronization
* Added `node-parity from-genesis` support for `--boundary-capture-dir`, kept chainsync sessions alive, captured UTxOs before boundary processing, and retried transient Koios `/tx_info` failures. Node parity workflows can now capture boundary data and continue through temporary transaction information failures.
* Removed Allegra-redeemed Byron UTxOs during node parity reconstruction and included bounded mismatch samples, making discrepancies easier to inspect without unbounded output.

#### Networking and consensus
* Granted ingress slots to peers that can corroborate Genesis data, allowing those peers to participate while corroboration runs.
* Emitted 10-field Praos headers on Dijkstra chains that do not use Leios and gated Leios block forging to applicable chains.
* Enforced CIP-164 wall clock timing for Leios votes and updated the related VoteManager and header event interfaces to carry the revised timing behavior.

#### Transaction processing and Plutus evaluation
* Cached `TxInfo` to `PlutusData` conversion across Alonzo, Babbage, and Conway and added a benchmark covering all three eras, so repeated conversions can reuse the cached result.
* Encoded structured Conway `LocalTxSubmission` rejection causes, including typed ledger failures and Plutus reconstruction context, so clients receive specific reason data.
* Reused cached transaction signature verification results when available, avoiding repeat verification for transactions with a known result.
* Retained successful Conway and Dijkstra Plutus phase two evaluations for reuse, avoiding repeated evaluation of the same successful result.
* Stored MIR pending rewards per `LedgerView`, allowing repeated reads within a view to use the cached reward state.
