## v0.90.2

**Title:** Improve synchronization reliability, ledger accuracy, and API performance

**Version:** v0.90.2

**Release:** [v0.90.2](https://github.com/blinklabs-io/dingo/releases/tag/v0.90.2)

**Comparison:** [v0.90.1...v0.90.2](https://github.com/blinklabs-io/dingo/compare/v0.90.1...v0.90.2)

Dingo v0.90.2 improves network synchronization reliability, ledger and API correctness, resource usage, MCP and UTxO behavior, and operational visibility.

### Recommended Network Compatibility ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

### English

#### Synchronization and networking
* Prevented genesis and origin ChainSync from advancing beyond block zero until Dingo has an applied point, preventing truncated chains.
* Deferred header re-verification until ledger settlement and used bounded waits to keep synchronization responsive.
* Clamped the `Limit on Eagerness` to the immutable tip and resynchronized after bounded eagerness waits.
* Preserved peers after local authorization recovery by recording a distinct resynchronization reason.
* Memoized successful peer-fork ancestor state checks within each consensus context.
* Fell back to the header pipeline connection when Dingo selected no peer.

#### Ledger, APIs, and performance
* Replaced operation certificate `COUNT(*)` lookups with index-friendly `MAX(sequence)` lookups.
* Applied live delegated stake and circulating supply fractions to `GetStakeDistribution2` while preserving `GetPoolDistr2` semantics.
* Returned exact arbitrary-precision Blockfrost epoch output totals and rejected negative subtotals.
* Serialized concurrent `GetUTxOWhole` requests while preserving complete results.
* Cached repeated UTxO RPC spent-output lookups during each predicate evaluation.

#### MCP, observability, and resource limits
* Reserved a two-query sub-budget for caller-supplied MCP SQLite SQL within four shared read slots and failed fast when the shared capacity was busy.
* Counted restricted Praos equal-height slot battles, deduplicated those events, and reported `RemoteSlot`.
* Held observer headers at the forecast horizon.
* Bounded Genesis header retention and walks by header count and byte budgets.

### 日本語

#### 同期とネットワーク
* 適用済みのポイントが存在するまで Genesis と Origin の ChainSync がブロック 0 を越えて進まないようにし、チェーンの欠落を防ぎました。
* 台帳の確定までヘッダーの再検証を遅延し、同期の応答性を保つため待機時間を制限しました。
* `Limit on Eagerness` を不変チップに制限し、制限時間付きの eagerness 待機後に再同期するようにしました。
* ローカル認証の復旧後もピアを保持し、再同期の理由を別に記録するようにしました。
* 各コンセンサスコンテキストで成功したピアフォーク祖先の状態確認をメモ化しました。
* Dingo がピアを選択しない場合にヘッダーパイプライン接続へフォールバックするようにしました。

#### 台帳、API、性能
* オペレーション証明書の `COUNT(*)` 検索をインデックスに適した `MAX(sequence)` 検索へ置き換えました。
* `GetStakeDistribution2` がライブの委任済みステークと流通供給量の割合を使うようにし、`GetPoolDistr2` の動作は維持しました。
* Blockfrost のエポック出力合計を任意精度で正確に返し、負の小計を拒否するようにしました。
* 並行する `GetUTxOWhole` 要求を直列化し、完全な結果を維持するようにしました。
* 各述語評価で繰り返される UTxO RPC の使用済み出力検索をキャッシュするようにしました。

#### MCP、可観測性、リソース制限
* 呼び出し元が指定した MCP SQLite SQL に、4 つの共有読み取り枠内で 2 クエリのサブ予算を設け、共有容量が使用中の場合は即座に失敗するようにしました。
* 制限された Praos の同一高さスロット競合を数え、重複を排除して `RemoteSlot` を報告するようにしました。
* オブザーバーのヘッダーを予測 horizon で保持するようにしました。
* Genesis ヘッダーの保持と走査をヘッダー数およびバイト予算で制限するようにしました。

### Español

#### Sincronización y red
* Impidió que ChainSync de Genesis y Origin avanzara más allá del bloque cero hasta que existiera un punto aplicado, evitando cadenas truncadas.
* Retrasó la reverificación de encabezados hasta la liquidación del ledger y limitó las esperas para mantener la sincronización receptiva.
* Limitó `Limit on Eagerness` al extremo inmutable y volvió a sincronizar después de esperas de eagerness con límite.
* Conservó los pares después de recuperar la autorización local y registró un motivo de resincronización distinto.
* Memorizó las comprobaciones correctas del estado del antecesor de la bifurcación del par dentro de cada contexto de consenso.
* Usó la conexión de la canalización de encabezados cuando Dingo no seleccionó ningún par.

#### Ledger, API y rendimiento
* Sustituyó las búsquedas `COUNT(*)` de certificados de operación por búsquedas `MAX(sequence)` compatibles con índices.
* Hizo que `GetStakeDistribution2` usara el stake delegado activo y las fracciones del suministro circulante, manteniendo la semántica de `GetPoolDistr2`.
* Devolvió totales exactos de salidas de época de Blockfrost con precisión arbitraria y rechazó subtotales negativos.
* Serializó las solicitudes simultáneas de `GetUTxOWhole` y conservó los resultados completos.
* Almacenó en caché las búsquedas repetidas de salidas gastadas de UTxO RPC durante cada evaluación de predicado.

#### MCP, observabilidad y límites de recursos
* Reservó un subpresupuesto de dos consultas para el SQL SQLite de MCP proporcionado por el llamador dentro de cuatro ranuras de lectura compartidas y falló rápidamente cuando la capacidad estaba ocupada.
* Contó las contiendas de slots de igual altura de Praos restringido, eliminó duplicados e informó `RemoteSlot`.
* Mantuvo los encabezados del observador en el horizonte previsto.
* Limitó la retención y los recorridos de encabezados de Genesis por cantidad de encabezados y presupuestos de bytes.
