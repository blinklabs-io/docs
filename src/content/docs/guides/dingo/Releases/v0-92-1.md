## v0.92.1

**Title:** Improve ledger recovery, validation, and processing reliability

**Version:** v0.92.1

**Release:** [v0.92.1](https://github.com/blinklabs-io/dingo/releases/tag/v0.92.1)

**Comparison:** [v0.92.0...v0.92.1](https://github.com/blinklabs-io/dingo/compare/v0.92.0...v0.92.1)

Dingo v0.92.1 improves recovery after rollback, transaction processing, governance state imports, peer validation, and the efficiency of SQLite operations and test suites.

### Recommended Network Compatibility ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

#### Ledger recovery and peer synchronization
* Fixed peer fork header checks after rollback, allowing the ledger to validate headers when stored epoch information predates the fork.
* Bounded reward preparation by the number of delegators, keeping reward processing proportional to the delegation set.

#### Transaction processing and storage
* Batched eligible mixed Leios payment windows in SQLite, retaining a bounded amount of pending data and preserving write, state creation, and rollback behavior while using direct deposits when batching is unavailable.
* Avoided temporary copies while SQLite calculates aggregate values, preserving parsed results.
* Narrowed reads used to recover consumed inputs, with an optional reader for spend state, a fallback for older storage paths, and at most one read at the Mithril boundary.
* Updated conformance corpus compatibility so validation continues to use supported test data.

#### Chain recovery and governance state
* Restored the ledger from a shared chain ancestor, bringing the primary chain and ledger metadata back to the newest applied ancestor with a guarded fallback to origin.
* Reconciled imported DRep membership atomically at the snapshot anchor for protocol version 10 and later.
* Preserved strict Conway governance expiration decisions during snapshot import and rejected malformed or contradictory data.
* Recovered selected idle chain synchronization streams after header delivery without realigning across peers from advertisements alone.
* Limited rollback address restoration to the spent slot while keeping SQLite planning compatible across database dialects.
* Shared successful header verification results across peers with a bounded cache keyed by header identity and epoch nonce for headers outside Byron.
* Strengthened aggregate signature checks by rejecting empty lottery signer entries and tying weighted checks to signer keys.

#### Test suite improvements
* Refined ledger, consensus, and networking test coverage by removing low-value cases and making the suites faster.
* Consolidated database, storage, and parity test coverage around shared fixtures and targeted regression cases.
* Streamlined SQLite test coverage with focused cases, smaller fixtures, in-memory stores, and tests that run safely in parallel.
* Accelerated node, API, and protocol test suites with focused coverage and test-only seams while preserving production behavior.
