## v0.92.1

**Title:** Improve ledger recovery, validation, and processing reliability

**Version:** v0.92.1

**Release:** [v0.92.1](https://github.com/blinklabs-io/dingo/releases/tag/v0.92.1)

**Comparison:** [v0.92.0...v0.92.1](https://github.com/blinklabs-io/dingo/compare/v0.92.0...v0.92.1)

Dingo v0.92.1 improves recovery after rollback, transaction processing, governance state imports, peer validation, and the efficiency of SQLite operations and test suites.

### Recommended Network Compatibility ⚠️

| Network             | Compatible |
|---------------------|------------|
| mainnet             | ⛔         |
| preprod-testnet     | ✅         |
| preview-testnet     | ✅         |
| musashi             | ✅         |

#### Ledger recovery and peer synchronization
* Fixed peer fork header verification after rollback, allowing the ledger to validate headers beyond its cached epoch.
* Bounded reward precomputation by delegator count, keeping reward processing proportional to the delegation set.

#### Transaction processing and storage
* Batched eligible mixed Leios payment windows in SQLite, retaining bounded overlays and preserving flush, materialization, and rollback behavior while using direct deposits when batching is unavailable.
* Avoided temporary copies of SQLite aggregate arguments while preserving parsed values.
* Narrowed consumed input recovery reads, with an optional spend state reader, a fallback for older storage paths, and at most one Mithril boundary read.
* Updated conformance corpus compatibility so validation continues to use the supported corpus format.

#### Chain recovery and governance state
* Restored the ledger from a shared chain ancestor, rolling primary chain and ledger metadata stores to the newest applied ancestor with a guarded origin fallback.
* Reconciled imported DRep membership atomically at the snapshot anchor for protocol version 10 and later.
* Preserved strict Conway governance expiration verdicts during snapshot import and rejected malformed or contradictory data.
* Recovered selected idle chainsync streams after header delivery without realigning across peers from advertisement only evidence.
* Limited rollback address restoration by spent slot while retaining dialect aware SQLite planning behavior.
* Shared successful stateless header cryptography verdicts across peers with a bounded cache keyed by header identity and epoch nonce for headers outside Byron.
* Strengthened STM aggregate signature checks by rejecting empty lottery index signer entries and binding weighted verification to signer keys.

#### Test suite improvements
* Refined ledger, consensus, and networking test coverage by removing low value cases and making the suites faster.
* Consolidated database, storage, and parity test coverage around shared fixtures and targeted regression cases.
* Streamlined SQLite test coverage with focused cases, smaller fixtures, in memory stores, and tests that run safely in parallel.
* Accelerated node, API, and protocol test suites with focused coverage and test only seams while preserving production behavior.
